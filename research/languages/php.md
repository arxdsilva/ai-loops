> **Summary:** A strong PHP team treats PHP as a typed language: `declare(strict_types=1)` everywhere, PHPStan at level 8+ (or `max`) with a baseline, PER-CS formatting via PHP-CS-Fixer or Pint, Composer with a committed `composer.lock`, `composer audit` in CI, and PHPUnit/Pest with PCOV or Xdebug coverage in Clover form. PHP has no race detector; the honest substitute is random test order plus parallel runs (ParaTest) and a state-leak check for worker-mode servers. Biggest loops gaps: (1) the gate, coverage parser, arch parser and post-edit hook are Go-only, so none of the PHP toolchain runs; (2) no language detection (`composer.json`) and no PHP cache/artifact cleanup (`.phpunit.cache`, `var/cache`, `bootstrap/cache`); (3) no repo-management, security (OWASP/SAST) or framework-convention guidance, and the hexagonal layout in the specs is Go-shaped while Laravel/Symfony push Active Record and framework-coupled layers.

Rules follow [TAXONOMY.md](TAXONOMY.md), using the row format `ID | Rule | Why | Sev | Source | loops today | Enforce`. Gaps are judged against [LOOPS_BASELINE.md](LOOPS_BASELINE.md). A dagger (†) after a source title means the URL is a canonical docs page that was not opened in this session; every other URL was opened and the claim checked.

## 1. REPO: repository and project management

Canonical tree for a service (framework-neutral, hexagonal, PSR-4 `App\` => `src/`):

```text
.
├── composer.json            # require/require-dev, autoload (psr-4), autoload-dev, config.platform.php, scripts
├── composer.lock            # COMMITTED for applications
├── .php-version             # or .tool-versions (asdf/mise); mirrors config.platform.php
├── phpunit.xml.dist         # <source><include>src</include></source>, cache dir, random order
├── phpstan.neon.dist        # level, paths, baseline include
├── phpstan-baseline.neon    # generated; shrink over time
├── .php-cs-fixer.dist.php   # @PER-CS3x0 (or pint.json for Laravel)
├── rector.php               # optional, dry-run in CI
├── deptrac.php              # layer rules (deptrac.yaml in older versions) (domain/application/adapters)
├── .editorconfig  .gitattributes  .gitignore  CODEOWNERS
├── bin/ or public/index.php # entry points (front controller / console)
├── config/                  # framework config only
├── src/                     # see ARCH-02 tree
├── tests/                   # Unit/  Integration/  Functional|Feature/  (mirrors src/)
├── migrations/ or database/migrations/
├── var/ or storage/ + bootstrap/cache/   # runtime, git-ignored
└── vendor/                  # git-ignored
```

## 3. ARCH: architecture

PHP's two dominant frameworks pull in opposite directions. **Laravel** ships Eloquent (Active Record: the model is the row and talks to the DB), facades and a `app/Models` layout; **Symfony** is built around a DI container, `src/` with free layout, and Doctrine ORM (Data Mapper: plain entity objects, persistence in `EntityManager`). Hexagonal is natural in Symfony (autowired interfaces, Doctrine attribute/XML mapping outside the domain) and requires discipline in Laravel (keep Eloquent models in the adapter layer; the domain uses plain classes and a repository interface). Choose a **modular monolith** by default; microservices only when team/scale boundaries demand it. CQRS/event sourcing are optional (Symfony Messenger, Laravel events/queues, `EventSauce`/Prooph for ES). Serverless (Bref on AWS Lambda) fits stateless HTTP/queue handlers; the actor model has no mainstream PHP form (Swoole coroutines/channels are the nearest).

ARCH-02 mapping (framework-neutral PSR-4 tree, `App\` => `src/`; deptrac layers shown on the right):

```text
src/
├── Domain/                      # layer: Domain      (no framework, no IO, no clock)
│   └── Order/ Order.php  OrderId.php  Money.php  OrderPlaced.php  OrderRepository.php?  # ports owned by consumer
├── Application/                 # layer: Application (use cases, ports)
│   └── Order/ PlaceOrder.php  PlaceOrderHandler.php  Port/{Clock,PaymentGateway,OrderStore}.php
├── Infrastructure/              # layer: Adapter-out (Doctrine/Eloquent/PDO/HTTP clients/queues)
│   ├── Persistence/ DoctrineOrderStore.php  (or EloquentOrderStore.php + Eloquent/OrderModel.php)
│   └── Clock/ SystemClock.php
├── Http/  (or UI/)              # layer: Adapter-in  (controllers, form requests, serializers)
│   └── Order/ PlaceOrderController.php  PlaceOrderRequest.php
├── Console/                     # layer: Adapter-in  (artisan / bin/console commands)
└── Kernel.php | Providers/      # composition root: container config, bindings
config/services.yaml | bootstrap/app.php   # wiring only
```

Laravel variant: put Eloquent models in `src/Infrastructure/Persistence/Eloquent/` (not `app/Models`), set `App\` or a `Shop\` namespace in `composer.json`, and register interface => implementation bindings in a service provider (the composition root). Symfony variant: Doctrine mapping via XML/PHP files or attributes on an `Infrastructure` mapping class so domain entities stay annotation-free (attributes on domain entities are a pragmatic, flagged violation).

## 4. IDIOM: what to do and what to avoid

| ID | Rule | Why | Sev | Source | loops today | Enforce |
|---|---|---|---|---|---|---|
| `PHP-IDIOM-01` | Put `declare(strict_types=1);` in every PHP file (after `<?php`, before `namespace`), and enforce it with PHP-CS-Fixer `declare_strict_types`; throw exceptions, never return `false`/`null` as an error signal in your own code; wrap with context via `previous: $e`; one exception hierarchy rooted at an app base class; catch the narrowest type, never bare `catch (\Throwable)` without rethrow/log. [IDIOM-01] | Strict types stop silent scalar coercion; PER-CS defines the declaration's position; `Error`s and `Exception`s both implement `Throwable`. | MUST | [PER Coding Style](https://www.php-fig.org/per/coding-style/), [PHP exceptions](https://www.php.net/manual/en/language.error-handling.php) | missing | gate |
| `PHP-IDIOM-02` | Never use `@` error suppression; convert PHP warnings/notices to exceptions (`set_error_handler` that throws `ErrorException`, as frameworks do) and run with `error_reporting=E_ALL`. | `PHP-IDIOM-03` | Use nullable types (`?T`, or a union with `null`) explicitly; never default a typed param to `null` implicitly (`string $x = null` is deprecated in 8.4, write `?string $x = null`); use the null-safe operator `?->` and `??`/`??=`; prefer a Null Object or an empty value object over returning `null` from services. ## 5. CONC: concurrency and the `-race` equivalent

**Loops race policy:** `mode = none`. PHP has no race detector (no TSan-style tool for user code). Substitute enforced by loops: run the suite with `--order-by=random` under two different `--random-order-seed` values, serially and in parallel (`vendor/bin/paratest --processes=N`), with `--fail-on-warning --fail-on-risky`; for worker-mode apps add a "same worker, N requests" leak test. Argv: `vendor/bin/phpunit --order-by=random --fail-on-warning --fail-on-risky` and `vendor/bin/paratest --processes=4`.

| ID | Rule | Why | Sev | Source | loops today | Enforce |
|---|---|---|---|---|---|---|
| `PHP-CONC-01` | Know the model: PHP-FPM/Apache is shared-nothing (one request = one fresh PHP context; state dies at request end); CLI scripts are single-threaded; long-running servers (FrankenPHP worker, RoadRunner, Swoole/OpenSwoole, ReactPHP, Amp) keep the application in memory across requests; Fibers (8.1+) give cooperative multitasking in one thread. [CONC-01] | Different model = different bug class: no data races in FPM, state leaks in workers. | MUST | [FrankenPHP worker](https://frankenphp.dev/docs/worker/), [PHP Fibers](https://www.php.net/manual/en/language.fibers.php)† | missing | review |

## Top 10 footguns

1. **Missing `strict_types`.** Bad: `function f(int $x)` called with `"5abc"` coerces silently (or `"5"` passes as 5). Fix: `declare(strict_types=1);` in every file. ([PER-CS](https://www.php-fig.org/per/coding-style/))
2. **Loose comparison and type juggling.** Bad: `if ($hash == $expected)` / `in_array($x, $list)`. Fix: `hash_equals`, `===`, and `in_array($x, $list, true)`. ([PHP comparison](https://www.php.net/manual/en/language.operators.comparison.php))
3. **`unserialize()` on user data.** Bad: `unserialize($_COOKIE['cart'])`. Fix: `json_decode(..., JSON_THROW_ON_ERROR)` or HMAC plus `allowed_classes:false`. ([PHP manual](https://www.php.net/manual/en/function.unserialize.php))
4. **SQL built from strings.** Bad: `"SELECT * FROM u WHERE n='$n'"`. Fix: `prepare` + `execute([':n'=>$n])`, allow-listed identifiers. ([OWASP SQLi](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html))
5. **State leaking across requests in worker mode.** Bad: singleton holding the `Request`, static cache arrays. Fix: pass request data per call, `ResetInterface`, leak test, `--max-requests`. ([Octane](https://laravel.com/docs/13.x/octane), [FrankenPHP](https://frankenphp.dev/docs/worker/))
6. **N+1 queries via lazy relations.** Bad: `foreach ($posts as $p) echo $p->author->name`. Fix: `Post::with('author')`, `preventLazyLoading()`. ([Eloquent](https://laravel.com/docs/13.x/eloquent))
7. **Float money and mutable `DateTime`.** Bad: `0.1+0.2` totals, `new DateTime()` everywhere. Fix: integer minor units/`brick/money`, `DateTimeImmutable` + `Clock`. ([PHP DateTimeImmutable](https://www.php.net/manual/en/class.datetimeimmutable.php))
8. **`env()` outside config after `config:cache` / `allow-plugins: true`.** Bad: `env('KEY')` in a service; wildcard plugin trust. Fix: read env only in `config/*.php`; list plugins explicitly. ([Composer config](https://getcomposer.org/doc/06-config.md))
9. **Dev tooling and Xdebug in production, `display_errors=On`.** Bad: `composer install` without `--no-dev`. Fix: `--no-dev --classmap-authoritative`, php.ini hardening. ([OWASP PHP config](https://cheatsheetseries.owasp.org/cheatsheets/PHP_Configuration_Cheat_Sheet.html))
10. **Hiding debt in the PHPStan baseline / `@` suppression.** Bad: regenerate baseline after every failure; `@$arr['k']`. Fix: only shrink the baseline; handle errors explicitly. ([PHPStan CLI](https://phpstan.org/user-guide/command-line-usage))
