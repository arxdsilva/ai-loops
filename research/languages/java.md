> **Summary:** A strong Java backend team pins a JDK through the wrapper plus a toolchain, builds with Maven or Gradle (Kotlin DSL) using BOMs, enforces format (Spotless) and bug patterns (Error Prone, SpotBugs/FindSecBugs) in the build, tests with JUnit 5/6 + AssertJ + Mockito + Testcontainers, and measures JaCoCo XML. The JVM has no general race detector, so races are mitigated by immutability, `java.util.concurrent`, jcstress/Lincheck for the few lock-free spots, and JUnit parallel + random-order runs.
> Biggest gaps in loops: (1) the gate, coverage parser, arch checker and hooks are Go-only (no Maven/Gradle, no JaCoCo, no ArchUnit adapter); (2) no race substitute exists, so loops needs an explicit `none` policy with a parallel-and-shuffle test run; (3) no repo-management, supply-chain, packaging or framework rules (BOMs, wrappers, Spring Boot/JPA traps, Testcontainers, native image).

Rules follow [TAXONOMY.md](TAXONOMY.md), using the row format `ID | Rule | Why | Sev | Source | loops today | Enforce`. Gaps are judged against [LOOPS_BASELINE.md](LOOPS_BASELINE.md).

Terms: "Maven" = Apache Maven 3.9.x/3.10.x unless noted; "Gradle" = 9.x with the Kotlin DSL. Commands are shown for Maven first, then Gradle.

## 1. REPO: repository and project management

Canonical tree for a Spring Boot hexagonal service (Maven, single module; for Gradle replace `pom.xml` with `build.gradle.kts` + `settings.gradle.kts` + `gradle/libs.versions.toml`):

```
orders-service/
  .mvn/wrapper/maven-wrapper.properties   # committed; mvnw, mvnw.cmd at root
  .mvn/jvm.config  .mvn/maven.config      # JVM flags / default CLI flags (e.g. -B -ntp)
  .sdkmanrc  (or .tool-versions)          # java=25.0.x-tem
  pom.xml                                 # parent = spring-boot-starter-parent, or import the BOM
  src/main/java/com/acme/orders/
    domain/ application/ adapter/ config/ # see ARCH
  src/main/resources/ application.yaml  db/migration/V1__init.sql  logback-spring.xml
  src/test/java/...                       # mirrors main packages; *Test (unit), *IT (integration)
  src/test/resources/
  src/integrationTest/java/               # optional, Gradle jvm-test-suite or build-helper in Maven
  Dockerfile  compose.yaml  .editorconfig  .gitignore  .gitattributes
  .github/ (workflows, CODEOWNERS, dependabot.yml or renovate.json, PULL_REQUEST_TEMPLATE.md)
  CHANGELOG.md  README.md  docs/adr/  LICENSE
```

Multi-module (Maven reactor / Gradle multi-project): a parent POM or `settings.gradle.kts` with `domain`, `application`, `adapters-*`, `bootstrap` modules so the compiler enforces direction (see ARCH-04).

## 3. ARCH: architecture

Styles in the ecosystem (ARCH-01):
- **Layered MVC (controller, service, repository)** is the Spring default and what most code is; it leaks JPA entities into services and web DTOs, so fight it with package rules.
- **Hexagonal / clean / onion** fits naturally with Spring (any bean can implement a port), Quarkus (CDI) and Micronaut (compile-time DI); use it for any domain with real rules. Frameworks fight it mainly through annotations (`@Entity`, `@Service`, `@JsonProperty`) in the domain.
- **DDD tactical** maps to records for value objects, classes with invariants for entities/aggregates, repositories as ports, Spring `ApplicationEventPublisher` or `@DomainEvents` for domain events; Spring Data aggregate roots are a pragmatic compromise.
- **CQRS/event sourcing:** Axon Framework (Axon Server) or hand-rolled; only with proven need.
- **Modular monolith** is the recommended starting point: Spring Modulith verifies module boundaries and provides event publication registry, module tests and docs. Microservices only where independent scaling or teams demand them.
- **Event-driven:** Spring Cloud Stream/Kafka, Quarkus Reactive Messaging; use the outbox (API-05).
- **Serverless:** Quarkus/Micronaut on Lambda with native image or SnapStart; Spring Cloud Function.
- **Actor model:** Akka (BSL licence since 2022) / Apache Pekko; rare.

Concrete ARCH-02 tree (Spring Boot, single module, package-by-feature then by layer; ArchUnit/Spring Modulith enforce direction):

```
src/main/java/com/acme/orders/
  OrdersApplication.java                 # @SpringBootApplication; ONLY composition (or in bootstrap module)
  order/                                 # Modulith module "order" (top-level package)
    domain/        Order.java OrderId.java (record) OrderRepository.java (port, consumer-owned)
                   Clock/IdGenerator ports; domain events; NO org.springframework.*, jakarta.persistence.*
    application/   PlaceOrderUseCase.java (inbound port interface) PlaceOrderService.java (impl, @Transactional here)
    adapter/
      in/web/      OrderController.java OrderRequest.java (record + Bean Validation) ProblemHandler.java
      in/messaging/ OrderEventsListener.java
      out/persistence/ OrderJpaEntity.java OrderJpaRepository.java (Spring Data) OrderPersistenceAdapter.java OrderMapper.java
      out/http/    PaymentsClient.java (implements domain port)
    package-info.java                    # @ApplicationModule(allowedDependencies = {...})
  config/          BeanConfig.java  @ConfigurationProperties records  (composition root wiring of ports to adapters)
```

Multi-module equivalent: `orders-domain` (no deps), `orders-application` (depends on domain), `orders-adapter-web`, `orders-adapter-persistence`, `orders-bootstrap` (depends on all; the only module with Spring Boot plugin). Build tool enforces direction.

## 4. IDIOM: what to do and what to avoid

| ID | Rule | Why | Sev | Source | loops today | Enforce |
|---|---|---|---|---|---|---|
| `JAVA-IDIOM-01` | Use unchecked (`RuntimeException` subclasses) for programming errors and for domain failures that callers cannot recover from; use checked exceptions only for recoverable conditions the caller must handle. Spring and modern libraries are unchecked; wrap checked exceptions from adapters (`IOException`, `SQLException`) in an adapter-level unchecked type at the boundary. [IDIOM-01] | Checked exceptions force signatures through every layer (and break lambdas). | SHOULD | [Effective Java Items 69-72](https://www.oreilly.com/library/view/effective-java/9780134686097/) ; [Oracle: Unchecked exceptions, the controversy](https://docs.oracle.com/javase/tutorial/essential/exceptions/runtime.html) | covered (`GO_BEST` §8-9 neutral core, error taxonomy in `HEXAGONAL`) | review |
| `JAVA-IDIOM-02` | Never swallow: no empty `catch`, no `catch (Exception \| Throwable)` outside a boundary, no `e.printStackTrace()`. Wrap with cause (`new DomainException("...", e)`), log once at the boundary, and restore interrupt status (`Thread.currentThread().interrupt()`) when catching `InterruptedException`. [IDIOM-01] | Lost causes and swallowed interrupts make shutdown and debugging impossible. | MUST | [Error Prone `CatchAndPrintStackTrace`, `InterruptedExceptionSwallowed`](https://errorprone.info/bugpatterns) ; [Java Concurrency in Practice ch. 7](https://jcip.net/) | go-only (`GO_BEST` §8 never swallow) | gate |
| `JAVA-IDIOM-03` | Use `Optional<T>` only as a method return type for "maybe no result"; never as a field, parameter, collection element or `Optional<Optional>`; never call `get()` without `isPresent` (use `orElseThrow`, `map`, `ifPresentOrElse`); never return `null` for `Optional`/collections (return `Optional.empty()` / `List.of()`). [IDIOM-02] | Optional is not serializable, adds allocation and does not remove null from parameters. | MUST | [Optional Javadoc (API note)](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Optional.html) ; [Error Prone `OptionalNotPresent`](https://errorprone.info/bugpatterns) | missing | gate |
| `JAVA-IDIOM-04` | Express null contract with JSpecify (`@NullMarked` on package, `@Nullable` on exceptions) and enforce with NullAway; Spring Framework 7 and Boot 4 use JSpecify. ## 5. CONC: concurrency and the `-race` equivalent

**Loops race policy: `mode = none`.** The JVM has no general-purpose data-race detector (no ThreadSanitizer for HotSpot Java bytecode). The substitute check loops enforces is: run the unit tests with JUnit 5 parallel execution and random method order, repeated twice with different seeds, and run jcstress/Lincheck suites when the project has them.

- Maven: `./mvnw -B -ntp verify -Djunit.jupiter.execution.parallel.enabled=true -Djunit.jupiter.execution.parallel.mode.default=concurrent -Djunit.jupiter.execution.parallel.mode.classes.default=concurrent -Djunit.jupiter.testmethod.order.default=org.junit.jupiter.api.MethodOrderer\$Random -Djunit.jupiter.execution.order.random.seed=$SEED`. Surefire forwards session user properties to the forked JVM, and JUnit reads configuration parameters from system properties.
- Gradle: user properties are not forwarded to the test JVM; put the same keys in `src/test/resources/junit-platform.properties` or `tasks.test { systemProperty("junit.jupiter.execution.parallel.enabled", "true") }` and a `-PraceSeed` property.
- Repeat: run the suite twice with different seeds (`SEED=1`, `SEED=2`); a test that passes in one and fails in another is a race or an order dependency and blocks the gate.

## Top 10 footguns

1. **Open-session-in-view and lazy loading.** Bad: default `spring.jpa.open-in-view=true`; controllers touching lazy collections. Fix: `spring.jpa.open-in-view=false`, fetch with `JOIN FETCH`/DTO projections inside the transaction. ([Mihalcea](https://vladmihalcea.com/the-open-session-in-view-anti-pattern/))
2. **N+1 queries.** Bad: `orders.forEach(o -> o.getItems().size())`. Fix: `@EntityGraph`/`JOIN FETCH`/`default_batch_fetch_size`, assert query counts in tests. ([Hibernate guide](https://docs.hibernate.org/orm/current/userguide/html_single/Hibernate_User_Guide.html#fetching))
3. **`@Transactional` self-invocation or on private methods.** Bad: `this.save()` calling an annotated method. Fix: move to another bean or use programmatic `TransactionTemplate`. ([Spring](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html))
4. **Entity `equals`/`hashCode` and Lombok `@Data` on entities.** Bad: `@Data @Entity`. Fix: id-based equals with constant `hashCode`, no Lombok `@ToString` on associations. ([Mihalcea](https://vladmihalcea.com/how-to-implement-equals-and-hashcode-using-the-jpa-entity-identifier/))
5. **`Optional` as a field/parameter or `.get()`.** Bad: `void f(Optional<X> x)`, `opt.get()`. Fix: overloads or nullable param with JSpecify; `orElseThrow`. ([Javadoc](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Optional.html))
6. **Mutable singleton beans.** Bad: Spring `@Service` with a `HashMap` field written per request. Fix: stateless beans, immutable state, `ConcurrentHashMap`. ([JCIP](https://jcip.net/))
7. **Swallowed `InterruptedException` / blocked virtual-thread pool.** Bad: `catch (InterruptedException e) {}`. Fix: `Thread.currentThread().interrupt()` and propagate. ([Error Prone](https://errorprone.info/bugpatterns))
8. **Using preview APIs (StructuredTaskScope) on LTS.** Bad: `--enable-preview` in production on JDK 25. Fix: executors/`CompletableFuture` until JEP 543 is final in JDK 28 and an LTS carries it. ([JEP 543](https://openjdk.org/jeps/543))
9. **`double` for money, `new BigDecimal(0.1)`, `SimpleDateFormat` shared.** Fix: `BigDecimal("0.10")`, `java.time`. ([java.time](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/time/package-summary.html))
10. **Native deserialization/XXE/SSRF defaults.** Bad: `ObjectInputStream` on request body, `DocumentBuilderFactory.newInstance()` unconfigured. Fix: JSON with a closed type set, secure-processing features. ([OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html))

## Open questions

1. **One argv per check vs build-tool variants.** Java projects use Maven or Gradle (or both across repos). The draft schema has a single `checks` list; the block above adds a `variants` key. The maintainer should decide whether to split into two pack profiles (`java-maven`, `java-gradle`) or select the variant at `init` from the detected build file.
2. **Maven 4.** Maven 4.0.0 is still on release candidates (`4.0.0-rc-7` is the latest on Maven Central as of 2026-11); the pack assumes 3.9.x/3.10.x (3.10.0 is GA; the spot run on it confirmed the `mvnw`/Surefire/JaCoCo argv) and `mvnw`. Re-check before the pack ships; Maven 4 changes the POM model (`4.1.0`) and adds a build cache.
3. **JaCoCo in Maven:** the XML path cannot be redirected with a documented user property (only `outputDirectory` in POM configuration), so `{coverage}` placeholder substitution does not work as it does for Go. loops must glob `**/target/site/jacoco/jacoco.xml` or the project must configure the output directory in the POM. Confirm that is acceptable.
4. **Gradle CLI parameters do not reach the test JVM.** The parallel/random race substitute therefore needs either committed `junit-platform.properties` (which affects every developer run) or a build-script hook reading a Gradle property. Maintainer decision: is it acceptable for loops to require a project-side property for the substitute?
5. **Structured concurrency status.** JEP 543 (final in JDK 28, due 2027-03) is `Integrated` as of this research, not yet released; JDK 27 shipped it as the seventh preview (JEP 533). Scoped values were finalised in JDK 25 (JEP 506). Re-verify on JDK 28 GA.
6. **Spotless single-file formatting** is not a documented CLI use case, so `post_edit.format_file` is `null`; options are google-java-format's CLI jar directly (adds an install step and may disagree with the project's Spotless config) or a whole-module `spotless:apply`.
7. **Detection of the DI framework** (Spring/Quarkus/Micronaut) by dependency names is a heuristic; sources do not define a canonical marker.
8. **OSV-Scanner vs OWASP dependency-check.** Both are listed; there is no authoritative statement of which is better. The pack prefers OSV-Scanner for the gate because it needs no NVD key, which is a judgement.
9. **Mockito and JDK 25:** the dynamic agent warning (JEP 451) status of Mockito's inline mock maker by Mockito 6 was not verified; check the Mockito release notes when the pack is built.
