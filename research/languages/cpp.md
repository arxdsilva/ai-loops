# C++ (backend services): backend practices and loops gap analysis

| | |

| As of | 2026-11 |
| Researcher | `B1-cpp` |
| Verifier | (filled in by B2) |

> **Summary:** A strong C++ backend team builds with CMake (target-based, presets) or Bazel, pins dependencies with a vcpkg manifest baseline or a Conan lockfile, compiles with a strict warning set plus hardening flags, formats with clang-format, lints with clang-tidy, and tests under three separate sanitizer builds (TSan; ASan+UBSan; plain coverage) in CTest. The race policy is a **build mode**, not a flag: `-fsanitize=thread` needs its own build tree and cannot be combined with ASan.
> Biggest gaps vs loops: (1) the gate, race-guard, stop-gate and `go-env` hook are Go-only, and C++ needs a configure+build+sanitizer-preset model rather than one `go test -race` argv; (2) the coverage reader only parses Go profiles, and C++ yields lcov/Cobertura through gcovr or `llvm-cov export`; (3) nothing in loops covers ownership/RAII/UB rules, hardening flags, layer enforcement through CMake target links, or lockfile/baseline discipline.

Rules follow [TAXONOMY.md](TAXONOMY.md), using the row format `ID | Rule | Why | Sev | Source | loops today | Enforce`. Gaps are judged against [LOOPS_BASELINE.md](LOOPS_BASELINE.md). "CG" below is the [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines) (rule numbers like `R.1` are its own IDs).

## 1. REPO: repository and project management

Canonical tree for a service (pitchfork-style layout, one CMake target per layer):

```text
orders-service/
  CMakeLists.txt              # project(), enable_testing(), add_subdirectory(...)
  CMakePresets.json           # dev, ci, tsan, asan-ubsan, coverage presets (committed)
  CMakeUserPresets.json       # personal, git-ignored
  vcpkg.json                  # manifest + "builtin-baseline"  (or conanfile.txt + conan.lock)
  vcpkg-configuration.json    # optional: registries
  .clang-format  .clang-tidy  .clangd  .editorconfig  .gitignore  .gitattributes
  cmake/                      # Warnings.cmake, Hardening.cmake, Sanitizers.cmake (modules only)
  proto/                      # .proto contracts (gRPC) or openapi/
  src/
    domain/                   # CMake target orders_domain  (STATIC, no external deps)
    application/              # target orders_application (links domain)
    adapters/
      inbound_http/           # target orders_http  (links application, Beast/Drogon)
      outbound_pg/            # target orders_pg    (links application, libpqxx)
    app/main.cpp              # composition root, target orders_service (links everything)
  include/orders/...          # only if a public library; else headers live beside sources
  tests/
    unit/  integration/  fuzz/  bench/
  docs/adr/  .github/workflows/ci.yml  Dockerfile
```

## 2. TOOL: toolchain

## 3. ARCH: architecture

ARCH-02 mapping (C++ with CMake targets as layers; namespace = directory):

```text
src/
  domain/CMakeLists.txt         add_library(orders_domain STATIC ...)       # links nothing but std
    order.hpp order.cpp         namespace orders::domain
    ports.hpp                   (only if domain-owned ports)
  application/CMakeLists.txt    add_library(orders_application STATIC ...)  # target_link_libraries(... PUBLIC orders_domain)
    place_order.hpp/.cpp        namespace orders::app; ports (abstract classes or concepts) owned here
  adapters/
    inbound_http/CMakeLists.txt add_library(orders_http ...)    # PRIVATE orders_application Boost::beast
    outbound_pg/CMakeLists.txt  add_library(orders_pg ...)      # PRIVATE orders_application libpqxx::pqxx
  app/CMakeLists.txt            add_executable(orders_service main.cpp)     # PRIVATE all of the above (composition root)
tests/{unit,integration}/       link the layer under test + GTest::gtest_main
```

## 4. IDIOM: what to do and what to avoid

| ID | Rule | Why | Sev | Source | loops today | Enforce |
|---|---|---|---|---|---|---|

## 5. CONC: concurrency and the `-race` equivalent

**Loops race policy: `mode = build`**: configure and run the tests in a dedicated ThreadSanitizer build, `cmake --preset tsan && cmake --build --preset tsan && ctest --preset tsan --output-on-failure`, where the `tsan` preset sets `CMAKE_CXX_FLAGS="-fsanitize=thread -fno-omit-frame-pointer -g -O1"` (and the same in `CMAKE_EXE_LINKER_FLAGS`) in its own `binaryDir`, and the test preset sets `TSAN_OPTIONS="halt_on_error=1 second_deadlock_stack=1"`. ASan+UBSan are a second, separate build (`asan-ubsan` preset) because TSan cannot be combined with ASan or LSan (GCC docs).

## Top 10 footguns

1. **Dangling references/views.** Bad: `std::string_view v = make_string();` or returning `const T&` to a local or a temporary. Fix: own the data (`std::string`), return by value, and enable `-Wdangling` plus ASan. ([CG F.43, F.45](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
2. **Callbacks capturing `this`.** Bad: `async_read(buf, [this](auto ec, auto n){...})` on an object that may be destroyed. Fix: `shared_from_this()` or coroutines owning the state. ([Asio](https://www.boost.org/doc/libs/release/doc/html/boost_asio.html))
3. **Uninstrumented or mixed sanitizer builds.** Bad: running TSan with only your code instrumented, or combining `-fsanitize=thread,address`. Fix: a dedicated `tsan` preset and separate `asan-ubsan` preset. ([GCC](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html))
4. **Data races as UB.** Bad: unsynchronised `bool done` read in a loop. Fix: `std::atomic<bool>`, `std::stop_token`, or a lock guarded by `std::scoped_lock`. ([CG CP.2](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
5. **Exception escaping a thread, `noexcept` function or destructor.** Bad: `std::thread t([]{ throw 1; });`. Fix: catch at the thread/task entry and convert to an error. ([CG E.16](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
6. **Raw `new`/`delete` and manual ownership.** Bad: `Foo* f = new Foo; ... delete f;`. Fix: `std::make_unique<Foo>()`. ([CG R.11](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
7. **Signed overflow and out-of-bounds `operator[]`.** Bad: `v[i]` with unchecked `i`, `int` size arithmetic. Fix: `-D_GLIBCXX_ASSERTIONS`/libc++ hardening, `std::span`, `.at()` at boundaries, UBSan in CI. ([libc++ hardening](https://libcxx.llvm.org/Hardening.html))
8. **Uninitialised members/locals.** Bad: `int x; use(x);`. Fix: `int x{};`, in-class initialisers, `-ftrivial-auto-var-init=zero` as backstop. ([OpenSSF](https://best.openssf.org/Compiler-Hardening-Guides/Compiler-Options-Hardening-Guide-for-C-and-C++.html))
9. **`using namespace` in headers and include-order dependencies.** Bad: `using namespace std;` in a `.hpp`. Fix: qualified names; headers self-contained (IWYU). ([CG SF.7](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
10. **Blocking the event loop / ignoring deadlines.** Bad: sync DB call or `future.get()` inside an Asio/Drogon/userver handler. Fix: async driver or a dedicated pool; set deadlines on every call. ([gRPC deadlines](https://grpc.io/docs/guides/deadlines/))

## Open questions

1. **One gate, several builds.** TSan plus coverage was spot-run by B2 and combines on both compilers (GCC `-fsanitize=thread --coverage`; Clang `-fsanitize=thread -fprofile-instr-generate -fcoverage-mapping`, then `llvm-cov export -format=lcov`), so a single `tsan+coverage` preset is feasible and halves the builds; ASan+UBSan must stay separate. Maintainer decision: one merged check or several.
2. **`fails_on` value for exit-code tools.** The TAXONOMY schema shows only `"output"`; this pack assumes the default is non-zero exit.
3. **Exceptions vs `std::expected`.** The Core Guidelines (exceptions by default) and Google style (no exceptions) disagree, and no source settles it. The pack should let the project's `.clang-tidy`/ADR decide ("project rules win") and require only one stated strategy per layer.
4. **Coverage tool: gcovr vs llvm-cov.** gcovr (GCC) is the common default; llvm-cov is more accurate for templates and branches under Clang. The pack should select by detected compiler (`CMAKE_CXX_COMPILER_ID`), but this needs a design.
5. **Unverified facts.** (a) OSV-Scanner supports `conan.lock` but not `vcpkg.json` (verified); (b) Renovate has no vcpkg manager and Dependabot does (verified); (c) the C++26 ISO ballot status is unconfirmed (secondary reports of a failed DIS ballot in 2026-10, no ISO source); (d) Clang 23.1.0 shipped 2026-08-25, CMake 4.4 stable with 4.5 in RC. I fetched the tool docs for TSan, ASan, UBSan, GCC instrumentation, gcovr lcov, llvm-cov, CMake presets and modules, ccache, libc++ hardening, OpenSSF, libFuzzer, clang-tidy, IWYU, vcpkg versioning, Conan lockfiles and diff_cover, but I took gcovr `--cobertura`, Renovate and several OWASP URLs from memory; B2 should open them.
6. **Module and `import std` readiness** moves quickly; re-check the CMake and compiler status each release.
7. **Race-guard on macOS.** TSan supports Darwin arm64/x86_64, but Apple libc++ and system library interception differ; the pack should not assume Linux.
8. **Testcontainers for C++** (`testcontainers-native`) is community-maintained, and its maturity is unverified.
