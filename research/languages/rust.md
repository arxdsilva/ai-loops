> **Summary:** A strong Rust backend team runs one Cargo workspace with `[workspace.dependencies]` and `[workspace.lints]`, pins the toolchain in `rust-toolchain.toml`, commits `Cargo.lock`, and gates on `cargo fmt --check`, `cargo clippy -D warnings`, nextest, cargo-llvm-cov, cargo-deny and cargo-audit. Hexagonal layers map naturally onto crates, so the dependency rule is enforced by the compiler through `Cargo.toml` and not by a linter. Data races are impossible in safe Rust, so the "race" gate becomes `#![forbid(unsafe_code)]` plus, for crates with `unsafe` or hand-rolled atomics, miri, loom and an optional nightly TSan build.
> Biggest loops gaps: (1) the gate, coverage parser, post-edit hook, arch parser and run-scoped cache are Go-only and know nothing about `cargo`, lcov or `target/`; (2) `race.mode` has no native flag in Rust, so the pack needs a `none`+substitute policy with an optional `build` tier; (3) no repo, toolchain-pinning, supply-chain (cargo-deny/audit) or release guidance exists in loops.

Rules follow [TAXONOMY.md](TAXONOMY.md), using the row format `ID | Rule | Why | Sev | Source | loops today | Enforce`. Gaps are judged against [LOOPS_BASELINE.md](LOOPS_BASELINE.md).

Note on "loops today": neutral workflow rules (`WORKFLOW` §1-§4, §6, `ROLES.md` hard rules for tests, 70% new-code coverage and the race rule) are `covered`; anything that is Go tooling (gate, post-edit, race-guard, `go-env`, `arch` parser) is `go-only`; repo/CI/release/security/packaging/observability are `missing`.

## 1. REPO: repository and project management

Canonical tree for a service (Cargo workspace, virtual manifest, hexagonal crates):

```text
my-service/
├── Cargo.toml              # [workspace] members=["crates/*"], resolver="3", [workspace.package|dependencies|lints]
├── Cargo.lock              # committed (binary workspace)
├── rust-toolchain.toml     # channel pin + components (rustfmt, clippy)
├── rustfmt.toml            # style_edition / max_width only if deviating
├── clippy.toml             # thresholds (cognitive-complexity, too-many-arguments, disallowed-*)
├── deny.toml               # cargo-deny: advisories, licenses, bans, sources
├── .cargo/config.toml      # [alias] xtask/ci, [env], target rustflags (no secrets)
├── .config/nextest.toml    # nextest profiles (default, ci)
├── crates/
│   ├── domain/             # pure: no IO, no tokio/sqlx/axum
│   ├── application/        # use cases + ports (traits); depends on domain only
│   ├── adapter-http/       # axum handlers (inbound)
│   ├── adapter-postgres/   # sqlx repositories (outbound)
│   └── bootstrap/          # composition root, the [[bin]] (main.rs): config, wiring, shutdown
├── migrations/             # sqlx/diesel migrations (or crates/adapter-postgres/migrations)
├── tests/ or crates/*/tests/   # integration tests (each file = a test binary)
├── xtask/                  # optional: cargo-xtask automation in Rust (no Makefile)
├── .github/workflows/ci.yml, renovate.json|dependabot.yml, CODEOWNERS
├── Dockerfile, README.md, CHANGELOG.md, LICENSE, docs/adr/
```

Single-crate services use `src/main.rs` + `src/lib.rs` (thin binary over a library) with `src/{domain,application,adapters}` modules; Cargo's package layout puts integration tests in `tests/`, benches in `benches/`, examples in `examples/`, extra binaries in `src/bin/`.

## 3. ARCH: architecture

Concrete mapping of the loops layers onto a Cargo workspace with axum + sqlx (crates are the enforcement unit; module visibility is only the second line of defence):

```text
crates/
  domain/            lib   deps: (std, thiserror, serde? no; uuid, time as plain value types only)
    src/{lib.rs, order/{mod.rs, entity.rs, value.rs, event.rs, error.rs}}     # pub(crate) by default
  application/       lib   deps: domain
    src/{lib.rs, ports/{order_repo.rs, clock.rs, id_gen.rs}, usecase/{place_order.rs}}   # ports = traits defined by the consumer
  adapter-http/      lib   deps: application, domain, axum, tower-http, serde   # inbound adapter (DTOs, extractors, error mapping)
  adapter-postgres/  lib   deps: application, domain, sqlx                     # outbound adapter (implements ports)
  bootstrap/         bin   deps: all of the above, tokio, tracing, config      # composition root: build pool, impl ports, router, graceful shutdown
```

Rule: `domain` has no path to any other workspace crate or IO crate; `application` depends only on `domain`; adapters depend inward; only `bootstrap` sees everything. `cargo tree -p domain` must list only std-adjacent crates.

## 5. CONC: concurrency and the `-race` equivalent

**Loops race policy:** `mode = none` for the default gate with substitute = compile-time `Send`/`Sync` data-race freedom plus `unsafe_code = "forbid"` (the clippy/rustc deny lints are the enforced check); a `build` tier is required only for crates that contain `unsafe` or atomics: `cargo +nightly miri test -p <crate>` (UB/data races, interleavings via `MIRIFLAGS="-Zmiri-many-seeds"`) and the loom tests, and optionally TSan: `RUSTFLAGS="-Zsanitizer=thread" RUSTDOCFLAGS="-Zsanitizer=thread" cargo +nightly test -Zbuild-std --target x86_64-unknown-linux-gnu` (swap target for `aarch64-apple-darwin` on a Mac). Loom: `RUSTFLAGS="--cfg loom" cargo test --release`.

| ID | Rule | Why | Sev | Source | loops today | Enforce |
|---|---|---|---|---|---|---|
| `RUST-CONC-01` | Async I/O services run on the `tokio` multi-thread runtime (`#[tokio::main]`, `flavor = "multi_thread"`); OS threads only for blocking/CPU work; `std::thread::scope` for scoped parallelism; use `rayon` for CPU data-parallelism, never inside an async task without `spawn_blocking`. [CONC-01] | One runtime per process; mixing runtimes causes panics/deadlocks. | MUST | [Tokio tutorial](https://tokio.rs/tokio/tutorial); [Tokio: bridging with sync code](https://tokio.rs/tokio/topics/bridging) | missing | review |

## Top 10 footguns

1. **Blocking the async runtime.** Bad: `std::fs::read`/`thread::sleep`/CPU loop in an `async fn`. Fix: `tokio::fs`, `tokio::time::sleep`, `spawn_blocking`, or rayon. ([spawn_blocking](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html))
2. **Holding a `std::sync::Mutex` guard across `.await`.** Bad: `let g = m.lock().unwrap(); foo().await;`. Fix: scope the guard before awaiting, or message passing; deny `await_holding_lock`. ([tokio shared state](https://tokio.rs/tokio/tutorial/shared-state))
3. **`unwrap()`/`expect()` on external input and slice indexing.** Bad: `body.get("x").unwrap()`, `v[i]`. Fix: `ok_or(Error::Missing)?`, `.get(i)`; deny `unwrap_used`. ([Rust Book ch. 9](https://doc.rust-lang.org/book/ch09-03-to-panic-or-not-to-panic.html))
4. **Cancellation-unsafe `select!`/timeouts.** Bad: `select!` with a future that loses buffered data when dropped. Fix: use cancel-safe methods, move state outside, make writes transactional. ([select!](https://docs.rs/tokio/latest/tokio/macro.select.html#cancellation-safety))
5. **Detached `tokio::spawn` that swallows panics/errors.** Bad: `tokio::spawn(work());`. Fix: keep the `JoinHandle`/`JoinSet`, log `JoinError`, use a `CancellationToken`. ([JoinSet](https://docs.rs/tokio/latest/tokio/task/struct.JoinSet.html))
6. **Release-mode integer overflow and `as` casts.** Bad: `let total = a + b;`, `x as u32`. Fix: `checked_add`, `u32::try_from(x)?`, `overflow-checks = true`. ([Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html))
7. **`.clone()` to appease the borrow checker and unbounded channels.** Bad: cloning large data per request, `unbounded_channel()`. Fix: borrow or `Arc`, bounded `mpsc::channel(n)`. ([Rust Performance Book](https://nnethercote.github.io/perf-book/heap-allocations.html))
8. **Byte-slicing UTF-8 strings.** Bad: `&s[..10]`. Fix: `s.chars().take(10)`, `s.get(..10)`. ([std::string::String](https://doc.rust-lang.org/std/string/struct.String.html))
9. **Un-timed outbound calls and a `reqwest::Client` per request.** Bad: `reqwest::get(url)`. Fix: shared `Client::builder().timeout(..)`. ([reqwest Client](https://docs.rs/reqwest/latest/reqwest/struct.Client.html))
10. **Stale/unlocked dependency graph and unvetted `build.rs`.** Bad: uncommitted `Cargo.lock`, no `--locked`, no `cargo deny`. Fix: commit the lockfile, `--locked`, `cargo deny check`, `cargo audit`. ([cargo-deny](https://embarkstudios.github.io/cargo-deny/))

## Open questions

1. **Race policy shape.** Rust has no flag form. Should loops accept `mode = none` with a `substitute` plus the extra `race.build` tier (miri/loom/TSan) I added, or extend the schema with `mode = "build"` per crate class? TSan needs nightly, `-Zbuild-std` and `--target`; support is limited to Linux/macOS/FreeBSD targets (Unstable Book), and `cargo miri` needs nightly.
2. **Stable version.** The `1.99.0`/`1.99.1` dates (2026-10-01 / 2026-10-15) come from search results that I could not confirm on blog.rust-lang.org. Verify with `rustup check` before writing the pack.
3. **Inline unit tests inflate new-code coverage.** `#[cfg(test)] mod tests` lives inside source files, so lcov includes test lines. Options: accept the bias, filter by `--ignore-filename-regex`, or nightly `coverage(off)`. The maintainers should pick.
4. **diff-cover and lcov.** diff-cover accepts LCov directly (verifier, README); loops may shell out to it or compute new-code coverage itself.
5. **Cargo.lock for libraries.** The Cargo FAQ no longer prescribes "do not commit"; it leaves the choice to the project. The pack commits it everywhere for deterministic CI; confirm.
6. **Edition-2024 workspace dependency semantics.** The Cargo workspaces page says a member's `default-features` override on edition 2024 needs a very recent Cargo; I did not verify the exact version, so the pack does not rely on it.
7. **Run-scoped `CARGO_TARGET_DIR` cost.** A cold per-run target dir recompiles the whole dependency graph (minutes). Decide whether runs share one target dir per worktree plus sccache, or isolate fully. `CARGO_HOME` should stay shared.
8. **`cargo llvm-cov` + `CARGO_TARGET_DIR`.** llvm-cov writes artifacts to `<target>/llvm-cov-target` by default (`CARGO_LLVM_COV_TARGET_DIR` overrides); confirm cleanup picks it up.
9. **Source verification limits.** Several tool pages (rust-clippy index, miri README) returned redirects or 503 during research; those rows cite the tool's official URL from prior knowledge and should be re-fetched by B2.
