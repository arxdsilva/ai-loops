> **Summary:** A strong Ruby team pins Ruby in `.ruby-version` and gems in a committed `Gemfile.lock`, runs RuboCop (or Standard) plus Brakeman and bundler-audit in CI, tests with RSpec or Minitest in random order under SimpleCov, and keeps Rails models thin by pushing logic into plain Ruby objects, often with Packwerk boundaries.
> Ruby has **no data-race detector**, so loops cannot run "tests with race"; the honest substitute is random order plus parallel processes plus a repeat count.
> Biggest gaps: (1) the gate is Go-only (no `bundle`, `rubocop`, `rspec`, SimpleCov/lcov), (2) loops has no "no race detector" policy, (3) loops' arch checker cannot see Ruby dependencies because Zeitwerk code has no import statements (it needs Packwerk or a constant scanner).

Rules follow [TAXONOMY.md](TAXONOMY.md), using the row format `ID | Rule | Why | Sev | Source | loops today | Enforce`. Gaps are judged against [LOOPS_BASELINE.md](LOOPS_BASELINE.md).

Short source keys used below: RG = [Rails Guides](https://guides.rubyonrails.org/), RSG = [Ruby Style Guide](https://rubystyle.guide/), BND = [Bundler docs](https://bundler.io/).

## 1. REPO: repository and project management

Canonical tree for a Rails service that follows loops' hexagon (see ARCH-02 for the mapping):

```text
.
├── .ruby-version            # 4.0.0 (or 3.4.x); the single Ruby pin
├── .tool-versions           # optional (mise/asdf); keep equal to .ruby-version
├── Gemfile                  # `ruby file: ".ruby-version"`
├── Gemfile.lock             # committed (application)
├── .rubocop.yml             # or .standard.yml
├── .rspec                   # --require spec_helper, --order random
├── .github/dependabot.yml   # bundler + github-actions ecosystems
├── bin/                     # binstubs: rails, rake, rspec, rubocop, setup, ci
├── app/                     # Rails autoload roots (models, controllers, jobs, ...)
├── config/                  # application.rb, environments/, puma.rb, database.yml
├── db/                      # migrate/, schema.rb (or structure.sql), seeds.rb
├── lib/                     # non-autoloaded code, tasks/
├── spec/ (or test/)         # tests mirror app/ and lib/
├── packs/ (optional)        # Packwerk packages, each with package.yml
├── tmp/  log/  coverage/    # git-ignored build/test output
└── vendor/bundle/           # git-ignored if BUNDLE_PATH=vendor/bundle
```

## 3. ARCH: architecture

How each style looks in Ruby:

- **Layered / MVC (Rails default).** Controllers, Active Record models, views. Fastest start; Active Record merges entity, repository and persistence, which fights hexagonal. Choose for CRUD-heavy products. ([Rails Guides](https://guides.rubyonrails.org/getting_started.html))
- **Hexagonal / clean.** Possible with plain Ruby objects in `app/domain` and `app/application`, Active Record confined to outbound adapters. Dry-rb ([dry-rb](https://dry-rb.org/)), Hanami and Trailblazer encourage it; Rails tolerates it. Choose when domain rules are rich.
- **Service objects / interactors.** `app/services/*.rb` with `call`, or the Interactor gem ([interactor](https://github.com/collectiveidea/interactor)) and Trailblazer operations ([trailblazer](https://github.com/trailblazer/trailblazer)). These are the idiomatic application layer (use cases), but a `services/` folder full of `XService.new(x).call` wrappers around callbacks is just procedural code.
- **DDD tactical.** Entities with identity, value objects via `Data.define` (Ruby 3.2+), aggregates as plain classes; Active Record rows are persistence records, not the domain.
- **CQRS / event sourcing.** Rails Event Store and Sequent exist; use only with a real audit or temporal need. Rails 8.1 adds structured event reporting for observability, not event sourcing ([8.1](https://rubyonrails.org/2025/10/22/rails-8-1)).
- **Modular monolith.** The Ruby answer is Packwerk packs (or engines) in one deployable ([packwerk](https://github.com/Shopify/packwerk)). Microservices only when a team or scaling boundary demands them.
- **Serverless / actors.** Rare in Ruby (AWS Lambda custom runtime exists). No mainstream actor library besides `concurrent-ruby` actors/agents and experimental Ractors.
- **Alternatives to Rails:** Hanami 2 (explicit slices, container, repositories via ROM) [hanamirb.org](https://hanamirb.org/), Roda ([roda](https://roda.jeremyevans.net/)) and Sinatra ([sinatrarb](https://sinatrarb.com/)) for small services; all are closer to hexagonal than Rails by default.

ARCH-02 directory tree (Rails + hexagonal; each folder under `app/` is an autoload root so the constant name drops the folder name):

```text
app/
├── domain/                 # pure Ruby: entities, value objects (Data.define), domain services, errors
│   └── billing/invoice.rb  # Billing::Invoice (no ActiveRecord, no Time.now, no Rails)
├── application/            # use cases + PORTS (module with abstract methods / duck-typed contracts)
│   └── billing/issue_invoice.rb   # Billing::IssueInvoice#call(...)
├── adapters/
│   ├── inbound/
│   │   ├── controllers/    # thin: parse/validate params, call use case, render
│   │   └── jobs/           # Sidekiq / ActiveJob entry points (thin)
│   └── outbound/
│       ├── persistence/    # ActiveRecord models + repositories implementing ports
│       └── clients/        # Faraday/HTTP gateways implementing ports
config/initializers/container.rb  # composition root (wires ports -> adapters); or Dry::Container
packs/billing/package.yml         # Packwerk: enforce_dependencies: true (privacy needs packwerk-extensions)
```

## 4. IDIOM: what to do and what to avoid

| ID | Rule | Why | Sev | Source | loops today | Enforce |
|---|---|---|---|---|---|---|
| `RUBY-IDIOM-01` | Raise exceptions for exceptional failures, inherit from `StandardError` (never `Exception`), define an app error hierarchy (`class MyApp::Error < StandardError`), and rescue the narrowest class. Never `rescue Exception` or an empty `rescue`. Re-raise with `raise ... , cause: e` or let `cause` be implicit. [IDIOM-01] | `rescue Exception` swallows `SignalException`/`NoMemoryError`; bare `rescue => e` without handling hides bugs. | MUST | [RSG: exceptions](https://rubystyle.guide/#exceptions), [Exception docs](https://docs.ruby-lang.org/en/master/Exception.html) | go-only (GO_BEST §8-§9 error taxonomy) | gate |
| `RUBY-IDIOM-02` | Do not use exceptions for control flow; return result objects or `nil`+reason for expected outcomes. Use `retry` sparingly with a cap. [IDIOM-01] | Raising is slow-ish and obscures flow. | AVOID | [RSG](https://rubystyle.guide/#exceptions) | go-only | review |
| `RUBY-IDIOM-03` | Absence is `nil`: use safe navigation `&.`, `Hash#fetch` (raises on missing key), `dig`, and `Array#first`/`find` with explicit handling. Avoid `try` chains and `nil` returns that carry meaning silently; do not return `false` for "not found". [IDIOM-02] | `nil` is falsy and propagates `NoMethodError` far from the cause. | SHOULD | [RSG: nil](https://rubystyle.guide/#no-nil-compare), [Safe navigation](https://docs.ruby-lang.org/en/master/syntax/calling_methods_rdoc.html) | missing | gate |
| `RUBY-IDIOM-04` | Start every file with `# frozen_string_literal: true` and freeze constants (`.freeze` or `Ractor.make_shareable`); model value objects with `Data.define(:a, :b)` (immutable, keyword init) and `Struct` with `keyword_init: true` only when mutation is needed. [IDIOM-03] | Mutable shared constants and strings are a classic thread-safety and aliasing bug. | MUST | [RuboCop Style/FrozenStringLiteralComment](https://docs.rubocop.org/rubocop/cops_style.html), [Data](https://docs.ruby-lang.org/en/master/Data.html) | missing | gate |

## 5. CONC: concurrency and the `-race` equivalent

**Loops race policy: `mode = none`.** Ruby has no data-race detector (no `-race`, no TSan support for Ruby-level code; CRuby's GVL makes many races benign but not all). Substitute loops should enforce: run the suite in **random order** with a printed seed and in **parallel processes** (`bundle exec rspec --order random`; Minitest/Rails randomise by default; `bundle exec parallel_rspec spec/` or Rails `parallelize(workers: :number_of_processors)`), plus a repeat run on changed specs (`for i in 1..N`) and no shared mutable globals. Ruby 3.4/4.0 CRuby does not offer a TSan build for Ruby code; TSan applies only to the C runtime.

|---|---|---|---|---|---|---|
| `RUBY-CONC-01` | Know the model: CRuby runs Ruby threads concurrently only for blocking I/O; the GVL serialises Ruby code, so CPU parallelism needs multiple processes (Puma workers, Sidekiq processes) or Ractors (still experimental in 4.0). Fibers plus the fiber scheduler (`Fiber.set_scheduler`, used by the `async` gem) give cooperative I/O concurrency. [CONC-01] | Picking the wrong model wastes cores or deadlocks. | MUST | [Thread](https://docs.ruby-lang.org/en/master/Thread.html), [Fiber::Scheduler](https://docs.ruby-lang.org/en/master/Fiber/Scheduler.html), [Ractor](https://docs.ruby-lang.org/en/master/Ractor.html), [Ruby 4.0 release](https://www.ruby-lang.org/en/news/2025/12/25/ruby-4-0-0-released/) | missing | review |

## Top 10 footguns

1. **No race detector.** Bad: assuming the GVL makes code thread-safe. Fix: no shared mutable state, `Mutex`/`Concurrent::Map`, random-order + parallel tests. ([Thread](https://docs.ruby-lang.org/en/master/Thread.html))
2. **`Marshal.load`/`YAML.load` on untrusted data.** Fix: `JSON.parse`, `YAML.safe_load(permitted_classes: [])`. ([OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html))
3. **SQL string interpolation.** Bad: `where("name = '#{x}'")`. Fix: `where(name: x)`. ([rails-sqli](https://rails-sqli.org/))
4. **Mass assignment.** Bad: `User.create(params[:user])` or `permit!`. Fix: strong params allowlist. ([RG](https://guides.rubyonrails.org/action_controller_overview.html))
5. **N+1 queries.** Bad: `posts.each { |p| p.author.name }`. Fix: `includes(:author)`, `strict_loading`. ([RG](https://guides.rubyonrails.org/active_record_querying.html))
6. **Shared mutable state in Puma.** Bad: `@@cache`, class-level `@x ||=`, mutable constants. Fix: `CurrentAttributes`, frozen constants, `Concurrent::Map`. ([RG: Threading](https://guides.rubyonrails.org/threading_and_code_execution.html))
7. **`rescue Exception` / empty rescue.** Fix: rescue `StandardError` subclasses, re-raise. ([RSG](https://rubystyle.guide/#exceptions))
8. **Non-idempotent jobs and enqueue inside a transaction.** Fix: idempotency keys, `after_commit` enqueue. ([Sidekiq](https://github.com/sidekiq/sidekiq/wiki/Best-Practices))
9. **Callback side effects and fat models.** Fix: explicit use cases. ([RG: callbacks](https://guides.rubyonrails.org/active_record_callbacks.html))
10. **Shared defaults and mutated literals.** Bad: `Hash.new([])`, string literals without `frozen_string_literal`. Fix: block form, freeze. ([Hash](https://docs.ruby-lang.org/en/master/Hash.html))

## Open questions

- **Coverage format `simplecov-json` (schema extension).** The LOOPS block uses `coverage.format: "simplecov-json"`, a value TAXONOMY §15 does not list (it names gocover, lcov, cobertura, jacoco). loops needs a parser for SimpleCov's `coverage/coverage.json` (coverage-v1.3 schema, verified by B2 round 2), or Ruby projects add `simplecov-lcov` and use `lcov`.
- **SimpleCov 1.x (resolved by B2).** `SimpleCov.start` and `enable_coverage :branch` remain; the DSL is `cover`/`skip`/`group`; there is no native lcov; `coverage/coverage.json` is written by default. loops parses that JSON, with lcov as a fallback. loops relies on the spec/test helper starting SimpleCov (the old `COVERAGE=1` convention is project-specific and was dropped). `test_jobs` is null because rspec has no jobs flag; parallelism is `parallel_rspec -n N` or `PARALLEL_WORKERS=N` for Rails.
- **Gate check `kind` values.** The TAXONOMY schema lists build/format/lint/test/vuln; I used `typecheck`, `arch`, `sast` and an `env`/`note` field on checks. Maintainers must decide whether to add these kinds.
- **Typing choice.** Sorbet vs RBS/Steep is unsettled in the community (Shopify uses Sorbet, Ruby core ships RBS); the pack should detect `sorbet/config` or `Steepfile` rather than pick one.
- **RuboCop `-f github`** exists (verified by B2); it could be added to the CI argv for annotations.
- **Race substitute strictness.** A repeat/stress count is not documented by any Ruby tool; loops must define its own N (suggest 3 runs of changed specs with different seeds).
- **Rails support dates** (8.1 bug fixes to about 2026-10, security to about 2027-10) are derived from the maintenance policy rule, not published dates.
- **Ruby 4.0 vs 3.4 default.** Ruby 4.0 is in normal maintenance since 2025-12-25; many gems and Rails apps still pin 3.4. The pack should read `.ruby-version` rather than assume.
- **ZJIT/Ractor**: both are experimental in 4.0; the "leave experimental status next year" goal is stated by the Ruby team but unreleased as of this research.
