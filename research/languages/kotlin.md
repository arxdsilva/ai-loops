> **Summary:** A strong Kotlin backend team builds with Gradle Kotlin DSL (wrapper, version catalog, convention plugins, dependency locking), keeps the domain a plain-Kotlin module with no framework imports, models errors with sealed types or typed `Raise`, uses structured concurrency with injected dispatchers and `runTest` virtual time, and measures coverage with Kover XML.
> The JVM has no general race detector. The honest policy is `none`: loops enforces parallel and repeated test execution plus Lincheck/`runTest` for concurrent code, not a flag.
> Biggest loops gaps: (1) the gate, coverage parser, arch parser, hooks and cache env are Go-only (Gradle, Kover XML and `build/`+`.gradle/`+`.kotlin/` are all unknown); (2) there is no language detection or race-substitute concept; (3) there is no repo-management, security (SAST/OWASP) or packaging guidance.

Rules follow [TAXONOMY.md](TAXONOMY.md), using the row format `ID | Rule | Why | Sev | Source | loops today | Enforce`. Gaps are judged against [LOOPS_BASELINE.md](LOOPS_BASELINE.md).

Source note: URLs marked "(fetched)" were opened during this research. Others are the official docs root/page for the named tool, cited from knowledge; B2 should open them (see Open questions).

## 5. CONC: concurrency and the `-race` equivalent

**Loops race policy: `mode = none`.** The JVM has no general-purpose data race detector (TSan is not supported on HotSpot; jcstress/Lincheck are targeted tools). Substitute enforced by loops: run `test` with parallel test execution on. These are JUnit config keys, so they must be set in `src/test/resources/junit-platform.properties` or via `tasks.test { systemProperty("junit.jupiter.execution.parallel.enabled", "true") }` (optionally driven by a `-P` property); a Gradle `-D` on the command line does NOT reach the test JVM (spot-run verified). Keys: `junit.jupiter.execution.parallel.enabled=true`, `junit.jupiter.execution.parallel.mode.default=concurrent`, `junit.jupiter.testmethod.order.default=org.junit.jupiter.api.MethodOrderer$Random`; optionally Gradle `maxParallelForks`, randomized/repeated runs for any test touching shared state (JUnit `@RepeatedTest(50)` or Kotest `invocations`), and Lincheck/`runTest` for concurrent code; reviewer must reject new `@Volatile`/`synchronized`/`Mutex` without a concurrency test.

| ID | Rule | Why | Sev | Source | loops today | Enforce |
|---|---|---|---|---|---|---|
| `KT-CONC-01` | Model: coroutines (structured concurrency) on top of JVM threads; Java 21+ virtual threads are an alternative for blocking code (Spring `spring.threads.virtual.enabled=true`). Do not mix both for the same workload without measurement. [CONC-01] | Pick one model per service | SHOULD | [Coroutines guide](https://kotlinlang.org/docs/coroutines-guide.html); [Spring virtual threads](https://docs.spring.io/spring-boot/reference/features/task-execution-and-scheduling.html) | go-only (§11-12) | review |
| `KT-CONC-02` | Never use `GlobalScope`; own scopes explicitly: `CoroutineScope(SupervisorJob() + dispatcher)` per component, cancelled on shutdown; use `coroutineScope {}` for all-or-nothing children and `supervisorScope {}` when siblings must survive one failure. ## Top 10 footguns

1. **Swallowed `CancellationException`.** Bad: `try { suspendCall() } catch (e: Exception) { log(e) }` or `runCatching { suspendCall() }`. Fix: rethrow `CancellationException` (or catch specific types). ([source](https://kotlinlang.org/docs/exception-handling.html))
2. **`GlobalScope` / orphan `launch`.** Bad: `GlobalScope.launch { ... }`. Fix: inject a `CoroutineScope(SupervisorJob()+dispatcher)` cancelled on shutdown, or `coroutineScope {}`. ([source](https://kotlinlang.org/docs/coroutines-guide.html))
3. **Blocking on `Dispatchers.Default`.** Bad: `launch { jdbc.query() }`. Fix: `withContext(Dispatchers.IO)`/`limitedParallelism`. ([source](https://kotlinlang.org/docs/coroutine-context-and-dispatchers.html))
4. **Platform types leaking.** Bad: `val n = javaApi.name()` exposed publicly (`String!`). Fix: declare `String?`/`String` explicitly; `-Xjsr305=strict`. ([source](https://kotlinlang.org/docs/java-interop.html))
5. **`!!` and `lateinit` in domain code.** Fix: `?:`, `requireNotNull`, constructor injection. ([source](https://kotlinlang.org/docs/null-safety.html))
6. **`data class` as JPA entity.** Bad: `@Entity data class User(var ...)`. Fix: plain `class` + `kotlin-jpa`/`allOpen`, domain mapping. ([source](https://kotlinlang.org/docs/no-arg-plugin.html))
7. **Wrong annotation use-site target (old default or `-Xannotation-default-target=first-only`).** Bad: `data class Dto(@get:NotBlank val a: String)` mismatched with the validator. Fix: `@field:NotBlank` explicitly, unless the build opts in to `-Xannotation-default-target=param-property` (preview from 2.2.0), where an unqualified annotation covers param and field. ([source](https://kotlinlang.org/docs/annotations.html#annotation-use-site-targets))
8. **Gradle up-to-date skips tests.** `./gradlew test` is a no-op when nothing changed; a gate would pass without running. Fix: `--rerun` (Gradle 7.6+) or `cleanTest`. ([source](https://docs.gradle.org/current/userguide/java_testing.html))
9. **Virtual time not applied.** Bad: `withContext(Dispatchers.IO) { delay(1000) }` in code under `runTest` waits real time. Fix: inject the dispatcher. ([source](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-test/))
10. **Transaction/MDC bound to a thread while coroutines hop threads.** Fix: `MDCContext()`, coroutine-aware tx managers. ([source](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-slf4j/))
