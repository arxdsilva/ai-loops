> **Summary:** A strong .NET team pins the SDK in `global.json`, centralises versions in `Directory.Packages.props` and build policy in `Directory.Build.props`, turns on nullable reference types plus `TreatWarningsAsErrors` and the Roslyn analyzers, and keeps hexagonal boundaries as separate projects (assembly references are the boundary). .NET has **no race detector**; the honest policy is `none` with a stress/parallelism substitute. Coverage is Cobertura via coverlet or Microsoft.Testing.Platform. The three biggest gaps in loops: (1) no language detection, no `dotnet` gate and no Cobertura parser; (2) no race-equivalent policy for ecosystems without `-race`; (3) the arch checker and cleanup cannot read `.csproj` references, `bin/obj`, `TestResults`.

Rules follow [TAXONOMY.md](TAXONOMY.md), using the row format `ID | Rule | Why | Sev | Source | loops today | Enforce`. Gaps are judged against [LOOPS_BASELINE.md](LOOPS_BASELINE.md). Abbreviations in Source cells: MS = learn.microsoft.com (en-us).

## 1. REPO: repository and project management

Canonical tree for a service (`dotnet new sln` + `classlib`/`webapi`/`xunit`; for xUnit v3 first run `dotnet new install xunit.v3.templates`; `.slnx` is the default solution format in the .NET 10 SDK):

```text
.
├── global.json                  # SDK pin (+ test runner opt-in for MTP)
├── Directory.Build.props        # shared TFM, Nullable, analyzers, TreatWarningsAsErrors, lock files
├── Directory.Build.targets
├── Directory.Packages.props     # Central Package Management: all versions live here
├── nuget.config                 # sources + packageSourceMapping
├── .editorconfig                # style + analyzer severities (dotnet format reads it)
├── .gitignore  .gitattributes  CODEOWNERS
├── Shop.slnx
├── src/
│   ├── Shop.Domain/             # no package refs, no ProjectReference
│   ├── Shop.Application/        # -> Domain; defines ports (interfaces)
│   ├── Shop.Infrastructure/     # -> Application; EF Core, HTTP clients (outbound adapters)
│   ├── Shop.Api/                # -> Application, Infrastructure; composition root (Program.cs)
│   └── Shop.Worker/             # second host, same composition pattern
├── tests/
│   ├── Shop.Domain.Tests/
│   ├── Shop.Application.Tests/
│   ├── Shop.Api.IntegrationTests/   # WebApplicationFactory + Testcontainers
│   └── Shop.Architecture.Tests/     # NetArchTest / ArchUnitNET
├── benchmarks/Shop.Benchmarks/
└── docs/adr/
```

## 3. ARCH: architecture

Styles in .NET:

- **Hexagonal / clean / onion:** idiomatic, using **projects and `ProjectReference` as boundaries**; Jason Taylor's and Ardalis's Clean Architecture templates and eShopOnWeb are the references. Choose for any service with real domain logic.
- **Layered / MVC:** the default of ASP.NET Core; choose for CRUD-heavy services; keep controllers thin.
- **DDD tactical:** records and `readonly struct` as value objects, aggregates with private setters and factory methods, repositories as interfaces in Application, domain events dispatched after `SaveChanges`.
- **CQRS / event sourcing:** MediatR (dual RPL-1.5/commercial licence from v13), Wolverine, or hand-rolled handlers; Marten for event sourcing on Postgres. Use only where read and write models diverge.
- **Event-driven:** MassTransit, Wolverine, NServiceBus (all with outbox support); Azure Service Bus SDK, Confluent.Kafka, RabbitMQ.Client.
- **Modular monolith vs microservices:** one solution with one project group per module, enforced by architecture tests, preferred default; split to microservices with .NET Aspire/YARP when team and scaling boundaries require it.
- **Serverless:** Azure Functions isolated worker, AWS Lambda (NativeAOT recommended for cold start).
- **Actor model:** Orleans (virtual actors), Akka.NET, Dapr actors.

ARCH-02 mapping (assembly = hexagon layer; the `.csproj` `ProjectReference` graph is the dependency rule):

```text
src/Shop.Domain/            # loops: internal/domain   (entities, value objects, domain events, domain services; no IO, no clock)
src/Shop.Application/       # loops: application       (use cases/handlers + ports: IOrderRepository, IClock via TimeProvider, IPaymentGateway)
src/Shop.Infrastructure/    # loops: adapters/outbound (EF Core DbContext + repositories, HTTP clients, message producers)
src/Shop.Api/               # loops: adapters/inbound + compose  (Program.cs = composition root; endpoints map to use cases)
  Endpoints/OrdersEndpoints.cs   Program.cs   appsettings*.json
src/Shop.Worker/            # inbound adapter: BackgroundService / consumers; own Program.cs composition root
tests/Shop.Architecture.Tests/   # asserts the reference graph and namespace rules
# reference graph: Api -> Application, Infrastructure ; Infrastructure -> Application ; Application -> Domain ; Domain -> (nothing)
```

## 4. IDIOM: what to do and what to avoid

| ID | Rule | Why | Sev | Source | loops today | Enforce |
|---|---|---|---|---|---|---|
| `CS-IDIOM-01` | Use exceptions for exceptional failures and `Result<T>`/discriminated-union style returns (or `bool TryXxx(out ...)`) for expected domain failures; throw the most specific type, derive custom exceptions from `Exception` (not `ApplicationException`), never `catch (Exception)` without rethrow/log, rethrow with `throw;` (never `throw ex;`), and never use exceptions for control flow. [IDIOM-01] | `throw ex` resets the stack trace; broad catches hide defects. | MUST | [MS: exception design guidelines](https://learn.microsoft.com/en-us/dotnet/standard/design-guidelines/exceptions) · [CA2200](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca2200) | covered (`GO_BEST §8-9` neutral core, `HEXAGONAL` error taxonomy) | review |

## 5. CONC: concurrency and the `-race` equivalent

**Loops race policy: `mode = none`.** .NET has no built-in managed race detector (ThreadSanitizer does not support managed code; the Go-style `-race` flag does not exist). The substitute loops should enforce: (1) tests run with parallelism **on** (xUnit parallelises test collections by default; do not disable it), (2) a dedicated concurrency stress suite (trait `Category=Concurrency`) that runs the shared-state tests many times with `Parallel.For`/`Task.WhenAll` and `Barrier`/`ManualResetEventSlim`, run N times in the gate (for example 20), (3) analyzers for async and lock misuse (CA2007, CA2012, CA2016, CA1849, CS4014, VSTHRD via Microsoft.VisualStudio.Threading.Analyzers) as errors, (4) design away shared mutable state (immutable records, `Channel<T>`, `ConcurrentDictionary`, `Interlocked`). The argv is the normal test command (`dotnet test`) plus a repeat via a loop in loops; there is no flag.

## Top 10 footguns

1. **Sync-over-async.** Bad: `var x = service.GetAsync().Result;` Fix: `await service.GetAsync(ct)` all the way up; analyzers CA2012, VSTHRD002. ([MS best practices](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/best-practices))
2. **`async void`.** Bad: `async void Handle()` (exceptions crash the process). Fix: return `Task`. ([MS async](https://learn.microsoft.com/en-us/dotnet/csharp/asynchronous-programming/))
3. **`new HttpClient()` per call.** Bad: `using var c = new HttpClient();` (socket exhaustion). Fix: `IHttpClientFactory`. ([MS HttpClient guidelines](https://learn.microsoft.com/en-us/dotnet/fundamentals/networking/http/httpclient-guidelines))
4. **EF Core N+1 and tracking.** Bad: lazy-loaded navigation in a loop, tracked read-only queries. Fix: `Include`/projection, `AsNoTracking()`, `AsSplitQuery()`. ([MS efficient querying](https://learn.microsoft.com/en-us/ef/core/performance/efficient-querying))
5. **`DbContext` shared or captured by a singleton.** Bad: injecting `DbContext` in a singleton or `Task.WhenAll` over one context. Fix: scoped lifetime, `IDbContextFactory<T>`. ([MS DbContext config](https://learn.microsoft.com/en-us/ef/core/dbcontext-configuration/))

7. **Null-forgiving `!` and ignored nullable warnings.** Bad: `name!.Length`. Fix: honest annotations, `required`, guard clauses, warnings as errors. ([MS nullable](https://learn.microsoft.com/en-us/dotnet/csharp/nullable-references))
8. **`throw ex;` and swallowed exceptions.** Bad: `catch (Exception ex) { throw ex; }`. Fix: `throw;`, catch specific types. ([CA2200](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca2200))
9. **`DateTime.Now` and culture-sensitive string ops.** Bad: `DateTime.Now`, `s.ToLower()`, `string.Compare(a,b)`. Fix: `TimeProvider.GetUtcNow()`, `StringComparison.Ordinal`/`InvariantCulture`. ([MS strings](https://learn.microsoft.com/en-us/dotnet/standard/base-types/best-practices-strings))
