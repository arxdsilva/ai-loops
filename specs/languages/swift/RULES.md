# Swift (server-side) rules

Language: Swift 6.4.x, server-side (SwiftPM, SwiftNIO, Hummingbird 2, Vapor 4). As of 2026-11. Source research: `research/languages/swift.md` (verified; rule IDs kept). Universal rules live in `specs/ARCHITECTURE.md`, `specs/SOLID.md` and `specs/WORKFLOW.md`; this file adds only what is Swift-specific. Project rules win over these defaults: log each override with `loops run override`.

Severity: MUST = the gate or a reviewer blocks; SHOULD = the default, deviate with a reason; AVOID = do not, unless the project already does.

## REPO: repository and project management

- **`SWIFT-REPO-01`** (MUST) Use one SwiftPM package with `Sources/<Target>` and `Tests/<Target>Tests`; do not commit an `.xcodeproj` for a server. Executables go in `executableTarget`, libraries in `target`. SwiftPM infers target dirs from `Sources/`, `Tests/`; the folder name is the module name used by `import`. ([SwiftPM Package Manager docs](https://docs.swift.org/latest/documentation/packagemanagerdocs/))
- **`SWIFT-REPO-02`** (MUST) Add `// swift-tools-version: 6.4` (or the lowest version you support, at least 6.0) on line 1 of `Package.swift`. A 6.x tools version makes Swift 6 language mode the default for targets. Language mode follows the tools version; verified locally: `swift package init` writes 6.4 and no `swiftLanguageModes`. ([Swift migration guide](https://www.swift.org/migration/documentation/migrationguide/))
- **`SWIFT-REPO-03`** (SHOULD) Prefer one package with multiple targets over multi-package until a part has a separate release cadence; use local `.package(path:)` dependencies for a multi-package monorepo. SwiftPM has no workspace concept like Cargo/Go; targets give the boundary, packages give versioning. ([SwiftPM docs: Package.swift manifest](https://docs.swift.org/latest/documentation/packagemanagerdocs/))
- **`SWIFT-REPO-04`** (SHOULD) Bootstrap with `swift package init --type executable --name <Svc>` or the Hummingbird/Vapor templates (`hummingbird-project/template`, `vapor new`); then delete sample code, commit a `.swift-format` (or format the template once; the stock template fails `swift format lint --strict`), and create the four layer targets. Official starters carry the right tools version and `.gitignore`. ([Building for production (swift.org)](https://www.swift.org/documentation/server/guides/building.html))
- **`SWIFT-REPO-05`** (MUST) Commit `Package.resolved` for services and executables; for libraries do not rely on it (consumers ignore it). In CI run `swift build --force-resolved-versions` (aliases `--disable-automatic-resolution`, `--only-use-versions-from-resolved-file`) so a stale lockfile fails the build. The flag "fail[s] resolution if it is out-of-date" (verified in `swift package resolve --help`). ([SwiftPM docs: resolving versions](https://docs.swift.org/latest/documentation/packagemanagerdocs/))
- **`SWIFT-REPO-06`** (MUST) Declare dependencies with `from:` (semver up-to-next-major) for SSWG/Apple packages; use `exact:` or a revision only for forks or security pins and comment why. Never use `branch:` on a release. SwiftPM forbids unstable (branch) dependencies in tagged releases consumed by others and they break reproducibility. ([SwiftPM docs: Package.swift](https://docs.swift.org/latest/documentation/packagemanagerdocs/))
- **`SWIFT-REPO-07`** (SHOULD) Automate dependency updates with Dependabot (`package-ecosystem: "swift"`) or Renovate (`swift` manager); review `Package.resolved` diffs like code. Remove unused `.product(...)` entries; `--explicit-target-dependency-import-check=error` catches undeclared imports, not unused ones. Both bots read `Package.swift`/`Package.resolved`. ([Dependabot ecosystems](https://docs.github.com/en/code-security/dependabot/ecosystems-supported-by-dependabot/supported-ecosystems-and-repositories))
- **`SWIFT-REPO-08`** (SHOULD) Release a library by pushing a SemVer git tag `X.Y.Z` (no `v` is conventional but `vX.Y.Z` also resolves); SwiftPM resolves from tags, no registry upload needed. Services release a container image tagged by git SHA + semver. Keep a CHANGELOG. Swift Package Index and SwiftPM read git tags; there is no central publish step (the Swift Package Registry spec, SE-0292, is optional). ([SE-0292 Package Registry Service](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0292-package-registry-service.md))
- **`SWIFT-REPO-09`** (MUST) Pin the toolchain with a `.swift-version` file (read by swiftly) and mirror it in the Docker base image tag and the CI matrix. swiftly supports `.swift-version` as a shared project setting. ([swiftly README](https://github.com/swiftlang/swiftly))
- **`SWIFT-REPO-10`** (MUST) Keep `.gitignore` with `/.build`, `/Packages`, `.swiftpm/xcode/`, `.swiftpm/configuration/registries.json`, `xcuserdata/`, `DerivedData/`, `.netrc`, `.DS_Store` (what `swift package init` emits); also ignore coverage output and `*.profraw`. Commit `.swift-format`, `.editorconfig`, `CODEOWNERS`. `.build/` can be GBs; `.netrc` holds credentials. Verified locally: init writes exactly this list. ([swift package init template (verified locally)](https://docs.swift.org/latest/documentation/packagemanagerdocs/))
- **`SWIFT-REPO-11`** (SHOULD) CI stages: restore cache of `.build` keyed on `Package.resolved` + tools version, `swift format lint --strict -r Sources Tests`, SwiftLint, `swift build --force-resolved-versions -c release`, `swift test --sanitize=thread --enable-code-coverage`, export lcov, SBOM/audit, container build. Matrix: latest and previous Swift minor on Linux (Ubuntu), plus macOS only if you ship there. SSWG graduation requires CI on the two latest recommended Swift versions; a server targets Linux. ([SSWG incubation process](https://www.swift.org/sswg/incubation-process.html))
- **`SWIFT-REPO-12`** (SHOULD) Use conventional commits; they drive `loops release`. No Swift-specific commit rules. Ecosystem has no mandated changelog tool. ([Conventional Commits](https://www.conventionalcommits.org/))

## TOOL: toolchain

- **`SWIFT-TOOL-01`** (MUST) Target Swift 6.4.x (latest stable, as of 2026-11); Swift releases roughly twice a year (6.2 Sep 2025, 6.4 2026-09-15) with no LTS; Hummingbird 2.27+ dropped 6.1 and needs Swift >= 6.2. Install via swiftly on Linux/macOS (`swiftly install latest`, `swiftly use`), or the official `swift:<ver>` Docker images. Frameworks track the last two or three minors; no LTS means pin and upgrade deliberately. ([Swift 6.4 release](https://www.swift.org/blog/swift-6.4-released/))
- **`SWIFT-TOOL-02`** (MUST) Format with the toolchain-bundled `swift format` (swift-format, since Swift 6). Check argv: `swift format lint --strict --recursive Sources Tests`; fix: `swift format format --in-place --recursive Sources Tests`. Config: `.swift-format` (JSON, found by walking up); COMMIT a `.swift-format` (e.g. `{"version":1,"indentation":{"spaces":4}}` to match the `swift package init` template, or run `swift format format -i -r Sources Tests` once at bootstrap), because the fresh template (4-space indent) fails `lint --strict` against the default 2 spaces (verified by B2 on swift:6.4.2/Linux); dump defaults with `swift format dump-configuration`. `--strict` turns warnings into a non-zero exit (lint prints to stderr, so `fails_on` must be exit code, not output). ([swift-format README](https://github.com/swiftlang/swift-format))
- **`SWIFT-TOOL-03`** (SHOULD) Choose ONE style/lint stack: swift-format for layout (official, no SourceKit), plus SwiftLint for semantic rules (`swiftlint lint --strict`, `.swiftlint.yml`, `opt_in_rules`, `analyzer_rules` need a compiler log and are slow). Do not run both formatters in autofix mode; disable overlapping rules. They overlap (line length, trailing commas) and fight each other when both rewrite. ([SwiftLint](https://github.com/realm/SwiftLint))
- **`SWIFT-TOOL-04`** (MUST) Type checking is the compiler: Swift 6 language mode (complete strict concurrency) and `-warnings-as-errors` in CI (`swiftSettings: [.treatAllWarnings(as: .error)]` or `swift build -Xswiftc -warnings-as-errors`). Enable upcoming features deliberately (`.enableUpcomingFeature("ExistentialAny")`, `"InternalImportsByDefault"`, `"MemberImportVisibility"`). Swift 6 mode makes data-race diagnostics errors; warnings left as warnings rot. ([Swift migration guide](https://www.swift.org/migration/documentation/migrationguide/))
- **`SWIFT-TOOL-05`** (SHOULD) Vulnerability/supply chain: there is NO first-party `swift audit`. Use GitHub Dependabot security alerts (Swift supported) and, in CI, `swift package generate-sbom` (SE-0509, Swift 6.4, SPDX or CycloneDX). OSV-Scanner does NOT support `Package.resolved` (verified against its supported-lockfiles page); Dependabot does support Swift. Honest gap: loops cannot assume a vuln command exists; `vuln` check is `null`. ([Swift 6.4 release](https://www.swift.org/blog/swift-6.4-released/))
- **`SWIFT-TOOL-06`** (SHOULD) LSP is `sourcekit-lsp` (in the toolchain); use the Swift VS Code extension (it integrates with swiftly). Do not let editor format-on-save use a different formatter than CI (`swift format` vs SwiftLint `--fix`). Prebuilt `swift-syntax` for macros is on by default in 6.4 (`--enable-experimental-prebuilts`). Editor/CI drift causes churn diffs. ([Swift 6.4 release](https://www.swift.org/blog/swift-6.4-released/))
- **`SWIFT-TOOL-07`** (MUST) Swift Build is the default SwiftPM build system in 6.4 (`--build-system swiftbuild`; `native` is deprecated). Output lands under `.build/out/Products/Debug` on macOS and `.build/out/Products/Debug-linux-<arch>` on Linux (verified), not the old `.build/<triple>/debug` layout (only with `--build-system native`); always query paths with `swift build --show-bin-path` and `swift test --show-codecov-path`, never hardcode. Layout changed between build systems and OSes. ([Swift 6.4 release](https://www.swift.org/blog/swift-6.4-released/))

## ARCH: architecture

- **`SWIFT-ARCH-01`** (SHOULD) Choose hexagonal as the default: layers as SwiftPM targets (Domain, Application, adapters, App). Use a modular monolith (one package, many targets) first; split into services only on a deploy/ownership boundary. Hummingbird (composition via generics, explicit) suits it better than Vapor's global `Application` object, but both work. Targets give compile-time boundaries for free. ([Hummingbird docs](https://docs.hummingbird.codes/2.0/documentation/hummingbird/))
- **`SWIFT-ARCH-02`** (SHOULD) Model DDD tactical patterns with value types: entities as `struct` with an `id`, value objects as `struct` with validating `init throws`, aggregates as one root `struct`/`actor`-owned state, repositories as protocols in Application, domain events as an `enum`. Value semantics make aggregates copy-safe and `Sendable` by default. ([Swift API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/))
- **`SWIFT-ARCH-03`** (SHOULD) CQRS/event sourcing and actors: use an `actor` for in-process single-owner state (a projection, a cache, an aggregate registry) and message-passing via `AsyncStream`; do not build a custom mailbox. For cross-process events use Kafka/NATS/SQS clients behind a port. Swift actors give serialized access with compile-time checks; Swift has no OTP-style supervision tree. ([Swift Concurrency: actors](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/concurrency/))
- **`SWIFT-ARCH-04`** (SHOULD) Serverless: Swift on AWS Lambda uses `swift-aws-lambda-runtime` with a static Linux SDK binary; keep handlers thin and reuse the same Application target. Same hexagon, different inbound adapter. ([swift-aws-lambda-runtime](https://github.com/swift-server/swift-aws-lambda-runtime))
- **`SWIFT-ARCH-05`** (MUST) Module = target name = `Sources/<Target>` directory; `import Domain`. Access levels: `internal` (default) is module-private; use `public` only on the port/use-case API; `package` (SE-0386) shares between targets of one package without exposing it to consumers; `open` is for classes meant for subclassing (rare). Cycles between modules are impossible; cycles inside one module are allowed. Access level is the second boundary after target dependencies. ([SE-0386 package access modifier](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0386-package-access-modifier.md))
- **`SWIFT-ARCH-06`** (MUST) Imports are `import Module`, `@testable import Module`, `internal import Module` (SE-0409, with `InternalImportsByDefault`), or `import struct Module.Type`; loops' arch parser must read the first token after `import` (skipping the kind keyword) and map it to a target by name. `@_exported import` is an AVOID. Parsing needs the exact forms; `@_exported` leaks a dependency through the boundary. ([SE-0409 access-level modifiers on import](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0409-access-level-on-imports.md))
- **`SWIFT-ARCH-07`** (MUST) Enforce direction in `Package.swift` plus `swift build --explicit-target-dependency-import-check=error`; for rules beyond that (domain must not import Foundation networking, NIO, Vapor, Hummingbird, Fluent, PostgresNIO) use `loops arch` with a Swift parser, or a SwiftLint `custom_rules` regex on `Sources/Domain/**` as a stopgap. No ArchUnit equivalent is established. Verified locally that the flag exists (values none/warn/error, default none). ([SwiftLint custom_rules](https://github.com/realm/SwiftLint))
- **`SWIFT-ARCH-08`** (SHOULD) Wire manually in the App target (`@main` creates adapters, injects them into use cases, builds the router). Avoid global singletons and service locators; DI containers (swift-dependencies, Factory) are optional and never inside Domain. Hummingbird passes dependencies via the `RequestContext`/router builder; Vapor via `app.storage`/`Request.application` (a locator; keep access to the adapter layer). Explicit init injection is checked by the compiler. ([Hummingbird docs](https://docs.hummingbird.codes/2.0/documentation/hummingbird/))
- **`SWIFT-ARCH-09`** (MUST) Keep Domain free of I/O, clock, randomness: inject a `Clock` (stdlib `Clock` protocol, `ContinuousClock`; `TestClock` from swift-clocks in tests), a `RandomNumberGenerator`, and ID generation; flag `Date()`, `Date.now`, `UUID()`, `.random(in:)`, `Task {`, `URLSession`, `FileManager`, `ProcessInfo` in Domain. These make tests non-deterministic and hide dependencies. ([Clock (Swift stdlib)](https://developer.apple.com/documentation/swift/clock))
- **`SWIFT-ARCH-10`** (SHOULD) Ports are `protocol`s defined in Application (consumer-owned), small (1-3 requirements), with `Sendable` and async throws methods; use `any Port` (with `ExistentialAny`) at wiring and generics (`some Port` / `<R: OrderRepository>`) on hot paths. Protocol-oriented design; `any` costs a box and dynamic dispatch. ([Protocols](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/protocols/))
- **`SWIFT-ARCH-11`** (SHOULD) SOLID limits: keep files under about 400 lines, functions under 50, a type under about 10 public members, and init/function parameters under 5 (use a parameter struct). Prefer composition over inheritance; classes only when identity or reference semantics are needed (`final class` by default). Swift favours structs/protocols; deep class hierarchies are a smell. ([Swift API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/))

## IDIOM: what to do and what to avoid

- **`SWIFT-IDIOM-01`** (MUST) Use `throws` with typed domain error `enum`s conforming to `Error` (and `Sendable`); use typed throws (`throws(OrderError)`, SE-0413) at domain boundaries where the error set is closed. Wrap lower-level errors with context at the adapter; never `catch {}` silently and never `try?` where failure matters. Swift errors are unchecked; typed throws restore exhaustiveness. ([Error Handling](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/errorhandling/))
- **`SWIFT-IDIOM-02`** (MUST) Never use `try!`, `fatalError`, or `!` force-unwrap in server code paths driven by input; use `guard let`, `if let`, `??`, `try`. Reserve `precondition`/`fatalError` for programmer errors at startup. Swift crashes the whole process on a trap. A trap kills every in-flight request; there is no per-request recover. ([The Basics: Optionals](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/thebasics/))
- **`SWIFT-IDIOM-03`** (MUST) Model absence with `Optional`; do not use sentinel values (`-1`, `""`). Prefer `guard let` early exit; avoid implicitly unwrapped optionals (`T!`) except for framework-injected outlets. Optionals are compiler-checked. ([The Basics](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/thebasics/))
- **`SWIFT-IDIOM-04`** (SHOULD) Default to `struct`/`enum` and `let`; use `var` only when mutated; make types `Sendable` by value composition. `final class` with immutable stored `let` properties is also `Sendable`. Value semantics remove shared mutable state. ([Structures and Classes](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/classesandstructures/))
- **`SWIFT-IDIOM-05`** (MUST) Model closed sets as `enum` with associated values and `switch` exhaustively (no `default:` on domain enums; use `@unknown default` only for non-frozen external enums); use `if case`/`switch` pattern matching. Adding a case becomes a compile error at every use. ([Enumerations](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/enumerations/))
- **`SWIFT-IDIOM-06`** (MUST) Resources: Swift has ARC, not GC pauses, but no `finally` for async; use `defer` (async calls inside `defer` run to completion in Swift 6.4, SE-0493), `withTaskCancellationShield` (SE-0504) for cleanup that must survive cancellation, and `~Copyable` types or `with...` closures for scoped resources (`withThrowingTaskGroup`, `PostgresClient.withConnection`). Break retain cycles with `[weak self]`/`unowned` in escaping closures. Leaked connections and retain cycles are the common leaks. ([Swift 6.4 release](https://www.swift.org/blog/swift-6.4-released/))
- **`SWIFT-IDIOM-07`** (MUST) Time: use `Date` only at the edge and `Duration`/`ContinuousClock` for intervals; format dates with `Date.FormatStyle`/`ISO8601FormatStyle` (explicit `TimeZone`/UTC), never `DateFormatter` shared across threads (not `Sendable`). Money is `Decimal`, never `Double`. Strings are Unicode: `count` is O(n), index via `String.Index`. Classic date/time and Unicode footguns. ([Date.FormatStyle](https://developer.apple.com/documentation/foundation/date/formatstyle))
- **`SWIFT-IDIOM-08`** (MUST) Follow the Swift API Design Guidelines: clarity at the point of use, `UpperCamelCase` types, `lowerCamelCase` members, argument labels that read as a phrase, mutating/non-mutating pairs (`sort()` / `sorted()`), no abbreviations; document public API with `///` DocC comments. The official guideline; SwiftLint/ swift-format enforce parts. ([API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/))
- **`SWIFT-IDIOM-09`** (AVOID) Avoid macros/property wrappers/result builders in the domain; they are fine at edges (Codable, Swift Testing `@Test`, Hummingbird/Vapor DSL, `@Observable` n/a on server). Avoid `Mirror`/`Any`/`AnyObject` type erasure and `@objc` dynamism on Linux. Macros hide behaviour and slow builds (swift-syntax). ([Macros](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/macros/))
- **`SWIFT-IDIOM-10`** (SHOULD) Equality/hash: synthesize `Equatable`/`Hashable` from stored properties; do not hand-write `==` without `hash(into:)`; do not use `Float`/`Double` as dictionary keys; value-type `Codable` DTOs live in adapters, not Domain. Hand-written conformances drift apart. ([Equatable](https://developer.apple.com/documentation/swift/equatable))
- **`SWIFT-IDIOM-11`** (MUST) Footgun avoidance: `try!`/`!` crashes; `Array` index out of range traps (use `.first`, `indices.contains`); integer overflow traps (use `addingReportingOverflow` or `&+` deliberately); `Dictionary` iteration order is random; capture lists in escaping closures; `Task {}` inherits actor context (use `Task.detached` knowingly). Traps terminate the server. ([Swift book: Advanced Operators (overflow)](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/advancedoperators/))

## CONC: concurrency and the `-race` equivalent

Race policy (WORKFLOW §6, mode `flag`): every target compiles in Swift 6 language mode and tests run with `swift test --sanitize=thread`. TSan is mutually exclusive with `address`; run ASan/UBSan as a separate optional job. Where TSan cannot run on the host the gate fails with "race policy unavailable", it never skips.

- **`SWIFT-CONC-01`** (MUST) Model: async/await on cooperative thread pool + structured concurrency (`async let`, `TaskGroup`) + actors; SwiftNIO `EventLoop`s underneath (Hummingbird/Vapor run handlers as `async`). No GIL. Swift concurrency is the default model; NIO `EventLoopFuture` is legacy. ([Concurrency (Swift book)](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/concurrency/))
- **`SWIFT-CONC-02`** (MUST) Compile every target in Swift 6 language mode: shared mutable state must be an `actor`, `Sendable`, `Mutex` (`Synchronization.Mutex`, Swift 6) or `nonisolated(unsafe)` with a written justification; passing non-`Sendable` values across isolation domains is a compile error. Never silence with `@unchecked Sendable` without a lock and a comment. The compiler proves data-race freedom for safe code. ([Migration guide](https://www.swift.org/migration/documentation/migrationguide/))
- **`SWIFT-CONC-03`** (MUST) Run tests with `swift test --sanitize=thread` in CI and in the loops hard gate; it catches what the compiler cannot (`@unchecked Sendable`, `nonisolated(unsafe)`, C/ObjC interop, `Mutex` misuse). Linux needs the toolchain's TSan runtime (bundled in official images). Expect 5-15x slowdown, so scope to unit/integration tests. The Swift equivalent of `go test -race` is sanitizer build mode. ([swift test --sanitize (verified locally: `address, thread, undefined, scudo, fuzzer`)](https://docs.swift.org/latest/documentation/packagemanagerdocs/))
- **`SWIFT-CONC-04`** (SHOULD) Migrate incrementally: `swift package migrate` applies upcoming-feature fix-its per target; adopt `-strict-concurrency=complete` per target (`.enableUpcomingFeature("StrictConcurrency")`) before flipping to `.swiftLanguageMode(.v6)`. Never downgrade a target to `.v5` to pass a gate without logging an override. Prevents regressions during migration; matches the loops "every override is logged" rule. ([Migration guide](https://www.swift.org/migration/documentation/migrationguide/))
- **`SWIFT-CONC-05`** (MUST) `@MainActor` is for UI; on the server avoid it. With "approachable concurrency" (`.enableUpcomingFeature("ApproachableConcurrency")`, written into `swift package init` output in 6.4) keep default isolation `nonisolated` for libraries/servers and do not set `defaultIsolation(MainActor.self)` in a server target. Main-actor default isolation would serialize handlers on one thread. ([Swift migration guide](https://www.swift.org/migration/documentation/migrationguide/))
- **`SWIFT-CONC-06`** (MUST) Cancellation is cooperative: call `try Task.checkCancellation()` or `Task.isCancelled` in loops, pass `async` work through structured tasks so cancelling a request cancels children; use `withTaskCancellationHandler` to wire cancellation to I/O; never `Task.detached` for request work. Unstructured tasks leak past the request and ignore cancellation. ([Concurrency: Tasks](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/concurrency/#Tasks-and-Task-Groups))
- **`SWIFT-CONC-07`** (MUST) Do not block the cooperative pool: no `sleep()`, `DispatchSemaphore.wait`, synchronous file/DB/`URLSession` data calls or heavy CPU in `async` code; use `try await Task.sleep(for:)`, async clients, and for CPU work use a dedicated `NIOThreadPool`/`NIOSingletons`. Do not mix `DispatchSemaphore` and `await`. The pool has about one thread per core; blocking starves all requests. ([SwiftNIO guidance](https://github.com/apple/swift-nio))
- **`SWIFT-CONC-08`** (SHOULD) Bound concurrency and backpressure: `withThrowingTaskGroup` with a sliding window (add a task as one finishes), `AsyncStream` with `bufferingPolicy: .bufferingNewest(n)`, `swift-async-algorithms` for merge/debounce; set timeouts on every outbound call. Unbounded `addTask` loops exhaust memory/connections. ([swift-async-algorithms](https://github.com/apple/swift-async-algorithms))
- **`SWIFT-CONC-09`** (MUST) Run background work and graceful shutdown with `swift-service-lifecycle` (`ServiceGroup`, `Service`, signal handling `SIGTERM`/`SIGINT`, `gracefulShutdown()`); register server, DB client, OTel and workers in one `ServiceGroup`. The SSWG standard for lifecycle; Hummingbird embeds it. ([swift-service-lifecycle](https://github.com/swift-server/swift-service-lifecycle))
- **`SWIFT-CONC-10`** (SHOULD) Swift Testing runs tests in parallel by default and `swift test --parallel` parallelizes XCTest; mark shared-resource suites `@Suite(.serialized)`; never depend on test order. Parallel runs surface hidden shared state. ([swift-testing](https://github.com/swiftlang/swift-testing))

## TEST: testing

Coverage recipe: `swift test --enable-code-coverage` writes `default.profdata` in the `codecov/` dir that `swift test --show-codecov-path` points into. Discover the test objects, never hardcode them: macOS `<bin>/<T>.xctest/Contents/MacOS/<T>`, Linux (default Swift Build) `<bin>/<T>-test-runner` or `<T>.so`, one per test target, with `<bin>` from `swift build --show-bin-path` (`.build/out/Products/Debug` on macOS, `.build/out/Products/Debug-linux-<arch>` on Linux; `<Pkg>PackageTests.xctest` exists only with the deprecated `--build-system native`). Export with `llvm-cov export -format=lcov -instr-profile=<codecov>/default.profdata -object <o1> -object <o2> ...` (`xcrun llvm-cov` on macOS). Pass every object with `-object`: extra positionals are read as source filters and silently drop targets (verified on macOS, 2 test targets).

- **`SWIFT-TEST-01`** (SHOULD) Use Swift Testing (`import Testing`, `@Test`, `@Suite`, `#expect`, `#require`) for all new tests; keep XCTest only for performance tests (`measure`), UI/Obj-C interop and frameworks that still ship XCTest helpers (Vapor's `XCTVapor`/`VaporTesting`, Hummingbird `HummingbirdTesting` works with both). Swift 6.4 lets `XCTAssert` run inside Swift Testing and `#expect` inside XCTest. swift-testing is bundled in the toolchain, parallel, and macro-based; mixing is supported. ([swift-testing](https://github.com/swiftlang/swift-testing))
- **`SWIFT-TEST-02`** (MUST) Layout: `Tests/<Target>Tests/*.swift`; file `FooTests.swift` tests `Foo`; Swift Testing suites are `struct`s with `@Suite`; XCTest classes end in `Tests` and methods begin `test`. Test recognition globs: `Tests/**/*.swift`, `**/*Tests.swift`, `**/*Test.swift`. `testTarget` defaults to `Tests/<name>`. ([SwiftPM: test targets](https://docs.swift.org/latest/documentation/packagemanagerdocs/))
- **`SWIFT-TEST-03`** (SHOULD) Write parameterized tests with `@Test(arguments: [...])` (the Swift Testing equivalent of table-driven tests); name with `@Test("does X when Y")`; arrange-act-assert; group with `.tags(...)` and run subsets with `swift test --filter`/`--skip`. Each argument is its own case in reports. ([swift-testing: parameterized tests](https://github.com/swiftlang/swift-testing))
- **`SWIFT-TEST-04`** (SHOULD) Test doubles: hand-written fakes/stubs implementing the port protocols (`InMemoryOrderRepository`, spy actors); no mocking library is standard (swift has no runtime reflection mocking; avoid macro mock generators unless already adopted). Do not mock the domain or value types. Protocol ports make fakes trivial. ([Protocols](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/protocols/))
- **`SWIFT-TEST-05`** (SHOULD) Integration: use real Postgres via Testcontainers (`testcontainers-swift` is community, immature) or docker-compose in CI; create an isolated schema/DB per test or suite; HTTP tests use `HummingbirdTesting` (`app.test(.router)` runs without sockets) or `VaporTesting`/XCTVapor `app.test(.GET, ...)`. In-process app testing avoids port races. ([Hummingbird testing](https://docs.hummingbird.codes/2.0/documentation/hummingbird/))
- **`SWIFT-TEST-06`** (MUST) Coverage argv: `swift test --enable-code-coverage` (default is disabled), then `llvm-cov export -format=lcov` with one `-object` per test binary (recipe above). `--show-codecov-path` prints the JSON; derive profdata/binary locations rather than hardcoding. Exclude tests and dependencies with `-ignore-filename-regex='(/checkouts/|\.build/|/Tests/|/DerivedSources/)'` or lcov post-filter; exclude generated code by `*.pb.swift`. Paths differ per build system and OS; line-level only. ([llvm-cov export](https://llvm.org/docs/CommandGuide/llvm-cov.html))
- **`SWIFT-TEST-07`** (MUST) New-code coverage >= 70%: loops parses the lcov file (`SF:<path>`, `DA:<line>,<hits>`, `end_of_record`), intersects with `git diff -U0 <base>` added lines in `Sources/**/*.swift` (excluding generated), and fails below 70%; `diff-cover coverage.lcov --compare-branch=<base> --fail-under=70` is the third-party equivalent. Same hard gate as Go, different parser. ([diff-cover](https://github.com/Bachmann1234/diff_cover))
- **`SWIFT-TEST-08`** (AVOID) Property tests: `SwiftCheck` (community, stagnant) or parameterized `@Test` with seeded random inputs; Swift Testing has no built-in property mode. Fuzz: `--sanitize=fuzzer` exists for libFuzzer targets. Mutation: no mature server-side tool (Muter exists, slow); skip by default. Be honest about the ecosystem gap. ([SwiftCheck](https://github.com/typelift/SwiftCheck))
- **`SWIFT-TEST-09`** (SHOULD) Flakiness: inject `Clock`; avoid `Task.sleep` in tests (use `confirmation(expectedCount:)` or `AsyncStream` expectations); run `swift test --repeat-until fail --maximum-repetitions 20` on a suspect Swift Testing test (Swift 6.4, verified in `--help`); set `.timeLimit(.minutes(1))` traits. Swift 6.4 can repeat tests (ST-0024). ([Swift 6.4 release](https://www.swift.org/blog/swift-6.4-released/))
- **`SWIFT-TEST-10`** (SHOULD) TDD loop: `swift test --filter 'DomainTests.OrderTests/testPlace'` (regex on `<target>.<case>/<test>`), `swift test --skip-build` after a build, `swift test list`/`-l` to list; no built-in watch mode (use `watchexec -e swift swift test --filter ...`). Incremental builds reuse `.build/`. Single-test selection is regex based. ([SwiftPM docs](https://docs.swift.org/latest/documentation/packagemanagerdocs/))

## PERF: performance and profiling

- **`SWIFT-PERF-01`** (SHOULD) Benchmark with `ordo-one/package-benchmark` (`swift package benchmark`, thresholds + baselines, mallocs/ARC counters); XCTest `measure {}` is a weak fallback; never time with `Date()` loops. Always benchmark `-c release`. package-benchmark is the de-facto statistical harness. ([package-benchmark](https://github.com/ordo-one/package-benchmark))
- **`SWIFT-PERF-02`** (SHOULD) Profile with `perf` on Linux (`perf record -g .build/release/App`, flame graphs), Valgrind/heaptrack for memory, Instruments on macOS, and `swift-backtrace` for crashes (Linux has no default backtrace on older toolchains; Swift 5.9+ ships backtracing configurable via `SWIFT_BACKTRACE`). No pprof; Linux perf is standard. ([Server guide: building](https://www.swift.org/documentation/server/guides/building.html))
- **`SWIFT-PERF-03`** (MUST) Ship `-c release`; consider `-Xswiftc -cross-module-optimization` (verify with benchmarks) and `--static-swift-stdlib`; avoid existential `any` on hot paths, large struct copies in actors, repeated `String` concatenation, and `Array` copy-on-write surprises (`isKnownUniquelyReferenced`). ARC traffic dominates: look for retain/release in profiles. Debug builds are "significantly slower". ([Building for production](https://www.swift.org/documentation/server/guides/building.html))
- **`SWIFT-PERF-04`** (SHOULD) Use `Foundation` sparingly on Linux (`swift-foundation` is the new fast core); prefer `NIOCore.ByteBuffer`, `Span`/`InlineArray` (Swift 6.2+), and `JSONEncoder` reuse; avoid `String(format:)` and regex on hot paths; pool nothing by hand. Foundation on Linux historically lagged Darwin. ([swift-foundation](https://github.com/swiftlang/swift-foundation))

## SEC: security

- **`SWIFT-SEC-01`** (MUST) Never build SQL by string concatenation. PostgresNIO `PostgresQuery` supports string interpolation where interpolated values become bind parameters; in SQLKit use `\(bind: x)` and `\(ident: x)`; in Fluent use the typed query builder. Process execution: `Subprocess` (1.0 in Swift 6.4) with an argv array, never `sh -c` with user input. Interpolation is safe only through the library's `ExpressibleByStringInterpolation` type. ([PostgresNIO](https://github.com/vapor/postgres-nio))
- **`SWIFT-SEC-02`** (MUST) Decode untrusted input with `Codable` into typed DTOs with size limits (`maxUploadSize`/`collectBody(upTo:)`); avoid `NSKeyedUnarchiver` and `NSCoding` with `requiresSecureCoding = false` (Darwin legacy); XML via `XMLParser` has external-entity risk: disable `shouldResolveExternalEntities`. Codable is schema-bound; keyed unarchive can instantiate arbitrary classes. ([OWASP Deserialization](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html))
- **`SWIFT-SEC-03`** (MUST) Web risks: validate redirect targets against an allowlist; resolve file paths with `URL.standardizedFileURL` and check prefix to stop traversal (Vapor/Hummingbird `FileMiddleware` rejects `..`); block SSRF to link-local/private ranges in AsyncHTTPClient callers; add CORS middleware with explicit origins (`CORSMiddleware`/Hummingbird `CORSMiddleware`) and CSRF protection for cookie sessions. Neither framework enables CORS/CSRF by default. ([OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html))
- **`SWIFT-SEC-04`** (MUST) Crypto: use `swift-crypto` (`import Crypto`, CryptoKit API on Linux) for hashing/AEAD/HMAC; passwords via `Bcrypt` (Vapor) or Argon2 library, never raw SHA; randomness via `SystemRandomNumberGenerator` (cryptographically secure) or `SymmetricKey(size:)`; compare MACs with constant-time APIs; no secrets in source, `.env` committed, or logs. `Insecure.MD5/SHA1` exist for legacy only. ([swift-crypto](https://github.com/apple/swift-crypto))
- **`SWIFT-SEC-05`** (MUST) Validate at the adapter boundary: Vapor `Validatable` (`validations`), Hummingbird `Codable` + custom `init(from:)` or a `Validator`; convert to domain value objects whose `init throws` enforces invariants. Domain stays trusted. ([Vapor Validation](https://docs.vapor.codes/))
- **`SWIFT-SEC-06`** (MUST) Supply chain: commit `Package.resolved`; SwiftPM checks fingerprints (`--resolver-fingerprint-checking strict` default) and warns on signing entity changes (`--resolver-signing-entity-checking warn`); pin by `exact`/revision for critical deps; review `Package.swift` of new deps and build plugins (they run at build time; SwiftPM sandboxes them, do not pass `--disable-sandbox`); never `swift package --allow-writing-to-package-directory` for untrusted plugins. Plugins and macros execute code at build time. ([SwiftPM docs](https://docs.swift.org/latest/documentation/packagemanagerdocs/))
- **`SWIFT-SEC-07`** (SHOULD) SAST: no Swift-first tool is dominant. Use Semgrep (Swift supported), CodeQL (Swift on macOS runners), and SwiftLint security-adjacent rules; the compiler with Swift 6 mode and strict warnings is the main check. Open gap. ([Semgrep Swift](https://semgrep.dev/docs/supported-languages))

## DATA: persistence

- **`SWIFT-DATA-01`** (SHOULD) Choose by framework: Fluent ORM if you use Vapor and accept model-in-domain coupling; PostgresNIO (`PostgresClient`, async, pooled) or SQLKit for Hexagonal services where the repository adapter maps rows to domain types. Keep Fluent `Model` classes in the adapter, never in Domain. Fluent models are `final class` + property wrappers (non-`Sendable`-friendly). ([PostgresNIO](https://github.com/vapor/postgres-nio))
- **`SWIFT-DATA-02`** (MUST) Migrations: Fluent `AsyncMigration` (`prepare`/`revert`, registered with `app.migrations.add`; run `swift run App migrate`) or plain SQL migration files applied by Flyway/golang-migrate/`sqitch` in CI. Keep forward-only in production, expand-contract for zero downtime. Fluent migrations are Swift code tied to the service; SQL tools are language-neutral. ([Fluent migrations](https://docs.vapor.codes/))
- **`SWIFT-DATA-03`** (MUST) Transactions at the application use-case boundary: `PostgresClient.withTransaction { }` / Fluent `database.transaction { }`; pass the transactional connection to repository ports via a unit-of-work port, not a global. Default isolation is `READ COMMITTED`; use `SERIALIZABLE` + retry for invariants. Transactions are closures, which suits scoped resources. ([PostgresNIO](https://github.com/vapor/postgres-nio))
- **`SWIFT-DATA-04`** (MUST) Fluent traps: relations are lazy; use `.with(\.$children)` (eager load) to avoid N+1; `@Parent`/`@Children` fields not loaded throw at access; `Model` classes are not `Sendable`, so map to domain structs before crossing an actor. Fluent has no session/identity map; the N+1 risk is explicit loading. ([Fluent relations](https://docs.vapor.codes/))
- **`SWIFT-DATA-05`** (MUST) Connections: one shared `PostgresClient` (pool) per process, started inside the `ServiceGroup` (`await client.run()`), with `Configuration.options.connectTimeout`, pool min/max sized to core count, and statement timeouts; no per-request connection. PostgresNIO pools and applies backpressure. ([PostgresNIO](https://github.com/vapor/postgres-nio))

## API: APIs and integration

- **`SWIFT-API-01`** (MUST) HTTP framework: Hummingbird 2 (small, async/await, modular, `Router`, `RouterMiddleware`, typed `RequestContext`) or Vapor 4 (batteries included, Fluent, Leaf). Vapor 5 is in beta (Beta 4, 2026-10) so build production on Vapor 4 or Hummingbird. Request lifecycle: NIO channel -> middleware chain -> route handler -> response. Check release status before choosing; Vapor 5 is not GA. ([Hummingbird releases](https://github.com/hummingbird-project/hummingbird/releases))
- **`SWIFT-API-02`** (SHOULD) Contracts: OpenAPI-first with `swift-openapi-generator` (build plugin or committed generated code) plus `swift-openapi-hummingbird`/`-vapor` transports; gRPC with `grpc-swift-2` (async) and swift-protobuf; version via path prefix or content negotiation. Generated sources are not hand-edited. Typed server stubs from the spec. ([swift-openapi-generator](https://github.com/apple/swift-openapi-generator))
- **`SWIFT-API-03`** (MUST) Map domain errors to RFC 9457 problem+json in one error middleware (Hummingbird `HTTPError`/`MiddlewareProtocol`; Vapor `AbortError`/`ErrorMiddleware`); never leak internal error text. Single mapping point at the adapter edge. ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457))
- **`SWIFT-API-04`** (MUST) Resilience: every outbound call has a timeout (AsyncHTTPClient `HTTPClient.Configuration.timeout`, `deadline:`), bounded retries with jittered backoff, idempotency keys on mutating endpoints, rate-limit middleware. No standard circuit-breaker library; write one as an actor. Defaults are lenient. ([async-http-client](https://github.com/swift-server/async-http-client))
- **`SWIFT-API-05`** (SHOULD) Messaging: Kafka via `swift-kafka-client`, NATS via `nats.swift`, AWS SQS/SNS via `aws-sdk-swift` or Soto; RabbitMQ via `rabbitmq-nio`; use the outbox pattern and idempotent consumers (at-least-once). Ecosystem is thin; keep clients behind ports. ([swift-kafka-client](https://github.com/swift-server/swift-kafka-client))
- **`SWIFT-API-06`** (MUST) HTTP client: one long-lived `HTTPClient` (AsyncHTTPClient) or `URLSession` for the process, shut down via `shutdown()`/ServiceGroup; propagate cancellation by structured tasks and set deadlines. On Linux `URLSession` needs `import FoundationNetworking`. Creating a client per request leaks event loops; an un-shutdown `HTTPClient` crashes in debug. ([async-http-client](https://github.com/swift-server/async-http-client))

- **`SWIFT-OPS-01`** (MUST) Config: 12-factor env vars into a typed `Sendable` struct at startup using `swift-configuration` (Apple, providers for env/JSON/reloading) or `swift-argument-parser` + `ProcessInfo`; Hummingbird has `Environment`. - **`SWIFT-OPS-03`** (SHOULD) Native/AOT: Swift compiles ahead of time to a native binary already; no JIT/GraalVM question. Cross-compile with Swift SDKs (`swift sdk install ...`, Static Linux SDK). - **`SWIFT-OPS-06`** (MUST) Artifacts left behind: `.build/` (incl. `.build/out`, `checkouts`, `repositories`, `codecov/`), `.swiftpm/` (Xcode workspace state), `*.profraw`, `*.profdata`, `*.lcov`, `coverage.json`, `Package.resolved` is source (keep), `.netrc`. ## Top 10 footguns

1. Force unwrap, `try!` or an array trap kills the whole process: `guard let`, `.first`, `try` with a mapped error.
2. Blocking the cooperative pool (`semaphore.wait()`, sync DB or file I/O in `async`): async clients, `Task.sleep(for:)`, `NIOThreadPool`.
3. Silencing Sendable errors with `@unchecked Sendable` or `nonisolated(unsafe)` and no lock: use an `actor` or `Mutex`, keep TSan in the gate.
4. Staying in Swift 5 mode to get green (`.swiftLanguageMode(.v5)`): migrate per target with `swift package migrate`, log any override.
5. Unstructured `Task {}` or `Task.detached` for request work loses cancellation and errors: `async let`, `TaskGroup`, `ServiceGroup` for background work.
6. Retain cycles from escaping closures capturing `self`: `[weak self]`, or struct and actor designs.
7. Shipping a debug build: `swift build -c release`.
8. `branch:` dependencies or an uncommitted `Package.resolved`: `from:`, commit the lockfile, build with `--force-resolved-versions`.
9. A shared `DateFormatter` and non-UTC dates: `Date.FormatStyle` with an explicit time zone.
10. The Domain target importing a framework (`Vapor`, `Fluent`, NIO): Domain `dependencies: []`, `--explicit-target-dependency-import-check error`, Fluent models stay in the adapter.
