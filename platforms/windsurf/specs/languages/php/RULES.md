# PHP Rules

Citable rule book for PHP backends (PHP 8.2-8.5, PHPUnit 12/13, Composer 2, Laravel 13, Symfony 7.4/8.1), as of 2026-11. Source: `research/languages/php.md` (verified, with its rule IDs kept). The toolchain data is `specs/languages/php/pack.json`.

Cite by ID (`PHP-SEC-03`). Universal rules live elsewhere: architecture in `specs/ARCHITECTURE.md`, SOLID in `specs/SOLID.md`, and the run protocol in `specs/WORKFLOW.md`. The project's own configs (`phpstan.neon*`, `.php-cs-fixer*.php`, `pint.json`, `phpunit.xml*`, `deptrac.*`) and framework conventions win over a rule here; log every override with `loops run override` (WORKFLOW §1).

Row format: ID, severity, rule, why, source. A trailing `[XXX-nn]` is the neutral taxonomy rule the row specialises.

## REPO: repository and project management

- **`PHP-REPO-01`** (MUST) Keep one `composer.json` per deployable at the repo root; sources in `src/` (PSR-4 `App\`), tests in `tests/` (PSR-4 `autoload-dev`), public entry only `public/index.php`; keep `vendor/` and runtime dirs out of VCS. [REPO-01] Composer autoload maps a namespace prefix to a directory; a web root that exposes only `public/` keeps source and `.env` unreachable. ([Composer basic usage](https://getcomposer.org/doc/01-basic-usage.md))
- **`PHP-REPO-02`** (SHOULD) In a monorepo use one root `composer.json` with `path` repositories (or a splitter such as symplify/monorepo-builder) per package; never share `vendor/` between deployables. [REPO-02] Composer has no native workspaces; `path` repos symlink local packages and keep lock resolution honest. ([Composer repositories](https://getcomposer.org/doc/05-repositories.md))
- **`PHP-REPO-03`** (SHOULD) Bootstrap with the official starter, not hand-rolled: `composer create-project laravel/laravel app`, `symfony new app` (or `composer create-project symfony/skeleton`), or `composer init` for a framework-free service; day-one files: lock, PHPUnit config, PHPStan config, CS config, CI, `.editorconfig`, `.env.example`. [REPO-03] Starters carry the framework's blessed layout and security defaults. ([Symfony best practices](https://symfony.com/doc/current/best_practices.html))
- **`PHP-REPO-04`** (MUST) Commit `composer.lock` for applications and libraries alike; CI and deploys run `composer install` (never `update`); upgrade deliberately with `composer update vendor/pkg`. [REPO-04] `install` reproduces the exact lock; `update` resolves anew and changes the world. ([Composer basic usage](https://getcomposer.org/doc/01-basic-usage.md))
- **`PHP-REPO-05`** (MUST) Declare the production runtime in `config.platform.php` (and `ext-*` you need) so the resolver matches production; pair with `composer check-platform-reqs` in CI. [REPO-04] Faking the platform stops Composer picking packages your prod PHP cannot run, but it also hides real mismatches; verify both. ([Composer config: platform](https://getcomposer.org/doc/06-config.md))
- **`PHP-REPO-06`** (MUST) Use `require` for runtime and `require-dev` for tooling; set `config.sort-packages: true`; use caret constraints (`^8.3`), never `*` or `dev-main` in applications; run `composer validate --strict` in CI. [REPO-04] Stable diffs, no accidental dev dependencies in production, schema errors caught early. ([Composer config](https://getcomposer.org/doc/06-config.md))
- **`PHP-REPO-07`** (MUST) Allow Composer plugins explicitly: set `config.allow-plugins` to an object listing only the plugins you trust; never `true`. [REPO-04] [SEC-06] Plugins and scripts execute code at install time; default is deny-all since Composer 2.2. ([Composer config: allow-plugins](https://getcomposer.org/doc/06-config.md))
- **`PHP-REPO-08`** (SHOULD) Automate dependency updates with Renovate or Dependabot (`composer` ecosystem); group dev tools separately; remove unused packages with `composer-unused` and find undeclared usage with `composer-require-checker`. [REPO-04] Keeps the lock fresh and the dependency graph honest. ([composer-unused](https://github.com/composer-unused/composer-unused))
- **`PHP-REPO-09`** (SHOULD) Libraries: SemVer tags `vX.Y.Z` on Git; Packagist reads the tag (no `version` key in `composer.json`); keep `CHANGELOG.md` (Keep a Changelog); applications tag releases and build an immutable artifact. [REPO-05] Packagist derives versions from VCS tags; a `version` field causes conflicts. ([Composer schema: version](https://getcomposer.org/doc/04-schema.md))
- **`PHP-REPO-10`** (SHOULD) Pin the PHP version for contributors with `.php-version` or `.tool-versions` (asdf/mise/phpenv) and keep it equal to `config.platform.php` and the Docker base image tag. [REPO-06] One version across laptop, CI and prod removes "works on 8.4" bugs. ([Composer config: platform](https://getcomposer.org/doc/06-config.md))
- **`PHP-REPO-11`** (MUST) Git-ignore `/vendor/`, `.env` (commit `.env.example`), `/.phpunit.cache/`, `.phpunit.result.cache`, `.php-cs-fixer.cache`, `/var/`, `/storage/*.key`, `/bootstrap/cache/*.php`, `/coverage/`; set `*.php text eol=lf` and `export-ignore` for tests in `.gitattributes`. [REPO-07] Prevents committing third-party code, secrets and build output. ([Composer basic usage](https://getcomposer.org/doc/01-basic-usage.md))
- **`PHP-REPO-12`** (SHOULD) CI stages, in order: `composer validate --strict` -> `composer install --no-interaction --prefer-dist` -> CS check -> PHPStan -> `deptrac analyse` -> PHPUnit with coverage -> `composer audit --locked`; matrix over supported PHP minors (8.3, 8.4, 8.5) and `--prefer-lowest` for libraries. [REPO-08] Fails fast on the cheap checks and proves the declared constraint range. ([PHP supported versions](https://www.php.net/supported-versions.php))
- **`PHP-REPO-13`** (SHOULD) Cache `COMPOSER_CACHE_DIR` (the Composer download cache, key on `composer.lock` hash), not `vendor/`; use `actions/cache` or the CI equivalent. [REPO-08] The download cache is safe to share across jobs; a cached `vendor/` can mask a missing lock change. ([Composer CLI: COMPOSER_CACHE_DIR](https://getcomposer.org/doc/03-cli.md))
- **`PHP-REPO-14`** (SHOULD) Conventional commits drive the CHANGELOG/tag; the loops branch and commit rules apply unchanged. [REPO-09] Neutral process rule. ([Conventional Commits 1.0](https://www.conventionalcommits.org/en/v1.0.0/))

## TOOL: toolchain

- **`PHP-TOOL-01`** (MUST) Target PHP 8.4 or 8.5 for new services (8.3 minimum; Laravel 13 needs 8.3+, PHPUnit 13 needs 8.4+). Do not start on 8.2: security support ends 2026-12-31. Cadence: one minor every November. Install through the distro/Docker `php:8.x-cli` image, `mise`/`asdf`, or `shivammathur/setup-php` in CI. [TOOL-01] Support windows as of 2026-11: 8.2 sec to 2026-12-31; 8.3 sec to 2027-12-31; 8.4 sec to 2028-12-31; 8.5 sec to 2029-12-31. ([PHP supported versions](https://www.php.net/supported-versions.php))
- **`PHP-TOOL-02`** (MUST) Format with PER Coding Style (the successor of PSR-12; PER-CS 3.1 "extends, expands and replaces" it) using PHP-CS-Fixer `@PER-CS` (config `.php-cs-fixer.dist.php`; check: `vendor/bin/php-cs-fixer check --diff`, fix: `fix`) or Laravel Pint (`vendor/bin/pint --test`). Pick one formatter per repo. [TOOL-02] A single machine-enforced style ends style review noise; PER-CS requires PSR-1, 4 spaces, LF, soft 120 col. ([PER Coding Style](https://www.php-fig.org/per/coding-style/), [PHP-CS-Fixer](https://cs.symfony.com/))
- **`PHP-TOOL-03`** (AVOID) Use PHP_CodeSniffer only where a team already has a `phpcs.xml` ruleset (e.g. Slevomat, WordPress); do not run it alongside PHP-CS-Fixer on the same rules. [TOOL-03] PHPCS reports, PHP-CS-Fixer fixes; two fixers fight each other. ([PHP_CodeSniffer](https://github.com/PHPCSStandards/PHP_CodeSniffer))
- **`PHP-TOOL-04`** (MUST) Run PHPStan (levels 0-10; 10 stricter than `max` of 9 in older versions; `--level max` tracks the highest) at level 8 or higher for new code, level 6 minimum for legacy with a generated baseline: `vendor/bin/phpstan analyse --no-progress --memory-limit=1G`. [TOOL-04] Level 6 requires typehints, 8 handles nullables, 9-10 strict `mixed`; the baseline lets old code pass while new code is held to the bar. ([PHPStan rule levels](https://phpstan.org/user-guide/rule-levels), [PHPStan CLI](https://phpstan.org/user-guide/command-line-usage))
- **`PHP-TOOL-05`** (SHOULD) Regenerate the baseline only to shrink it (`phpstan analyse --generate-baseline`); never baseline an error you introduced; commit `phpstan-baseline.neon`; add framework extensions (`larastan/larastan`, `phpstan/phpstan-symfony`, `phpstan-doctrine`) and `phpstan-strict-rules` / `phpstan-deprecation-rules`. [TOOL-04] A growing baseline is hidden debt; framework magic is invisible to PHPStan without the extension. ([PHPStan CLI: baseline](https://phpstan.org/user-guide/command-line-usage))
- **`PHP-TOOL-06`** (SHOULD) Psalm is an alternative to PHPStan, not an addition: levels 1 (strictest) to 8, default 2; if a repo already has `psalm.xml`, follow it (project rules win), otherwise use PHPStan. [TOOL-04] Two analysers duplicate findings; Psalm's lower number means stricter, the opposite of PHPStan. ([Psalm error levels](https://psalm.dev/docs/running_psalm/error_levels/))
- **`PHP-TOOL-07`** (SHOULD) Use Rector for upgrades and refactors (`vendor/bin/rector process --dry-run` in CI, `process` locally, `rector.php` with `withPaths`/prepared sets); never run it unattended on the whole tree without a green baseline. [TOOL-03] Automated PHP-version and framework upgrades are the safest way to adopt new syntax; wrong sets rewrite behaviour. ([Rector docs](https://getrector.com/documentation))
- **`PHP-TOOL-08`** (MUST) Scan dependencies with `composer audit --locked` (exit 1 on advisories; formats plain, json, summary, table; `--abandoned` takes fail, report or ignore); keep `config.policy.advisories.block` at its default `true` (the legacy `audit.block-insecure` key is deprecated in its favour). [TOOL-05] Composer queries the Packagist/FriendsOfPHP advisory data; abandoned packages fail by default since 2.7. ([Composer CLI: audit](https://getcomposer.org/doc/03-cli.md), [Composer config: audit](https://getcomposer.org/doc/06-config.md))
- **`PHP-TOOL-09`** (SHOULD) Generate an SBOM with `cyclonedx/cyclonedx-php-composer` (`composer CycloneDX:make-sbom`) and enforce licenses with `composer licenses` or `composer-license-checker`. [TOOL-05] Supply-chain evidence for release artifacts. ([CycloneDX PHP Composer](https://github.com/CycloneDX/cyclonedx-php-composer))
- **`PHP-TOOL-10`** (SHOULD) Editor baseline: Intelephense or Phpactor as LSP; enable PHPStan in the editor with the same `phpstan.neon`; make format-on-save call PHP-CS-Fixer/Pint only, and disable the LSP's own PSR-12 formatter. [TOOL-06] A second formatter reformats on save and produces churn against the CI check. ([Intelephense](https://intelephense.com/))

## ARCH: architecture

- **`PHP-ARCH-01`** (SHOULD) Default to a modular monolith with hexagonal modules (`src/<Module>/{Domain,Application,Infrastructure,Http}`); extract a service only along a module boundary that already has no shared tables. [ARCH-01] PHP request model scales horizontally by process; the cost is in boundaries, not in runtime. ([Symfony best practices](https://symfony.com/doc/current/best_practices.html))
- **`PHP-ARCH-02`** (MUST) Layer dependency direction: `Http`/`Console` -> `Application` -> `Domain`; `Infrastructure` -> `Application` (implements its ports) and `Domain`; `Domain` depends on nothing but PHP core and other domain code. [ARCH-02] Same dependency rule as loops, expressed with PSR-4 namespaces. ([Deptrac](https://deptrac.github.io/deptrac/), [Cosmic Python: ports and adapters](https://www.cosmicpython.com/book/chapter_02_repository.html))
- **`PHP-ARCH-03`** (MUST) Map imports to layers by namespace prefix (PSR-4): one class per file, file path = FQCN minus the prefix; read dependencies from `use` statements (`use A\B\C;`, `use function`, `use const`, grouped `use A\{B, C};`) and from fully-qualified names in code. [ARCH-03] PSR-4 is the autoloading standard; the arch checker resolves a `use` string to a directory with the `composer.json` psr-4 map. ([PSR-4](https://www.php-fig.org/psr/psr-4/))
- **`PHP-ARCH-04`** (MUST) Know PHP visibility: `public`/`protected`/`private` per member, `final` classes by default for application code, `readonly` and `private(set)` for state; there is no package-private, so layer boundaries are enforced by tooling, not the language; cycles between namespaces are legal in PHP and must be forbidden by deptrac. [ARCH-03] Autoloading makes cycles compile; only a checker catches them. ([PHP 8.4 release](https://www.php.net/releases/8.4/en.php))
- **`PHP-ARCH-05`** (MUST) Enforce layers with deptrac: `vendor/bin/deptrac analyse` with layers defined by namespace collectors and rulesets (`Application` accesses `Domain`; `Domain` accesses nothing); fail the build on violations and on unassigned classes. Alternatives: PHPat (PHPStan extension) or `phparkitect`. [ARCH-04] Maps 1:1 to `loops arch`; deptrac is the de-facto PHP tool. Config format (`deptrac.php` is the current default per the docs, `deptrac.yaml` the older format). ([Deptrac](https://deptrac.github.io/deptrac/), [phparkitect](https://github.com/phparkitect/arkitect))
- **`PHP-ARCH-06`** (MUST) Wire dependencies with constructor injection and the framework container only at the composition root (Symfony autowire/`services.yaml`, Laravel service providers); never inject the container, call `app()`/`Container::get()` or facades from domain or application code (service locator). [ARCH-05] Locators hide dependencies, break tests and are unsafe under worker-mode servers. ([Symfony best practices: services](https://symfony.com/doc/current/best_practices.html), [Laravel Octane DI](https://laravel.com/docs/13.x/octane))
- **`PHP-ARCH-07`** (MUST) Keep the domain pure: no `new DateTimeImmutable()`/`time()`/`date()` without an injected `ClockInterface` (PSR-20) or app `Clock` port; no `random_int`/`uniqid`/`mt_rand` inline (inject an id/random port); no `$_ENV`/`$_SERVER`/`getenv()`, `file_get_contents`, `curl_*`, PDO, Eloquent or Doctrine ORM imports. [ARCH-06] Betrays impurity and makes tests time-dependent. ([PSR-20 Clock](https://www.php-fig.org/psr/psr-20/))
- **`PHP-ARCH-08`** (SHOULD) Define ports as small `interface`s in the consuming layer (`Application\Port\Clock`), named by capability not technology; adapters implement them; prefer PSR interfaces for cross-cutting ones (PSR-3 logger, PSR-6/16 cache, PSR-7/17/18 HTTP, PSR-11 container, PSR-14 events, PSR-20 clock). [ARCH-07] Consumer-owned ports are loops policy; PSRs give portable seams. ([PHP-FIG PSRs](https://www.php-fig.org/psr/))
- **`PHP-ARCH-09`** (SHOULD) SOLID sizing heuristics: classes <= 300 lines and one reason to change; methods <= 30 lines; <= 4 constructor params (group into a value object beyond that); no abstract base "god" classes; prefer composition over `extends`, interfaces over traits for behaviour; mark classes `final`. [ARCH-08] PHP lets inheritance and traits grow without friction. ([Deptrac](https://deptrac.github.io/deptrac/), [PER Coding Style](https://www.php-fig.org/per/coding-style/))
- **`PHP-ARCH-10`** (SHOULD) Laravel: do not call Eloquent (`User::find()`, `->save()`) from the domain or application layer; wrap it in a repository adapter that maps Eloquent rows to domain objects; treat `app/Models` as infrastructure. Symfony: keep Doctrine mapping separate or attribute-only on entities, flush only in an application-layer unit-of-work. [ARCH-01] [FW-02] Active Record fuses entity and persistence; Data Mapper separates them. ([Laravel structure](https://laravel.com/docs/12.x/structure))

## IDIOM: what to do and what to avoid

- **`PHP-IDIOM-01`** (MUST) Put `declare(strict_types=1);` in every PHP file (after `<?php`, before `namespace`), and enforce it with PHP-CS-Fixer `declare_strict_types`; throw exceptions, never return `false`/`null` as an error signal in your own code; wrap with context via `previous: $e`; one exception hierarchy rooted at an app base class; catch the narrowest type, never bare `catch (\Throwable)` without rethrow/log. [IDIOM-01] Strict types stop silent scalar coercion; PER-CS defines the declaration's position; `Error`s and `Exception`s both implement `Throwable`. ([PER Coding Style](https://www.php-fig.org/per/coding-style/), [PHP exceptions](https://www.php.net/manual/en/language.error-handling.php))
- **`PHP-IDIOM-02`** (MUST) Never use `@` error suppression; convert PHP warnings/notices to exceptions (`set_error_handler` that throws `ErrorException`, as frameworks do) and run with `error_reporting=E_ALL`. [IDIOM-01] The silence operator hides real failures; PHP 8 promoted many warnings to `Error`s. ([OWASP PHP config](https://cheatsheetseries.owasp.org/cheatsheets/PHP_Configuration_Cheat_Sheet.html))
- **`PHP-IDIOM-03`** (MUST) Use nullable types (`?T`, or a union with `null`) explicitly; never default a typed param to `null` implicitly (`string $x = null` is deprecated in 8.4, write `?string $x = null`); use the null-safe operator `?->` and `??`/`??=`; prefer a Null Object or an empty value object over returning `null` from services. [IDIOM-02] Implicitly nullable params are deprecated since 8.4; null chains are the top source of `TypeError`. ([PHP 8.4 release](https://www.php.net/releases/8.4/en.php))
- **`PHP-IDIOM-04`** (SHOULD) Model values as `final readonly class` (8.2+) with promoted constructor properties; use `readonly` properties for entities' identity; in 8.4+ use asymmetric visibility (`public private(set)`) instead of private-plus-getter; in 8.5 use `clone($this, [...])` for with-ers. [IDIOM-03] Immutable value objects remove aliasing bugs; 8.4/8.5 shrink the boilerplate. ([PHP 8.4 release](https://www.php.net/releases/8.4/en.php), [PHP 8.5 release](https://www.php.net/releases/8.5/en.php))
- **`PHP-IDIOM-05`** (SHOULD) Replace class constants and magic strings with backed `enum`s (8.1+); give them methods and `tryFrom()` at the boundary; use `match` (exhaustive, strict comparison, throws `UnhandledMatchError`) instead of `switch`. [IDIOM-04] `switch` uses loose `==`; `match` is strict and exhaustive; enums are typed sets. ([PHP enumerations](https://www.php.net/manual/en/language.enumerations.php))
- **`PHP-IDIOM-06`** (MUST) Type everything: parameter, return and property types on every method (use `mixed` only deliberately), union/intersection types, `never`, `static`, `void`; document generics and array shapes with PHPDoc (`list<Foo>`, `array{id:int}`, `@template`) because PHP has no runtime generics. [IDIOM-04] The type system has no generics, so PHPStan reads PHPDoc as the type language. ([PHPStan rule levels](https://phpstan.org/user-guide/rule-levels))
- **`PHP-IDIOM-07`** (MUST) Compare with `===`/`!==`; pass `true` as the strict flag to `in_array`/`array_search`; avoid `==` on strings and numbers; validate numeric strings with `filter_var`/`ctype_digit` or `is_numeric` plus range. [IDIOM-06] Type juggling: `"abc" == 0` and `"0e123" == "0e456"` bugs, and magic-hash auth bypasses; PHP 8 changed `0 == "a"` to false but string-to-string numeric comparisons still juggle. ([PHP comparison operators](https://www.php.net/manual/en/language.operators.comparison.php))
- **`PHP-IDIOM-08`** (MUST) Use `DateTimeImmutable` with an explicit `DateTimeZone('UTC')` and ISO-8601 strings across boundaries; never `date()`/`strtotime()` for business logic; use `Clock` (PSR-20) to get "now"; use `mb_*` functions and UTF-8 for text; use `bcmath`/`brick/math` or integer minor units for money, never `float`. [IDIOM-06] Mutable `DateTime` aliasing, server-timezone dependence and float rounding are classic PHP production bugs. ([PHP DateTimeImmutable](https://www.php.net/manual/en/class.datetimeimmutable.php))
- **`PHP-IDIOM-09`** (SHOULD) Release resources deterministically: `try/finally` for files, locks and transactions; unset or close large handles; do not rely on `__destruct` for correctness; with PDO, close by dropping references; in long-running workers avoid growing statics and open handles. [IDIOM-05] PHP frees at request end, but workers and CLI jobs run for days. ([FrankenPHP worker](https://frankenphp.dev/docs/worker/))
- **`PHP-IDIOM-10`** (SHOULD) Follow PER-CS naming: `StudlyCaps` classes, `camelCase` methods/properties, `UPPER_SNAKE` constants; one class per file; interfaces without `Interface` suffix is optional but be consistent per repo; PHPDoc only where types do not already say it; mark overrides `#[\Override]` (8.3+); mark deprecations `#[\Deprecated]` (8.4+) and ignorable returns `#[\NoDiscard]` (8.5). [IDIOM-07] `#[\Override]` catches silent signature drift. ([PER Coding Style](https://www.php-fig.org/per/coding-style/), [PHP 8.5 release](https://www.php.net/releases/8.5/en.php))
- **`PHP-IDIOM-11`** (AVOID) Avoid dynamic metaprogramming in business code: no evaluating strings as PHP code, no `extract`, variable-variables, `$$x`, `__call`/`__get` magic without `@method`/`@property` annotations, no `compact`/`extract` for data flow; use attributes (`#[Route]`, `#[ORM\Entity]`) for framework metadata and keep reflection in adapters. [IDIOM-08] Magic defeats static analysis and IDEs. ([PHPStan rule levels](https://phpstan.org/user-guide/rule-levels))
- **`PHP-IDIOM-12`** (SHOULD) Prefer first-class callable syntax (`strlen(...)`, `$this->handle(...)`) over string/array callables; use `array_map`/generators for pipelines; use property hooks (8.4) only for trivial validation/derivation, never to hide IO or heavy work. [IDIOM-04] Callables as strings cannot be analysed; hooks run on every access. ([PHP 8.4 release](https://www.php.net/releases/8.4/en.php))

## CONC: concurrency and the `-race` equivalent

- **`PHP-CONC-01`** (MUST) Know the model: PHP-FPM/Apache is shared-nothing (one request = one fresh PHP context; state dies at request end); CLI scripts are single-threaded; long-running servers (FrankenPHP worker, RoadRunner, Swoole/OpenSwoole, ReactPHP, Amp) keep the application in memory across requests; Fibers (8.1+) give cooperative multitasking in one thread. There is no GIL-like threading problem; the hazard is leaked state. [CONC-01] Different model = different bug class: no data races in FPM, state leaks in workers. ([FrankenPHP worker](https://frankenphp.dev/docs/worker/), [PHP Fibers](https://www.php.net/manual/en/language.fibers.php))
- **`PHP-CONC-02`** (MUST) In worker mode, treat static properties, globals, singletons, in-memory caches, `ini_set`, `chdir`, timezone, `setlocale`, seeded RNG and default stream context as process-global and persistent; reset engine state each loop (`error_clear_last()`, `libxml_clear_errors()`, `http_clear_last_response_headers()` 8.4+); give request-scoped Symfony services `ResetInterface`. [CONC-02] These persist across requests in FrankenPHP and cause cross-user data leaks. ([FrankenPHP worker](https://frankenphp.dev/docs/worker/))
- **`PHP-CONC-03`** (MUST) Under Laravel Octane never inject the container, the `Request` or the config repository into a singleton's constructor; pass request data as method arguments or resolve lazily via closure; never append to a static array (memory leak); set `--max-requests` (default 500) as a safety net, not a fix. [CONC-02] Octane boots once; stale container/request in singletons leaks one user's data to the next. ([Laravel Octane](https://laravel.com/docs/13.x/octane))
- **`PHP-CONC-04`** (MUST) Race detection: none exists. Substitute checks: random order (`--order-by=random`, record `--random-order-seed`), parallel runs via ParaTest (each process gets `TEST_TOKEN`/`UNIQUE_TEST_TOKEN` for per-process DB/schema), `--process-isolation` for suspected global-state tests, repeating a suspect test N times. Do not claim "race-free" from a green run. [CONC-03] [CONC-04] Parallel+random exposes order dependence and shared-fixture bugs, the PHP equivalent of what `-race` finds in Go. ([PHPUnit textui](https://docs.phpunit.de/en/12.5/textui.html), [ParaTest](https://github.com/paratestphp/paratest))
- **`PHP-CONC-05`** (MUST) Async/event-loop code (ReactPHP, Amp v3 on Fibers, Swoole coroutines): never call blocking functions (`sleep`, `file_get_contents` on URLs, sync PDO/curl) inside the loop; use the library's non-blocking clients; apply timeouts and cancellation tokens; Swoole coroutines must not share a single PDO/Redis connection between coroutines (use a pool). [CONC-05] One blocked call stalls every coroutine in the worker. ([Laravel Octane: Swoole](https://laravel.com/docs/13.x/octane))
- **`PHP-CONC-06`** (MUST) Background work: use a queue (Symfony Messenger with `messenger:consume`, Laravel queues/Horizon) with a process supervisor (Supervisor/systemd/k8s); jobs must be idempotent; set `--time-limit`/`--memory-limit`/`--limit` so workers recycle, and handle SIGTERM for graceful stop (`stopwaitsecs`). [CONC-06] Workers are long-lived PHP processes that leak and must restart cleanly. ([Laravel Octane: supervisor](https://laravel.com/docs/13.x/octane), [Symfony Messenger](https://symfony.com/doc/current/messenger.html))
- **`PHP-CONC-07`** (MUST) Share nothing in tests: reset static state (`Mockery::close()`, clear singletons, `Carbon::setTestNow()` reset), use a transaction or schema per test/process, and never depend on test execution order. [CONC-02] [TEST-09] PHPUnit runs all tests in one process unless isolated. ([PHPUnit textui](https://docs.phpunit.de/en/12.5/textui.html))

## TEST: testing

- **`PHP-TEST-01`** (SHOULD) Use PHPUnit 12/13 (or Pest 4 on top of it) for unit and integration tests; use the framework test kit for HTTP (`Symfony\WebTestCase`/`KernelTestCase`, Laravel `Tests\TestCase` feature tests); keep browser E2E (Panther, Dusk, Playwright) out of the unit gate. [TEST-01] PHPUnit 12 supports PHP 8.3+, 13 requires 8.4+ (released 2026-02-06). ([PHPUnit supported versions](https://phpunit.de/supported-versions.html))
- **`PHP-TEST-02`** (MUST) Layout: `tests/Unit`, `tests/Integration`, `tests/Functional` (Symfony) or `tests/Feature` (Laravel) mirroring `src/`; files named `*Test.php`, classes `FooTest extends TestCase`, methods `test*` or `#[Test]`; globs `tests/**/*Test.php`. [TEST-02] PHPUnit discovers `*Test.php` by default; tests are never in the PSR-4 `autoload` map. ([Laravel structure](https://laravel.com/docs/12.x/structure), [PHPUnit textui](https://docs.phpunit.de/en/12.5/textui.html))
- **`PHP-TEST-03`** (SHOULD) Use `#[DataProvider]` (static public method returning iterable with named cases) for table tests; Pest: `->with([...])`; AAA structure; names describe behaviour (`test_rejects_expired_token`). [TEST-03] PHPUnit 12 attributes replaced `@dataProvider` annotations. ([Symfony best practices: tests](https://symfony.com/doc/current/best_practices.html))
- **`PHP-TEST-04`** (SHOULD) Prefer hand-written fakes (in-memory repository, fixed `Clock`) over mocks; use PHPUnit's `createStub`/`createMock` or Mockery/Prophecy only at true boundaries; never mock the class under test, value objects or the ORM. [TEST-04] Mocks of internal collaborators lock in implementation. ([PHPUnit docs](https://docs.phpunit.de/))
- **`PHP-TEST-05`** (SHOULD) Integration tests use a real database (MySQL/Postgres container via Testcontainers-PHP, docker compose service, or SQLite only if prod is SQLite); isolate per test with a transaction rollback (`DatabaseTransactions`, DAMA DoctrineTestBundle) or `RefreshDatabase`/migrations once per run; per ParaTest process use `TEST_TOKEN` in the DB name. [TEST-05] SQLite-for-MySQL hides dialect bugs; shared DBs break under parallelism. ([ParaTest](https://github.com/paratestphp/paratest))
- **`PHP-TEST-06`** (MUST) Coverage: install PCOV (`pecl install pcov`) or Xdebug 3; run `XDEBUG_MODE=coverage vendor/bin/phpunit --coverage-cobertura <file>`; PCOV is line-only, branch and path coverage (`--path-coverage`) need Xdebug; disable ignore comments in CI with `--disable-coverage-ignore`; exclude generated code via `<source><exclude>` or `#[CodeCoverageIgnore]`/`@codeCoverageIgnore`. [TEST-06] Without a driver PHPUnit prints "no code coverage driver is available" and writes nothing. ([PHPUnit code coverage](https://docs.phpunit.de/en/12.5/code-coverage.html), [PHPUnit CLI](https://docs.phpunit.de/en/12.5/cli-options.html))
- **`PHP-TEST-07`** (MUST) Enforce >= 70% coverage of new lines: loops parses Cobertura (default path chosen by loops, e.g. `{coverage}`) and the git diff itself; `diff-cover coverage.xml --compare-branch=origin/main --fail-under=70` is an equivalent external check; Pest has `--min=N` for total coverage only (not new code). [TEST-07] Total-coverage gates reward old code; the loops hard gate is about changed lines. ([Pest coverage](https://pestphp.com/docs/test-coverage))
- **`PHP-TEST-08`** (SHOULD) Add `--strict-coverage` (risky if code outside `#[CoversClass]/#[UsesClass]` runs) only for libraries; property testing with `eris/eris` or `giorgiosironi/eris`; mutation testing with Infection (`vendor/bin/infection --min-msi=70 --threads=max`) on domain code, not whole app. [TEST-08] Mutation score catches tests that never assert; strict coverage is noisy on apps. ([Infection](https://infection.github.io/))
- **`PHP-TEST-09`** (MUST) Fail on flaky signals: `--fail-on-warning --fail-on-risky --fail-on-deprecation`, `--order-by=random --random-order-seed=<n>`, inject `Clock`, use `Carbon::setTestNow`/`ClockMock` and seeded RNG, set `failOnWarning`/`beStrictAboutOutputDuringTests`/`beStrictAboutTestsThatDoNotTestAnything` in `phpunit.xml`. [TEST-09] Strict config makes a vacuous or noisy test fail the build. ([PHPUnit CLI](https://docs.phpunit.de/en/12.5/cli-options.html), [PHPUnit textui](https://docs.phpunit.de/en/12.5/textui.html))
- **`PHP-TEST-10`** (SHOULD) TDD loop: `vendor/bin/phpunit --filter=FooTest::testBar`, `--group`, `--testdox`, `--stop-on-failure`, `--order-by=defects` (rerun failures first; needs the result cache); Pest `--watch`/`--parallel`; Laravel `php artisan test --parallel`. [TEST-10] Fast feedback; keep `.phpunit.cache` between runs locally. ([PHPUnit CLI](https://docs.phpunit.de/en/12.5/cli-options.html))
- **`PHP-TEST-11`** (SHOULD) Pest is an acceptable alternative front end to PHPUnit (same engine, same coverage drivers, `pest --coverage --min=N --coverage-cobertura <file>`); a repo uses one; project rules win. [TEST-01] Many Laravel codebases use Pest; coverage flags are compatible. ([Pest coverage](https://pestphp.com/docs/test-coverage))

## PERF: performance and profiling

- **`PHP-PERF-01`** (SHOULD) Benchmark with PHPBench (`vendor/bin/phpbench run --report=aggregate`, `--ref` baseline) for hot code; compare against a stored baseline, not a single run. [PERF-01] PHPBench gives statistically grouped iterations. ([PHPBench](https://phpbench.readthedocs.io/))
- **`PHP-PERF-02`** (SHOULD) Profile with Xdebug profiler (`xdebug.mode=profile`), Blackfire, or SPX/XHProf; use continuous profiling (Blackfire, Pyroscope, Datadog) in production; never leave Xdebug loaded in production. [PERF-02] Xdebug slows PHP several-fold; profilers must be sampled. ([Xdebug docs](https://xdebug.org/docs/))
- **`PHP-PERF-03`** (MUST) Production runtime: enable OPcache (`opcache.enable=1`, `opcache.validate_timestamps=0` with deploy-time reset, `opcache.memory_consumption` sized), preloading only if measured, JIT only for CPU-bound code; install with `composer install --no-dev --optimize-autoloader --classmap-authoritative` (or `-o -a`). [PERF-03] Classmap-authoritative autoloading removes filesystem lookups; OPcache removes recompilation. ([Composer CLI: install](https://getcomposer.org/doc/03-cli.md), [OPcache](https://www.php.net/manual/en/book.opcache.php))
- **`PHP-PERF-04`** (SHOULD) Avoid hot-path traps: N+1 queries, `array_merge` in loops (use `[...$a, ...$b]`/`yield`), loading whole result sets (use generators/`cursor()`/`toIterable()`), `in_array` on large arrays (use keyed arrays), regex in loops, repeated `json_decode`; stream large files with `SplFileObject`/generators. [PERF-04] Memory limit and per-request CPU are the common ceilings. ([Laravel Eloquent](https://laravel.com/docs/13.x/eloquent))
- **`PHP-PERF-05`** (SHOULD) Worker-mode servers (FrankenPHP, RoadRunner, Octane) remove per-request bootstrap; adopt only with the CONC-02/03 rules and a leak test; set `MAX_REQUESTS`/`--max-requests` and `gc_collect_cycles()` per loop. [PERF-03] Big win, big state-leak risk. ([FrankenPHP worker](https://frankenphp.dev/docs/worker/))

## SEC: security

- **`PHP-SEC-01`** (MUST) Use PDO prepared statements with bound parameters (`$pdo->prepare('... WHERE name = :name'); $stmt->execute([':name' => $v])`), set `PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION` and `PDO::ATTR_EMULATE_PREPARES => false`; never concatenate or interpolate input; allow-list identifiers and sort directions (map to fixed strings); ORMs: use bound parameters, avoid `whereRaw`/`DB::raw`/DQL string building with input. [SEC-01] Parameter markers bind values only; identifiers cannot be bound. ([OWASP SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html))
- **`PHP-SEC-02`** (MUST) Never `unserialize()` untrusted input (even with `allowed_classes`); use `json_decode($s, true, 512, JSON_THROW_ON_ERROR)`; if you must unserialize stored data, verify an HMAC first (`hash_equals`) and pass `['allowed_classes' => false]` or a fixed list; prefer `__serialize()/__unserialize()` over `__sleep/__wakeup` (soft-deprecated in 8.5). Disable external entities for XML (`LIBXML_NONET`, never `LIBXML_NOENT`). [SEC-02] Object injection gadget chains (POP) in `unserialize` lead to RCE; PHP warns `allowed_classes` does not make it safe. ([PHP unserialize](https://www.php.net/manual/en/function.unserialize.php), [OWASP Deserialization](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html))
- **`PHP-SEC-03`** (MUST) Avoid command and code execution: no evaluating strings as PHP code, no `assert` with strings, `system/exec/shell_exec/passthru/proc_open/popen` with input (use Symfony Process with an argv array and `escapeshellarg` only as last resort); back-tick operator is deprecated in 8.5; `disable_functions` for the unused ones. [SEC-01] Shell injection and RCE. ([PHP 8.5 release](https://www.php.net/releases/8.5/en.php), [OWASP PHP config](https://cheatsheetseries.owasp.org/cheatsheets/PHP_Configuration_Cheat_Sheet.html))
- **`PHP-SEC-04`** (MUST) Hash passwords with `password_hash($p, PASSWORD_ARGON2ID)` (OWASP: m=19456 KiB, t=2, p=1 minimum; benchmark) or the default bcrypt (`PASSWORD_DEFAULT`, cost 12 since PHP 8.4, tune to ~350 ms; 72-byte input limit); verify with `password_verify`, upgrade with `password_needs_rehash`; never pass a `salt` option; column >= 255 bytes. [SEC-04] The API selects salt and algorithm for you; bcrypt truncates at 72 bytes. ([PHP password_hash](https://www.php.net/manual/en/function.password-hash.php), [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html))
- **`PHP-SEC-05`** (MUST) Randomness for security: `random_bytes()`/`random_int()`; never `rand`, `mt_rand`, `uniqid`, `lcg_value`; compare secrets with `hash_equals`; encrypt with libsodium (`sodium_crypto_secretbox`) or `defuse/php-encryption`, never custom ciphers or `md5`/`sha1` for passwords or tokens. [SEC-04] `mt_rand` is predictable; `==` on hashes leaks timing and juggles ("0e…"). ([PHP random_bytes](https://www.php.net/manual/en/function.random-bytes.php))
- **`PHP-SEC-06`** (MUST) Web risks: escape output by context (Twig and Blade autoescape on; avoid Blade `{!! !!}` and the Twig `raw` filter); CSRF protection on (Laravel `PreventRequestForgery`/`VerifyCsrfToken`, Symfony `csrf_protection`); validate redirects against an allow-list; resolve uploaded/user paths with `realpath` and a base-dir check; SSRF: allow-list outbound hosts for URL fetchers; set CORS explicitly. [SEC-03] Default framework protections exist, bypass is by raw output. ([OWASP XSS Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html), [OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html), [Symfony CSRF](https://symfony.com/doc/current/security/csrf.html), [Laravel 13 release notes](https://laravel.com/docs/13.x/releases))
- **`PHP-SEC-07`** (MUST) `php.ini` production: `expose_php=Off`, `display_errors=Off`, `log_errors=On`, `allow_url_include=Off` (and `allow_url_fopen=Off` if unused), `session.cookie_secure/httponly=1`, `session.cookie_samesite=Strict` (or Lax), `session.use_strict_mode=1`, `open_basedir` where practical, `disable_functions` for exec family. [SEC-04] Hardened defaults per OWASP. ([OWASP PHP Configuration](https://cheatsheetseries.owasp.org/cheatsheets/PHP_Configuration_Cheat_Sheet.html))
- **`PHP-SEC-08`** (MUST) Validate at the adapter boundary with the framework: Symfony Validator constraints on DTOs, Laravel `FormRequest`; the domain re-checks invariants in constructors/value objects; mass assignment: Eloquent `$fillable` (never `$guarded = []` with request input); Symfony forms/serializer groups. [SEC-05] Mass assignment and unvalidated input are the top framework-level bugs. ([Laravel validation](https://laravel.com/docs/13.x/validation))
- **`PHP-SEC-09`** (MUST) Supply chain: commit `composer.lock`, run `composer audit --locked` in CI, restrict `allow-plugins`, vet scripts (`post-install-cmd`), use `composer install --no-scripts` in untrusted CI contexts, pin private registries; check new packages for typosquats and abandonment (`--abandoned=fail`). [SEC-06] Composer plugins/scripts run code at install. ([Composer config](https://getcomposer.org/doc/06-config.md))
- **`PHP-SEC-10`** (SHOULD) SAST: PHPStan with `phpstan-strict-rules` plus Psalm taint analysis (`psalm --taint-analysis`) or Semgrep PHP rules (`semgrep --config p/php`); optionally `enlightn/security-checker`-style audit via `composer audit`. [SEC-07] Taint analysis tracks input to SQL/shell sinks. ([Psalm security analysis](https://psalm.dev/docs/security_analysis/))

## DATA: persistence

- **`PHP-DATA-01`** (SHOULD) Pick by framework: Laravel -> Eloquent (Active Record) with the query builder for reports; Symfony -> Doctrine ORM (Data Mapper) with DBAL/DQL for reads; framework-free -> Doctrine DBAL, Cycle ORM or plain PDO behind a repository port. In a hexagonal app the repository port returns domain objects, never Eloquent models/Doctrine proxies. [DATA-01] Active Record couples domain to the row; the port hides it. ([Laravel structure](https://laravel.com/docs/12.x/structure), [Symfony best practices](https://symfony.com/doc/current/best_practices.html))
- **`PHP-DATA-02`** (MUST) Migrations: Doctrine Migrations (`doctrine:migrations:diff`/`migrate`, `--dry-run`, `--no-interaction`) or Laravel migrations (`php artisan migrate --force`, `migrate:status`); commit them, never edit applied ones, use expand-contract for zero-downtime (add nullable column -> backfill -> switch -> drop), and keep `down()` optional but correct. [DATA-02] Forward-only discipline with reversible dev ergonomics. ([Doctrine Migrations](https://www.doctrine-project.org/projects/doctrine-migrations/en/current/index.html))
- **`PHP-DATA-03`** (MUST) Transaction boundary is the application use case (one handler = one transaction): Doctrine `wrapInTransaction`, Laravel `DB::transaction`; do not begin transactions in controllers or domain; emit domain events/outbox rows inside it and dispatch after commit (`afterCommit`). [DATA-03] The unit of work belongs to the application layer. ([Doctrine wrapInTransaction](https://www.doctrine-project.org/projects/doctrine-orm/en/current/reference/transactions-and-concurrency.html), [Laravel database transactions](https://laravel.com/docs/13.x/database#database-transactions))
- **`PHP-DATA-04`** (MUST) Prevent N+1: eager-load (`with()`, `Model::preventLazyLoading()` in non-prod, Doctrine `JOIN FETCH`/`fetch: EAGER` with care), paginate with keyset where large, `chunkById`/`toIterable` for batches; beware Doctrine's identity map and `clear()` in long loops. [DATA-04] Lazy relations issue one query per row. ([Laravel Eloquent](https://laravel.com/docs/13.x/eloquent))
- **`PHP-DATA-05`** (SHOULD) Connections: PHP-FPM opens one connection per worker per request (use a proxy like PgBouncer/ProxySQL, avoid `PDO::ATTR_PERSISTENT` unless tested); workers/Octane must reconnect after failures; set connect and query timeouts (`PDO::ATTR_TIMEOUT`, driver options); Swoole needs a coroutine connection pool. [DATA-05] Connection storms and stale persistent handles. ([Laravel Octane](https://laravel.com/docs/13.x/octane))
- **`PHP-DATA-06`** (SHOULD) Store money as integer minor units or `DECIMAL` with `brick/money`; timestamps as UTC; UUIDv7/ULID ids from an id port, not DB auto-increment, when ids cross service boundaries. [DATA-01] Float money and implicit time zones corrupt data. ([brick/money](https://github.com/brick/money))

## API: APIs and integration

- **`PHP-API-01`** (MUST) HTTP stack: Symfony HttpFoundation/HttpKernel + routing attributes, Laravel routing + middleware pipeline, Slim/Mezzio for PSR-7/15 middleware; controllers are thin adapters that map request -> command and result -> response; no business logic in controllers. [API-01] Keeps the inbound adapter replaceable. ([Symfony best practices: controllers](https://symfony.com/doc/current/best_practices.html))
- **`PHP-API-02`** (SHOULD) Contracts: API Platform (Symfony) or OpenAPI spec (`zircote/swagger-php` attributes, `dedoc/scramble` for Laravel) generated and diffed in CI; version in the URL or header; JSON:API resources are built in to Laravel 13. [API-02] Generated contracts prevent drift. ([Laravel 13 release notes](https://laravel.com/docs/13.x/releases))
- **`PHP-API-03`** (SHOULD) Return RFC 9457 problem details (`application/problem+json`) from one exception-to-response mapper (Symfony ErrorRenderer/API Platform, Laravel `Handler::render`); map domain errors to 4xx and never leak stack traces (`APP_DEBUG=false`). [API-03] One error shape for clients. ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457))
- **`PHP-API-04`** (MUST) Resilience on outbound calls: explicit connect/total timeouts on every client, bounded retries with backoff+jitter only on idempotent verbs, Idempotency-Key for POST, circuit breaker around flaky dependencies, and rate limiting inbound (Symfony RateLimiter, Laravel `RateLimiter`/`throttle`). [API-04] PHP request timeouts (`max_execution_time`) do not cap a hung socket. ([Symfony HttpClient](https://symfony.com/doc/current/http_client.html))
- **`PHP-API-05`** (MUST) Messaging: Symfony Messenger (AMQP/Redis/Doctrine/SQS transports) or Laravel queues; use the transactional outbox, make handlers idempotent (at-least-once), configure retry and failure transport; Kafka via `php-rdkafka` is long-running only. [API-05] Delivery is at-least-once; duplicates are normal. ([Symfony Messenger](https://symfony.com/doc/current/messenger.html))
- **`PHP-API-06`** (SHOULD) HTTP clients: use PSR-18 (`Psr\Http\Client\ClientInterface`) via Symfony HttpClient or Guzzle behind a port; one client instance per host in worker mode; propagate trace headers and deadlines; do not use `file_get_contents($url)` for APIs. [API-06] PSR-18 keeps the client swappable; raw functions have no timeouts by default. ([PSR-18](https://www.php-fig.org/psr/psr-18/))

[FW-02] Frameworks assume their layout (generators, discovery). ([Laravel structure](https://laravel.com/docs/12.x/structure), [Symfony best practices](https://symfony.com/doc/current/best_practices.html))
- **`PHP-FW-03`** (MUST) Laravel footguns: `env()` outside config after `config:cache`; Eloquent `$guarded = []`; lazy loading N+1; facades/`app()` in domain; static/singleton state under Octane; heavy work in service providers' `boot`; `bootstrap/cache` stale after deploy (run `php artisan optimize`/`optimize:clear`). [FW-03] Documented failure modes. ([Laravel Octane](https://laravel.com/docs/13.x/octane))
- **`PHP-FW-04`** (MUST) Symfony footguns: public services/`$container->get()`; missing `ResetInterface` on stateful services in worker mode; Doctrine `flush()` scattered through code; `APP_ENV=dev` in prod; stale `var/cache` after deploy (`cache:clear --env=prod --no-debug`, `cache:warmup`); entities with framework attributes leaking into the domain. [FW-03] Documented failure modes. ([Symfony best practices](https://symfony.com/doc/current/best_practices.html), [FrankenPHP worker](https://frankenphp.dev/docs/worker/))

## Top 10 footguns

1. Missing `strict_types`: `f(int $x)` silently coerces `"5"`. Fix: `declare(strict_types=1);` in every file (`PHP-IDIOM-01`).
2. Loose comparison: `$hash == $expected`, `in_array($x, $l)`. Fix: `hash_equals`, `===`, `in_array(..., true)`.
3. `unserialize()` on user data. Fix: `json_decode(..., JSON_THROW_ON_ERROR)`, or HMAC plus `allowed_classes: false`.
4. SQL built from strings. Fix: `prepare` + `execute`, allow-listed identifiers.
5. State leaking across requests in worker mode (singleton holding the `Request`, static caches). Fix: per-call data, `ResetInterface`, a two-requests leak test, `--max-requests`.
6. N+1 queries via lazy relations. Fix: eager load (`with`), `preventLazyLoading()`.
7. Float money and mutable `DateTime`. Fix: integer minor units or `brick/money`, `DateTimeImmutable` + a PSR-20 `Clock`.
8. `env()` outside `config/*.php` after `config:cache`; `allow-plugins: true`. Fix: read env only in config files; list plugins explicitly.
9. Dev tooling and Xdebug in production, `display_errors=On`. Fix: `composer install --no-dev --classmap-authoritative`, hardened php.ini.
10. Hiding debt in the PHPStan baseline or with `@`. Fix: only shrink the baseline; handle errors explicitly.
