# C++ rules (backend services)

C++23 (ISO published); C++26 technically finished 2026-03, ISO publication unconfirmed, so do not depend on it. GCC 16.2, Clang/LLVM 23.1, CMake 4.4. As of 2026-11. Source: `research/languages/cpp.md` (rows keep their IDs). Pack: `specs/languages/cpp/pack.json`. Skill: `skills/lang-cpp/SKILL.md`.

Project rules win: a project's own `.clang-format`, `.clang-tidy`, presets, style guide and ADRs override these defaults, and each override is logged with `loops run override`. Universal rules are not repeated here: see `specs/ARCHITECTURE.md`, `specs/SOLID.md` and `specs/WORKFLOW.md` §6. "CG" is the [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines).

Rule form: `**ID** (MUST|SHOULD|AVOID) Rule. Why. (source)`.


## REPO: repository and project management

- **`CPP-REPO-01`** (SHOULD) Use the pitchfork layout: `src/` (or `include/<proj>/` for public headers), `tests/`, `docs/`, `cmake/`, `external/` only for vendored code; one directory per CMake target, merged headers+sources inside it. Predictable layout lets tools and agents find code and test globs. ([Pitchfork Layout](https://github.com/vector-of-bool/pitchfork))
- **`CPP-REPO-02`** (MUST) Write target-based "modern CMake": `add_library`/`add_executable` plus `target_link_libraries(... PRIVATE/PUBLIC/INTERFACE)`, `target_include_directories`, `target_compile_features(cxx_std_20)`; never set global `include_directories`, `link_libraries` or `CMAKE_CXX_FLAGS` inside subdirectories. Usage requirements propagate per target, which also encodes the layer graph (ARCH-04) ([cmake-buildsystem(7)](https://cmake.org/cmake/help/latest/manual/cmake-buildsystem.7.html))
- **`CPP-REPO-03`** (MUST) Commit `CMakePresets.json` (configure, build, test, workflow presets) and git-ignore `CMakeUserPresets.json`; CI and developers call `cmake --preset X`, `cmake --build --preset X`, `ctest --preset X`, or `cmake --workflow --preset X`. One source of truth for flags and sanitizer modes; schema version 13 is the newest as of CMake 4.5 RC, use the lowest version your CMake floor supports. ([cmake-presets(7)](https://cmake.org/cmake/help/latest/manual/cmake-presets.7.html))
- **`CPP-REPO-04`** (MUST) Build out-of-source into `build/<preset>/` (preset `binaryDir`); never run in-source builds (`CMAKE_DISABLE_IN_SOURCE_BUILD`). Keeps the tree clean and lets the cleanup delete one directory. ([cmake-presets(7)](https://cmake.org/cmake/help/latest/manual/cmake-presets.7.html))
- **`CPP-REPO-05`** (SHOULD) Choose the build system deliberately: CMake is the default (largest ecosystem, vcpkg/Conan integration); Bazel (`MODULE.bazel`, bzlmod) for large monorepos needing hermetic, remote-cached builds; Meson (+ wraps) for smaller projects; do not mix two as sources of truth. CMake dominates the ecosystem; Bazel buys hermeticity at a high migration and rule-maintenance cost. ([Bazel C++ tutorial](https://bazel.build/start/cpp))
- **`CPP-REPO-06`** (SHOULD) Use one repo with multiple CMake targets (modular monolith) by default; use `add_subdirectory` for in-repo libraries; reach for polyrepo only for independently versioned libraries published as vcpkg/Conan packages. Cross-target refactors stay atomic; package boundaries are costly in C++ because of ABI. ([cmake-buildsystem(7)](https://cmake.org/cmake/help/latest/manual/cmake-buildsystem.7.html))
- **`CPP-REPO-07`** (SHOULD) Bootstrap with a minimal committed skeleton: `CMakeLists.txt`, presets, dependency manifest, `.clang-format`, `.clang-tidy`, a passing `tests/` smoke test, CI file, `Dockerfile`; there is no official generator, so copy a vetted template (for example the cpp-best-practices `cmake_template` or the cmake-init output). A day-one repo that already builds, formats, lints and tests under sanitizers prevents later retrofits. ([cmake-init](https://github.com/friendlyanon/cmake-init))
- **`CPP-REPO-08`** (MUST) Declare dependencies in a manifest, never by copying sources or `FetchContent` of untagged HEAD: vcpkg `vcpkg.json` with `"builtin-baseline"` (+ `version>=` constraints, `overrides` to pin), or Conan 2 `conanfile.txt/py` with a committed `conan.lock`. Baselines/lockfiles make builds reproducible and are what scanners read. ([vcpkg versioning](https://learn.microsoft.com/en-us/vcpkg/users/versioning))
- **`CPP-REPO-09`** (MUST) Commit `vcpkg.json` and the baseline hash (or `conan.lock`) for applications; regenerate the lock deliberately (`vcpkg x-update-baseline`, `conan lock create .`) in a dedicated PR; in CI pass `--lockfile=conan.lock` explicitly. vcpkg resolves the lowest version satisfying all constraints, so the baseline is the lockfile equivalent; Conan lockfiles are strict by default. ([vcpkg x-update-baseline](https://learn.microsoft.com/en-us/vcpkg/commands/update-baseline))
- **`CPP-REPO-10`** (SHOULD) Automate dependency updates: Dependabot has a `vcpkg` ecosystem that updates `builtin-baseline` (version updates only, no security updates); Renovate has `conan` and `bazel-module` managers but no vcpkg manager; for Conan use Renovate, and refresh locks in a scheduled PR. Without automation C++ dependencies rot because updating is manual. ([Dependabot supported ecosystems](https://docs.github.com/en/code-security/dependabot/ecosystems-supported-by-dependabot/supported-ecosystems-and-repositories))
- **`CPP-REPO-11`** (SHOULD) Version with SemVer in `project(<name> VERSION x.y.z)`, tag `vX.Y.Z`, set SOVERSION only for shared libraries you publish, keep a `CHANGELOG.md`; services ship as OCI images, so the tag is the image tag. Sign images/provenance with Sigstore or SLSA GitHub attestations. ABI breaks are silent in C++; for services the container is the release artifact. ([CMake project()](https://cmake.org/cmake/help/latest/command/project.html))
- **`CPP-REPO-12`** (MUST) Pin the toolchain: record compiler + CMake versions in the CI image tag and a `toolchain` preset or `CMAKE_TOOLCHAIN_FILE`; pin a vcpkg triplet and the vcpkg checkout (baseline) so two machines produce the same build. Different compilers give different warnings, UB behaviour and ABI. ([cmake-toolchains(7)](https://cmake.org/cmake/help/latest/manual/cmake-toolchains.7.html))
- **`CPP-REPO-13`** (SHOULD) Hygiene files: `.gitignore` covers `build/`, `cmake-build-*/`, `CMakeUserPresets.json`, `vcpkg_installed/`, `compile_commands.json`, `*.gcda`, `*.gcno`, `*.profraw`, `.cache/` (clangd); `.gitattributes` sets `* text=auto` and `*.cmake linguist-language=CMake`; `.editorconfig` with 4 or 2 spaces; pre-commit runs `clang-format` and `cmake-format`/`gersemi`. Stops multi-GB build trees entering history. ([pre-commit](https://pre-commit.com/))
- **`CPP-REPO-14`** (MUST) CI stages: restore caches (ccache, vcpkg binary cache) → `clang-format --dry-run -Werror` → configure → build (warnings as errors) → clang-tidy → `ctest` under TSan and under ASan+UBSan → coverage build → OSV scan → package; matrix over GCC and Clang (and MSVC if shipped). Each compiler finds different bugs; sanitizers need separate builds so they are separate jobs. ([GitHub starter workflow: CMake](https://github.com/actions/starter-workflows/blob/main/ci/cmake-single-platform.yml))
- **`CPP-REPO-15`** (SHOULD) Use conventional commits with generated changelogs as loops does; no C++-specific deviation. Same rule as other packs. ([Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/))

## TOOL: toolchain

- **`CPP-TOOL-01`** (MUST) Target C++20 as the floor (`target_compile_features(<t> PUBLIC cxx_std_20)`, `CMAKE_CXX_STANDARD_REQUIRED ON`, `CMAKE_CXX_EXTENSIONS OFF`); use C++23 where the whole CI matrix supports it. As of 2026-11: C++23 is published, C++26 (reflection, contracts, `std::execution`) was technically finished by WG21 in 2026-03, but ISO publication is unconfirmed (secondary reports say the DIS ballot failed in 2026-10; no ISO primary source) and compiler coverage is partial (GCC 16 ships reflection and contracts); do not depend on C++26 in service code. `-std=gnu++` extensions reduce portability; C++20 gives concepts, ranges, `std::span`, coroutines. ([cppreference compiler support](https://en.cppreference.com/w/cpp/compiler_support))
- **`CPP-TOOL-02`** (AVOID) Treat C++20 modules as opt-in, not baseline: CMake scans modules for GCC 14+, Clang 16+, MSVC 14.34+ with Ninja 1.11+ or VS generators (CMP0155), but `import std` is still gated by an experimental flag and modules from IMPORTED targets are unsupported (CMake 4.4 docs); keep headers as the default interface. Toolchain, IDE and package-manager support for modules is uneven. ([cmake-cxxmodules(7)](https://cmake.org/cmake/help/latest/manual/cmake-cxxmodules.7.html))
- **`CPP-TOOL-03`** (MUST) Format with `clang-format` driven by a committed `.clang-format` (`BasedOnStyle: Google` or `LLVM`/`Chromium` plus a few overrides); check argv: `clang-format --dry-run -Werror <files>`; fix argv: `clang-format -i <files>`. Never mix two formatters. One formatter ends style debates; `--dry-run -Werror` makes a non-zero exit. ([ClangFormat](https://clang.llvm.org/docs/ClangFormat.html))
- **`CPP-TOOL-04`** (MUST) Compile with a strict warning set on every target: GCC/Clang `-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion -Wnon-virtual-dtor -Wold-style-cast -Woverloaded-virtual -Wnull-dereference -Wdouble-promotion -Wformat=2 -Wimplicit-fallthrough`; MSVC `/W4 /permissive-`; enable `-Werror` (`/WX`) in CI and dev presets, but not for downstream source builds (use `-Werror=format-security` there); implement it in `cmake/Warnings.cmake`, set via `CMAKE_COMPILE_WARNING_AS_ERROR ON`. Warnings catch UB precursors; blanket `-Werror` in released sources breaks on new compilers (OpenSSF guidance) ([OpenSSF Compiler Hardening Guide](https://best.openssf.org/Compiler-Hardening-Guides/Compiler-Options-Hardening-Guide-for-C-and-C++.html))
- **`CPP-TOOL-05`** (MUST) Lint with `clang-tidy` from a `.clang-tidy` file: enable `bugprone-*`, `cppcoreguidelines-*`, `modernize-*`, `performance-*`, `concurrency-*`, `clang-analyzer-*`, `readability-*` minus the noisy ones (`-modernize-use-trailing-return-type`, `-readability-magic-numbers`), set `WarningsAsErrors: '*'` for the chosen set and `HeaderFilterRegex` to project headers; run `run-clang-tidy -p build/<preset>` against `compile_commands.json` (`CMAKE_EXPORT_COMPILE_COMMANDS=ON`). Config in the repo makes the result reproducible; command-line options override the file. ([clang-tidy](https://clang.llvm.org/extra/clang-tidy/))
- **`CPP-TOOL-06`** (SHOULD) Run `include-what-you-use` (IWYU) via `CMAKE_CXX_INCLUDE_WHAT_YOU_USE` or `iwyu_tool.py -p build`, using the IWYU branch that matches the Clang version (Clang 22 → IWYU 0.26, Clang 23 → 0.27); run it advisory (non-blocking) because it breaks across Clang releases. Keeps include graph minimal and build times down; the tool is fragile. ([include-what-you-use](https://github.com/include-what-you-use/include-what-you-use))
- **`CPP-TOOL-07`** (SHOULD) Run `cppcheck` (`--project=build/<preset>/compile_commands.json --error-exitcode=1 --enable=warning,performance,portability`) or Clang Static Analyzer / CodeQL as a second analyzer in CI; do not block on style-only checks. Different engines find different defects; MISRA/AUTOSAR checks only matter for regulated code. ([Cppcheck manual](https://cppcheck.sourceforge.io/manual.html))
- **`CPP-TOOL-08`** (SHOULD) There is no external type checker: strictness comes from the compiler flags (TOOL-04), `-fstrict-flex-arrays=3`, `-ftrivial-auto-var-init=zero` for production, and `[[nodiscard]]`, `explicit`, `enum class`, concepts; run `-fanalyzer` on GCC as an advisory check. C++ type safety is opt-in. ([GCC static analyzer](https://gcc.gnu.org/onlinedocs/gcc/Static-Analyzer-Options.html))
- **`CPP-TOOL-09`** (SHOULD) Scan dependencies with OSV-Scanner on the lockfile (`conan.lock` is a supported lockfile type; vcpkg manifests have no first-party scanner yet: check the baseline commit against the vcpkg security advisories and the upstream CVE feeds); generate an SBOM with `vcpkg` SPDX output (`installed/<triplet>/share/<port>/vcpkg.spdx.json`), `conan` CycloneDX (`conan-sbom`) or `syft`. Native C++ has no `npm audit`; coverage is patchy (OSV supports `conan.lock` only, not `vcpkg.json`, and a pinned old zlib reported no issues in a spot run, so Conan advisory coverage looks thin) ([OSV-Scanner](https://google.github.io/osv-scanner/))
- **`CPP-TOOL-10`** (SHOULD) Editor: use `clangd` with `compile_commands.json` at the root (symlink or `CMAKE_EXPORT_COMPILE_COMMANDS`), a committed `.clangd` (`CompileFlags: CompilationDatabase: build/dev`), and format-on-save through clangd so `clang-format` is the only formatter. Wrong compilation database gives phantom errors. ([clangd](https://clangd.llvm.org/config))

## ARCH: architecture

- **`CPP-ARCH-01`** (SHOULD) Pick the style by need: hexagonal/clean as the default for a service, modular monolith (one binary, many CMake targets) before microservices; event-driven via a broker client in an outbound adapter; the actor model only through a framework (CAF, userver tasks). C++ build times and ABI make many small services costly. See specs/ARCHITECTURE.md §2. ([Boost Asio](https://www.boost.org/doc/libs/release/doc/html/boost_asio.html))
- **`CPP-ARCH-02`** (MUST) Make each layer a CMake library target with minimal `PRIVATE/PUBLIC` links, and expose headers only through `target_include_directories`; `domain` links nothing, `application` links `domain`, adapters link `application`, `app` links all. The link graph is the dependency rule; wrong includes fail to compile. ([cmake-buildsystem(7)](https://cmake.org/cmake/help/latest/manual/cmake-buildsystem.7.html))
- **`CPP-ARCH-03`** (MUST) Use one namespace per layer (`orders::domain`, `orders::app`, `orders::adapters::pg`) mirroring directories; no `using namespace` in headers (CG SF.7) and no anonymous-namespace definitions in headers. A namespace is not a module: enforcement relies on files and targets. ([CG SF.7, SF.21](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-ARCH-04`** (MUST) Know the visibility model: C++ has no package-private, so use private/protected members, internal headers in `src/` (not `include/`), `detail` namespaces and `PRIVATE` include directories. Include cycles are legal, and CMake permits cycles among STATIC libraries (it repeats them on the link line), so forbid target cycles yourself by checking the `cmake --graphviz` or File API graph. CMake does not reject target cycles, so nothing else will. ([CG SF.8-SF.9](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-ARCH-05`** (MUST) Write includes as `#include "orders/domain/order.hpp"` for project headers (path relative to the include root, quotes) and `<...>` for system and third-party; always use include guards or `#pragma once` consistently; the arch checker resolves them with `include-path` against the target's include dirs. The loops arch checker needs a deterministic header-to-layer mapping. ([CG SF.10-SF.13](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-ARCH-06`** (MUST) Enforce direction mechanically: `loops arch` (the `include-path` resolver over `#include` lines), CMake target links (a header from an unlinked target fails to compile), `cmake --graphviz=deps.dot` checked for forbidden edges and cycles, optionally IWYU mappings, and Bazel `visibility` with `--check_visibility`. There is no ArchUnit for C++; link graphs are the closest native tool. ([cmake --graphviz](https://cmake.org/cmake/help/latest/module/CMakeGraphVizOptions.html))
- **`CPP-ARCH-07`** (MUST) Wire dependencies by hand in `app/main.cpp` (constructor injection with `std::unique_ptr<Port>`/references or templates); avoid DI containers (Boost.DI is acceptable but not needed) and global singletons/service locators. Manual wiring is explicit and cheap in C++. See specs/ARCHITECTURE.md §21. ([CG I.2, I.3](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-ARCH-08`** (MUST) Keep `domain/` free of I/O, clocks, randomness, threads and frameworks: it may include only `<string>`, `<vector>`, `<optional>`, `<variant>`, `<expected>`, `<chrono>` types (not `now()`), and project domain headers; take a `Clock&` and `Rng&` port. Pure domain is deterministic and testable without sanitizers. See specs/ARCHITECTURE.md §3. ([CG I.2, P.4](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-ARCH-09`** (SHOULD) Define ports in the consumer (application) as small abstract classes with a virtual destructor, or as C++20 `concept`s when the implementation is chosen at compile time (zero-cost); use `std::function` only for single-method callbacks; prefer value semantics and `std::variant` over class hierarchies inside the domain. Concepts remove the vtable cost; virtual is simpler for runtime swap and test doubles. See specs/ARCHITECTURE.md §6. ([CG C.121, I.25, T.20](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-ARCH-10`** (SHOULD) Apply tactical DDD with value types: value objects are `const`-member or immutable structs with `operator==` (`= default` in C++20), entities have identity ids, aggregates expose behaviour, repositories are ports returning `std::expected`/`std::optional`. Copy/move semantics make value objects natural. See specs/ARCHITECTURE.md §5. ([CG C.10, C.20, C.80-C.89](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-ARCH-11`** (SHOULD) SOLID in C++: rule of zero, small classes (no public data on invariants, CG C.2), interface segregation by splitting abstract classes, Liskov through non-virtual interface idiom (public non-virtual calling private virtual, CG C.131 area), and keep files under ~400 lines, functions under ~50 lines, parameters ≤ 4-5 (CG F.2, F.3, I.23). Size heuristics, since compile time grows with header size. See specs/SOLID.md. ([CG C.2, F.2, F.3, I.23](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))

## IDIOM: what to do and what to avoid

- **`CPP-IDIOM-01`** (MUST) Choose one error strategy per boundary: exceptions for exceptional, rare failures in code that is not exception-free; `std::expected<T,E>` (C++23) for expected business failures in domain/application code; map both to a typed error at the adapter edge; never return error codes plus out-parameters, and never use `catch (...) {}` without rethrow or log. The exceptions-vs-codes debate is unresolved (CG E.1 recommends exceptions; Google bans them; P0709 explored alternatives), so pick one rule per layer and write it down. ([CG E.1-E.3, E.17](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-02`** (MUST) If exceptions are used: throw by value, catch by `const&`, derive from `std::exception`, mark destructors and moves `noexcept`, and catch at thread/task/callback boundaries (an exception escaping a `std::thread` function or a `noexcept` function calls `std::terminate`). Uncaught exceptions in threads or coroutines abort the whole service. ([CG E.14, E.15, E.12, E.16](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-03`** (MUST) Treat undefined behaviour as the top defect class: no out-of-range `operator[]` without checks, no signed overflow, no uninitialised reads, no dangling references (returning refs to locals, `string_view` to temporaries), no strict-aliasing violations; run UBSan and ASan in CI (CONC-04). UB makes optimisers delete checks and hides bugs until production. ([CG ES.20, ES.100-ES.106, SL.con.3](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-04`** (SHOULD) Prefer `std::optional<T>` for "maybe a value", references for "must exist", `gsl::not_null<T*>` or a reference for non-null pointers, and never use raw `nullptr` as a business signal; raw `T*` means non-owning and nullable only. Makes absence explicit in the type. ([CG F.60, I.12, R.3](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-05`** (MUST) Own through RAII: no `new`/`delete`/`malloc` in application code, `std::make_unique`/`std::make_shared`; `unique_ptr` is the default owner, `shared_ptr` only for genuinely shared lifetime (and never in a cycle: break with `weak_ptr`); pass `T&`/`T*` for non-owning use and `unique_ptr<T>` by value to transfer ownership. RAII is the language's resource-safety story; leaks and double frees disappear. ([CG R.1, R.3, R.11, R.20-R.24, R.30-R.37, I.11](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-06`** (MUST) Follow the rule of zero (declare none of the special members; hold resources in members that manage themselves), or the rule of five when a class owns a raw resource; mark single-argument constructors `explicit`, base destructors `virtual` (or protected non-virtual), and polymorphic classes non-copyable. Copy/move bugs are the classic C++ resource leak. ([CG C.20, C.21, C.35, C.46, C.67](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-07`** (SHOULD) Use value semantics and immutability by default: `const` everything that can be, `constexpr` where possible, `enum class` over plain enums, `struct` with defaulted `operator<=>`/`==` for value types, aggregate initialisation with designated initialisers (C++20), no mutable globals. Reduces aliasing and data races. ([CG Con.1-Con.5, Enum.3, I.2](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-08`** (MUST) Pass parameters by the cheap rule: small trivially copyable types by value, others by `const&`, sink arguments by value then `std::move`, outputs by return value (struct for multiple); views (`std::span<T>`, `std::string_view`) for ranges and text but never store them beyond the owner's lifetime. `string_view` and `span` dangling is a top UAF source. ([CG F.15-F.21, F.24, F.25](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-09`** (SHOULD) Use the standard library over hand-rolled code: `std::vector` as the default container, `std::array` for fixed sizes, `std::string` (never `char*`), ranges/algorithms over raw loops, `std::format`/`fmt::format` over `printf`/`iostream` formatting; use `.at()` or hardened `operator[]` at trust boundaries. Safer and as fast. ([CG SL.con.1, SL.str.1, SL.io.50, ES.50](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-10`** (MUST) Handle time with `std::chrono` types (`std::chrono::sys_time`, `duration`, C++20 time zones) and inject a clock port; use UTC internally, convert at the edge; never store durations as bare `int` or `double`. Unit-confusion bugs and non-deterministic tests. See specs/ARCHITECTURE.md §20. ([cppreference chrono](https://en.cppreference.com/w/cpp/chrono))
- **`CPP-IDIOM-11`** (MUST) Always initialise: use brace-init (`T x{}`), in-class member initialisers, `= delete` for unwanted ops, avoid narrowing; compile with `-ftrivial-auto-var-init=zero` for production as a backstop, not a substitute. Uninitialised reads are UB. ([CG ES.20, ES.23, ES.46, C.45](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-12`** (SHOULD) Naming: follow one published style (Google: `snake_case` functions/files, `CamelCase` types, `kConstant`, `member_`; or Core Guidelines/`std`-style `snake_case` everywhere); no Hungarian prefixes; do not start identifiers with underscore + capital or contain `__`. Consistency, and reserved identifiers are UB. ([Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html))
- **`CPP-IDIOM-13`** (AVOID) Limit metaprogramming: prefer `constexpr` functions and C++20 concepts over SFINAE and macros; macros only for include guards, logging with `__FILE__`, or platform detection; no preprocessor tricks for control flow; no RTTI or `dynamic_cast` in hot or domain code (variants and visitors instead). Template error messages and macro hygiene hurt maintainability. ([CG ES.30-ES.33, T.10, T.11, T.150](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-IDIOM-14`** (MUST) No C-style casts, `reinterpret_cast` or `const_cast` without a comment; use `static_cast`/`std::bit_cast`; no C-style variadics, arrays decay, or `memcpy` on non-trivial types; use `std::byte` for raw memory. Casts silence the compiler about UB. ([CG ES.48-ES.50, C.90, ES.61](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))

## CONC: concurrency and the `-race` equivalent

- **`CPP-CONC-01`** (MUST) Know the model: OS threads (`std::thread`/`std::jthread`), thread pools (Asio `thread_pool`, userver task processors), coroutines (C++20 `co_await` with Asio/Boost.Cobalt/userver), event loops with a few I/O threads; there is no GIL, so every shared mutable object needs a documented owner. Data races are UB, not just wrong results. ([CG CP.1-CP.4](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-CONC-02`** (MUST) Avoid sharing; when needed, guard with RAII locks (`std::scoped_lock`/`std::unique_lock`, never bare `lock()/unlock()`), keep critical sections tiny, never call unknown code while holding a lock, use `std::atomic` only for single variables with the default `seq_cst` order unless proved otherwise, and prefer message passing (queues, strands) to shared state. Locks without RAII leak on exceptions; relaxed atomics are expert-only. ([CG CP.2, CP.20, CP.21, CP.22, CP.42, CP.100](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-CONC-03`** (MUST) Detect races with ThreadSanitizer: compile and link everything (tests and dependencies, so use a `tsan` vcpkg triplet or Conan profile) with `-fsanitize=thread -fno-omit-frame-pointer -g -O1`; expect 5x-15x slowdown and 5x-10x memory; Linux x86_64/aarch64 and macOS only, no 32-bit; use `TSAN_OPTIONS=suppressions=...` only through project config for third-party false positives; annotate custom fibers and coroutines. TSan is the only practical C++ race detector, and uninstrumented dependencies cause missed races or false positives. ([ThreadSanitizer](https://clang.llvm.org/docs/ThreadSanitizer.html))
- **`CPP-CONC-04`** (MUST) Race policy (`race.mode = build`, WORKFLOW §6): the full gate runs the required `test-tsan` check, which configures, builds and runs the whole CTest suite from a dedicated `tsan` preset with its own `binaryDir`, with `TSAN_OPTIONS="halt_on_error=1 second_deadlock_stack=1"`. A second required check, `test-asan-ubsan`, builds `-fsanitize=address,undefined -fno-sanitize-recover=all -fno-omit-frame-pointer` separately. A host where TSan cannot run fails the gate ("race policy unavailable"); it never skips. The race-guard hook does not deny `ctest` runs, because an ASan or plain run is legitimate. TSan and ASan are mutually exclusive, so the policy is a build mode, not a flag. ([ThreadSanitizer](https://clang.llvm.org/docs/ThreadSanitizer.html))
- **`CPP-CONC-05`** (SHOULD) Make sanitizer builds reproducible with CMake: a `Sanitizers.cmake` module reading `SANITIZE=thread\|address,undefined\|none`, applied through `target_compile_options` and `target_link_options` on an INTERFACE target linked by every target; set `TSAN_OPTIONS` in the test preset `environment` or with `set_tests_properties(... ENVIRONMENT ...)`. A single switch avoids mixed instrumented and uninstrumented builds. ([cmake-presets(7)](https://cmake.org/cmake/help/latest/manual/cmake-presets.7.html))
- **`CPP-CONC-06`** (MUST) Know the sanitizer incompatibilities: TSan cannot share a binary with ASan, LSan or MSan; ASan and UBSan combine; MSan (Clang, Linux) needs an instrumented libc++ and every dependency, so skip it for services. TSan combines with coverage: GCC `--coverage -fprofile-update=atomic`, Clang `-fprofile-instr-generate -fcoverage-mapping` (the `tsan` preset carries both, D3). Do not combine sanitizers with `-D_FORTIFY_SOURCE`. Mixed flags give false reports or no instrumentation. ([GCC instrumentation options](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html))
- **`CPP-CONC-07`** (MUST) Async pitfalls: never block (sleep, sync DB, `future.get()`) on an I/O thread or coroutine; give every async operation a deadline/timeout; support cancellation (`std::stop_token`, Asio cancellation slots); keep lifetimes alive for in-flight callbacks (`shared_from_this`, or coroutines owning state); bound queues for backpressure. Dangling `this` in callbacks is the top Asio crash. ([Boost.Asio cancellation](https://www.boost.org/doc/libs/release/doc/html/boost_asio/overview/core/cancellation.html))
- **`CPP-CONC-08`** (MUST) Background work: use `std::jthread` (joins on destruction, has a stop token) instead of `std::thread` + `detach` (never detach); give pools an explicit shutdown (stop accepting, drain, join) driven by a signal handler that only sets an atomic/asio signal_set, not logic. Detached threads outlive the objects they use. ([CG CP.23-CP.26](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-CONC-09`** (SHOULD) Complement TSan with `clang-tidy concurrency-*` and Clang Thread Safety Analysis (`-Wthread-safety`, `GUARDED_BY`/`REQUIRES` annotations over a capability-annotated mutex wrapper); run stress/repeat tests (`ctest --repeat until-fail:N`) under TSan for flaky races. Static annotations catch lock misuse without timing luck. ([Clang Thread Safety Analysis](https://clang.llvm.org/docs/ThreadSafetyAnalysis.html))

## TEST: testing

- **`CPP-TEST-01`** (SHOULD) Use GoogleTest + GoogleMock as the default unit framework (`GTest::gtest_main`, `gtest_discover_tests()` so each `TEST` is a CTest test); Catch2 v3 (BDD sections, `catch_discover_tests`) and doctest (header-light, fast compile) are acceptable; pick one per repo. Discovery makes `ctest -R` and sharding work. ([GoogleTest](https://google.github.io/googletest/))
- **`CPP-TEST-02`** (MUST) Layout: `tests/unit/<layer>/*_test.cpp`, `tests/integration/`, `tests/fuzz/`, `tests/bench/`; one test executable per layer target linking that target; register with `add_test` or discovery; identify tests by globs `**/*_test.cc`, `**/*_test.cpp`, `**/test_*.cpp`, `tests/**`. The hard test gate needs to recognise test files vs source. ([Google C++ Style: Test names](https://google.github.io/styleguide/cppguide.html#Function_Names))
- **`CPP-TEST-03`** (SHOULD) Style: `TEST(Suite, DoesXWhenY)`, fixtures (`TEST_F`) for shared setup only, parametrised tests with `INSTANTIATE_TEST_SUITE_P` (the table-driven form), Arrange-Act-Assert; use `EXPECT_*` for non-fatal and `ASSERT_*` only when the test cannot continue. Clear failure messages and one failure per concept. ([GoogleTest value-parameterized tests](https://google.github.io/googletest/advanced.html#value-parameterized-tests))
- **`CPP-TEST-04`** (SHOULD) Test doubles: prefer hand-written fakes of ports; use GoogleMock (`MOCK_METHOD`, `EXPECT_CALL`) only for interaction checks at the application/port boundary; do not mock value types or the standard library; avoid `NiceMock` hiding unexpected calls. Over-mocking couples tests to implementation. ([GoogleMock for Dummies](https://google.github.io/googletest/gmock_for_dummies.html))
- **`CPP-TEST-05`** (SHOULD) Integration tests use real dependencies: Testcontainers (testcontainers-native C++ is community-maintained, so verify its maturity) or docker-compose started by a CTest fixture (`FIXTURES_REQUIRED`), a throw-away database/schema per test, ports from the OS (bind to 0). In-memory substitutes diverge from Postgres/Redis. ([CTest fixtures](https://cmake.org/cmake/help/latest/prop_test/FIXTURES_REQUIRED.html))
- **`CPP-TEST-06`** (MUST) Measure coverage from the merged `tsan` build (D3): on GCC, `gcovr --root . --object-directory build/tsan --lcov {coverage} --filter src/` after `--coverage -fprofile-update=atomic`; on Clang (the `clang` variant), `llvm-profdata merge -sparse` then `llvm-cov export -format=lcov` over the test binaries, with `LLVM_PROFILE_FILE` set in the test preset. Both give lcov. Exclude generated code (`*.pb.cc`, `*.pb.h`, `*.grpc.pb.*`), `build/` and `third_party/`. gcovr merges gcov data across translation units, and lcov is the simplest format for loops to read. Spot runs on GCC 16.2 and Clang 22 passed with TSan and coverage combined. ([gcovr lcov](https://gcovr.com/en/stable/output/lcov.html))
- **`CPP-TEST-07`** (MUST) New code must have at least 70% line coverage (`loops gate` coverage, WORKFLOW §6): loops intersects the added lines of `git diff -U0 <base>` in `source_globs` files (minus `test_globs` and generated code) with the `DA:` lines of the lcov, counting only executable lines present in it. This is the loops hard rule; lcov `DA` records give per-line hits. ([diff_cover](https://github.com/Bachmann1234/diff_cover))
- **`CPP-TEST-08`** (SHOULD) Fuzz parsers and codecs with libFuzzer (`LLVMFuzzerTestOneInput`, build `-fsanitize=fuzzer,address,undefined`; run `./fuzz CORPUS -max_total_time=60` in CI, `-fork=N` for resilience); keep a seed corpus in the repo; use OSS-Fuzz for open source; use RapidCheck or Catch2 generators for property tests. Fuzzing is the best defence for binary/text parsing in C++. ([LibFuzzer](https://llvm.org/docs/LibFuzzer.html))
- **`CPP-TEST-09`** (SHOULD) Flakiness: randomise order (`--gtest_shuffle --gtest_random_seed`), inject clock/RNG ports, never `sleep` for synchronisation, set `TIMEOUT` per test (`ctest --timeout`), repeat (`--gtest_repeat`, `ctest --repeat until-fail:N`) under TSan for suspected races. Races surface only under repetition. ([GoogleTest runfaq](https://google.github.io/googletest/advanced.html#shuffling-the-tests))
- **`CPP-TEST-10`** (MUST) Run `ctest` with `--output-on-failure --no-tests=error`; for local loops use `ctest --preset <p> -R <regex>`, `--rerun-failed` and `-j<N>`; build fast with ccache (`-DCMAKE_CXX_COMPILER_LAUNCHER=ccache`). Never drop `--no-tests=error`. An empty test selection exits 0 without it, so zero tests would pass the gate. ([ctest(1)](https://cmake.org/cmake/help/latest/manual/ctest.1.html))
- **`CPP-TEST-11`** (SHOULD) Mutation testing is optional (Mull for LLVM, `dextool` mutate); use it only on the domain layer, nightly. Costly in C++. ([Mull](https://github.com/mull-project/mull))

## PERF: performance and profiling

- **`CPP-PERF-01`** (SHOULD) Benchmark with Google Benchmark (`BENCHMARK(...)`, `--benchmark_format=json`, `--benchmark_repetitions=10 --benchmark_report_aggregates_only`) and compare runs with its `compare.py` (Mann-Whitney U); build benchmarks in `Release` (`-O2`/`-O3`, `-DNDEBUG`), never under sanitizers. Statistical comparison avoids noise. ([google/benchmark user guide](https://github.com/google/benchmark/blob/main/docs/user_guide.md))
- **`CPP-PERF-02`** (MUST) Profile before changing: `perf record -g`/`perf report` + flame graphs, `valgrind --tool=callgrind`, `heaptrack`/`massif`/jemalloc heap profiling for memory, Tracy/`tcmalloc` pprof for continuous profiling; build with `-g -fno-omit-frame-pointer`. Optimisation without measurement is guessing. ([perf wiki](https://perf.wiki.kernel.org/index.php/Main_Page))
- **`CPP-PERF-03`** (SHOULD) Tune the build: `Release`/`RelWithDebInfo` with `-O2`, LTO (`CMAKE_INTERPROCEDURAL_OPTIMIZATION`), optional PGO (`-fprofile-use`), a faster allocator (jemalloc/mimalloc/tcmalloc), a fast linker (`lld`/`mold`), unity builds only if tests keep passing; ccache for builds. Most services gain from allocator and LTO. ([CMake IPO](https://cmake.org/cmake/help/latest/variable/CMAKE_INTERPROCEDURAL_OPTIMIZATION.html))
- **`CPP-PERF-04`** (SHOULD) Avoid hot-path mistakes: copying large objects (pass `const&`/move), `std::endl` flushing, `std::string` concatenation in loops (reserve/format), `std::shared_ptr` copies in tight loops, virtual calls in inner loops, `std::map` where `unordered_map`/flat map fits, allocation per request (use pools/arenas, `std::pmr`), `std::function` in hot paths, false sharing (`alignas(std::hardware_destructive_interference_size)`), and exceptions for control flow. These dominate C++ service profiles. ([CG Per.1-Per.19, F.15, SL.io.50](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-PERF-05`** (AVOID) Do not "optimise" without a benchmark: no `inline`/`register`/`noexcept` sprinkling without evidence; do not pessimise via `std::move` on return of locals (blocks copy elision, `-Wpessimizing-move`). Copy elision beats `move` ([CG Per.2, F.48](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))

## SEC: security

- **`CPP-SEC-01`** (MUST) Memory safety is the main risk: roughly two thirds of severe vulnerabilities in large C/C++ codebases are memory-safety bugs; use RAII, `std::span`, `std::string`, bounds-checked access at trust boundaries, enable library hardening (`-D_GLIBCXX_ASSERTIONS`, libc++ `_LIBCPP_HARDENING_MODE=_LIBCPP_HARDENING_MODE_FAST` or `EXTENSIVE`), and ban `strcpy`, `sprintf`, `gets`, `strcat` and manual `memcpy` with computed sizes. Bounds and lifetime errors cause RCE. ([libc++ hardening](https://libcxx.llvm.org/Hardening.html))
- **`CPP-SEC-02`** (MUST) Compile and link production binaries hardened (OpenSSF): `-O2 -D_FORTIFY_SOURCE=3 -D_GLIBCXX_ASSERTIONS -fstack-protector-strong -fstack-clash-protection -fcf-protection=full` (x86_64) or `-mbranch-protection=standard` (AArch64) `-fPIE -pie -Wl,-z,relro -Wl,-z,now -Wl,-z,noexecstack -ftrivial-auto-var-init=zero -fno-delete-null-pointer-checks -fno-strict-overflow -fstrict-flex-arrays=3`; verify with `checksec` or `hardening-check`; do not enable `_FORTIFY_SOURCE` in sanitizer builds. Cheap mitigations raise exploit cost. ([OpenSSF Compiler Hardening Guide](https://best.openssf.org/Compiler-Hardening-Guides/Compiler-Options-Hardening-Guide-for-C-and-C++.html))
- **`CPP-SEC-03`** (MUST) Prevent injection with parameterised queries (libpqxx `exec_params`, SOCI `use()`, prepared statements) and never format SQL with `std::format`/`+`; execute processes with `execve`-style argument vectors (`posix_spawn`, `boost::process::v2`), never `system()`/`popen()` with user data. Same principle as every language. ([OWASP SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html))
- **`CPP-SEC-04`** (MUST) Parse untrusted data defensively: use schema-checked formats (Protobuf, FlatBuffers with the verifier, simdjson/nlohmann with size limits); no raw `memcpy` of network structs, no `reinterpret_cast` of buffers, limit input sizes and nesting depth, disable XML external entities in libxml2 (`XML_PARSE_NONET`, never `XML_PARSE_NOENT`); fuzz every parser (TEST-08). Parser bugs dominate CVEs. ([OWASP Deserialization](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html))
- **`CPP-SEC-05`** (MUST) Web risks: validate and canonicalise paths (`std::filesystem::weakly_canonical` then prefix check) to stop traversal, allow-list outbound hosts to stop SSRF, set secure cookie flags/CORS explicitly in the framework, verify TLS (never `SSL_VERIFY_NONE`, `CURLOPT_SSL_VERIFYPEER=0`). Frameworks give no defaults here. ([OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html))
- **`CPP-SEC-06`** (MUST) Crypto: use a vetted library (OpenSSL 3.x EVP API, libsodium, BoringSSL, Botan), never roll primitives; hash passwords with Argon2id (libsodium `crypto_pwhash`) or scrypt/bcrypt; random bytes from the library CSPRNG (`RAND_bytes`, `randombytes_buf`), never `rand()` or `std::mt19937`; compare secrets in constant time (`CRYPTO_memcmp`, `sodium_memcmp`); wipe secrets with `OPENSSL_cleanse`/`sodium_memzero`, not `memset`. The compiler removes dead `memset`s. ([OWASP Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html))
- **`CPP-SEC-07`** (MUST) Secrets come from env/vault at runtime, are never in source, images or logs, and are held in non-swappable memory where feasible (`sodium_mlock`); scan with gitleaks/trufflehog. 12-factor and leak prevention. ([OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html))
- **`CPP-SEC-08`** (MUST) Supply chain: pin the vcpkg baseline / Conan lockfile, use a private binary cache or mirror, verify source hashes (vcpkg `SHA512`), review new ports, avoid piping a downloaded script into a shell, and `FetchContent` of mutable branches, build in a pinned container, and attach provenance. Source dependencies run arbitrary CMake code at build time. ([vcpkg versioning](https://learn.microsoft.com/en-us/vcpkg/users/versioning))
- **`CPP-SEC-09`** (SHOULD) SAST: CodeQL (`cpp` queries), Clang Static Analyzer and `clang-tidy` `bugprone-*`/`cert-*`, cppcheck and Semgrep (`p/c`/`p/cpp`); run fuzzers and sanitizers as dynamic analysis; CERT C++ and MISRA only when a customer needs them. Static analyzers find different defects from sanitizers. ([SEI CERT C++](https://wiki.sei.cmu.edu/confluence/pages/viewpage.action?pageId=88046682))

## DATA: persistence

- **`CPP-DATA-01`** (SHOULD) Prefer a thin SQL layer over a full ORM: libpqxx (PostgreSQL), SOCI, sqlpp11/sqlpp23 (typed query builder), Boost.MySQL, or the framework's async driver (userver, Drogon ORM); use ODB only for generated mappings; keep SQL in the outbound adapter. The C++ ORM ecosystem is small and macro/codegen-heavy. ([libpqxx](https://pqxx.org/libpqxx/))
- **`CPP-DATA-02`** (MUST) Migrations with a standalone, forward-only tool run before app start (Flyway, Liquibase, `sqitch`, goose, `dbmate`), not in the service binary; use expand/contract for zero downtime. There is no C++ standard migration tool. See specs/ARCHITECTURE.md §18. ([Flyway](https://documentation.red-gate.com/fd/migrations-271585107.html))
- **`CPP-DATA-03`** (MUST) Open transactions in the application layer through a unit-of-work port; implement it with an RAII guard (`pqxx::work`, rollback on destruction); keep them short; document isolation levels (default READ COMMITTED) and retry on serialisation failure. RAII rolls back on exceptions. See specs/ARCHITECTURE.md §18. ([libpqxx transactions](https://libpqxx.readthedocs.io/stable/))
- **`CPP-DATA-04`** (SHOULD) Avoid N+1 queries and lazy loading in mapping layers: use joins or batched `IN (...)`/`ANY($1)`; never return a connection-bound cursor from a repository. Lifetimes of rows tie to the connection. ([libpqxx docs](https://libpqxx.readthedocs.io/stable/))
- **`CPP-DATA-05`** (MUST) Use a connection pool with timeouts (userver's pools, Drogon's `DbClient`, `boost::mysql::connection_pool`, or `pqxx` pool wrapper), query timeouts and a max-lifetime; never share a connection across threads without a lock; use async drivers on I/O threads. Blocking drivers stall event loops. ([Boost.MySQL connection_pool](https://www.boost.org/doc/libs/release/libs/mysql/doc/html/mysql/connection_pool.html))

## API: APIs and integration

- **`CPP-API-01`** (SHOULD) Pick a framework by workload: Boost.Beast over Asio for low-level control, Drogon (async, C++17/20, built-in ORM and websockets), userver (coroutine-based, many drivers), gRPC C++ for RPC; run HTTP handlers on the I/O executor and never block them. Frameworks differ in threading and lifetime rules. ([Boost.Beast](https://www.boost.org/doc/libs/release/libs/beast/doc/html/index.html))
- **`CPP-API-02`** (SHOULD) Contract-first: `.proto` files compiled by `protoc` with the gRPC plugin in CMake (`protobuf_generate`, `grpc_cpp_plugin`) and checked with `buf lint`/`buf breaking`; for REST, an OpenAPI document with a generator (openapi-generator `cpp-restbed-server`/`cpp-pistache` are weak) or hand-written adapters validated by contract tests; generated code lands in the build tree. Generated files must be excluded from coverage and lint. ([gRPC C++ basics](https://grpc.io/docs/languages/cpp/basics/))
- **`CPP-API-03`** (SHOULD) Prefer the gRPC C++ callback API (`CallbackService`, reactors) over the CQ-based async API for new code; set deadlines on every client call (`ClientContext::set_deadline`), propagate cancellation, and return canonical status codes. The callback API is the recommended async model. ([gRPC C++ callback tutorial](https://grpc.io/docs/languages/cpp/callback/))
- **`CPP-API-04`** (MUST) Validate at the adapter boundary and map domain errors to RFC 9457 problem details (`application/problem+json`) or gRPC status codes; the domain never sees HTTP types. Keeps the domain pure. See specs/ARCHITECTURE.md §13. ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html))
- **`CPP-API-05`** (MUST) Resilience in outbound adapters: timeouts on every call, retries with exponential backoff and jitter on idempotent operations only, circuit breaker, idempotency keys for writes, rate limiting; the libraries are mostly in-house (userver has built-in), gRPC supports retry policy via service config. No de-facto library like resilience4j. ([gRPC retry](https://grpc.io/docs/guides/retry/))
- **`CPP-API-06`** (MUST) Messaging: use librdkafka (cppkafka/modern-cpp-kafka wrappers), AMQP-CPP or rabbitmq-c, NATS C client (cnats), AWS SDK for C++; implement the transactional outbox in the persistence adapter; make consumers idempotent for at-least-once delivery; commit offsets after processing. Same semantics as other languages; clients are C-library wrappers. ([librdkafka](https://github.com/confluentinc/librdkafka))
- **`CPP-API-07`** (MUST) HTTP client: use Boost.Beast/Asio, libcurl (multi handle, `CURLOPT_TIMEOUT_MS`, `CURLOPT_CONNECTTIMEOUT_MS`), cpr, or the framework client; reuse connections, set deadlines, check TLS verification. Defaults wait forever. ([libcurl easy options](https://curl.se/libcurl/c/curl_easy_setopt.html))

## OBS: observability

- **`CPP-OBS-01`** (SHOULD) Log with spdlog or fmt-based logger (async mode, JSON sink) or the framework logger (userver, Drogon/trantor); structured fields, levels, correlation/trace ids; never log secrets or personal data; never write via `std::cout` in services. Async logging avoids blocking request threads. ([spdlog](https://github.com/gabime/spdlog))
- **`CPP-OBS-02`** (SHOULD) Metrics via prometheus-cpp or OpenTelemetry metrics, named per Prometheus conventions (`snake_case`, base units, `_total` for counters); keep label cardinality bounded. High cardinality kills metrics backends. ([prometheus-cpp](https://github.com/jupp0r/prometheus-cpp))
- **`CPP-OBS-03`** (SHOULD) Tracing via the OpenTelemetry C++ SDK (traces and metrics stable; logs maturing, check the status table); build with `WITH_OTLP_GRPC/HTTP`, propagate W3C `traceparent`, and pass context across async boundaries explicitly (there is no auto-instrumentation agent for C++). Manual instrumentation is required. ([OpenTelemetry C++](https://opentelemetry.io/docs/languages/cpp/))
- **`CPP-OBS-04`** (MUST) Expose `/healthz` (liveness, no dependency checks) and `/readyz` (readiness: DB, broker) from a separate lightweight handler or listener; userver has built-in monitor/ping handlers, gRPC has the standard Health Checking protocol (`grpc.health.v1`). Orchestrators route on readiness. ([gRPC health checking](https://grpc.io/docs/guides/health-checking/))
- **`CPP-OBS-05`** (SHOULD) Make crashes diagnosable: build with `-g` (split debug info), keep symbol files per release, enable core dumps (`ulimit -c`, `kernel.core_pattern`), install a `std::set_terminate` handler that logs a stack trace (`std::stacktrace` C++23), and print TSan/ASan reports to stderr in sanitizer environments. Segfaults give no exception message. ([std::stacktrace](https://en.cppreference.com/w/cpp/utility/basic_stacktrace))

## OPS: configuration, packaging and deployment

- **`CPP-OPS-01`** (MUST) Config from environment/files into a typed struct at startup (CLI11/cxxopts, `toml++`, yaml-cpp, framework config); validate and fail fast; secrets only from env/vault. 12-factor. See specs/ARCHITECTURE.md §19. ([The Twelve-Factor App: Config](https://12factor.net/config))
- **`CPP-OPS-02`** (SHOULD) Package as a multi-stage OCI image: build stage with the pinned toolchain image, runtime stage `gcr.io/distroless/cc-debian12` (dynamic glibc) or `scratch`/`alpine` for static musl builds; run as non-root, read-only root filesystem, `HEALTHCHECK` or probes. Small attack surface; C++ links libstdc++ dynamically unless you ship it. ([distroless](https://github.com/GoogleContainerTools/distroless))
- **`CPP-OPS-03`** (SHOULD) Linking: prefer dynamic glibc with `-static-libstdc++ -static-libgcc` or a fully static musl build only if you have no `dlopen`/NSS/glibc-specific needs; strip with `objcopy --only-keep-debug` + `strip` and ship symbols separately. Static glibc breaks NSS and DNS; musl allocator is slow. ([GCC link options](https://gcc.gnu.org/onlinedocs/gcc/Link-Options.html))
- **`CPP-OPS-04`** (MUST) Graceful shutdown: handle `SIGTERM`/`SIGINT` with `asio::signal_set` (not raw signal handlers doing real work), stop accepting, drain in-flight requests with a deadline, join threads, flush logs, exit 0; the only async-signal-safe actions in a raw handler are `write` and setting a `volatile sig_atomic_t`/lock-free atomic. Non-async-signal-safe calls in handlers are UB. See specs/ARCHITECTURE.md §22. ([signal-safety(7)](https://man7.org/linux/man-pages/man7/signal-safety.7.html))
- **`CPP-OPS-05`** (MUST) Run-scoped caches: scope only `CCACHE_TEMPDIR` per run. Keep `CCACHE_DIR`, `VCPKG_DEFAULT_BINARY_CACHE`, `VCPKG_DOWNLOADS` and `CONAN_HOME` (it also holds profiles, remotes and `global.conf`) shared, because scoping them re-downloads and rebuilds everything; the vcpkg binary cache directory must exist before vcpkg runs. Enable ccache with `-DCMAKE_CXX_COMPILER_LAUNCHER=ccache`. The build directory is a preset `binaryDir`, not an env var. Per-run scoping of downloads is slow; build outputs and temp files are what collide. ([ccache manual](https://ccache.dev/manual/latest.html))
- **`CPP-OPS-06`** (MUST) Know the artifacts a build leaves: `build/`, `cmake-build-*/`, `CMakeCache.txt`, `CMakeFiles/`, `compile_commands.json`, `Testing/`, `*.gcda`, `*.gcno`, `*.gcov`, `*.profraw`, `*.profdata`, `*.lcov`, `vcpkg_installed/`, `core` and `core.[0-9]*`. Cleanup deletes an artifact directory only when it did not exist at the baseline (D25), and the `core` globs must never match `core.cpp`. Drives the loops cleanup. ([CMake generated files](https://cmake.org/cmake/help/latest/manual/cmake-buildsystem.7.html))
- **`CPP-OPS-07`** (SHOULD) Reproducible builds: pin toolchain image by digest, set `SOURCE_DATE_EPOCH`, avoid `__DATE__`/`__TIME__`, use `-ffile-prefix-map=<source dir>=.`, and publish an SBOM and signature. Verifiable artifacts. ([Reproducible Builds](https://reproducible-builds.org/docs/))

## DOC: documentation and review

- **`CPP-DOC-01`** (SHOULD) Document public headers with Doxygen comments (`///` or `/** */`, `@param`, `@return`, `@throws`/error contract, ownership and lifetime notes); generate with `doxygen` from `Doxyfile` or CMake `doxygen_add_docs`; enable `-Wdocumentation` on Clang. Ownership and lifetime are API contracts in C++. ([Doxygen](https://www.doxygen.nl/manual/docblocks.html))
- **`CPP-DOC-02`** (SHOULD) Repo docs: README with build/test/sanitizer commands, `docs/adr/` for decisions (build system, error strategy, exceptions policy), `CHANGELOG.md`, a `CONTRIBUTING.md` that names the presets. Build instructions are the main onboarding cost. ([ADR](https://adr.github.io/))
- **`CPP-DOC-03`** (MUST) Review focus: ownership and lifetimes first (who frees, dangling refs, callbacks capturing `this`), exception safety (basic/strong guarantee), data races, integer overflow and bounds, `noexcept` correctness, header hygiene and ABI, build-system link correctness, sanitizer/clang-tidy green. The highest-severity C++ defects are ownership and UB. ([CG Philosophy and Interfaces](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
- **`CPP-DOC-04`** (SHOULD) Mark uncertain-lifetime APIs with `[[nodiscard]]`, `[[clang::lifetimebound]]`/`[[gnu::...]]` where available, and document thread-safety class by class ("thread-safe", "thread-compatible", "thread-hostile"). Lifetime attributes let Clang warn about dangling references. ([Clang lifetimebound](https://clang.llvm.org/docs/AttributeReference.html#lifetimebound))

## FW: frameworks

- **`CPP-FW-01`** (SHOULD) Dominant choices as of 2026-11: Boost.Asio/Beast (low-level, most widely deployed foundation), gRPC C++ (RPC, Bazel/CMake), userver (coroutine microservice framework, used at 2GIS and T-Bank), Drogon (async web framework); the usage evidence is vendor/community self-reporting, there is no survey as precise as other ecosystems (JetBrains Developer Ecosystem lists C++ mostly as systems/embedded), so treat ranking as qualitative. Source honesty. ([userver](https://userver.tech/))
- **`CPP-FW-02`** (MUST) Framework conventions: Drogon expects controllers registered by macros (`METHOD_LIST_BEGIN`) and config JSON, with the ORM generating models (`drogon_ctl`); userver imposes components + YAML static config, its own coroutine runtime and `testsuite` (pytest-based) for functional tests; gRPC imposes generated `Service` classes and CMake `protobuf_generate`; Asio imposes executor/strand/completion-token discipline. Follow the framework layout inside the inbound adapter, and keep the application layer framework-free. Frameworks leak into every layer unless adapters stay thin. ([userver docs](https://userver.tech/))
- **`CPP-FW-03`** (MUST) Framework footguns: Asio handlers capturing raw `this` (use `shared_from_this` or coroutines), calling `io_context.run()` from many threads without strands, blocking in a handler, Drogon controllers doing blocking DB calls on the I/O loop, gRPC unbounded streams without flow control or deadlines, userver code using `std::mutex`/`std::this_thread::sleep_for` instead of `engine::` primitives, and mixing exceptions across framework callback boundaries. They cause production stalls and crashes. ([Asio strands](https://www.boost.org/doc/libs/release/doc/html/boost_asio/overview/core/strands.html))
- **`CPP-FW-04`** (SHOULD) Hexagonal mapping per framework: the inbound adapter owns controller/handler classes that call an application use-case (`PlaceOrderUseCase::execute`) and translate DTO ↔ domain; outbound adapters implement application ports with framework clients; `main.cpp` builds the object graph and starts the server (userver: component list and static config; Drogon: `app().registerController`; gRPC: `ServerBuilder::RegisterService`). Maintains the dependency rule despite framework magic. ([Drogon](https://github.com/drogonframework/drogon))

## Top 10 footguns

1. **Dangling references/views.** Bad: `std::string_view v = make_string();` or returning `const T&` to a local or a temporary. Fix: own the data (`std::string`), return by value, and enable `-Wdangling` plus ASan. ([CG F.43, F.45](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
2. **Callbacks capturing `this`.** Bad: `async_read(buf, [this](auto ec, auto n){...})` on an object that may be destroyed. Fix: `shared_from_this()` or coroutines owning the state. ([Asio](https://www.boost.org/doc/libs/release/doc/html/boost_asio.html))
3. **Uninstrumented or mixed sanitizer builds.** Bad: running TSan with only your code instrumented, or combining `-fsanitize=thread,address`. Fix: a dedicated `tsan` preset and separate `asan-ubsan` preset. ([GCC](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html))
4. **Data races as UB.** Bad: unsynchronised `bool done` read in a loop. Fix: `std::atomic<bool>`, `std::stop_token`, or a lock guarded by `std::scoped_lock`. ([CG CP.2](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
5. **Exception escaping a thread, `noexcept` function or destructor.** Bad: `std::thread t([]{ throw 1; });`. Fix: catch at the thread/task entry and convert to an error. ([CG E.16](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
6. **Raw `new`/`delete` and manual ownership.** Bad: `Foo* f = new Foo; ... delete f;`. Fix: `std::make_unique<Foo>()`. ([CG R.11](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
7. **Signed overflow and out-of-bounds `operator[]`.** Bad: `v[i]` with unchecked `i`, `int` size arithmetic. Fix: `-D_GLIBCXX_ASSERTIONS`/libc++ hardening, `std::span`, `.at()` at boundaries, UBSan in CI. ([libc++ hardening](https://libcxx.llvm.org/Hardening.html))
8. **Uninitialised members/locals.** Bad: `int x; use(x);`. Fix: `int x{};`, in-class initialisers, `-ftrivial-auto-var-init=zero` as backstop. ([OpenSSF](https://best.openssf.org/Compiler-Hardening-Guides/Compiler-Options-Hardening-Guide-for-C-and-C++.html))
9. **`using namespace` in headers and include-order dependencies.** Bad: `using namespace std;` in a `.hpp`. Fix: qualified names; headers self-contained (IWYU). ([CG SF.7](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines))
10. **Blocking the event loop / ignoring deadlines.** Bad: sync DB call or `future.get()` inside an Asio/Drogon/userver handler. Fix: async driver or a dedicated pool; set deadlines on every call. ([gRPC deadlines](https://grpc.io/docs/guides/deadlines/))
