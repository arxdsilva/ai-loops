# TypeScript / JavaScript (server-side) rules

Node 26 (Active LTS since 2026-10-28; 24 and 22 are Maintenance), TypeScript 5.8+ (7.0 is the native port), vitest 5, npm 11, as of 2026-11. Source: `research/languages/typescript.md`, with its Verification section applied. Bun and Deno deltas are marked in the rules. Pack data: `specs/languages/typescript/pack.json`; digest skill: `skills/lang-typescript`.

Project rules win: follow the repo's own configs (eslint or Biome, Prettier, tsconfig, package manager, test runner) over these defaults, and log each deviation with `loops run override` (`ROLES.md`, Project rules first). Layering, SOLID, testing and repo hygiene rules shared by every language live in `specs/ARCHITECTURE.md` and `specs/SOLID.md`; rules below only say how they look in TypeScript.


## REPO: repository and project management

- **`TS-REPO-01`** (SHOULD) Put sources in `src/`, tests colocated as `*.test.ts` (unit) or under `test/` (integration/e2e), emit to `dist/`, and set `"files": ["dist"]` or never publish the service at all. `package.json` has no standard layout, so a convention keeps globs and Docker copies stable. ([Node packages](https://nodejs.org/api/packages.html))
- **`TS-REPO-02`** (SHOULD) Use native workspaces (`"workspaces"` in npm/yarn/bun, `pnpm-workspace.yaml` in pnpm) for multi-package repos, with TS project references (`composite`, `tsc -b`) between packages. One lockfile, hoisted installs and incremental builds. ([npm workspaces](https://docs.npmjs.com/cli/v11/using-npm/workspaces))
- **`TS-REPO-03`** (AVOID) Add Turborepo or Nx only when task caching/graph ordering across 3+ packages is needed; otherwise plain workspace scripts. Task runners add config and cache-poisoning surface. ([Turborepo docs](https://turborepo.com/docs))
- **`TS-REPO-04`** (MUST) Bootstrap with `npm init -y` + `tsc --init`, or `npm create`/`pnpm create` of the framework (`nest new`, `npm create hono@latest`, `npm init fastify`); day one has lockfile, tsconfig, lint, test, CI, `.gitignore`, `engines`. A repo without a gate on commit one never gets one. ([NestJS first steps](https://docs.nestjs.com/first-steps))
- **`TS-REPO-05`** (MUST) Pick one package manager per repo, declare it in `"packageManager": "pnpm@x.y.z"`, commit exactly one lockfile, and install in CI with `npm ci` / `pnpm install --frozen-lockfile` / `yarn install --immutable` / `bun install --frozen-lockfile`. Two lockfiles drift; `npm install` mutates the lock and hides drift. ([npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci))
- **`TS-REPO-06`** (MUST) Commit the lockfile for applications and for libraries' own CI; pin direct deps exactly (`save-exact=true` in `.npmrc`) or rely on the lock plus Renovate. Reproducible installs; the lock pins transitive deps. ([Node security best practices](https://nodejs.org/en/learn/getting-started/security-best-practices))
- **`TS-REPO-07`** (SHOULD) Automate updates with Renovate or Dependabot, grouped, with a release cooldown (`minimumReleaseAge` in Renovate, pnpm `minimumReleaseAge`, npm `min-release-age=1`, v11.10+). Fresh malicious releases are usually yanked within hours. ([Renovate docs](https://docs.renovatebot.com/))
- **`TS-REPO-08`** (SHOULD) Remove unused deps and exports with `knip` in CI. Unused deps widen the supply-chain surface. ([knip](https://knip.dev/))
- **`TS-REPO-09`** (SHOULD) For published packages use SemVer, Changesets for changelogs/versions, `npm publish --provenance` (or trusted publishing, no token) from GitHub Actions with `id-token: write`, and check contents with `npm publish --dry-run` plus a `files` allowlist. Provenance links the tarball to the source commit. ([npm provenance](https://docs.npmjs.com/generating-provenance-statements))
- **`TS-REPO-10`** (MUST) Pin the toolchain three ways: `"engines": {"node": ">=24 <27"}` in `package.json` (set `engine-strict=true` in `.npmrc`), `.nvmrc` (`24`) or `.node-version`, and the Docker base tag; use `volta`/`mise`/`fnm` as the manager. `engines` alone only warns unless strict; CI and prod must match dev. ([npm package.json engines](https://docs.npmjs.com/cli/v11/configuring-npm/package-json#engines))
- **`TS-REPO-11`** (MUST) Ignore `node_modules/`, `dist/`, `coverage/`, `*.tsbuildinfo`, `.turbo/`, `.env*` (keep `.env.example`), and add `.editorconfig`, `.gitattributes` (`* text=auto eol=lf`), and a pre-commit runner (lefthook or husky + lint-staged). Keeps artifacts and secrets out of git. ([GitHub gitignore Node template](https://github.com/github/gitignore))
- **`TS-REPO-12`** (MUST) CI stages in order: install frozen, format check, lint, `tsc --noEmit`, build, test with coverage, `npm audit`/OSV, package; cache the package-manager store (not `node_modules`) keyed on the lockfile hash; matrix over supported Node majors. Fail fast and cheap first. ([actions/setup-node caching](https://github.com/actions/setup-node#caching-global-packages-data))
- **`TS-REPO-13`** (SHOULD) Use Conventional Commits and let Changesets/release-please generate changelogs and tags. Same flow as loops releases. ([Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/))

## TOOL: toolchain

- **`TS-TOOL-01`** (MUST) Run production on an Active or Maintenance LTS only. As of 2026-11: Node 26 is Active LTS (released 2026-05-05, LTS since 2026-10-28); 24 (Maintenance since 2026-10-20) and 22 are Maintenance LTS; 20 and 25 are EOL; 27 is alpha. From Node 27 the cadence becomes annual. EOL lines get no security fixes. ([Node releases](https://nodejs.org/en/about/previous-releases))
- **`TS-TOOL-02`** (MUST) Format with Prettier (`prettier --check .`; write with `--write`), config `.prettierrc.json`, and `.prettierignore`; or Biome's formatter if Biome is the linter. Never run both on the same files. One formatter ends style debates; two fight. ([Prettier CLI](https://prettier.io/docs/cli))
- **`TS-TOOL-03`** (MUST) Lint with ESLint flat config (`eslint.config.mjs`, `defineConfig`) plus `typescript-eslint` `strictTypeChecked` with `parserOptions.projectService: true`, run with `--max-warnings=0`; typescript-eslint supports TypeScript `>=4.8.4 <6.1.0` and does not list TS 7 (the native port, 7.0.2 latest on npm), so pin `typescript` to a supported 5.x/6.0 for linting or run TS 7 only for `tsc` until support lands. Type-aware rules catch floating promises and unsafe `any`. ([typescript-eslint typed linting](https://typescript-eslint.io/getting-started/typed-linting/))
- **`TS-TOOL-04`** (SHOULD) Acceptable alternative: Biome (`biome ci --reporter=github`) for speed; the CLI docs do not document type-aware rules, so treat it as unverified whether Biome replaces typescript-eslint rules such as `no-floating-promises`; keep `tsc` and a floating-promise check somewhere. Biome is one fast binary; its type-aware coverage is unverified. ([Biome CLI](https://biomejs.dev/reference/cli/))
- **`TS-TOOL-05`** (MUST) Enable at least `@typescript-eslint/no-floating-promises`, `no-misused-promises`, `await-thenable`, `no-explicit-any`, `consistent-type-imports`, and `eqeqeq`. These are the async and typing footguns. ([no-floating-promises](https://typescript-eslint.io/rules/no-floating-promises/))
- **`TS-TOOL-06`** (MUST) Typecheck with `tsc --noEmit` (or `tsc -b` in project references) as its own gate step even if the bundler/test runner strips types. esbuild, swc, vitest and Node strip types without checking them. ([Node TypeScript](https://nodejs.org/api/typescript.html))
- **`TS-TOOL-07`** (MUST) Set `strict: true`, `noUncheckedIndexedAccess: true`, `exactOptionalPropertyTypes: true`, `noImplicitOverride: true`, `verbatimModuleSyntax: true`, `noFallthroughCasesInSwitch: true`, `skipLibCheck: true`. `strict` alone leaves `arr[i]` typed as `T`, not `T | undefined`. ([tsconfig reference](https://www.typescriptlang.org/tsconfig/))
- **`TS-TOOL-08`** (MUST) Audit with `npm audit --audit-level=high --omit=dev` (pnpm: `pnpm audit --prod`), plus OSV-Scanner `osv-scanner scan source -r .` (v2 syntax); generate an SBOM with `npm sbom --sbom-format cyclonedx`. Advisory DBs differ; OSV reads lockfiles directly. ([npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit))
- **`TS-TOOL-09`** (SHOULD) Use the TypeScript language server (tsserver) via the editor with the workspace TypeScript version, and make format-on-save use only the repo's formatter. Editor TS version mismatch gives phantom errors. ([VS Code TypeScript](https://code.visualstudio.com/docs/languages/typescript))
- **`TS-TOOL-10`** (SHOULD) Node can run `.ts` directly via type stripping (stable in v25.2 and v24.12; default-on since v22.18/v23.6): use it for scripts and tests only if code is `erasableSyntaxOnly` (no `enum`, runtime `namespace`, parameter properties, decorators) and imports carry `.ts` extensions; keep a real build for services. Stripping is not type-checking; unsupported syntax throws `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`. ([Node TypeScript](https://nodejs.org/api/typescript.html))

## ARCH: architecture

- **`TS-ARCH-01`** (SHOULD) Choose hexagonal for services with real business rules and several IO edges; a thin CRUD service may stay layered, but write the choice as an ADR. Avoids ceremony where there is no domain. ([Hexagonal architecture (Cockburn)](https://alistair.cockburn.us/hexagonal-architecture/))
- **`TS-ARCH-02`** (MUST) Map loops layers to `src/domain`, `src/application`, `src/adapters/{inbound,outbound}`, `src/compose`, `src/main.ts` as in the tree above. Gives the arch checker fixed prefixes. See specs/ARCHITECTURE.md §4. ([dependency-cruiser rules](https://github.com/sverweij/dependency-cruiser/blob/main/doc/rules-reference.md))
- **`TS-ARCH-03`** (MUST) Import statements are `import x from './a.js'`, `import {y} from '@/app/z'`, `import type {T} from '...'`, `export * from`, `import('...')`, and CJS `require('...')`; relative specifiers resolve against the importing file and must carry the extension under `nodenext`. The arch parser needs every form including dynamic and type-only. ([Node ESM](https://nodejs.org/api/esm.html))
- **`TS-ARCH-04`** (MUST) There is no package-private visibility: ES modules export or not; `private` is TS-only and `#field` is runtime-private. Enforce layers with dependency-cruiser (`forbidden` rules by path regex, `severity: error`) or eslint-plugin-boundaries/`no-restricted-imports`; cycles are legal at runtime but break ESM init order, so forbid them (`circular: true`). The language will not stop `domain` importing `adapters`. ([dependency-cruiser rules](https://github.com/sverweij/dependency-cruiser/blob/main/doc/rules-reference.md))
- **`TS-ARCH-05`** (MUST) dependency-cruiser rule shape: `{name:"domain-pure", severity:"error", from:{path:"^src/domain"}, to:{path:"^src/(application|adapters|compose)|^node_modules/(?!zod)"}}`; run `depcruise src --config .dependency-cruiser.cjs`. Concrete, mechanical, exit-code driven. ([dependency-cruiser](https://github.com/sverweij/dependency-cruiser))
- **`TS-ARCH-06`** (MUST) Wire dependencies by constructor or factory argument in `compose/`; with NestJS use constructor injection with `@Inject(TOKEN)` for ports. Avoid service locators (`moduleRef.get`, global container lookups), property/field injection in domain or application, and `@Global()` modules. Hidden dependencies break unit tests and the dependency rule. ([NestJS providers](https://docs.nestjs.com/providers))
- **`TS-ARCH-07`** (MUST) Keep `domain/` free of `node:fs`, `node:net`, `node:http`, `node:child_process`, `process.env`, `Date.now()`, `new Date()`, `Math.random()`, `crypto.randomUUID()`, `fetch`, framework decorators, ORM entities; inject `Clock` and `IdGen` ports. Determinism and testability. See specs/ARCHITECTURE.md. See skills/consistency. ([Node process.env](https://nodejs.org/api/process.html#processenv))
- **`TS-ARCH-08`** (SHOULD) Define ports as small `interface`s in `application/` next to the consumer; adapters satisfy them structurally; use `type` branded ids (`type OrderId = string & {readonly __brand: 'OrderId'}`). Structural typing makes tiny ports free. ([TS handbook interfaces](https://www.typescriptlang.org/docs/handbook/2/objects.html))
- **`TS-ARCH-09`** (SHOULD) Size heuristics: file under ~300 lines, function under ~40 lines and cognitive complexity under 15 (`complexity`, `max-lines-per-function`, `max-params: 4` in ESLint), classes with one reason to change. Mirrors loops SOLID warnings. ([ESLint max-params](https://eslint.org/docs/latest/rules/max-params))
- **`TS-ARCH-10`** (MUST) Decorator-heavy NestJS entities (`@Entity`, `@Column`, `@ApiProperty`) belong in outbound/inbound adapters; map to plain domain objects at the boundary. Decorators couple the domain to TypeORM/Swagger. ([NestJS techniques: database](https://docs.nestjs.com/techniques/database))
- **`TS-ARCH-11`** (AVOID) Barrel files (`index.ts` re-exports) are allowed only at module public-API level, never across layers, and not inside hot modules. Barrels create accidental cycles and defeat tree-shaking and test startup. ([Vite performance: avoid barrel files](https://vite.dev/guide/performance#avoid-barrel-files))

## IDIOM: what to do and what to avoid

- **`TS-IDIOM-01`** (MUST) Throw `Error` subclasses only (never strings or plain objects), set `cause` (`new Error('x', {cause: e})`), model expected failures as a discriminated-union `Result` in domain/application, and map to HTTP at the edge. `catch (e)` is `unknown`; context is lost without `cause`. ([MDN Error cause](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error/cause))
- **`TS-IDIOM-02`** (MUST) Never `catch {}` silently; narrow with `instanceof` or a type guard before use (`useUnknownInCatchVariables` is on under `strict`). Swallowed errors hide faults. ([tsconfig useUnknownInCatchVariables](https://www.typescriptlang.org/tsconfig/#useUnknownInCatchVariables))
- **`TS-IDIOM-03`** (MUST) Handle absence with `T | undefined` and strict null checks; use `??` and `?.` rather than `||` for defaults; avoid `null` in new domain types, and treat `null` only as a wire/DB value at the adapter. `||` swallows `0` and `''`. ([TS handbook narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html))
- **`TS-IDIOM-04`** (AVOID) Avoid non-null assertions (`!`) and `as` casts on external data; validate with zod/valibot instead. Casts are unchecked lies. ([typescript-eslint no-non-null-assertion](https://typescript-eslint.io/rules/no-non-null-assertion/))
- **`TS-IDIOM-05`** (SHOULD) Prefer `readonly` fields, `ReadonlyArray`, `as const`, `Object.freeze` at boundaries, and immutable updates (`structuredClone`, spread); mutating shared module state is a bug. Shared mutable singletons are the JS version of a data race. ([TS handbook readonly](https://www.typescriptlang.org/docs/handbook/2/objects.html#readonly-properties))
- **`TS-IDIOM-06`** (MUST) Model states as discriminated unions with an exhaustive `switch` ending in a `never` assertion; avoid `enum` (runtime code, breaks type stripping): use string-literal unions or `as const` objects. Exhaustiveness is checked by the compiler. ([TS handbook narrowing: exhaustiveness](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#exhaustiveness-checking))
- **`TS-IDIOM-07`** (MUST) Ban `any`; use `unknown` at untrusted boundaries and narrow it; `@ts-expect-error` with a reason beats `@ts-ignore`, which is banned. `any` turns the checker off transitively. ([typescript-eslint ban-ts-comment](https://typescript-eslint.io/rules/ban-ts-comment/))
- **`TS-IDIOM-08`** (MUST) Release resources with `using`/`await using` (TS 5.2, Node 24+ for `Symbol.dispose` on some types) or `try/finally`; always close DB clients, streams and servers, and use `stream.pipeline` (promises) instead of `.pipe`. Unclosed handles keep the process alive and leak. ([TS 5.2 using](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-2.html))
- **`TS-IDIOM-09`** (MUST) Use `===`/`!==`; compare objects structurally with `node:util` `isDeepStrictEqual`, never `==` or `JSON.stringify`; use `Map`/`Set` for non-string keys. Reference equality surprises. ([ESLint eqeqeq](https://eslint.org/docs/latest/rules/eqeqeq))
- **`TS-IDIOM-10`** (MUST) Store instants as UTC ISO-8601 or epoch ms, never local time strings; use `Temporal` (Node flag-gated/polyfill as of 2026-11, check status) or `date-fns`/`luxon`, and never do money arithmetic in `number` (use integer minor units or `decimal.js`/`bigint`). `Date` is mutable, `0.1+0.2!==0.3`. ([MDN Temporal](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal))
- **`TS-IDIOM-11`** (SHOULD) Follow the Google TypeScript Style Guide naming: `UpperCamelCase` types, `lowerCamelCase` values, `CONSTANT_CASE` constants, no `I` prefix, named exports over default exports; document public API with TSDoc. Default exports defeat rename and grep. ([Google TS style guide](https://google.github.io/styleguide/tsguide.html))
- **`TS-IDIOM-12`** (AVOID) Decorators, `Proxy`, string evaluation (`new Function` and the global evaluator) and monkey-patching built-ins are allowed only inside framework adapters (NestJS decorators); never in domain code. Magic hides dependencies and breaks type stripping. ([typescript-eslint rules: implied string evaluation](https://typescript-eslint.io/rules/))
- **`TS-IDIOM-13`** (MUST) Footguns: `parseInt` without radix on user input, `Array.sort()` without comparator (string sort), `for..in` over arrays, `JSON.parse` result typed as `any`, `Number` precision above 2^53, `forEach(async ...)` (does not await). Each is a known production bug. ([MDN Array.sort](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/sort))
- **`TS-IDIOM-14`** (SHOULD) Use ESM: `"type": "module"`, `"module": "nodenext"`, explicit file extensions in relative imports, `import.meta.dirname` instead of `__dirname`; dual CJS/ESM publishing only for libraries, via the `exports` map (Node supports `require(esm)` from 22.12). Mixed module systems cause `ERR_REQUIRE_ESM` and double-instance bugs. ([Node packages exports](https://nodejs.org/api/packages.html))

## CONC: concurrency and the `-race` equivalent

- **`TS-CONC-01`** (MUST) Know the model: one JS thread runs an event loop; I/O is async via libuv; CPU work uses `worker_threads`; `cluster`/multiple processes scale across cores. Choice of scaling unit follows from this. ([Node event loop](https://nodejs.org/en/learn/asynchronous-work/event-loop-timers-and-nexttick))
- **`TS-CONC-02`** (MUST) Treat module-level mutable state, in-memory caches, and check-then-act across an `await` as shared state: do not read, `await`, then write back; use a per-key mutex/queue, DB constraints, or atomic ops. Another request interleaves at every `await`. ([Node: Don't block the event loop](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop))
- **`TS-CONC-03`** (SHOULD) Between workers use `postMessage` with structured clone; use `SharedArrayBuffer` plus `Atomics` only with a documented protocol; never share mutable objects. The only true memory races in JS live here. ([worker_threads](https://nodejs.org/api/worker_threads.html))
- **`TS-CONC-04`** (MUST) No JS race detector exists: record `race.mode = none` and enforce shuffled + concurrent + repeated test runs (vitest `--sequence.shuffle.files --sequence.shuffle.tests --sequence.seed=N --sequence.concurrent`, `--repeats=N`; node:test `--test-randomize --test-concurrency` (`--test-randomize` needs Node 26.1+, early development, absent on Node 24/22); jest 30 `--randomize`). Surfaces order and shared-state dependence, the realistic race class. ([Vitest CLI](https://vitest.dev/guide/cli.html))
- **`TS-CONC-05`** (AVOID) Do not use test retries (`--retry.count`, default 0) to hide flaky tests in the gate; keep retry count 0. Retries mask races. ([Vitest CLI](https://vitest.dev/guide/cli.html))
- **`TS-CONC-06`** (MUST) Never block the event loop: no `*Sync` fs/crypto calls in request paths, no big `JSON.parse`/`JSON.stringify`, no catastrophic-backtracking regex on user input; offload CPU to `worker_threads` or a queue (e.g., piscina). One blocked tick stalls every request. ([Don't block the event loop](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop))
- **`TS-CONC-07`** (MUST) Every promise is awaited, returned, or explicitly `void`-ed with a catch (`no-floating-promises`); `Promise.all` fails fast, use `Promise.allSettled` when partial results are fine; cap parallelism (p-limit). Node's default `--unhandled-rejections=throw` crashes the process on an unhandled rejection. ([Node process unhandledRejection](https://nodejs.org/api/process.html#event-unhandledrejection))
- **`TS-CONC-08`** (MUST) Propagate cancellation with `AbortSignal` (`AbortSignal.timeout(ms)`, `AbortSignal.any([...])`); pass `signal` to `fetch`, `fs.promises`, `events.once`, streams, DB drivers that accept it; abort on client disconnect and shutdown. JS has no implicit context; cancellation is opt-in. ([Node AbortSignal](https://nodejs.org/api/globals.html#class-abortsignal))
- **`TS-CONC-09`** (MUST) Set server timeouts (`headersTimeout`, `requestTimeout`, `keepAliveTimeout`) and client timeouts on every outbound call. Slowloris and hung upstreams. ([Node security best practices](https://nodejs.org/en/learn/getting-started/security-best-practices))
- **`TS-CONC-10`** (SHOULD) Background work uses a durable queue (BullMQ, pg-boss, SQS), idempotent handlers, and shutdown that stops accepting jobs, drains in-flight ones, then exits. In-process timers die with the pod. See skills/jobs-and-state-machines. ([BullMQ](https://docs.bullmq.io/))

## TEST: testing

- **`TS-TEST-01`** (SHOULD) Default to vitest (ESM/TS native, fast, Jest-compatible API); jest 30 is acceptable for existing suites; `node:test` for zero-dependency libraries; Bun users use `bun test`, Deno users `deno test`; end-to-end via supertest or `app.inject()` (Fastify) or Playwright for browsers. Jest's ESM/TS support still needs transforms. ([Vitest](https://vitest.dev/guide/))
- **`TS-TEST-02`** (MUST) Test file globs: `**/*.test.ts`, `**/*.spec.ts`, `**/*.test.mts`, `**/*.e2e-spec.ts`, `**/__tests__/**`, `test/**`; JS twins `*.test.js`/`*.test.mjs`. The test guard and ownership globs need them. ([Vitest include](https://vitest.dev/config/include))
- **`TS-TEST-03`** (SHOULD) Use `describe`/`it`, `it.each` / `test.each` tables, arrange-act-assert, and names that read `it('rejects an expired token')`. Same table-driven discipline as Go. ([Vitest test API](https://vitest.dev/api/))
- **`TS-TEST-04`** (SHOULD) Prefer fakes of ports (in-memory repo, fake clock) over module mocking; use `vi.fn`/`vi.spyOn` for interaction checks, `vi.useFakeTimers()` for time, and `msw` or `undici` MockAgent for HTTP; avoid `vi.mock` of internal modules. Module mocking couples tests to file layout. ([Vitest mocking](https://vitest.dev/guide/mocking))
- **`TS-TEST-05`** (SHOULD) Integration tests use Testcontainers for Node with a real Postgres/Redis/Kafka, one schema or transaction per test (or `TRUNCATE`), and migrations applied once in a global setup. Mocks of the DB hide SQL and driver bugs. ([Testcontainers for Node](https://node.testcontainers.org/))
- **`TS-TEST-06`** (MUST) Coverage: install `@vitest/coverage-v8`; command `vitest run --coverage --coverage.reporter=lcov` writes `coverage/lcov.info`; `coverage.include: ['src/**/*.ts']` so untested files count; v8 provider uses AST remapping since vitest 3.2 and matches Istanbul accuracy. Alternatives: jest `--coverage --coverageReporters=lcov` (`coverage/lcov.info`), `node --test --experimental-test-coverage --test-reporter=lcov --test-reporter-destination=lcov.info`, Bun `bun test --coverage --coverage-reporter=lcov` (`coverage/lcov.info`), Deno `deno test --coverage=cov && deno coverage cov --lcov`. lcov is the common denominator and carries line+branch. ([Vitest coverage](https://vitest.dev/guide/coverage.html))
- **`TS-TEST-07`** (SHOULD) Exclude generated code and types-only files via `coverage.exclude` (`**/*.d.ts`, `**/generated/**`, `**/*.config.*`, `**/migrations/**`); the generated header marker is `@generated` or `// This file was automatically generated`. Generated code distorts the percentage. ([Vitest coverage config](https://vitest.dev/config/coverage))
- **`TS-TEST-08`** (MUST) Compute coverage of new code in loops: parse lcov, intersect `DA:` lines with the `git diff -U0` added ranges of non-test source files, require at least 70%; do not rely on `coverage.thresholds`, which is repo-wide. `diff-cover` (Python) can also read coverage reports, but its lcov support is unverified here. Hard gate is about changed lines. ([Vitest coverage config thresholds/changed](https://vitest.dev/config/coverage))
- **`TS-TEST-09`** (SHOULD) Use fast-check for property tests on parsers, money math, state machines, and codecs (`fc.assert(fc.property(...))`, seed via `fc.configureGlobal({seed})`); add Stryker mutation tests on the domain package only, nightly. Properties find edge cases tables miss; mutation is expensive. ([fast-check docs](https://fast-check.dev/docs/introduction/))
- **`TS-TEST-10`** (MUST) Test isolation: no shared module state between tests; keep vitest `isolate: true` (default) and the `forks` pool; reset mocks (`mockReset`, `restoreMocks`) and timers; control `Date` and randomness via injected ports. Leaks cause order-dependent failures. ([Vitest CLI](https://vitest.dev/guide/cli.html))
- **`TS-TEST-11`** (SHOULD) Set `testTimeout`/`hookTimeout` explicitly and fail on open handles (`--detectOpenHandles` for jest, `why-is-node-running` for debugging). Hung tests stall the gate. ([Vitest testTimeout](https://vitest.dev/config/testtimeout))
- **`TS-TEST-12`** (SHOULD) Fast loop: `vitest` (watch by default in a TTY), `vitest run path/to/file.test.ts -t "name"`, `vitest related <file>` or `vitest run --changed <base>` for impacted tests; CI uses `vitest run` (no watch) and `--shard=i/n` across runners. Tight TDD loop; CI must not hang in watch mode. ([Vitest CLI](https://vitest.dev/guide/cli.html))

## PERF: performance and profiling

- **`TS-PERF-01`** (SHOULD) Benchmark with Vitest 5 benchmarking: put benchmarks in `*.bench.ts` files and run them with `vitest bench` (they do not run from `*.test.ts` under `vitest run`; `import {bench} from "vitest"` in a test file throws "bench is not a function" in 5.1) or tinybench/mitata directly, never ad-hoc `Date.now()` loops; compare against a saved baseline and treat results as noisy. JIT warm-up and GC distort single runs. ([Vitest benchmarking](https://vitest.dev/guide/benchmarking))
- **`TS-PERF-02`** (SHOULD) Profile CPU with `node --cpu-prof` or `--inspect` + Chrome DevTools, heap with `--heap-prof`/heap snapshots, and use `clinic.js` or `0x` flamegraphs; continuous profiling via Pyroscope or Datadog if available. Measure before tuning. ([Node diagnostics](https://nodejs.org/en/learn/diagnostics/user-journey))
- **`TS-PERF-03`** (SHOULD) Tune memory with `--max-old-space-size` sized under the container limit, use `NODE_ENV=production`, avoid per-request closures in hot paths, and prefer streams over buffering large bodies. Node's default heap may exceed the cgroup limit and cause OOM kills. ([Node CLI options](https://nodejs.org/api/cli.html#--max-old-space-sizesize-in-mib))
- **`TS-PERF-04`** (AVOID) Avoid hot-path mistakes: sync I/O, `JSON.stringify` of large graphs per request, N+1 awaits in a loop (batch with `Promise.all` plus a limit), spreading large arrays in reduce (O(n^2)), unbounded in-memory caches, and regex on untrusted input. Common Node latency killers. ([Don't block the event loop](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop))
- **`TS-PERF-05`** (SHOULD) Startup: build to JS with `tsc`/swc/esbuild for production images; do not run `ts-node` or `tsx` in production; consider Node's compile cache (`module.enableCompileCache()`) for CLIs. Runtime transpile adds seconds to cold start. ([Node module compile cache](https://nodejs.org/api/module.html#module-compile-cache))

## SEC: security

- **`TS-SEC-01`** (MUST) Use parameterised queries only (`pg` `$1`, Prisma/Drizzle/Kysely builders); never build SQL with template strings from input; use `execFile`/`spawn` with an argv array and never `exec` or `shell: true` for untrusted data. SQL and command injection. ([OWASP SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html))
- **`TS-SEC-02`** (MUST) Parse untrusted JSON with `JSON.parse` then a schema; reject `__proto__`/`constructor` keys, avoid recursive merges and `Object.assign` of input, use `Object.create(null)` maps or `Map`; avoid `yaml.load` unsafe tags, string evaluation, `vm` as a sandbox, and `node-serialize`; disable XML external entities in XML parsers. Prototype pollution and deserialization RCE. ([Node security best practices](https://nodejs.org/en/learn/getting-started/security-best-practices))
- **`TS-SEC-03`** (MUST) Add `helmet` (Express/Fastify `@fastify/helmet`/Hono `secureHeaders`), configure CORS with an explicit origin allowlist, use CSRF tokens or SameSite cookies for cookie auth, block SSRF with an allowlist and no redirects to private ranges, and canonicalise paths (`path.resolve` then prefix check) to stop traversal. Defaults are permissive. ([OWASP Node.js Security](https://cheatsheetseries.owasp.org/cheatsheets/Nodejs_Security_Cheat_Sheet.html))
- **`TS-SEC-04`** (MUST) Read secrets from env or a vault only in `main.ts`/config adapter; never commit `.env`; hash passwords with argon2id (`argon2`) or `crypto.scrypt`; use `crypto.randomBytes`/`randomUUID` for tokens (never `Math.random`); compare secrets with `crypto.timingSafeEqual`. Wrong primitives are silent vulnerabilities. ([OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html))
- **`TS-SEC-05`** (MUST) Validate every inbound payload, env var and queue message at the adapter with zod or valibot (`schema.parse`/`safeParse`), derive types with `z.infer`, and pass only parsed values inward; fastify uses JSON Schema (ajv), NestJS uses `class-validator` with `ValidationPipe({whitelist:true, forbidNonWhitelisted:true})`. TS types vanish at runtime. ([Zod](https://zod.dev/))
- **`TS-SEC-06`** (MUST) Treat install scripts as untrusted: use `npm ci --ignore-scripts` (or `ignore-scripts=true` in `.npmrc`) and allow builds per package; pnpm blocks dependency build scripts by default and uses `allowBuilds` with `strictDepBuilds`; also `blockExoticSubdeps`, `minimumReleaseAge` (default 1 day) and `trustPolicy: no-downgrade`; verify with `npm audit signatures`. `postinstall` runs arbitrary code at install (Shai-Hulud, event-stream class attacks). ([pnpm supply chain security](https://pnpm.io/supply-chain-security))
- **`TS-SEC-07`** (MUST) Review lockfile diffs in PRs, watch for typosquats and new maintainers, use scoped registries/mirrors, and never `npm install` a package an agent suggests without checking it exists and its age. LLM-hallucinated package names are squatted. ([OWASP Node.js Security](https://cheatsheetseries.owasp.org/cheatsheets/Nodejs_Security_Cheat_Sheet.html))
- **`TS-SEC-08`** (SHOULD) Run SAST with Semgrep (`semgrep scan --config p/typescript --config p/nodejs`) and/or CodeQL; ESLint `eslint-plugin-security` is a weak supplement. Pattern rules catch injection sinks. ([Semgrep docs](https://semgrep.dev/docs/))
- **`TS-SEC-09`** (SHOULD) Consider Node's permission model (`--permission --allow-fs-read=... `) for hardening; flags change between releases, so check the docs for the pinned version. Limits the damage from malicious dependencies. ([Node permissions](https://nodejs.org/api/permissions.html))
- **`TS-SEC-10`** (MUST) Never log secrets, tokens, or full request bodies; use pino `redact` paths. Logs leak credentials. ([pino redaction](https://getpino.io/#/docs/redaction))

## DATA: persistence

- **`TS-DATA-01`** (SHOULD) Prefer a typed query builder or thin ORM: Kysely or Drizzle for SQL-first teams, Prisma for schema-first with generated client, TypeORM/MikroORM only where already used; raw SQL via `pg`/`postgres.js` for hot paths. Keep ORM entities in adapters. Types from schema beat hand-written casts. ([Kysely](https://kysely.dev/))
- **`TS-DATA-02`** (MUST) Migrations are versioned files in `migrations/`, applied by a tool (Prisma Migrate, drizzle-kit, node-pg-migrate, Knex, Flyway) in CI/deploy, never `synchronize: true` in prod; use expand-contract for zero downtime. Auto-sync drops data. ([Prisma Migrate](https://www.prisma.io/docs/orm/prisma-migrate))
- **`TS-DATA-03`** (SHOULD) Open transactions in the application layer through a `UnitOfWork` port (`runInTransaction(fn)`), pass the tx handle explicitly (or via `AsyncLocalStorage`), and keep them short with no network calls inside. Hidden ambient transactions leak across `await`s. See specs/ARCHITECTURE.md. ([Node AsyncLocalStorage](https://nodejs.org/api/async_context.html))
- **`TS-DATA-04`** (AVOID) Avoid N+1: use joins, `include`/`with`, DataLoader batching (GraphQL), and `inArray` batches; log query counts in tests; avoid lazy-loading proxies (TypeORM `lazy`). N+1 is the top ORM defect. ([DataLoader](https://github.com/graphql/dataloader))
- **`TS-DATA-05`** (MUST) Use one shared pool per process (`pg.Pool` with `max`, `idleTimeoutMillis`, `connectionTimeoutMillis`, `statement_timeout`), handle `pool.on('error')`, release clients in `finally`, and size `max` against `processes × replicas` vs DB limits. Leaked clients exhaust the pool. ([node-postgres pool](https://node-postgres.com/apis/pool))
- **`TS-DATA-06`** (SHOULD) Use the outbox pattern for events published with a DB write and make consumers idempotent. Dual writes lose messages. See skills/consistency. ([Transactional outbox](https://microservices.io/patterns/data/transactional-outbox.html))

## API: APIs and integration

- **`TS-API-01`** (SHOULD) Choose per FW section: Fastify for performance and schema-first, NestJS for large teams, Hono for edge/multi-runtime, Express for legacy; routes live in inbound adapters, middleware handles cross-cutting concerns only. Frameworks differ in lifecycle hooks. ([Fastify lifecycle](https://fastify.dev/docs/latest/Reference/Lifecycle/))
- **`TS-API-02`** (SHOULD) Generate the contract rather than hand-writing: code-first OpenAPI from zod/typebox (`@fastify/swagger`, `@asteasolutions/zod-to-openapi`, `@nestjs/swagger`) or OpenAPI-first with `openapi-typescript`; gRPC via `@grpc/grpc-js` + `ts-proto`; version via path or header. Drift between docs and code. ([OpenAPI spec](https://spec.openapis.org/oas/latest.html))
- **`TS-API-03`** (MUST) Return RFC 9457 `application/problem+json` for errors from one central error handler; map domain errors to status codes at the adapter; never leak stack traces. Uniform, safe errors. ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457))
- **`TS-API-04`** (MUST) Outbound calls get timeout (`AbortSignal.timeout`), bounded retries with jittered backoff only for idempotent operations, circuit breaker (`opossum`/`cockatiel`), and idempotency keys on mutating endpoints; inbound rate-limit with `@fastify/rate-limit`/`express-rate-limit`. Cascading failures. ([cockatiel](https://github.com/connor4312/cockatiel))
- **`TS-API-05`** (MUST) Messaging: kafkajs/Confluent client with manual commit after processing, BullMQ/NATS/SQS clients with DLQ; handlers are idempotent because delivery is at-least-once. Redelivery is normal. ([KafkaJS](https://kafka.js.org/))
- **`TS-API-06`** (MUST) Use built-in `fetch` (undici) with a shared `Agent` for keep-alive and pass `signal`; use `undici` directly for pooling control; avoid `axios` defaults without timeouts. Default `fetch` has no timeout. ([Node fetch/undici](https://nodejs.org/api/globals.html#fetch))
- **`TS-API-07`** (MUST) Limit request body size and parse only expected content types (`bodyLimit` in Fastify, `express.json({limit})`). Memory DoS. ([Fastify server options](https://fastify.dev/docs/latest/Reference/Server/#bodylimit))

## OBS: observability

- **`TS-OBS-01`** (MUST) Log JSON with pino (Fastify's default; `nestjs-pino`), levels `fatal..trace`, a request-id per request propagated via `AsyncLocalStorage`, and no PII; never `console.log` in services. Structured logs are queryable; pino is async and fast. ([pino](https://getpino.io/))
- **`TS-OBS-02`** (SHOULD) Expose Prometheus metrics via `prom-client` (or the OpenTelemetry metrics SDK), with `snake_case` names, base units and bounded label cardinality. Label explosion costs money. ([prom-client](https://github.com/siimon/prom-client))
- **`TS-OBS-03`** (SHOULD) Trace with OpenTelemetry JS: `@opentelemetry/sdk-node` plus auto-instrumentations, loaded before app code (`node --import ./instrumentation.js`), W3C trace context propagated to logs; tracing and metrics are stable, logs are maturing (check as of 2026-11). Late-loaded SDK misses patched modules (ESM needs the import hook). ([OpenTelemetry JS](https://opentelemetry.io/docs/languages/js/))
- **`TS-OBS-04`** (MUST) Provide `/healthz` (liveness, no dependencies) and `/readyz` (readiness, checks DB), via `@nestjs/terminus` or a plain route; flip readiness to false at shutdown start. Orchestrators route on these. ([NestJS Terminus](https://docs.nestjs.com/recipes/terminus))
- **`TS-OBS-05`** (MUST) Report errors with Sentry or OTel exception events, and register `process.on('unhandledRejection')`/`'uncaughtException'` handlers that log then exit non-zero, never continue. Continuing after uncaught exceptions leaves undefined state. ([Node process events](https://nodejs.org/api/process.html#event-uncaughtexception))

## OPS: configuration, packaging and deployment

- **`TS-OPS-01`** (MUST) Parse `process.env` once in a config module with a zod schema (or `@nestjs/config` + validation, `env-schema`), fail fast on boot, inject typed config, never read `process.env` elsewhere; Node `--env-file=.env` is for dev only. Typed, fail-fast config. ([Twelve-Factor config](https://12factor.net/config))
- **`TS-OPS-02`** (MUST) Package as a multi-stage Docker image: build stage `npm ci` + `tsc`, runtime stage `npm ci --omit=dev`, copy `dist/`, pinned LTS base tag or digest (slim or distroless), `USER node`, `NODE_ENV=production`, `.dockerignore` for `node_modules`, `.git`, `.env`. Small, reproducible, non-root. ([OWASP Node.js Docker](https://cheatsheetseries.owasp.org/cheatsheets/NodeJS_Docker_Cheat_Sheet.html))
- **`TS-OPS-03`** (SHOULD) Single-binary options (Node SEA, `bun build --compile`, `deno compile`) are viable for CLIs and simple services but have limits (SEA is CJS-first, native addons); default to container images. Trade-offs: size, addon support. ([Node SEA](https://nodejs.org/api/single-executable-applications.html))
- **`TS-OPS-04`** (MUST) Handle `SIGTERM`/`SIGINT`: flip readiness, `server.close()` (plus `closeIdleConnections()`), abort in-flight with an `AbortController`, close DB and queue clients, force-exit after a deadline; run `node dist/main.js` via exec form, not `npm start`, with `--init`/tini. npm does not forward signals; Kubernetes sends SIGTERM. ([Node http server.close](https://nodejs.org/api/http.html#serverclosecallback))
- **`TS-OPS-05`** (SHOULD) Run-scoped caches: point `npm_config_cache` (npm), `PNPM_HOME`/`npm_config_store_dir` (pnpm store), `YARN_CACHE_FOLDER`, `BUN_INSTALL_CACHE_DIR`, `DENO_DIR` at the per-run dir; `TMPDIR` for temp; `node_modules/.cache` (eslint, babel, vite) lives in the tree. Avoid polluting the user's global cache; re-downloads are costly. ([npm config cache](https://docs.npmjs.com/cli/v11/using-npm/config#cache))
- **`TS-OPS-06`** (MUST) Artifacts left behind: `dist/`, `build/`, `coverage/`, `*.tsbuildinfo`, `.turbo/`, `.vitest/`/`node_modules/.vite`, `node_modules/.cache/`, `.eslintcache`, `*.cpuprofile`, `*.heapprofile`, `*.heapsnapshot`, `.nyc_output/`, `junit.xml`, `lcov.info`; `node_modules/` itself only if created by the run. Drives cleanup. ([tsconfig tsBuildInfoFile](https://www.typescriptlang.org/tsconfig/#tsBuildInfoFile))
- **`TS-OPS-07`** (MUST) Do not use `npm install -g` in CI; invoke tools via `npx --no-install`, `pnpm exec` or `package.json` scripts so versions come from the lockfile. Global tools drift. ([npx](https://docs.npmjs.com/cli/v11/commands/npx))
- **`TS-OPS-08`** (SHOULD) Default to Node for new services; choose Bun (`bun.lock`, `bun test`, `bun run`) or Deno (`deno.json`, permissions by default) only deliberately, since test, coverage and install tooling differ per runtime. Runtime choice changes every command in the pack. ([Bun docs](https://bun.sh/docs))

- **`TS-DOC-02`** (SHOULD) README states Node version, package manager, scripts (`dev`, `build`, `test`, `lint`), env vars; keep ADRs in `docs/adr/` and a Changesets-generated `CHANGELOG.md`. Onboarding in one page. ([Changesets](https://github.com/changesets/changesets))

The highest-yield TS review items. ([Google TS style guide](https://google.github.io/styleguide/tsguide.html))

## FW: frameworks

- **`TS-FW-01`** (SHOULD) Dominant frameworks: Express (largest installed base, maintenance-mode feel), NestJS (enterprise), Fastify (performance), Hono (edge, multi-runtime); check current usage in the State of JS / npm trends before choosing. Pick on team size and runtime. ([State of JS](https://stateofjs.com/))
- **`TS-FW-02`** (SHOULD) NestJS: modules, DI, decorators; follow its folder-per-feature layout only if domain and application stay decorator-free; unit tests via `Test.createTestingModule`; conflict with hexagonal is entities/DTO decorators and global providers. Nest's default is layered. ([NestJS modules](https://docs.nestjs.com/modules))
- **`TS-FW-03`** (SHOULD) Fastify: encapsulated plugins with `fastify-plugin` only for shared decorators, JSON Schema per route, `app.inject()` for tests (no port), `fastify.register` as the composition root. Plugin scope is the DI mechanism. ([Fastify plugins](https://fastify.dev/docs/latest/Reference/Plugins/))
- **`TS-FW-04`** (SHOULD) Hono: web-standard `Request`/`Response`, `app.request()` for tests, `zValidator` for validation, runs on Node/Bun/Deno/Workers; keep handlers thin. Portability. ([Hono docs](https://hono.dev/docs/))
- **`TS-FW-05`** (MUST) Express: v5 handles rejected promises in async handlers; still add a final error middleware, and avoid `app.use` order bugs and `req.body` untyped access (parse with zod). v4 swallowed async errors. ([Express 5 migration](https://expressjs.com/en/guide/migrating-5.html))
- **`TS-FW-06`** (MUST) NestJS footguns: circular module/provider dependencies (`forwardRef`), request-scoped providers cascading and slowing everything, `@Global()` overuse, `synchronize: true`, missing `app.enableShutdownHooks()`; Express/Fastify footguns: unhandled async errors, missing `bodyLimit`. Known framework traps. ([NestJS injection scopes](https://docs.nestjs.com/fundamentals/injection-scopes))

## Top 10 footguns

1. **Floating promises.** Bad: `saveAudit(x);` (rejection becomes `unhandledRejection`, which crashes Node by default). Fix: `await saveAudit(x)` or `void saveAudit(x).catch(log)`; lint `no-floating-promises`. ([source](https://typescript-eslint.io/rules/no-floating-promises/))
2. **`forEach(async)`.** Bad: `items.forEach(async i => await save(i))`. Fix: `await Promise.all(items.map(save))` with a concurrency cap, or a `for...of` loop. ([source](https://typescript-eslint.io/rules/no-misused-promises/))
3. **Blocking the event loop.** Bad: `fs.readFileSync`, large `JSON.parse`, nested-quantifier regex in a handler. Fix: async APIs, `worker_threads`, input limits. ([source](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop))
4. **Types are not validation.** Bad: `const body = req.body as CreateUser`. Fix: `CreateUser.parse(req.body)` with zod/valibot. ([source](https://zod.dev/))
5. **`strict` without `noUncheckedIndexedAccess`.** Bad: `const x = arr[i]; x.id` types as safe. Fix: enable the flag and handle `undefined`. ([source](https://www.typescriptlang.org/tsconfig/#noUncheckedIndexedAccess))
6. **Install scripts and floating versions.** Bad: `npm install` in CI, `postinstall` allowed. Fix: `npm ci --ignore-scripts`, lockfile review, release cooldown. ([source](https://nodejs.org/en/learn/getting-started/security-best-practices))
7. **Prototype pollution.** Bad: `Object.assign(target, JSON.parse(input))` or recursive merge. Fix: schema validation, `Map`, `Object.create(null)`. ([source](https://nodejs.org/en/learn/getting-started/security-best-practices))
8. **Check-then-act across `await`.** Bad: `if (!(await exists(id))) await create(id)`. Fix: DB unique constraint with upsert, or a per-key lock. ([source](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop))
9. **PID 1 and signals.** Bad: `CMD npm start`, no shutdown handler (SIGTERM lost, requests dropped). Fix: `CMD ["node","dist/main.js"]` with an init process and graceful `server.close()`. ([source](https://cheatsheetseries.owasp.org/cheatsheets/NodeJS_Docker_Cheat_Sheet.html))
10. **Type stripping is not type checking, and `enum` breaks it.** Bad: shipping on `node file.ts` with no `tsc`, using `enum`/parameter properties. Fix: `tsc --noEmit` in the gate and `erasableSyntaxOnly`. ([source](https://nodejs.org/api/typescript.html))
