# loops for Cursor

Generated by `loops port build` from the canonical plugin (repository root). Do not edit; see specs/PLATFORMS.md §3.3.

## Install

- **Marketplace:** the repository root holds `.cursor-plugin/marketplace.json`, which points at `platforms/cursor`. Install `loops` from the Cursor marketplace, or import the repository into a team marketplace.
- **Local development:** copy this directory to `~/.cursor/plugins/local/loops` and restart Cursor.

Commands: `/work` (also model-invocable), `/init`, `/status`, `/report` (manual only).

## What is in the package

- `agents/`: the role subagents (`is_background` for roles that run in parallel waves). No role is `readonly`: every role writes its own run-dir file, so read-only roles are told in their instructions not to edit repo code.
- `skills/`, `specs/`, `templates/`, `ROLES.md`: the canonical workflow.
- `hooks/hooks.json`: session context, read and model guards, post-edit gofmt, tracing, subagent lanes and the stop gate (`loop_limit: 5`).
- `rules/loops.mdc`: the always-on plugin context.

## Binary

`bin/loops` uses `loops` from PATH when it reports version 0.4.1, else a cached binary, else downloads the prebuilt release binary for your OS/arch (checksum-verified, no Go needed). Only when no prebuilt binary exists does it fall back to `go install github.com/arxdsilva/ai-loops/cmd/loops@v0.4.1`.

## Caveats

- Tool allowlists are not expressible, and read-only roles are restricted by instruction only.
- Models: roles use `inherit` unless `loops port build --models <file.json>` maps the tiers.
