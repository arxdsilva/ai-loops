# Kotlin (JVM backend) rules

Kotlin `2.4.x` (stable 2.4.21), JDK 21 or 25 LTS, Gradle Kotlin DSL, as of 2026-11. Source: `research/languages/kotlin.md` (rule IDs kept; Verification applied). Pack: `specs/languages/kotlin/pack.json`. Universal rules are not repeated: layering is `specs/ARCHITECTURE.md`, SOLID is `specs/SOLID.md`, the gate and race policy are `specs/WORKFLOW.md §6`.

Project rules win: follow the project's own config (detekt/ktlint/`.editorconfig`, framework conventions) over these defaults, and log every override with `loops run override`.

Race policy: the JVM has no race detector, so `race.mode = none`. The gate enforces the substitute: parallel JUnit and random order from `junit-platform.properties` (`KT-TEST-10`), run once in `test` and twice more in `test-repeat`; `KT-CONC-04` covers Lincheck.


## REPO

- **`KT-REPO-01`** (MUST) Use the Gradle standard source layout `src/{main,test}/{kotlin,java,resources}`; mirror package names as directories (root package omitted is allowed). One top-level class per file named `Foo.kt`. Why: Tooling (Gradle, Kover, arch checker) assumes it. ([source](https://kotlinlang.org/docs/coding-conventions.html))
- **`KT-REPO-02`** (SHOULD) Use Gradle multi-project (`include(":domain", ":application", ...)` in `settings.gradle.kts`); split modules by hexagonal layer, not by technical noise. Keep a single repo until teams or release cadences diverge. Why: Module boundaries make the dependency rule compiler-enforced. ([source](https://docs.gradle.org/current/userguide/multi_project_builds.html))
- **`KT-REPO-03`** (SHOULD) Put shared build logic in an included build `build-logic/` (convention plugins in `src/main/kotlin/*.gradle.kts`), referenced via `pluginManagement { includeBuild("build-logic") }`. Do not use `allprojects {}`/`subprojects {}` or `buildSrc` for new work. Why: Convention plugins keep configuration-cache and incremental-build friendly. ([source](https://docs.gradle.org/current/userguide/implementing_gradle_plugins_precompiled.html))
- **`KT-REPO-04`** (SHOULD) Bootstrap from the official starter: Spring Initializr (Kotlin, Gradle-Kotlin) or `ktor-project-generator`/IntelliJ Ktor wizard; a day-one repo has wrapper, catalog, `.editorconfig`, detekt/ktlint config, CI, README, license, `.gitignore`. Why: Starts with the gates already wired. ([source](https://start.spring.io/))
- **`KT-REPO-05`** (MUST) Declare every dependency and plugin version once in `gradle/libs.versions.toml` and reference it as `libs.xxx`; no version strings in module build files. Why: Single place to bump, Renovate-friendly. ([source](https://docs.gradle.org/current/userguide/version_catalogs.html))
- **`KT-REPO-06`** (MUST) Enable dependency locking (`dependencyLocking { lockAllConfigurations() }`), generate with `./gradlew dependencies --write-locks`, and commit `gradle.lockfile` (apps and libraries both); use `LockMode.STRICT` in CI. Optionally add `gradle/verification-metadata.xml` for checksum verification. Why: Reproducible resolution, supply-chain integrity. ([source](https://docs.gradle.org/current/userguide/dependency_locking.html))
- **`KT-REPO-07`** (MUST) Pin the toolchain: commit `gradlew` + `gradle/wrapper/*`, run `./gradlew wrapper --gradle-version <x> --gradle-distribution-sha256-sum <h>`, and declare `kotlin { jvmToolchain(21) }` (foojay resolver in settings). Never rely on the `JAVA_HOME` of the machine. Why: Same JDK/Gradle everywhere. ([source](https://docs.gradle.org/current/userguide/gradle_wrapper.html))
- **`KT-REPO-08`** (SHOULD) Library publishing: SemVer, tag `v<x.y.z>`, publish to Maven Central via `maven-publish` + signing (central portal), include sources and Dokka javadoc jars. Services: ship a container, no registry publish. Why: Central requires signed, complete POMs. ([source](https://docs.gradle.org/current/userguide/publishing_maven.html))
- **`KT-REPO-09`** (MUST) `.gitignore` must contain `build/`, `.gradle/`, `.kotlin/`, `out/`, `*.iml`, `.idea/` (except shared config), `*.class`; keep `gradle-wrapper.jar` and `gradle.lockfile` tracked. Add `.editorconfig` (ktlint reads it) and `.gitattributes` with `* text=auto` and `*.bat text eol=crlf`. Why: Avoids committing build output; wrapper jar must stay. ([source](https://github.com/github/gitignore/blob/main/Gradle.gitignore))
- **`KT-REPO-10`** (SHOULD) CI order on every PR: wrapper validation (`gradle/actions/wrapper-validation`), `ktlintCheck`, `detekt`, `build` (compile with warnings-as-errors), `test` + `koverXmlReport`, `koverVerify`, vuln scan (OSV/dependency-check), image build. Cache with `gradle/actions/setup-gradle`. Why: Mirrors the loops gate. ([source](https://github.com/gradle/actions))
- **`KT-REPO-11`** (SHOULD) Automate updates with Renovate (preferred; understands version catalogs and Gradle locks) or Dependabot; group Kotlin plugin + `kotlinx-*` bumps. Remove unused dependencies with the `dependency-analysis-gradle-plugin` (`./gradlew buildHealth`). Why: Stale deps are the main vuln source. ([source](https://docs.renovatebot.com/modules/manager/gradle/))
- **`KT-REPO-12`** (SHOULD) Use conventional commits; generate changelogs from them (release-please/git-cliff). Version lives in one place (`gradle.properties` `version=` or the tag). Why: Matches loops release flow. ([source](https://www.conventionalcommits.org/))

## TOOL

- **`KT-TOOL-01`** (SHOULD) Target Kotlin `2.4.x` (stable `2.4.21`, as of 2026-11) on JDK 21 or 25 LTS; K2 is the only compiler since 2.0 (K1 removed from the default path), so do not set `languageVersion=1.9` unless forced. Upgrade within a release line promptly: stdlib support window is 18 months per line from 2.4. Manage JDKs with SDKMAN!/mise via `.tool-versions` or Gradle toolchains. Why: Support windows and K2 performance. ([source](https://kotlinlang.org/docs/releases.html))
- **`KT-TOOL-02`** (MUST) Format with ktlint (`./gradlew ktlintCheck`, auto-fix `ktlintFormat` via the `org.jlleitschuh.gradle.ktlint` plugin) using `.editorconfig` (`ktlint_code_style = ktlint_official`); use one formatter only (ktlint or IntelliJ style, not both). Set `kotlin.code.style=official`. Why: One deterministic formatter. ([source](https://ktlint.github.io/ktlint/latest/))
- **`KT-TOOL-03`** (SHOULD) Lint with detekt: apply the Gradle plugin: stable is `io.gitlab.arturbosch.detekt` 1.23.8 (as of 2026-11); `dev.detekt` 2.0.0-alpha.x is alpha, do not default to it, config in `config/detekt/detekt.yml` with `buildUponDefaultConfig = true`, baseline via `detektBaseline`, run `./gradlew detekt` (type-resolution tasks `detektMain`/`detektTest` for rules needing types). Emit SARIF for review. Why: Complexity, coroutine and style rules ktlint lacks. ([source](https://detekt.dev/docs/intro))
- **`KT-TOOL-04`** (SHOULD) Compile with `kotlin { compilerOptions { allWarningsAsErrors = true; progressiveMode = true } }` and `-Xjsr305=strict` (Spring) so Java nullability annotations are enforced; add `explicitApi()` for library modules. Why: The compiler is the type checker. ([source](https://kotlinlang.org/docs/gradle-compiler-options.html))
- **`KT-TOOL-05`** (SHOULD) Scan dependencies in CI with OSV-Scanner on `gradle.lockfile` (`osv-scanner scan source -L gradle.lockfile`) or OWASP dependency-check (`./gradlew dependencyCheckAnalyze`); emit a CycloneDX SBOM (`./gradlew cyclonedxBom`). Enforce a license allow-list. Why: Known-CVE gate. ([source](https://google.github.io/osv-scanner/))
- **`KT-TOOL-06`** (SHOULD) Editor baseline: IntelliJ IDEA (Kotlin plugin, K2 mode) or Kotlin LSP; disable the IDE auto-reformat on save if it disagrees with ktlint (import the ktlint `.editorconfig`). Why: Format-on-save conflicts cause diff churn. ([source](https://kotlinlang.org/docs/kotlin-ide.html))

## ARCH

- **`KT-ARCH-01`** (SHOULD) Default style: hexagonal over Gradle modules, modular monolith first; microservices only for independent scaling/ownership. DDD tactical: entities as classes, value objects as `@JvmInline value class`, aggregates with a single root, events as sealed hierarchies. CQRS/event sourcing only with a stated need. Why: Kotlin's sealed/value/data types express DDD cheaply. ([source](https://docs.spring.io/spring-modulith/reference/))
- **`KT-ARCH-02`** (MUST) Make each layer a Gradle module whose `build.gradle.kts` lists only inward dependencies (`:domain` has none; `:application` -> `:domain`; adapters -> `:application`; `:app` -> all). Use `api` vs `implementation` deliberately; use `implementation` by default. Why: A forbidden import fails at compile time. ([source](https://docs.gradle.org/current/userguide/multi_project_builds.html))
- **`KT-ARCH-03`** (MUST) Visibility: default to `internal` for module-private implementations and `private` otherwise; Kotlin `public` is the default so write `internal` explicitly. Package cycles are legal in Kotlin, so ban them with a test (Konsist/ArchUnit); module cycles are illegal in Gradle. Packages map to directories by convention only (not enforced), so the arch checker must read the `package` header, not the path. Imports: `import a.b.C`, `import a.b.*`, `import a.b.C as D`. Why: `internal` is module-scoped; paths can lie. ([source](https://kotlinlang.org/docs/visibility-modifiers.html))
- **`KT-ARCH-04`** (MUST) Enforce direction with Konsist (`Konsist.scopeFromProduction().assertArchitecture { domain.dependsOnNothing(); application.dependsOn(domain) }`) or ArchUnit run through JUnit; write them as ordinary tests in `app/src/test`. Why: Catches package-level violations inside one module. ([source](https://docs.konsist.lemonappdev.com/))
- **`KT-ARCH-05`** (MUST) Prefer manual constructor wiring in `app/` (or Spring `@Configuration` classes). Use constructor injection only; ban field injection (`@Autowired lateinit var`) and service locators (`ApplicationContext.getBean`, Koin `get()` in domain code). Koin or Kotlin-Inject are acceptable for Ktor. Why: Testable without a container. ([source](https://docs.spring.io/spring-framework/reference/languages/kotlin.html))
- **`KT-ARCH-06`** (MUST) Purity list (`Instant.now`, `UUID.randomUUID`, `GlobalScope`, framework imports) not Kotlin. Why: go-only.
- **`KT-ARCH-07`** (SHOULD) Ports are small Kotlin `interface`s (often `fun interface`) defined in `:application` by the consumer; adapters implement them. Suspend functions are fine on ports (`suspend fun save(order: Order)`) but never leak `Flow` of framework types. Why: Consumer-owned, small ports. ([source](https://kotlinlang.org/docs/fun-interfaces.html))
- **`KT-ARCH-08`** (SHOULD) Size heuristics: file under ~400 lines (conventions say "a few hundred"), function under ~30 lines, constructor/params <= 5-6 (use a data class or named args beyond that), detekt `LongMethod`, `LargeClass`, `LongParameterList`, `ComplexCondition`, `TooManyFunctions` enabled. Why: Objective SOLID signals. ([source](https://kotlinlang.org/docs/coding-conventions.html))
- **`KT-ARCH-09`** (MUST) Spring Boot with Kotlin: apply `kotlin("plugin.spring")` and `kotlin("plugin.jpa")` (all-open/no-arg) only in adapter modules; do not annotate domain classes with `@Entity`. Keep a separate persistence model mapped to the domain. Why: Open/no-arg plugins and JPA annotations pollute the domain. ([source](https://kotlinlang.org/docs/all-open-plugin.html))

## IDIOM

- **`KT-IDIOM-01`** (MUST) Errors: use sealed result/error types (or Arrow `Either`/`Raise`) for expected business failures; throw exceptions only for programmer errors/infrastructure. Kotlin has no checked exceptions. Never `catch (e: Exception)` without rethrowing `CancellationException`; never `runCatching` around suspend code without rethrowing cancellation. Wrap with a cause (`Foo(msg, cause)`). Why: Swallowed `CancellationException` breaks structured concurrency. ([source](https://kotlinlang.org/docs/exceptions.html))
- **`KT-IDIOM-02`** (AVOID) `kotlin.Result` is not for public APIs (it is a value class; explicit-API/lint restricts it as a return type and it mixes poorly with exceptions); use it for local `runCatching`-style plumbing only, and prefer sealed types for domain errors. Why: Result is not an error taxonomy. ([source](https://github.com/Kotlin/KEEP/blob/master/proposals/stdlib/result.md))
- **`KT-IDIOM-03`** (MUST) Null-safety: model absence as `T?`, never as sentinel values. Forbid `!!` outside tests (detekt `UnsafeCallOnNullableType`), prefer `?.`, `?:`, `requireNotNull(x) { msg }`, `checkNotNull`. Avoid `lateinit` for domain fields. Why: `!!` converts compile errors into NPEs. ([source](https://kotlinlang.org/docs/null-safety.html))
- **`KT-IDIOM-04`** (MUST) Platform types (`String!`) from Java: declare an explicit Kotlin type (`val s: String? = javaCall()` or `String`) at every Java boundary; public API must not expose platform types. Enable `-Xjsr305=strict` / `-Xjspecify-annotations=strict` so `@Nullable`/`@NonNull`/JSpecify become real nullability. Why: Platform types silently defer NPE to runtime. ([source](https://kotlinlang.org/docs/java-interop.html#null-safety-and-platform-types))
- **`KT-IDIOM-05`** (SHOULD) Immutability: `val` over `var`, read-only `List/Set/Map` types in APIs, `data class` for value holders (copy for change), `@JvmInline value class` for typed IDs/amounts (zero-boxing generally, but boxed when nullable/generic/interface). Never expose a `MutableList` from a public API; copy defensively. Why: Value semantics prevents aliasing bugs and primitive obsession. ([source](https://kotlinlang.org/docs/coding-conventions.html))
- **`KT-IDIOM-06`** (SHOULD) Use sealed interfaces/classes with exhaustive `when` as an expression (no `else` branch) for states, commands and errors; avoid `enum` + `when` with `else`. Prefer `data object` for stateless cases. Why: Compiler flags new cases. ([source](https://kotlinlang.org/docs/sealed-classes.html))
- **`KT-IDIOM-07`** (MUST) Resources: use `.use { }` on `Closeable`/`AutoCloseable` (Kotlin's try-with-resources), `use` on `Sequence`/streams, and structured scopes for coroutines; close Flow collectors by cancellation, not by flags. Never `GlobalScope.launch`. Why: Leaked connections/jobs. ([source](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.io/use.html))
- **`KT-IDIOM-08`** (MUST) Equality/time: `data class` gives `equals/hashCode/toString`; classes with `equals` must override `hashCode`; never put `data class` entities with mutable `var` in hash sets. Use `java.time` (`Instant`, `Duration`, `ZonedDateTime`) or `kotlin.time`, never `java.util.Date`/`Calendar`, `SimpleDateFormat`. Store instants in UTC. Why: Classic JVM traps. ([source](https://kt.academy/book/effectivekotlin))
- **`KT-IDIOM-09`** (SHOULD) Naming: `UpperCamelCase` types, `lowerCamelCase` functions, `SCREAMING_SNAKE_CASE` for `const`/deep-immutable top-level vals, no underscores in packages; library authors use explicit visibility and explicit return types; KDoc on public members, no `@param`/`@return` boilerplate. Why: Official style. ([source](https://kotlinlang.org/docs/coding-conventions.html))
- **`KT-IDIOM-10`** (SHOULD) Reflection/annotation processing: allowed at framework seams only (Jackson, Spring). Use KSP rather than kapt (kapt is in maintenance mode); avoid `Any`-typed reflection helpers and `@Suppress("UNCHECKED_CAST")` in domain code. Prefer `kotlinx.serialization` or the Jackson Kotlin module (`jackson-module-kotlin`) configured once. Why: Compile-time safety. ([source](https://kotlinlang.org/docs/ksp-overview.html))
- **`KT-IDIOM-11`** (AVOID) Avoid `object` singletons holding mutable state, top-level `var`, and `companion object` service locators; use constructor-injected instances. Avoid overusing extension functions that hide dependencies, scope functions (`let/also/apply`) nested more than two deep, and operator overloading beyond domain algebra. Why: Hidden state and unreadable chains. ([source](https://kt.academy/book/effectivekotlin))

## CONC

- **`KT-CONC-01`** (SHOULD) Model: coroutines (structured concurrency) on top of JVM threads; Java 21+ virtual threads are an alternative for blocking code (Spring `spring.threads.virtual.enabled=true`). Do not mix both for the same workload without measurement. Why: Pick one model per service. ([source](https://kotlinlang.org/docs/coroutines-guide.html))
- **`KT-CONC-02`** (MUST) Never use `GlobalScope`; own scopes explicitly: `CoroutineScope(SupervisorJob() + dispatcher)` per component, cancelled on shutdown; use `coroutineScope {}` for all-or-nothing children and `supervisorScope {}` when siblings must survive one failure. A `launch` failure cancels the parent unless a `SupervisorJob` is in the scope. Why: Structured concurrency guarantees no leaks. ([source](https://kotlinlang.org/docs/coroutine-context-and-dispatchers.html))
- **`KT-CONC-03`** (MUST) Shared mutable state: prefer immutability and confinement (single-threaded `limitedParallelism(1)` dispatcher, actor/`Channel`, `StateFlow`); otherwise use `Mutex` (suspend-aware, non-reentrant) or `java.util.concurrent`/atomics. `@Volatile` gives visibility only, not atomicity; `synchronized` blocks must not contain suspension points. Why: Prevents data races by design. ([source](https://kotlinlang.org/docs/shared-mutable-state-and-concurrency.html))
- **`KT-CONC-04`** (MUST) No race-substitute concept (`race.mode=none` + `substitute`); race-guard is Go-only. Why: missing.
- **`KT-CONC-05`** (MUST) Blocking: never call blocking IO (JDBC, `Thread.sleep`, `File.readText`) on `Dispatchers.Default`; wrap in `withContext(Dispatchers.IO)` (or a dedicated `limitedParallelism(n)` view) or use async drivers. Inject `CoroutineDispatcher` (default param) so tests can swap it. detekt `SleepInsteadOfDelay`, `InjectDispatcher`, `GlobalCoroutineUsage`, `SuspendFunWithFlowReturnType`. Why: Starves the CPU pool. ([source](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-test/))
- **`KT-CONC-06`** (MUST) Cancellation and timeouts: coroutines cancel cooperatively; long loops must call `ensureActive()`/`yield()`; use `withTimeout`/`withTimeoutOrNull` for deadlines; `try/finally` with `withContext(NonCancellable)` for cleanup that suspends; always rethrow `CancellationException`. Why: Prevents hung requests and leaked work. ([source](https://kotlinlang.org/docs/cancellation-and-timeouts.html))
- **`KT-CONC-07`** (SHOULD) Flow: cold `Flow` for streams, `StateFlow` for state, `SharedFlow(replay, extraBufferCapacity)` for events; choose a `buffer(...)`/`conflate()` strategy (backpressure) explicitly; collect in the owning scope; use `flowOn` for upstream dispatcher, never `withContext` inside `flow {}`; `stateIn(scope, SharingStarted.WhileSubscribed(5000), init)` for hot views. Why: Unbounded buffers and context violations. ([source](https://kotlinlang.org/docs/flow.html))
- **`KT-CONC-08`** (MUST) Background workers: wrap schedulers/consumers in a class owning a `CoroutineScope`, expose `close()`/`stop()` that `cancelAndJoin()`s, wire to JVM shutdown (Spring `@PreDestroy`/`SmartLifecycle`, Ktor `ApplicationStopping`). Use Quartz/JobRunr/db-scheduler for durable jobs. Why: Graceful drain. ([source](https://ktor.io/docs/server-events.html))

## TEST

- **`KT-TEST-01`** (SHOULD) Unit framework: JUnit 5 (Jupiter) as the platform (`useJUnitPlatform()`); Kotest assertions/property modules are welcome on top; choose Kotest runner or JUnit, not both styles, per module. E2E: Spring `@SpringBootTest`/`WebTestClient`, Ktor `testApplication { }`. Why: JUnit 5 is the Gradle/IDE baseline. ([source](https://junit.org/junit5/docs/current/user-guide/))
- **`KT-TEST-02`** (MUST) Layout/recognition: tests live in `src/test/kotlin` (unit) and a separate `integrationTest` source set (or `src/test` tagged) mirroring main packages; files `*Test.kt`, `*Tests.kt`, `*IT.kt`, `*Spec.kt` (Kotest). Globs: `**/src/test/**/*.kt`, `**/src/integrationTest/**/*.kt`, `**/*Test.kt`, `**/*Spec.kt`. Names may use backticks (`` fun `rejects empty order`() ``). Why: Drives test ownership globs. ([source](https://kotlinlang.org/docs/coding-conventions.html))
- **`KT-TEST-03`** (SHOULD) Style: arrange-act-assert, `@ParameterizedTest` + `@MethodSource`/`@CsvSource` (or Kotest `withData`) for table tests, `@Nested` for grouping, one behaviour per test, no shared mutable fixtures across tests. Why: Readable, isolated tests. ([source](https://junit.org/junit5/docs/current/user-guide/#writing-tests-parameterized-tests))
- **`KT-TEST-04`** (SHOULD) Doubles: prefer hand-written fakes for ports (in-memory repository); use MockK (`mockk<T>()`, `coEvery`/`coVerify` for suspend, `relaxed = true` sparingly) only at boundaries you do not own. Do not mock value objects, data classes or the class under test; avoid `mockkStatic`/`mockkObject` leaks (`unmockkAll` in teardown). Why: Fakes survive refactors. ([source](https://mockk.io/))
- **`KT-TEST-05`** (SHOULD) Integration: use Testcontainers (`PostgreSQLContainer`, `KafkaContainer`) with JUnit 5 `@Testcontainers`/Spring `@ServiceConnection`, one container per test class (singleton pattern) and `TRUNCATE`/transaction-rollback per test; run Flyway migrations against the real engine, never H2 as a Postgres stand-in. Why: Real engine catches dialect bugs. ([source](https://java.testcontainers.org/))
- **`KT-TEST-06`** (MUST) Gate parses only Go coverprofile; needs JaCoCo/Kover XML parser and Gradle command. Why: go-only.
- **`KT-TEST-07`** (MUST) No new-code coverage for JVM sources (`.kt` candidates, test globs, generated exclusion). Why: go-only.
- **`KT-TEST-08`** (SHOULD) Property/mutation: Kotest property (`checkAll`) or jqwik for invariants of domain logic; mutation with PIT (`info.solidsoft.pitest` Gradle plugin, `pitest-kotlin` filter) only on the domain module, on a schedule, not on every PR. Why: Mutation score finds weak tests. ([source](https://kotest.io/docs/proptest/property-based-testing.html))
- **`KT-TEST-09`** (MUST) Coroutines: use `runTest` (virtual time, 60 s default timeout) with `StandardTestDispatcher`/`testScheduler` (`advanceUntilIdle`, `advanceTimeBy`, `runCurrent`), `backgroundScope` for long-lived collectors, and inject dispatchers; `delay` on a real dispatcher is not virtualised. `Dispatchers.setMain` requires `resetMain()` in teardown. Inject `Clock` instead of calling `now()`. Why: Deterministic, fast async tests. ([source](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-test/))
- **`KT-TEST-10`** (MUST) Flakiness: no `Thread.sleep` in tests (use Awaitility or virtual time), per-test unique data, fixed `Random(seed)`, enable `junit.jupiter.execution.parallel.enabled` and `junit.jupiter.testmethod.order.default=org.junit.jupiter.api.MethodOrderer$Random` (the value must be the fully qualified class name; `random` alone is invalid), `@Timeout`. Why: Exposes order and race dependencies. ([source](https://junit.org/junit5/docs/current/user-guide/#writing-tests-test-execution-order))
- **`KT-TEST-11`** (SHOULD) Fast loop: `./gradlew test --tests 'com.acme.FooTest'` (or `--tests '*FooTest.method'`), `./gradlew test --continuous` for watch mode, build and configuration caches on (`org.gradle.caching=true`, `org.gradle.configuration-cache=true`). Always add `--rerun` (or `cleanTest`) when a gate must re-execute. Why: Gradle up-to-date checks skip tests otherwise. ([source](https://docs.gradle.org/current/userguide/java_testing.html#test_filtering))

## PERF

- **`KT-PERF-01`** (SHOULD) Benchmark with JMH through `kotlinx-benchmark` (Gradle plugin `org.jetbrains.kotlinx.benchmark`) or the `me.champeau.jmh` plugin; never hand-time with `System.nanoTime` in a loop; use `Blackhole`, multiple forks and warm-up; compare runs statistically (JMH error bars). Why: JIT makes naive timing meaningless. ([source](https://github.com/Kotlin/kotlinx-benchmark))
- **`KT-PERF-02`** (SHOULD) Profile with async-profiler (CPU, alloc, lock; `-e cpu -f out.jfr`) or JDK Flight Recorder (`-XX:StartFlightRecording`); view in JMC/IntelliJ. Continuous profiling: Pyroscope/Parca. Why: Low-overhead production profiling. ([source](https://github.com/async-profiler/async-profiler))
- **`KT-PERF-03`** (SHOULD) Tuning: set container-aware heap (`-XX:MaxRAMPercentage=75`), keep G1/ZGC defaults until measured, enable CDS/AppCDS or Spring AOT/CRaC for startup, cap `kotlinx.coroutines` pools via `limitedParallelism`. Why: Startup and memory in containers. ([source](https://docs.oracle.com/en/java/javase/21/docs/specs/man/java.html))
- **`KT-PERF-04`** (SHOULD) Hot-path mistakes: boxing in generic/nullable value classes, `Sequence` vs `List` misuse for small collections, `String +` in loops (use `buildString`), regexes compiled per call (hoist `Regex` to a val), `by lazy` with default synchronized mode on hot paths, `Flow` for one-shot values, `runBlocking` in request paths, `.toList()` chains copying large lists. Why: Common JVM/Kotlin allocation traps. ([source](https://kt.academy/book/effectivekotlin))

## SEC

- **`KT-SEC-01`** (MUST) SQL: always bind parameters (jOOQ DSL, Exposed DSL, `@Query` with `:named`, JDBC `PreparedStatement`); never build SQL with Kotlin string templates (`"... $id"`); `@Language("SQL")` on raw fragments for IDE checks only. Use `ProcessBuilder(list)` with argument lists, never `Runtime.exec(string)`. Why: Templates make injection easy. ([source](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html))
- **`KT-SEC-02`** (MUST) Deserialization: never use Java native serialization (`ObjectInputStream`) on untrusted data; configure Jackson without default typing (`activateDefaultTyping`), use `kotlinx.serialization` (type-safe, no reflection) or Jackson with explicit DTOs; disable XML external entities (`XMLConstants.FEATURE_SECURE_PROCESSING`, disallow doctype). SnakeYAML must use `SafeConstructor`. Why: Gadget-chain RCE. ([source](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html))
- **`KT-SEC-03`** (MUST) Web: validate outbound URLs against an allow-list (SSRF), canonicalise paths and reject `..` (`Path.normalize().startsWith(base)`), allow-list redirect targets, configure CORS explicitly (Spring `CorsConfiguration`, Ktor `install(CORS)` with `allowHost`, never `anyHost()` with credentials), keep CSRF on for cookie sessions. Why: OWASP A01/A10. ([source](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html))
- **`KT-SEC-04`** (MUST) Secrets: read from env/vault (Spring Cloud Vault, Kubernetes secrets), never commit `application-*.yml` with secrets; passwords via Argon2id/bcrypt (Spring `PasswordEncoder`, `Argon2PasswordEncoder`); randomness via `java.security.SecureRandom`, not `kotlin.random.Random`/`java.util.Random`; avoid MD5/SHA-1 and ECB; use JCA/Tink. Why: Standard guidance. ([source](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html))
- **`KT-SEC-05`** (MUST) Validate at the adapter boundary: Jakarta Bean Validation on DTOs (with `-Xannotation-default-target=param-property`, an opt-in preview from Kotlin 2.2.0, or on a compiler where that rule is the default, an unqualified annotation on a constructor property applies to both `@param` and `@field`; otherwise, under the old default or `first-only`, write `@field:NotBlank` explicitly. The release where the new rule becomes the default is unverified) or explicit constructors/`require` in value objects; the domain trusts its types. Why: Use-site target pitfall on older compilers: validation silently ignored. ([source](https://kotlinlang.org/docs/annotations.html#annotation-use-site-targets))
- **`KT-SEC-06`** (MUST) Supply chain: commit `gradle.lockfile`, enable dependency verification (`gradle/verification-metadata.xml`, `./gradlew --write-verification-metadata sha256 help`), restrict repositories in `dependencyResolutionManagement` with `repositoriesMode = FAIL_ON_PROJECT_REPOS`, validate the wrapper, sign and attest release artifacts (SLSA/sigstore). Why: Typosquatting, tampered jars. ([source](https://docs.gradle.org/current/userguide/dependency_verification.html))
- **`KT-SEC-07`** (SHOULD) SAST: Semgrep (Kotlin rules) and detekt's security-ish rules; SpotBugs + FindSecBugs works on Kotlin bytecode but with noise; run as a non-blocking report first. Why: Catches common sinks. ([source](https://semgrep.dev/docs/supported-languages/))

## DATA

- **`KT-DATA-01`** (SHOULD) Access style: jOOQ (type-safe SQL, codegen from migrated schema) for SQL-heavy services; Exposed (DSL, plus optional DAO) for Ktor/Kotlin-first small services; Spring Data JPA/Hibernate only when you need the entity graph and accept the pitfalls; Spring JDBC `JdbcClient`/R2DBC for thin cases. Whatever you pick lives in the persistence adapter only. Why: Fit-for-purpose. ([source](https://www.jooq.org/doc/latest/manual/))
- **`KT-DATA-02`** (MUST) Migrations: Flyway or Liquibase, versioned and forward-only (`V12__add_index.sql`); run migrations at deploy, not by Hibernate `ddl-auto` (`validate` or `none` in prod); use expand-then-contract for zero downtime (add nullable, backfill, switch, drop later). Why: Reviewed, repeatable schema. ([source](https://documentation.red-gate.com/flyway))
- **`KT-DATA-03`** (MUST) Transactions belong to the application layer (use-case boundary), expressed through a `TransactionRunner` port; `@Transactional` on use cases or adapter services, not on domain; with coroutines use Exposed `newSuspendedTransaction`/Spring's coroutine support, and never hold a transaction across a `delay` or remote call. Why: Thread-bound transaction context vs. coroutine switching. ([source](https://docs.spring.io/spring-framework/reference/languages/kotlin/coroutines.html))
- **`KT-DATA-04`** (MUST) JPA traps: avoid `data class` entities (equals/hashCode on mutable state and lazy proxies); use `class` with `kotlin-jpa` (no-arg) and `allOpen` for proxies; set `spring.jpa.open-in-view=false`; fetch with `JOIN FETCH`/entity graphs to avoid N+1; map to domain types in the adapter. Why: Kotlin data classes clash with Hibernate. ([source](https://kotlinlang.org/docs/no-arg-plugin.html))
- **`KT-DATA-05`** (SHOULD) Connections: HikariCP (default in Spring Boot) with explicit `maximumPoolSize`, `connectionTimeout`, `maxLifetime` below DB limits; size the pool for the dispatcher parallelism that does blocking JDBC; use R2DBC only if the whole stack is reactive. Why: Pool starvation under coroutines. ([source](https://github.com/brettwooldridge/HikariCP))

## API

- **`KT-API-01`** (MUST) HTTP: Spring Boot (MVC or WebFlux with coroutines, `suspend` controller methods) or Ktor (routing DSL, plugins). Keep controllers/routes thin: parse, call a use case, map result to a response. Why: Adapter-only logic. ([source](https://docs.spring.io/spring-framework/reference/languages/kotlin/coroutines.html))
- **`KT-API-02`** (SHOULD) Contracts: OpenAPI-first with `openapi-generator` (kotlin-spring/kotlin-server) or `springdoc-openapi`/Ktor OpenAPI plugin for code-first; protobuf/gRPC via `grpc-kotlin`; version with a URL prefix or media-type, additive-only changes. Why: Stable consumer contract. ([source](https://openapi-generator.tech/docs/generators/kotlin-spring/))
- **`KT-API-03`** (MUST) Errors at the edge: map sealed domain errors to RFC 9457 `application/problem+json` (Spring `ProblemDetail`/`@ControllerAdvice`; Ktor `StatusPages`); exhaustive `when` over the error type to pick status codes. Why: Consistent client contract. ([source](https://www.rfc-editor.org/rfc/rfc9457.html))
- **`KT-API-04`** (MUST) Resilience: set timeouts on every client (Ktor `HttpTimeout`, `RestClient`/WebClient, `withTimeout`); retry only idempotent calls with exponential backoff + jitter (Resilience4j Kotlin, Arrow Resilience); circuit breakers and rate limiters via Resilience4j; require an `Idempotency-Key` for POST retries. Why: Prevents cascading failure. ([source](https://resilience4j.readme.io/docs/getting-started))
- **`KT-API-05`** (MUST) Messaging: Spring Kafka/Reactor Kafka or `kafka-clients` + coroutines wrapper; transactional outbox in the same DB transaction, consumers idempotent (dedupe by message id); commit offsets only after processing; DLQ for poison messages. Why: At-least-once delivery. ([source](https://docs.spring.io/spring-kafka/reference/))
- **`KT-API-06`** (MUST) HTTP clients: one shared Ktor `HttpClient` (CIO/Java engine) or Spring `RestClient`/`WebClient` per upstream, closed on shutdown; propagate cancellation (coroutine) and a deadline; do not create a client per request. Why: Connection reuse. ([source](https://ktor.io/docs/client-create-and-configure.html))

## OBS

- **`KT-OBS-01`** (MUST) Log via SLF4J (Logback/Log4j2) wrapped by `kotlin-logging` (`private val log = KotlinLogging.logger {}`); JSON output (logstash-logback-encoder / Spring Boot structured logging); put correlation IDs in MDC and propagate through coroutines with `MDCContext()` (`kotlinx-coroutines-slf4j`); never log secrets/PII. Why: MDC is thread-local, coroutines switch threads. ([source](https://github.com/oshai/kotlin-logging))
- **`KT-OBS-02`** (SHOULD) Metrics: Micrometer (Spring Boot Actuator, Ktor `MicrometerMetrics`); names are lowercase dot-separated, units in base SI, low-cardinality tags only. Why: Backend-neutral, ubiquitous. ([source](https://docs.micrometer.io/micrometer/reference/))
- **`KT-OBS-03`** (SHOULD) Tracing: OpenTelemetry Java agent (`-javaagent:opentelemetry-javaagent.jar`) or Spring Boot OTel starter; Java OTel is stable for traces/metrics; context propagates across coroutines with `kotlinx-coroutines-opentelemetry`/`Context.asContextElement()`. Why: Context loss across dispatchers. ([source](https://opentelemetry.io/docs/languages/java/))
- **`KT-OBS-04`** (SHOULD) Health: Spring Actuator `/actuator/health/liveness` and `/readiness` (probes enabled); Ktor `/healthz` route; readiness checks dependencies, liveness must not. Why: Kubernetes semantics. ([source](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html))

- **`KT-OPS-01`** (MUST) Config: typed binding (`@ConfigurationProperties` with constructor binding on a `data class`, or Ktor HOCON `ApplicationConfig`/`hoplite`/`konf`), fail fast at startup, secrets from env/vault, no config in domain. ## FW

- **`KT-FW-01`** (SHOULD) Dominant: Spring Boot (by far the most-used JVM backend framework; first-class Kotlin support incl. coroutines), Ktor (JetBrains, coroutine-native), then Micronaut/Quarkus. Choose Spring for ecosystem and enterprise integration, Ktor for small, lean, Kotlin-first services. Why: Adoption and fit. ([source](https://docs.spring.io/spring-framework/reference/languages/kotlin.html))
- **`KT-FW-02`** (MUST) Spring conventions: `kotlin-spring` (all-open) plugin so `@Configuration`/`@Transactional` classes are proxiable; `@ConfigurationProperties` on data classes; `-Xjsr305=strict`; `application.yml` in `src/main/resources`; package-by-feature under the root app class. Where this fights hexagonal (annotations on domain), keep annotations in adapters/`app`. Why: Framework wins at the edges, domain stays pure. ([source](https://docs.spring.io/spring-boot/reference/features/kotlin.html))
- **`KT-FW-03`** (SHOULD) Ktor conventions: `Application.module()` extension functions, plugins via `install(...)`, routes in feature files, `testApplication`, HOCON/YAML config. No DI built in (use Koin/Kotlin-Inject or manual wiring in `module()`). Why: Ktor is a toolkit, not a container. ([source](https://ktor.io/docs/server-create-a-new-project.html))
- **`KT-FW-04`** (SHOULD) Framework footguns: Spring proxy self-invocation bypasses `@Transactional`; `suspend` + `@Transactional` needs the reactive/coroutine tx manager; final classes break proxies without all-open; Jackson without the Kotlin module ignores non-null defaults/constructors; Ktor handlers that block starve the event loop; `Dispatchers.setMain` global. Why: Known surprises. ([source](https://docs.spring.io/spring-framework/reference/core/aop/proxying.html))

## Top 10 footguns

1. **Swallowed `CancellationException`.** Bad: `try { suspendCall() } catch (e: Exception) { log(e) }` or `runCatching { suspendCall() }`. Fix: rethrow `CancellationException` (or catch specific types). ([source](https://kotlinlang.org/docs/exception-handling.html))
2. **`GlobalScope` / orphan `launch`.** Bad: `GlobalScope.launch { ... }`. Fix: inject a `CoroutineScope(SupervisorJob()+dispatcher)` cancelled on shutdown, or `coroutineScope {}`. ([source](https://kotlinlang.org/docs/coroutines-guide.html))
3. **Blocking on `Dispatchers.Default`.** Bad: `launch { jdbc.query() }`. Fix: `withContext(Dispatchers.IO)`/`limitedParallelism`. ([source](https://kotlinlang.org/docs/coroutine-context-and-dispatchers.html))
4. **Platform types leaking.** Bad: `val n = javaApi.name()` exposed publicly (`String!`). Fix: declare `String?`/`String` explicitly; `-Xjsr305=strict`. ([source](https://kotlinlang.org/docs/java-interop.html))
5. **`!!` and `lateinit` in domain code.** Fix: `?:`, `requireNotNull`, constructor injection. ([source](https://kotlinlang.org/docs/null-safety.html))
6. **`data class` as JPA entity.** Bad: `@Entity data class User(var ...)`. Fix: plain `class` + `kotlin-jpa`/`allOpen`, domain mapping. ([source](https://kotlinlang.org/docs/no-arg-plugin.html))
7. **Wrong annotation use-site target (old default or `-Xannotation-default-target=first-only`).** Bad: `data class Dto(@get:NotBlank val a: String)` mismatched with the validator. Fix: `@field:NotBlank` explicitly, unless the build opts in to `-Xannotation-default-target=param-property` (preview from 2.2.0), where an unqualified annotation covers param and field. ([source](https://kotlinlang.org/docs/annotations.html#annotation-use-site-targets))
8. **Gradle up-to-date skips tests.** `./gradlew test` is a no-op when nothing changed; a gate would pass without running. Fix: `--rerun` (Gradle 7.6+) or `cleanTest`. ([source](https://docs.gradle.org/current/userguide/java_testing.html))
9. **Virtual time not applied.** Bad: `withContext(Dispatchers.IO) { delay(1000) }` in code under `runTest` waits real time. Fix: inject the dispatcher. ([source](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-test/))
10. **Transaction/MDC bound to a thread while coroutines hop threads.** Fix: `MDCContext()`, coroutine-aware tx managers. ([source](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-slf4j/))
