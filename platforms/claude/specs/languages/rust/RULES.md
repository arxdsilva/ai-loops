# Rust rules

Rust backend rules for the `rust` pack. Rust stable 1.99, edition 2024, as of 2026-11. Source research: `research/languages/rust.md` (rule IDs kept for the trace). Rule format: `RUST-<SECTION>-NN (MUST|SHOULD|AVOID)`. Universal rules (layering, SOLID, TDD, the 70% new-code coverage gate) live in `specs/ARCHITECTURE.md`, `specs/SOLID.md` and `specs/WORKFLOW.md §6`; this file adds only what is Rust-specific. Project rules win: follow the project's own config (`rustfmt.toml`, `clippy.toml`, `[workspace.lints]`, `deny.toml`, `rust-toolchain.toml`) over these defaults and log each override with `loops run override`.

## REPO: repository and project management

- **`RUST-REPO-01`** (MUST) Use Cargo's standard package layout: `src/main.rs`/`src/lib.rs`, `src/bin/*.rs`, `tests/*.rs`, `benches/*.rs`, `examples/*.rs`; keep `main.rs` thin and put logic in a library crate so tests and benches can reach it. Cargo auto-discovers targets from this layout; a fat `main.rs` cannot be integration-tested. ([Cargo: Package Layout](https://doc.rust-lang.org/cargo/guide/project-layout.html))
- **`RUST-REPO-02`** (MUST) Use a Cargo workspace with a virtual root manifest, `members = ["crates/*"]` and an explicit `resolver = "3"`; set `default-members` when `xtask`/fuzz crates exist. One lockfile and one `target/` for all crates; virtual manifests have no `edition` to infer the resolver from, so it must be explicit. ([Cargo: Workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html))
- **`RUST-REPO-03`** (MUST) Declare every shared dependency once in `[workspace.dependencies]` and inherit with `dep.workspace = true`; share `version`, `edition`, `rust-version`, `license`, `repository` through `[workspace.package]`. One version per dependency across crates avoids duplicate-version bloat and drift. Needs Rust 1.64+. ([Cargo: Workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html))
- **`RUST-REPO-04`** (SHOULD) Split into crates along architectural boundaries (domain, application, each adapter, bootstrap), not per feature; keep crates in a flat `crates/` directory. Choose a monorepo workspace by default; split repos only for independently released libraries. Crate edges are the one boundary the compiler enforces; flat layout scales. Also faster incremental builds. ([Cargo: Workspaces (flat layout recommended)](https://doc.rust-lang.org/cargo/reference/workspaces.html))
- **`RUST-REPO-05`** (SHOULD) Bootstrap with `cargo new --vcs git <name>` (bin) or `--lib`, then add the day-one files: `rust-toolchain.toml`, `rustfmt.toml` (if needed), `[workspace.lints]`, `deny.toml`, CI workflow, `LICENSE`, `README`, `.gitignore` with `/target`. `cargo new` is the only official starter; everything else is a team convention. ([cargo new](https://doc.rust-lang.org/cargo/commands/cargo-new.html))
- **`RUST-REPO-06`** (MUST) Commit `Cargo.lock` for any workspace that ships a binary or service; run CI with `--locked` so a stale lockfile fails the build. For a pure library, committing it is still fine (reproducible CI, MSRV checks) but consumers ignore it. The lockfile pins the exact graph for your builds; `cargo install` ignores it unless `--locked`. The Cargo FAQ now leaves the choice to the project and lists CI determinism and bisecting as reasons to commit. ([Cargo FAQ: lockfile](https://doc.rust-lang.org/cargo/faq.html))
- **`RUST-REPO-07`** (MUST) Write dependency requirements as caret versions (`"1.2"`); never `*` or a git dependency on a published crate; pin git/path dependencies only in `[patch]`. Use `cargo add` so `rust-version` is respected. Wildcard requirements are rejected by crates.io; caret ranges let the lockfile do the pinning. ([Cargo: Specifying Dependencies](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html))
- **`RUST-REPO-08`** (SHOULD) Automate dependency updates with Renovate (`cargo` manager) or Dependabot (`cargo` ecosystem); group minor+patch, run `cargo deny check` and tests on every update PR. Remove unused deps with `cargo machete` (fast) or `cargo +nightly udeps`. Stale dependencies are the main Rust supply-chain exposure; unused ones add build time. ([Renovate cargo manager](https://docs.renovatebot.com/modules/manager/cargo/))
- **`RUST-REPO-09`** (SHOULD) Follow SemVer as Cargo defines it (0.x: minor is breaking); for libraries run `cargo semver-checks` before release. For services use `release-plz` or `cargo release` to bump versions, changelog and tag; keep one version in `[workspace.package]`. Rust SemVer has subtle breakage (trait impls, `#[non_exhaustive]`, auto traits); semver-checks automates the lint. ([Cargo: SemVer compatibility](https://doc.rust-lang.org/cargo/reference/semver.html))
- **`RUST-REPO-10`** (SHOULD) Publish libraries with `cargo publish` (use `publish = false` on every internal crate); sign/attest releases with GitHub artifact attestations or Sigstore; build release binaries with `cargo-dist` or a CI matrix. `publish = false` prevents accidental publication of private crates; provenance defends consumers. ([Cargo: Publishing](https://doc.rust-lang.org/cargo/reference/publishing.html))
- **`RUST-REPO-11`** (MUST) Pin the toolchain with `rust-toolchain.toml` (`[toolchain] channel = "1.99.0"`, `components = ["rustfmt","clippy"]`, optionally `profile = "minimal"`), and set `rust-version` (MSRV) in `[workspace.package]`. Choose and document an MSRV policy (N-2, or "latest stable" for services); a service may track latest stable. `rust-toolchain.toml` is read by rustup so local and CI use the same compiler; `rust-version` makes Cargo error on old compilers and lets `cargo add`/resolver pick compatible deps. ([rustup: overrides](https://rust-lang.github.io/rustup/overrides.html))
- **`RUST-REPO-12`** (SHOULD) Set `edition = "2024"` in `[workspace.package]` for new code (Rust 1.85+); migrate with `cargo fix --edition`. Edition 2024 makes `resolver = "3"` (MSRV-aware) the default and `unsafe_op_in_unsafe_fn` warn. Editions are opt-in per crate and interoperate; 2024 has the best defaults. ([Edition Guide: Rust 2024](https://doc.rust-lang.org/edition-guide/rust-2024/index.html))
- **`RUST-REPO-13`** (SHOULD) `.gitignore`: `/target`, `**/*.rs.bk`, `lcov.info`, `*.profraw`, `*.profdata`, `.env`; commit `Cargo.lock`, `.cargo/config.toml` (no secrets), `.config/nextest.toml`, `deny.toml`, `rust-toolchain.toml`, `.sqlx/` (if using sqlx offline mode). Add `.editorconfig`; add `CODEOWNERS` and a PR template. `target/` is multi-GB and never committed; `.sqlx/` query metadata must be committed for offline CI. ([Cargo: Package Layout](https://doc.rust-lang.org/cargo/guide/project-layout.html))
- **`RUST-REPO-14`** (SHOULD) CI stages, in order: checkout -> toolchain (rustup reads `rust-toolchain.toml`) -> cache (`Swatinem/rust-cache`) -> `cargo fmt --all --check` -> `cargo clippy ... -D warnings` -> `cargo build --locked` -> tests with coverage -> `cargo test --doc` -> `cargo deny check` + `cargo audit` -> package. Add a second job on the MSRV and (libraries) a `cargo hack --feature-powerset check`. Fast checks first; the cache keys on `Cargo.lock` and the toolchain. Cargo's own CI guide shows the same shape. ([Cargo: Continuous Integration](https://doc.rust-lang.org/cargo/guide/continuous-integration.html))
- **`RUST-REPO-15`** (SHOULD) Use conventional commits only if a tool consumes them (`release-plz`, `git-cliff`); otherwise loops' branching/commit rules apply unchanged. release-plz derives version bumps and the changelog from them. ([release-plz](https://release-plz.dev/docs))
- **`RUST-REPO-15`** (P2) Conventional commits are not in any spec, skill or role missing

## TOOL: toolchain

- **`RUST-TOOL-01`** (MUST) Install and switch toolchains only with `rustup`; track stable on a six-week cadence (1.99 as of 2026-11, Rust 2024 edition); there is no LTS, so bump the pin in `rust-toolchain.toml` in a dedicated PR every release or two. The compiler is the only supported toolchain; older stables get no backports. ([Rust release blog](https://blog.rust-lang.org/releases/))
- **`RUST-TOOL-02`** (MUST) Format with `cargo fmt --all` (rustfmt); CI check argv is `cargo fmt --all --check` (exit code 1 on any diff; no output parsing needed). Configure only in `rustfmt.toml` (`style_edition`, `max_width`); never use `#[rustfmt::skip]` without a reason. rustfmt is the single official formatter; the 2024 style edition is the default for new 2024-edition crates. ([rustfmt](https://rust-lang.github.io/rustfmt/))
- **`RUST-TOOL-03`** (MUST) Lint with clippy: `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`. Keep default groups (correctness=deny; suspicious, complexity, perf, style=warn). `-D warnings` turns every warning into a failure; `--all-targets` also lints tests, benches, examples. ([Clippy: lints](https://doc.rust-lang.org/clippy/lints.html))
- **`RUST-TOOL-04`** (SHOULD) Configure lint levels once in `[workspace.lints]` and opt every crate in with `[lints] workspace = true`; do not scatter `#![warn(...)]` attributes. Enable `clippy::pedantic` at `warn` with `priority = -1` and cherry-pick allows (`module_name_repetitions`, `missing_errors_doc` for private crates); do not enable `nursery` or `restriction` wholesale. Clippy says pedantic is expect-to-allow, and restriction/nursery are cherry-pick only. Requires Rust 1.74+. ([Cargo: lints table](https://doc.rust-lang.org/cargo/reference/manifest.html#the-lints-section))
- **`RUST-TOOL-05`** (SHOULD) Cherry-pick these to `deny` in the workspace: `clippy::unwrap_used`, `clippy::expect_used` (non-test), `clippy::panic`, `clippy::todo`, `clippy::unimplemented`, `clippy::dbg_macro`, `clippy::print_stdout`/`print_stderr` (use tracing), `clippy::await_holding_lock`, `clippy::await_holding_refcell_ref`, `clippy::large_futures`, `clippy::undocumented_unsafe_blocks`; and rustc `unsafe_code = "forbid"`, `missing_debug_implementations = "warn"`, `unused_must_use = "deny"`. Allow unwrap/expect in tests with `clippy.toml` `allow-unwrap-in-tests = true`. These catch panics-in-production, blocking locks held across `.await`, and ignored results. ([Clippy lints index](https://rust-lang.github.io/rust-clippy/master/index.html))
- **`RUST-TOOL-06`** (MUST) Type checking is the compiler: build with `cargo build --workspace --all-targets --locked` (and `cargo check` for the fast loop); treat rustc warnings as errors in CI with `-D warnings` via clippy, or `RUSTFLAGS="-D warnings"` only on a separate target dir. `RUSTFLAGS` changes the fingerprint and busts the cache if toggled on the same `target/`. ([Cargo: environment variables](https://doc.rust-lang.org/cargo/reference/environment-variables.html))
- **`RUST-TOOL-07`** (MUST) Run `cargo deny check` (advisories, licenses, bans, sources) as the single supply-chain gate and `cargo audit` as a second advisory source; commit `deny.toml`. Generate SBOMs with `cargo cyclonedx` or embed deps with `cargo auditable build`. cargo-deny covers four checks (exit code is a bitset: advisories 1, bans 2, licenses 4, sources 8); cargo-audit scans `Cargo.lock` against the RustSec DB. ([cargo-deny check](https://embarkstudios.github.io/cargo-deny/cli/check.html))
- **`RUST-TOOL-08`** (SHOULD) Editor baseline: rust-analyzer with `check.command = "clippy"` and format-on-save through rustfmt only (disable any second formatter). Install `rustfmt`, `clippy` and `rust-src` components through `rust-toolchain.toml`. rust-analyzer is the standard LSP; clippy-on-save surfaces gate failures before CI. ([rust-analyzer configuration](https://rust-analyzer.github.io/book/configuration.html))

## ARCH: architecture

- **`RUST-ARCH-01`** (SHOULD) Default to a modular monolith: one deployable binary, hexagonal crates inside the workspace; pick microservices only for independent scaling/ownership. Use hexagonal/ports-and-adapters as the default style; layered MVC only for CRUD-only services; CQRS/event sourcing only when the domain needs it (it is not framework-supported in Rust, use a plain crate). Rust's crate system gives modular-monolith boundaries for free; frameworks (axum, actix) are un-opinionated so hexagonal is not fought. ([Zero To Production In Rust](https://www.zero2prod.com/))
- **`RUST-ARCH-02`** (MUST) Map layers to crates: `domain`, `application` (ports + use cases), `adapter-*` (one per technology), `bootstrap` (binary, composition root). In a single-crate service use top-level modules `domain`, `application`, `adapters`, `main.rs`, with `pub(crate)` visibility. Cargo refuses cyclic crate dependencies and a crate cannot use what its `Cargo.toml` does not list. ([Cargo: Workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html))
- **`RUST-ARCH-03`** (MUST) Module semantics: items are private to their module by default; `pub(crate)` is the default for internals, `pub` only for the crate's API; a `mod` tree maps to files (`foo.rs` + `foo/bar.rs`, or `foo/mod.rs`); `use crate::a::b`, `use super::x`, `use dep_name::path`; imports within one crate may be cyclic, crates may not. The arch checker must resolve `use` first segments to workspace crates (hyphens in package names become underscores in paths). ([Rust Reference: Visibility and privacy](https://doc.rust-lang.org/reference/visibility-and-privacy.html))
- **`RUST-ARCH-04`** (MUST) Enforce dependency direction in `Cargo.toml` first: crates list only inward dependencies. Add a CI check from `cargo metadata --format-version 1` (or `cargo tree -p domain --edges normal`) that fails if `domain`/`application` reach `tokio`, `sqlx`, `axum`, `reqwest`, `diesel`; use `cargo-deny` `[bans]` with `wrappers` to restrict who may depend on a crate. The compiler already blocks missing deps; a metadata check blocks someone adding the dep. ([cargo-deny bans](https://embarkstudios.github.io/cargo-deny/checks/bans/cfg.html))
- **`RUST-ARCH-05`** (SHOULD) Inside one crate, forbid cross-layer imports with clippy `disallowed-types`/`disallowed-methods`/`disallowed-macros` in `clippy.toml`, and optionally `cargo-modules` to inspect the module graph. `disallowed-*` is native clippy config, no extra tool; it bans e.g. `std::time::SystemTime::now`. ([Clippy configuration: disallowed-methods](https://doc.rust-lang.org/clippy/lint_configuration.html))
- **`RUST-ARCH-06`** (MUST) Wire dependencies manually in `bootstrap/main.rs`: construct pool, adapters, use cases with `Arc<dyn Port>` or generics, pass to the router state. Do not use a DI container or global statics (`OnceLock` service locators). Rust's explicit ownership makes constructor injection simple; global state hides dependencies and breaks test isolation. ([Rust API Guidelines](https://rust-lang.github.io/api-guidelines/))
- **`RUST-ARCH-07`** (MUST) Keep the domain pure: no `std::fs`, `std::net`, `std::env`, `std::process`, `std::thread`, `tokio`, `sqlx`, `reqwest`, `tracing` macros that need a subscriber, `SystemTime::now`, `Instant::now`, `rand::*`, `Uuid::new_v4`; take `Clock`/`IdGenerator`/`Rng` ports and time as parameters. These betray IO, clock or randomness; the domain stays deterministic and testable without a runtime. ([Hexagonal in Rust (corroboration)](https://www.howtocodeit.com/guides/master-hexagonal-architecture-in-rust))
- **`RUST-ARCH-08`** (SHOULD) Define ports as small traits in the consuming crate (`application`), one capability each; use `async fn` in traits (stable since 1.75) for async ports, and `#[trait_variant::make(Send)]` or an explicit `impl Future + Send` bound so handlers stay `Send`; use `Arc<dyn Trait>` (with `async_trait`) only when dynamic dispatch is needed. `async fn` in traits is not dyn-compatible; the `Send` bound is required by tokio's multi-thread `spawn`. ([Rust blog: async fn in traits](https://blog.rust-lang.org/2023/12/21/async-fn-rpit-in-traits/))
- **`RUST-ARCH-09`** (SHOULD) Model the domain with newtypes, enums for state machines and private fields with validating constructors ("parse, don't validate"); aggregates expose methods that keep invariants; repositories are traits in `application`; domain events are plain enums returned from aggregate methods. Sum types make illegal states unrepresentable, which is Rust's DDD strength. ([API Guidelines: C-NEWTYPE, C-STRUCT-PRIVATE](https://rust-lang.github.io/api-guidelines/type-safety.html))
- **`RUST-ARCH-10`** (SHOULD) SOLID in Rust: one trait per capability (ISP), depend on traits at the edge and concrete types inside (DIP), extend with enums + traits not inheritance (OCP/LSP), `#[non_exhaustive]` on public enums that will grow. Size heuristics: functions <= 50 lines, `clippy::too_many_arguments` (default 7) as the parameter cap, `cognitive_complexity` threshold in `clippy.toml`, one module per ~400 lines. There is no inheritance; composition and traits carry the principles. Limits are loops-specific warnings, tunable. ([Clippy configuration](https://doc.rust-lang.org/clippy/lint_configuration.html))
- **`RUST-ARCH-11`** (SHOULD) Event-driven/actor style: use `tokio::sync::mpsc` + a task owning the state (actor by convention) before reaching for `actix`/`ractor`; durable events go through an outbox table and a broker client (`rdkafka`, `lapin`, `async-nats`). Message passing with a single owner avoids shared mutable state. ([Tokio: channels](https://tokio.rs/tokio/tutorial/channels))
- **`RUST-ARCH-12`** (SHOULD) Serverless: use `cargo-lambda` and the `lambda_runtime` crate; keep the handler as an inbound adapter and cold-start work in `bootstrap`. Rust's fast startup fits Lambda; the hexagon is unchanged. ([cargo-lambda](https://www.cargo-lambda.info/))

## IDIOM: idioms

- **`RUST-IDIOM-01`** (MUST) Return `Result<T, E>` for every fallible operation; propagate with `?`; never swallow with `let _ =` on a `Result` or `.ok()` without a comment; `#[must_use]` is on `Result` already. Reserve `panic!` for bugs (broken invariants). Recoverable vs unrecoverable is encoded in the type system. ([Rust Book ch. 9](https://doc.rust-lang.org/book/ch09-00-error-handling.html))
- **`RUST-IDIOM-02`** (MUST) Libraries and the inner crates (domain, application, adapters) define typed errors with `thiserror` (`#[derive(Error)]`, `#[from]`, `#[source]`); applications (`bootstrap`, CLI, tests) use `anyhow::Result` with `.context("...")`. Do not return `anyhow::Error` from a library API; do not return `Box<dyn Error>` from a public function. Callers match on typed errors; anyhow is for reporting only. ([thiserror](https://docs.rs/thiserror))
- **`RUST-IDIOM-03`** (MUST) Policy for `unwrap`/`expect`: forbidden in non-test code (deny `clippy::unwrap_used`); `expect("invariant: ...")` only for provable invariants (static regex, poisoned-lock decision), message states the invariant; allowed freely in tests. Index slicing `v[i]` on external input is also a panic: use `.get(i)`. A panic in an async worker aborts the task and, with `panic = "abort"`, the process. ([Clippy: unwrap_used](https://rust-lang.github.io/rust-clippy/master/index.html#unwrap_used))
- **`RUST-IDIOM-04`** (MUST) `unsafe` policy: `unsafe_code = "forbid"` in `[workspace.lints.rust]` for every crate; the rare crate needing FFI/atomics opts out explicitly, isolates `unsafe` in a tiny module, documents each block with `// SAFETY:` (deny `undocumented_unsafe_blocks`) and runs miri on it. Edition 2024 requires `unsafe` blocks inside `unsafe fn` and `unsafe extern`. Safe Rust gives memory safety and data-race freedom; every `unsafe` block is a proof obligation. ([Rustonomicon](https://doc.rust-lang.org/nomicon/))
- **`RUST-IDIOM-05`** (SHOULD) Model absence with `Option<T>`; never use sentinel values (`-1`, `""`); convert with `ok_or_else`/`ok_or(Error::X)`; use `let ... else` for early return and let chains (`if let ... && ...`, stable in 1.88, 2024 edition) to flatten nesting. No null exists in safe Rust; `Option` is checked at compile time. ([Rust Book: Option](https://doc.rust-lang.org/book/ch06-01-defining-an-enum.html))
- **`RUST-IDIOM-06`** (SHOULD) Immutable by default: `let` not `let mut`; derive `Clone, Debug, PartialEq, Eq, Hash` where meaningful; pass `&T`/`&str`/`&[T]` in parameters, return owned; prefer `Arc<T>` over deep clone for shared read-only data. Avoid `.clone()` to silence the borrow checker (clippy `redundant_clone`). Ownership makes aliasing explicit; clones hide design problems. ([Rust API Guidelines C-COMMON-TRAITS](https://rust-lang.github.io/api-guidelines/interoperability.html#types-eagerly-implement-common-traits-c-common-traits))
- **`RUST-IDIOM-07`** (SHOULD) Use enums (sum types) and exhaustive `match` for states and errors; avoid wildcard `_ =>` arms on your own enums so new variants break the build; add `#[non_exhaustive]` on public library enums/structs. Exhaustiveness checking is the main refactoring safety net. ([Rust Book ch. 6](https://doc.rust-lang.org/book/ch06-02-match.html))
- **`RUST-IDIOM-08`** (MUST) Use RAII: resources (files, pooled connections, guards, spans) are released in `Drop`; do not rely on `Drop` for async cleanup (no `.await` in `drop`): add an explicit `async fn close(self)` or use `tokio_util::sync::CancellationToken`/drop guards. Do not `mem::forget` or leak (`Box::leak`) in request paths. `Drop` is sync and may not run on abort/`process::exit`. ([Rust Book ch. 15.3 Drop](https://doc.rust-lang.org/book/ch15-03-drop.html))
- **`RUST-IDIOM-09`** (MUST) Strings: `String`/`&str` are UTF-8; never index by byte unless ASCII (`s[..n]` panics on a non-boundary); use `char_indices`, `str::get`, `unicode-segmentation` for graphemes; build with `String::with_capacity` + `push_str`/`write!`. Use `OsString`/`Path` for file names, not `String`. Byte slicing on UTF-8 panics at runtime. ([std::string::String](https://doc.rust-lang.org/std/string/struct.String.html))
- **`RUST-IDIOM-10`** (MUST) Time: use `time` or `chrono` with explicit UTC (`OffsetDateTime`/`DateTime<Utc>`), store UTC, convert at the edge; `Duration` for spans; never `SystemTime` for elapsed time (use `Instant`); inject a `Clock` port. Equality: derive `PartialEq`+`Eq`+`Hash` together and never put `f32/f64` in a `HashMap` key; use `BTreeMap` or sort for deterministic order (`HashMap` iteration order is random). Non-determinism breaks tests; floats lack `Eq`/`Hash`. ([std::collections::HashMap](https://doc.rust-lang.org/std/collections/struct.HashMap.html))
- **`RUST-IDIOM-11`** (MUST) Naming and API shape follow the Rust API Guidelines: RFC 430 casing (`snake_case` fns, `UpperCamelCase` types, `SCREAMING_SNAKE` consts), `as_`/`to_`/`into_` conversions, getters without `get_`, `iter`/`iter_mut`/`into_iter`, constructors `new`/`with_*`/`from_*`, `Builder` for many optional fields; all public types implement `Debug`; fields private. The guidelines are the community contract; clippy enforces several. ([Rust API Guidelines checklist](https://rust-lang.github.io/api-guidelines/checklist.html))
- **`RUST-IDIOM-12`** (SHOULD) Metaprogramming: prefer generics and traits; use `derive` macros freely; write declarative `macro_rules!` only when a function cannot work; write proc macros in a separate crate and avoid them in domain code; avoid reflection-like `Any` downcasting. Macros hurt compile time, IDE support and error messages; proc macros need `proc-macro = true` crates. ([Rust Book ch. 20.5 Macros](https://doc.rust-lang.org/book/ch20-05-macros.html))
- **`RUST-IDIOM-13`** (MUST) Footgun: integer overflow wraps silently in release (panics in debug); use `checked_*`/`saturating_*`/`wrapping_*` explicitly for money/counters and set `overflow-checks = true` in `[profile.release]` for services; avoid `as` for narrowing (use `try_from`; clippy `cast_possible_truncation`, pedantic). Release builds disable overflow checks by default. ([Cargo: profiles](https://doc.rust-lang.org/cargo/reference/profiles.html))
- **`RUST-IDIOM-14`** (MUST) Footgun: `std::sync::Mutex` guard held across `.await` makes the future `!Send` or deadlocks; keep the critical section synchronous, or use `tokio::sync::Mutex` only when the lock must span an await, or restructure to message passing (deny `clippy::await_holding_lock`). Footgun: `RefCell` borrow across `.await` (`await_holding_refcell_ref`). The most common async Rust bug. ([Tokio: shared state](https://tokio.rs/tokio/tutorial/shared-state))
- **`RUST-IDIOM-15`** (AVOID) Avoid `static mut` (denied in 2024 by `static_mut_refs`) and `std::env::set_var` (unsafe in 2024); read config once at startup. Avoid `lazy_static`; use `std::sync::LazyLock`/`OnceLock`. Both are unsound in multithreaded programs. ([Edition Guide 2024: unsafe env, static mut](https://doc.rust-lang.org/edition-guide/rust-2024/index.html))

## CONC: concurrency and the race substitute

- **`RUST-CONC-01`** (MUST) Async I/O services run on the `tokio` multi-thread runtime (`#[tokio::main]`, `flavor = "multi_thread"`); OS threads only for blocking/CPU work; `std::thread::scope` for scoped parallelism; use `rayon` for CPU data-parallelism, never inside an async task without `spawn_blocking`. One runtime per process; mixing runtimes causes panics/deadlocks. ([Tokio tutorial](https://tokio.rs/tokio/tutorial))
- **`RUST-CONC-02`** (MUST) Share state by ownership: move data into tasks, communicate with `mpsc`/`oneshot`/`watch`/`broadcast`; use `Arc<T>` for read-only sharing, `Arc<Mutex<T>>`/`RwLock` for mutation (prefer `parking_lot` or std; short critical sections), atomics only for counters/flags. Compile-time `Send + Sync` bounds make data races a compile error in safe code. Rust rejects unsynchronised shared mutation at compile time. ([Rustonomicon: Send and Sync](https://doc.rust-lang.org/nomicon/send-and-sync.html))
- **`RUST-CONC-03`** (SHOULD) Race detection layers, in cost order: (1) the compiler; (2) `unsafe_code = "forbid"`; (3) `cargo miri test` on crates with `unsafe`; (4) `loom` models for lock-free/atomics code (`#[cfg(loom)]` types, `loom::model`, run with `RUSTFLAGS="--cfg loom"` in `--release`); (5) nightly ThreadSanitizer for FFI/mixed code. Miri detects UB incl. data races in a single-process interpreter; loom explores interleavings under C11; TSan needs instrumented std (`-Zbuild-std`) to avoid false positives. ([Miri](https://github.com/rust-lang/miri))
- **`RUST-CONC-04`** (MUST) Loops race rule: `race.mode = none` with a required substitute. The gate's `clippy` check denies `unsafe_code`, `await_holding_lock` and `await_holding_refcell_ref`; a crate that needs `unsafe` opts out with an explicit `#[allow(unsafe_code)]` and `// SAFETY:` comments, and should also pass the optional `miri`, `loom` and `tsan` checks (enable them in config). Never add a retry or skip to hide a flaky test (WORKFLOW §6). There is no `-race` flag to force; TSan is nightly-only and needs a target and `-Zbuild-std`. ([Unstable Book: sanitizer](https://doc.rust-lang.org/nightly/unstable-book/compiler-flags/sanitizer.html))
- **`RUST-CONC-05`** (MUST) Never block the async runtime: no `std::fs`, `std::thread::sleep`, sync DB/HTTP drivers or heavy CPU in `async fn`; use `tokio::fs`, `tokio::time::sleep`, or `tokio::task::spawn_blocking` for short blocking work and `std::thread`/`rayon` for long-running or CPU-bound work. Aborting a `spawn_blocking` task has no effect; shutdown waits for started blocking tasks. A blocked worker thread stalls every task on it. ([tokio::task::spawn_blocking](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html))
- **`RUST-CONC-06`** (MUST) Cancellation safety: every `.await` is a cancellation point and a future may simply be dropped (timeouts, `select!`, client disconnect in axum). Do not hold half-applied state across `.await`; check the "cancel safety" note of each method used in `tokio::select!`; make DB writes transactional so a dropped handler rolls back. Dropped futures skip the rest of the function body. ([tokio::select! cancellation safety](https://docs.rs/tokio/latest/tokio/macro.select.html#cancellation-safety))
- **`RUST-CONC-07`** (SHOULD) Structured concurrency: spawn related tasks in a `tokio::task::JoinSet` (dropping it aborts all tasks; `join_next` is cancel safe; `shutdown().await` aborts and drains), or `tokio::join!`/`try_join!`; keep every `JoinHandle` and observe its `JoinError`; never fire-and-forget `tokio::spawn` without logging errors. Detached tasks swallow panics and outlive their owner. ([tokio::task::JoinSet](https://docs.rs/tokio/latest/tokio/task/struct.JoinSet.html))
- **`RUST-CONC-08`** (MUST) Futures that go to `tokio::spawn` must be `Send + 'static`: do not hold `Rc`, `RefCell`, `MutexGuard` or non-`Send` locals across `.await`; use `Arc`; wrap with `tokio::task::LocalSet` only for `!Send` work. A non-`Send` future fails to compile at the spawn site with a long error. ([Tokio tutorial: spawning, Send bound](https://tokio.rs/tokio/tutorial/spawning#send-bound))
- **`RUST-CONC-09`** (MUST) Bound everything: bounded `mpsc::channel(n)` for backpressure (`unbounded_channel` only with a documented cap), `tokio::sync::Semaphore` for concurrency limits, `tokio::time::timeout` on every outbound call, `tower::limit`/`timeout` layers inbound. Unbounded queues turn slow consumers into OOM. ([Tokio: channels](https://tokio.rs/tokio/tutorial/channels))
- **`RUST-CONC-10`** (MUST) Graceful shutdown: one `CancellationToken` (tokio-util) or `watch` channel, handle `SIGTERM` and Ctrl-C with `tokio::signal`, pass `with_graceful_shutdown` to `axum::serve`, drain workers with `JoinSet` and a deadline; do not call `std::process::exit` in handlers. Orchestrators send SIGTERM and then SIGKILL after a grace period. ([Tokio: graceful shutdown](https://tokio.rs/tokio/topics/shutdown))
- **`RUST-CONC-11`** (MUST) Do not use blocking std primitives (`std::sync::mpsc`, `Condvar`) in async code; do not call `block_on` from inside the runtime (panic); from sync code use `Handle::block_on` on a dedicated thread. Nested runtimes panic with "Cannot start a runtime from within a runtime". ([Tokio: bridging](https://tokio.rs/tokio/topics/bridging))

## TEST: testing and coverage

- **`RUST-TEST-01`** (MUST) Unit tests live next to the code in `#[cfg(test)] mod tests { use super::*; }`; integration tests in `tests/*.rs` (each file is its own binary using only the public API); doctests in `///` examples; use `#[tokio::test]` for async. Standard Rust test taxonomy; `cargo test` runs all three. ([Rust Book ch. 11](https://doc.rust-lang.org/book/ch11-03-test-organization.html))
- **`RUST-TEST-02`** (MUST) Recognise test files by glob: `**/tests/**/*.rs`, `**/benches/**/*.rs`, `**/tests.rs`, `**/*_test.rs`, `**/*_tests.rs`; unit tests are also inline in `src/**/*.rs` under `#[cfg(test)]`, so file-based "is test" detection is incomplete. Share helpers in `tests/common/mod.rs` (a `mod.rs` is not compiled as its own test). The loops test-file ownership glob and "new code has tests" check need this. ([Rust Book ch. 11.3](https://doc.rust-lang.org/book/ch11-03-test-organization.html))
- **`RUST-TEST-03`** (SHOULD) Name tests `behaviour_when_condition` (`rejects_expired_token`), arrange-act-assert, one behaviour per test; use `#[test_case]`/`rstest` for parametrised cases or a `for` loop over a table of `(input, expected)`; use `assert_eq!` with messages and `#[should_panic(expected = ...)]` sparingly (prefer returning `Result<(), E>` from tests). Table-driven tests are the Rust equivalent of Go's. ([rstest](https://docs.rs/rstest))
- **`RUST-TEST-04`** (SHOULD) Prefer hand-written fakes that implement the port trait (in-memory repositories) over mocks; use `mockall` (`#[automock]`) only to assert interactions at the boundary; use `wiremock` for outbound HTTP, never mock the type under test or the standard library. Fakes survive refactors; mocks couple to call sequences. ([mockall](https://docs.rs/mockall))
- **`RUST-TEST-05`** (SHOULD) Integration tests use real dependencies: `testcontainers` (Postgres/Redis/Kafka), `#[sqlx::test]` (a fresh database per test, migrations applied) and tower `ServiceExt::oneshot` to call an axum `Router` without a socket. Real SQL catches dialect/migration bugs that fakes hide. ([testcontainers-rs](https://docs.rs/testcontainers))
- **`RUST-TEST-06`** (MUST) Coverage uses `cargo llvm-cov {pkgs} --locked --lcov --output-path {coverage}` (needs the `llvm-tools-preview` component; loops creates the output directory). `tests/`, `benches/`, `examples/`, `build.rs`, `main.rs` and `src/bin/` are excluded from judging. Prefer it to tarpaulin. Source-based LLVM coverage works on Linux, macOS and Windows; the command exits 1 if the output directory is missing. ([cargo-llvm-cov](https://github.com/taiki-e/cargo-llvm-cov))
- **`RUST-TEST-07`** (MUST) New-code coverage is at least 70%: loops intersects the lcov `SF:`/`DA:` records with `git diff -U0` itself (no diff-cover). Inline `#[cfg(test)]` lines count as code, so the figure is biased upward; accept it and keep `tests/`, `benches/` excluded. Rust has no native diff coverage; the bias is accepted by decision D8. ([cargo-llvm-cov: lcov/cobertura](https://github.com/taiki-e/cargo-llvm-cov))
- **`RUST-TEST-08`** (SHOULD) Test runner: use `cargo-nextest` in CI (`cargo nextest run --workspace --all-features --locked --profile ci`; each test in its own process, retries/slow-timeout/JUnit in `.config/nextest.toml`); keep `cargo test --doc --workspace` as a separate step because nextest does not run doctests. Process-per-test isolation exposes global-state coupling and runs faster than `cargo test`; doctests unsupported. ([nextest running](https://nexte.st/docs/running/))
- **`RUST-TEST-09`** (SHOULD) Property testing with `proptest` (`proptest!` macro, shrinking, regression files committed under `proptest-regressions/`) for parsers, serialisation round-trips, state machines; fuzzing with `cargo fuzz` (libFuzzer, nightly, `fuzz/` crate excluded from the workspace default-members) for decoders and untrusted input; mutation testing with `cargo-mutants` on critical logic only. Property tests find edge cases; fuzzing finds panics in parsers. ([proptest book](https://proptest-rs.github.io/proptest/intro.html))
- **`RUST-TEST-10`** (SHOULD) Snapshot tests with `insta` (`cargo insta review`) for serialised output; keep snapshots small and reviewed. Golden files catch API response drift. ([insta](https://insta.rs/docs/))
- **`RUST-TEST-11`** (MUST) Flakiness: tests must not share global state or ports (use port 0 and `TcpListener::local_addr`); inject the clock; use `tokio::time::pause()` (feature `test-util`) for time; never `sleep` to wait. `cargo test` runs tests in parallel threads in one process, nextest in separate processes; cap with `--test-threads=N`/`-j N`. Process isolation and virtual time remove most flakes. ([tokio::time::pause](https://docs.rs/tokio/latest/tokio/time/fn.pause.html))
- **`RUST-TEST-12`** (SHOULD) Fast loop: `cargo check`, `cargo nextest run -p <crate> <filter>`, `cargo test -p <crate> -- <name> --exact`, `bacon`/`cargo watch -x test` for watch mode; use a fast linker (`mold`/`lld`) and `[profile.dev] debug = "line-tables-only"` or `debug = 0` for build speed. Compile time dominates Rust TDD. ([bacon](https://dystroy.org/bacon/))
- **`RUST-TEST-13`** (MUST) The hard gate runs `cargo test` or nextest with coverage, and fails when any test command exits non-zero, a test is `#[ignore]`d without a reason, or coverage of new code is under 70%. Never weaken a test to pass. Matches the hard rule in `ROLES.md`. ([cargo test](https://doc.rust-lang.org/cargo/commands/cargo-test.html))

## PERF: performance

- **`RUST-PERF-01`** (SHOULD) Benchmark with `criteria` (statistical, `cargo bench`, HTML report, `--save-baseline`/`--baseline` comparison) or `divan` (attribute-based, lighter, alloc counting); put benches in `benches/` with `harness = false`; use `std::hint::black_box`; benchmark in release only. `#[bench]` is nightly-only; criteria/divan are the stable options. ([criteria book](https://bheisler.github.io/criteria.rs/book/))
- **`RUST-PERF-02`** (SHOULD) Profile before optimising: `cargo flamegraph` (perf/dtrace) or `samply` for CPU, `dhat` or heaptrack for allocations, `tokio-console` for task stalls; build with `[profile.release] debug = "line-tables-only"` for symbols. Measure, then change. ([Rust Performance Book: profiling](https://nnethercote.github.io/perf-book/profiling.html))
- **`RUST-PERF-03`** (SHOULD) Release profile for services: `lto = "thin"`, `codegen-units = 1` (slower build, faster code), `panic = "abort"` only if no `catch_unwind`/panic hooks rely on unwinding, `opt-level = 3`; consider `jemalloc` (`tikv-jemallocator`) or `mimalloc` as the global allocator on glibc/musl. Cap build jobs. Build-time vs runtime tradeoffs are explicit in `Cargo.toml`. ([Rust Performance Book: build configuration](https://nnethercote.github.io/perf-book/build-configuration.html))
- **`RUST-PERF-04`** (SHOULD) Hot-path mistakes: needless `.clone()`/`.to_string()` allocation, collecting into a `Vec` just to iterate again, `String` concatenation in loops, `Box<dyn Trait>` in inner loops, locking per item, `format!` for logging when disabled (use tracing lazy fields), unbuffered I/O (wrap in `BufReader`/`BufWriter`), `HashMap` default SipHash on trusted small keys (use `rustc-hash`/`ahash` only after measuring). Common allocation and dispatch costs. ([Rust Performance Book: heap allocations](https://nnethercote.github.io/perf-book/heap-allocations.html))
- **`RUST-PERF-05`** (SHOULD) Async hot paths: do not `.await` in a tight loop over independent work (use `buffer_unordered`/`JoinSet`), avoid huge futures on the stack (`clippy::large_futures`; `Box::pin`), prefer `bytes::Bytes` for zero-copy buffers. Large futures bloat stack and memcpy. ([tokio tutorial: I/O, bytes](https://tokio.rs/tokio/tutorial/io))

## SEC: security

- **`RUST-SEC-01`** (MUST) SQL: use bind parameters only (`sqlx::query!`/`query_as!` with `$1`, diesel DSL, sea-orm `Statement::from_sql_and_values`); never `format!` into SQL; for dynamic identifiers use an allow-list. Commands: `std::process::Command::new(bin).arg(x)` with no shell (`sh -c`); never pass user input to a shell. The API separates code from data; `format!` reintroduces injection. ([OWASP SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html))
- **`RUST-SEC-02`** (MUST) Deserialise with `serde` into strict typed structs (`#[serde(deny_unknown_fields)]` for config), cap body sizes (`DefaultBodyLimit`, `RequestBodyLimitLayer`) and nesting; Rust has no executable-deserialisation gadget class, but `bincode`/`postcard` on untrusted input must be length-limited; avoid `serde_yaml` (unmaintained, archived in 2024) for new work; XML via `quick-xml` has no DTD/XXE entity expansion by default. Resource exhaustion, not code execution, is the Rust risk. ([OWASP Deserialization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html))
- **`RUST-SEC-03`** (MUST) Web: validate outbound URLs against an allow-list and block private ranges and redirects in `reqwest` (SSRF); join paths with `Path::canonicalize` + `starts_with(base)` or `tower-http` `ServeDir` (path traversal); configure CORS with `tower_http::cors::CorsLayer` with explicit origins (never `Any` with credentials); add CSRF protection for cookie sessions. Defaults are permissive in tower-http only if you ask for `Any`. ([OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html))
- **`RUST-SEC-04`** (MUST) Secrets: read from the environment/secret manager, wrap in `secrecy::SecretString` (redacted `Debug`, zeroised on drop), never log or derive `Debug` on structs with raw secrets; no secrets in `.cargo/config.toml` or Dockerfile layers. Crypto: use `rustls`, `ring`/`aws-lc-rs`, RustCrypto; hash passwords with `argon2` (or `scrypt`/`bcrypt`); compare tokens with `subtle::ConstantTimeEq`; random bytes from `rand::rngs::OsRng` / `getrandom`, never `rand::thread_rng` for keys unless documented CSPRNG. Do not roll your own crypto; do not use `openssl` vendoring unless needed. `Debug` derive leaks secrets into logs. ([OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html))
- **`RUST-SEC-05`** (MUST) Validate at the adapter boundary: parse DTOs into domain value types with `TryFrom` (parse, don't validate); use the `validator` or `garde` crate for DTO rules; axum extractors reject bad input with 400/422 before use cases run. Domain types make invalid data unrepresentable inside the hexagon. ([garde](https://docs.rs/garde))
- **`RUST-SEC-06`** (MUST) Supply chain: commit `Cargo.lock`, build with `--locked`, run `cargo deny check` with `[sources] unknown-registry = "deny"`, `unknown-git = "deny"`, allow-listed licenses, `[bans] multiple-versions = "warn"`; review `build.rs` and proc-macro crates when adding dependencies (they run arbitrary code at build time); optionally `cargo vet` for audit records. crates.io publishing uses trusted publishing (OIDC) where available. `build.rs` and proc macros execute on every developer machine and in CI. ([cargo-deny](https://embarkstudios.github.io/cargo-deny/))
- **`RUST-SEC-07`** (SHOULD) Static security analysis: clippy (default + `undocumented_unsafe_blocks`, `indexing_slicing`, `arithmetic_side_effects` at warn for sensitive crates), `cargo audit` for RustSec advisories, `cargo geiger` to count `unsafe` in the dependency tree, Semgrep Rust rules in CI. There is no Rust equivalent of gosec as a single tool. Clippy and RustSec are the de-facto SAST pair. ([RustSec](https://rustsec.org/))
- **`RUST-SEC-08`** (MUST) Panics are a denial-of-service vector: handlers must not panic on external input (no `unwrap`, slicing, integer division by input, `RefCell` double borrow); add `tower_http::catch_panic::CatchPanicLayer` as a last line of defence and alert on it. tokio isolates a panic to one task, but the request still fails and invariants may break. ([tower_http::catch_panic](https://docs.rs/tower-http/latest/tower_http/catch_panic/index.html))
- **`RUST-SEC-09`** (SHOULD) Run the process as non-root in a minimal image, set security headers (`tower_http::set_header`), enforce TLS with `rustls` (no `native-tls` unless needed), set request/handshake timeouts, and cap body and header sizes. Defence in depth at the edge. ([OWASP REST Security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html))

## DATA: persistence

- **`RUST-DATA-01`** (SHOULD) Default to `sqlx` (async, compile-time-checked raw SQL via `query!` macros, no DSL) for hexagonal repositories; choose `diesel` (sync, strongly typed DSL, `diesel_async` for async) when you want a typed query builder; choose `sea-orm` (async ORM on sqlx) for CRUD-heavy services needing relations. Keep the choice inside the outbound adapter crate. A raw-SQL style keeps SQL visible and ports small; ORM entities must not leak into the domain. ([sqlx](https://docs.rs/sqlx/latest/sqlx/))
- **`RUST-DATA-02`** (MUST) Migrations: `sqlx migrate add -r <name>` / `sqlx migrate run` (embedded with `sqlx::migrate!()` and run at startup or as a deploy step) or `diesel migration generate/run`; keep migrations forward-only and expand/contract for zero downtime (add nullable column -> backfill -> switch -> drop). Commit `.sqlx/` (from `cargo sqlx prepare --workspace`) and build CI with `SQLX_OFFLINE=true`; check it with `cargo sqlx prepare --check`. Compile-time query checking needs a live DB or the offline cache. ([sqlx-cli](https://github.com/launchbadge/sqlx/blob/main/sqlx-cli/README.md))
- **`RUST-DATA-03`** (MUST) Transactions are an application-layer concern: define a `UnitOfWork`/`Transactional` port, implemented in the adapter by `pool.begin()`/`tx.commit()`; a dropped `Transaction` rolls back, so use `?` freely; never hold a transaction across a network call. Rollback-on-drop makes error paths safe; long transactions pin connections. ([sqlx::Transaction](https://docs.rs/sqlx/latest/sqlx/struct.Transaction.html))
- **`RUST-DATA-04`** (SHOULD) Avoid N+1 queries: use `JOIN`s, `WHERE id = ANY($1)`/`IN`, or `sea-orm` `find_with_related`/`loader`; Rust ORMs do not lazy-load implicitly, so the trap is explicit loops of `.await` queries; check with query logging in tests. Per-item `.await` in a loop is the Rust form of N+1. ([SeaORM loader](https://www.sea-ql.org/SeaORM/docs/relation/model-loader/))
- **`RUST-DATA-05`** (MUST) Connections: one `sqlx::PgPool` per process created in `bootstrap` (`PgPoolOptions::max_connections`, `acquire_timeout`, `idle_timeout`, `max_lifetime`); size the pool below the DB limit across all replicas; set `statement_timeout`; use async drivers only (`sqlx`, `tokio-postgres`, `deadpool`/`bb8` pooling, `diesel_async`); never use the sync `diesel` inside async handlers without `spawn_blocking`. Pools without timeouts hang requests; sync drivers block the runtime. ([sqlx::pool](https://docs.rs/sqlx/latest/sqlx/struct.Pool.html))
- **`RUST-DATA-06`** (MUST) Map database rows to private row structs in the adapter and convert to domain types with `TryFrom`; never derive `sqlx::FromRow` or `Serialize` on domain entities. Keeps the domain free of persistence annotations. ([sqlx FromRow](https://docs.rs/sqlx/latest/sqlx/trait.FromRow.html))
- **`RUST-DATA-07`** (MUST) Money and precision: use `rust_decimal` or integer minor units, never `f64`; use `uuid` v7 for time-ordered keys (injected `IdGenerator`), `time`/`chrono` with UTC columns (`timestamptz`). Floating point is not exact; random v4 UUID keys fragment indexes. ([rust_decimal](https://docs.rs/rust_decimal))

## API: APIs and integration

- **`RUST-API-01`** (SHOULD) HTTP framework: default to `axum` (tokio + tower + hyper; handlers are async functions with extractors; `Router` state via `with_state`); layers (`tower::ServiceBuilder`, `tower-http`: trace, timeout, compression, cors, request-id, body limit) form the middleware stack, with the outermost layer first. `actix-web` is the mature alternative (own runtime wrapper, actor-based origins, its own middleware API). axum reuses tower so middleware is shared with tonic and clients. ([axum](https://docs.rs/axum/latest/axum/))
- **`RUST-API-02`** (MUST) Handlers are inbound adapters: extract and validate DTOs, call one use case, map the result; no business logic or SQL in handlers; share state through `State<AppState>` holding `Arc`s of use cases; `AppState: Clone + Send + Sync + 'static`. Thin handlers keep the hexagon intact. ([axum State](https://docs.rs/axum/latest/axum/extract/struct.State.html))
- **`RUST-API-03`** (SHOULD) Contracts: code-first with `utoipa` (+ `utoipa-axum`) or `aide` generating OpenAPI, or spec-first with `progenitor`/`oapi-codegen`-like generators; gRPC with `tonic` + `prost` (generate in `build.rs` into `OUT_DIR`, keep `.proto` in `proto/`, lint with `buf`); GraphQL with `async-graphql`; version in the path (`/v1`) or header. Generated types stay in the adapter crate. ([utoipa](https://docs.rs/utoipa))
- **`RUST-API-04`** (MUST) Errors at the edge: implement `IntoResponse` for one `ApiError` enum (thiserror) that maps domain/application errors to status codes and an RFC 9457 `application/problem+json` body; log the source error and return a stable code, never the internal message. One mapping point keeps errors consistent and leak-free. ([axum error handling](https://docs.rs/axum/latest/axum/error_handling/index.html))
- **`RUST-API-05`** (MUST) Resilience: `tower` `TimeoutLayer`, `ConcurrencyLimitLayer`, `LoadShedLayer`, rate limiting via `tower-governor` or `governor`; retries with exponential backoff and jitter (`backon`, `reqwest-retry`/`tower::retry`) only for idempotent calls; accept an `Idempotency-Key` header for POST with a stored result. Timeouts and limits are tower layers, so they compose. ([tower](https://docs.rs/tower/latest/tower/))
- **`RUST-API-06`** (MUST) Messaging: `rdkafka` (librdkafka wrapper), `lapin` (RabbitMQ), `async-nats`, `aws-sdk-sqs`; use the transactional outbox (write event in the same DB transaction, a relay task publishes) and idempotent consumers (dedupe by message id) because delivery is at-least-once; ack after the handler commits. Dual writes lose events. ([rdkafka](https://docs.rs/rdkafka))
- **`RUST-API-07`** (MUST) HTTP client: one long-lived `reqwest::Client` (connection pool, `rustls-tls`) cloned cheaply into adapters, always with `timeout`/`connect_timeout`; propagate cancellation by dropping the future and the trace context via `tracing`+OpenTelemetry headers; never build a client per request. Per-request clients defeat pooling and leak sockets. ([reqwest](https://docs.rs/reqwest/latest/reqwest/struct.Client.html))
- **`RUST-API-08`** (SHOULD) Streaming/WebSockets/SSE use axum's `Sse`, `WebSocketUpgrade` and bounded channels; handle client disconnect by cancellation (dropped future) and clean up in a `Drop` guard. Disconnects drop futures silently. ([axum Sse](https://docs.rs/axum/latest/axum/response/sse/index.html))

## OBS: observability

- **`RUST-OBS-01`** (MUST) Log with the `tracing` crate (structured fields, `#[instrument(skip(...))]`) and `tracing-subscriber` (`EnvFilter` from `RUST_LOG`, JSON layer in production); never `println!`/`eprintln!` (deny `print_stdout`); never log secrets or PII (`skip` them, use `secrecy`). `tracing` spans carry async context across `.await`; `log` has no spans. ([tracing](https://docs.rs/tracing))
- **`RUST-OBS-02`** (SHOULD) Correlation: add `tower_http::request_id::SetRequestIdLayer`/`PropagateRequestIdLayer` and `TraceLayer` with a span that records the request id, method, route and status; include the id in error responses. Ties logs, traces and client reports. ([tower_http::trace](https://docs.rs/tower-http/latest/tower_http/trace/index.html))
- **`RUST-OBS-03`** (SHOULD) Metrics with the `metrics` facade + `metrics-exporter-prometheus` (or the OpenTelemetry metrics SDK); name `snake_case`, base units, `_total` for counters, low-cardinality labels only (route template, not raw path). High-cardinality labels explode storage. ([metrics](https://docs.rs/metrics))
- **`RUST-OBS-04`** (SHOULD) Tracing: `opentelemetry` + `opentelemetry-otlp` + `tracing-opentelemetry` bridge; propagate W3C `traceparent` in inbound extractors and outbound reqwest middleware. The Rust OTel traces/metrics SDKs are usable; logs and some components are still maturing (check the status table). Context propagation across async tasks needs the tracing bridge. ([OpenTelemetry Rust](https://opentelemetry.io/docs/languages/rust/))
- **`RUST-OBS-05`** (MUST) Health: expose `/healthz` (liveness: process up) and `/readyz` (readiness: DB ping with a timeout, dependencies reachable) as plain axum routes; neither framework ships them built in. Orchestrators route traffic on readiness only. ([axum routing](https://docs.rs/axum/latest/axum/struct.Router.html))
- **`RUST-OBS-06`** (AVOID) Use `tokio-console` (`console-subscriber`, `--cfg tokio_unstable`) in development to find stuck tasks; do not enable it in production by default. Task-level diagnostics are unstable-gated. ([tokio-console](https://github.com/tokio-rs/console))

## OPS: configuration, packaging and operations

- **`RUST-OPS-01`** (MUST) Config: bind typed structs with `serde` from env vars (12-factor) layered over a file using `figment` or the `config` crate; validate on startup and fail fast; secrets as `SecretString`; `dotenvy` for local `.env` only. A bad config must stop the process, not a request. ([config](https://docs.rs/config))
- **`RUST-OPS-02`** (SHOULD) Package as a single static-ish binary in a multi-stage Dockerfile: `rust:<ver>` builder with `cargo-chef` (recipe/cook layers) or BuildKit cache mounts for `~/.cargo/registry` and `target`, final stage `gcr.io/distroless/cc-debian12` (glibc) or `scratch`/`alpine` with the `x86_64-unknown-linux-musl` target; `cargo build --release --locked`; strip symbols; run as non-root. Small attack surface and fast CI builds. ([cargo-chef](https://github.com/LukeMathWalker/cargo-chef))
- **`RUST-OPS-03`** (SHOULD) Native/AOT is the default (Rust compiles to native code); musl static builds avoid glibc mismatches but use a slower allocator (swap in `mimalloc`/`jemalloc`); no JVM-style warm-up. Rust has no AOT trade-off, only libc and allocator choices. ([Rust platform support](https://doc.rust-lang.org/nightly/rustc/platform-support.html))
- **`RUST-OPS-04`** (MUST) Lifecycle: install SIGTERM/SIGINT handlers (`tokio::signal::unix`), stop accepting new work, let in-flight requests finish within a deadline, flush telemetry, close the pool; set `terminationGracePeriodSeconds` above the drain deadline. Prevents dropped requests on deploy. ([Tokio: graceful shutdown](https://tokio.rs/tokio/topics/shutdown))
- **`RUST-OPS-05`** (MUST) Run-scoped caches: loops scopes `CARGO_TARGET_DIR` and `TMPDIR` per run and sets `CARGO_INCREMENTAL=0`; `CARGO_HOME`, `RUSTUP_HOME` and `SCCACHE_DIR` stay shared (Cargo's package-cache lock makes concurrent runs safe). Cap parallelism with `CARGO_BUILD_JOBS=2`; set `RUSTC_WRAPPER=sccache` to share compiled objects across per-run target dirs. One shared `target/` serialises parallel runs on the build-directory lock; a cold per-run target dir recompiles the whole graph, which sccache recovers. ([Cargo environment variables](https://doc.rust-lang.org/cargo/reference/environment-variables.html))
- **`RUST-OPS-06`** (MUST) Artifacts left behind: `target/` (can reach tens of GB; `cargo clean` or delete the run's `CARGO_TARGET_DIR`), `target/llvm-cov-target/` and `target/llvm-cov/` (cargo-llvm-cov), `lcov.info`, `cobertura.xml`, `*.profraw`, `*.profdata`, `proptest-regressions/` (keep, commit), `fuzz/corpus` and `fuzz/artifacts`, `.sqlx/` (keep, commit), `criteria` output under `target/criteria`, `flamegraph.svg`, `perf.data*`, `mutants.out/`, nextest `target/nextest/`, `Cargo.lock` changes on library crates. This list drives the cleanup; the committed ones must not be deleted. ([cargo-llvm-cov](https://github.com/taiki-e/cargo-llvm-cov))
- **`RUST-OPS-07`** (SHOULD) Reproducible builds: `cargo build --release --locked`, pinned toolchain, `--remap-path-prefix`/`[profile.release] trim-paths`, fixed `SOURCE_DATE_EPOCH`, and vendoring (`cargo vendor`) only when offline builds are required. Same inputs produce the same binary. ([Cargo: cargo vendor](https://doc.rust-lang.org/cargo/commands/cargo-vendor.html))
- **`RUST-OPS-08`** (SHOULD) `[profile.release]` and CI env defaults: `CARGO_TERM_COLOR=always`, `CARGO_INCREMENTAL=0` in CI, `RUST_BACKTRACE=1` in services, `RUST_LOG=info`; set `CARGO_NET_RETRY`; use `CARGO_NET_OFFLINE=true` after a `cargo fetch --locked` step for hermetic builds. Avoids network flakes and cache poisoning. ([Cargo environment variables](https://doc.rust-lang.org/cargo/reference/environment-variables.html))

## DOC: documentation and review

- **`RUST-DOC-01`** (MUST) Document every public item with `///` (first line a summary sentence; sections `# Errors`, `# Panics`, `# Safety`, `# Examples`); module docs with `//!`; examples are compiled doctests; build with `cargo doc --no-deps --workspace` with `RUSTDOCFLAGS="-D warnings"` and `#![warn(missing_docs)]` for library crates. Rustdoc checks links and examples; the API Guidelines require error/panic/safety sections. ([rustdoc book](https://doc.rust-lang.org/rustdoc/))
- **`RUST-DOC-02`** (SHOULD) Repo docs: `README` (what, build with `cargo`, run, config table), `CHANGELOG.md` (Keep a Changelog, generated by release-plz/git-cliff), ADRs in `docs/adr/`; include crate-level `//!` docs rendered as the crate README via `#![doc = include_str!("../README.md")]`. One source for crates.io, docs.rs and the repo. ([Keep a Changelog](https://keepachangelog.com/))
- **`RUST-DOC-03`** (SHOULD) Reviewer checklist, in order: (1) public API/types (newtypes, `non_exhaustive`, private fields); (2) error handling (`thiserror` vs `anyhow`, no `unwrap`); (3) ownership (needless `clone`, lifetimes, `Arc`); (4) async (blocking calls, locks across `.await`, cancellation, bounded channels); (5) `unsafe` and `// SAFETY:`; (6) dependency additions (`cargo deny`, `build.rs`); (7) tests/coverage; (8) layer direction in `Cargo.toml`. Matches the failure modes that Rust adds on top of general review. ([Rust API Guidelines](https://rust-lang.github.io/api-guidelines/checklist.html))
- **`RUST-DOC-04`** (SHOULD) Doc links use intra-doc links ``[`Type`]`` and `cargo doc` runs with `-D rustdoc::broken_intra_doc_links`; hide implementation details with `#[doc(hidden)]` and `pub(crate)`. Broken links rot silently. ([rustdoc: linking](https://doc.rust-lang.org/rustdoc/write-documentation/linking-to-items-by-name.html))
- **`RUST-DOC-05`** (SHOULD) Use `cargo semver-checks` and `cargo doc` in the PR for library crates; for services publish OpenAPI (utoipa output) as a build artifact. API drift is caught before release. ([cargo-semver-checks](https://github.com/obi1kenobi/cargo-semver-checks))

## FW: frameworks

- **`RUST-FW-01`** (SHOULD) Dominant frameworks: `axum` (tokio-rs; default for new work), `actix-web` (mature, high throughput), plus `tonic` (gRPC), `poem`/`rocket` (smaller share), with `tokio` as the runtime in the large majority of async code. Usage evidence: the 2024 State of Rust survey (published 2025-02) and crates.io download counts; confirm current ranking at selection time. Pick the ecosystem default unless there is a reason. ([State of Rust Survey 2024](https://blog.rust-lang.org/2025/02/13/2024-State-Of-Rust-Survey-results/))
- **`RUST-FW-02`** (MUST) axum conventions: extractors ordered with the body extractor last, `State` for dependencies, `Router::merge`/`nest` per bounded context, `ServiceBuilder` layers (outermost first), `Result<impl IntoResponse, ApiError>` handlers. These fit hexagonal: handlers are the inbound adapter. axum enforces no structure, so the layout comes from the team (and loops). ([axum docs](https://docs.rs/axum/latest/axum/))
- **`RUST-FW-03`** (MUST) actix-web conventions: `App::new().app_data(web::Data::new(...))` for shared state (wrapped in `Arc` internally), `HttpServer` per-thread app factory (state must be created once outside the factory), middleware via `wrap`, `actix-rt` runtime (single-threaded workers; avoid blocking with `web::block`). Project rules win if the repo already uses it. App factory runs once per worker; building a pool inside it multiplies pools. ([actix-web docs](https://actix.rs/docs/application/))
- **`RUST-FW-04`** (SHOULD) Framework footguns: axum extractor order (body-consuming extractors must be last), `Json` rejects return 422/400 plain text unless handled, `State` requires `Clone`, cloned `Mutex`es instead of `Arc<Mutex>`, forgetting the timeout layer, hyper `Connection: keep-alive` leaks without timeouts, actix `app_data` type mismatch silently yielding 500, sqlx macros failing offline without `.sqlx/`. Each of these shows up as a runtime or CI failure, not a compile error. ([axum extractors order](https://docs.rs/axum/latest/axum/extract/index.html#the-order-of-extractors))
- **`RUST-FW-05`** (SHOULD) Prefer `tower` services/layers over framework-specific middleware so cross-cutting concerns are reusable across axum, tonic and `reqwest` stacks; write custom layers only when `tower-http` has none. One middleware vocabulary. ([tower](https://docs.rs/tower/latest/tower/))

## Top 10 footguns

1. **Blocking the async runtime**: `std::fs::read`/`thread::sleep`/CPU loop in an `async fn` -> `tokio::fs`, `tokio::time::sleep`, `spawn_blocking`, or rayon.
2. **Holding a `std::sync::Mutex` guard across `.await`**: `let g = m.lock().unwrap(); foo().await;` -> scope the guard before awaiting, or message passing; deny `await_holding_lock`.
3. **`unwrap()`/`expect()` on external input and slice indexing**: `body.get("x").unwrap()`, `v[i]` -> `ok_or(Error::Missing)?`, `.get(i)`; deny `unwrap_used`.
4. **Cancellation-unsafe `select!`/timeouts**: `select!` with a future that loses buffered data when dropped -> use cancel-safe methods, move state outside, make writes transactional.
5. **Detached `tokio::spawn` that swallows panics/errors**: `tokio::spawn(work());` -> keep the `JoinHandle`/`JoinSet`, log `JoinError`, use a `CancellationToken`.
6. **Release-mode integer overflow and `as` casts**: `let total = a + b;`, `x as u32` -> `checked_add`, `u32::try_from(x)?`, `overflow-checks = true`.
7. **`.clone()` to appease the borrow checker and unbounded channels**: cloning large data per request, `unbounded_channel()` -> borrow or `Arc`, bounded `mpsc::channel(n)`.
8. **Byte-slicing UTF-8 strings**: `&s[..10]` -> `s.chars().take(10)`, `s.get(..10)`.
9. **Un-timed outbound calls and a `reqwest::Client` per request**: `reqwest::get(url)` -> shared `Client::builder().timeout(..)`.
10. **Stale/unlocked dependency graph and unvetted `build.rs`**: uncommitted `Cargo.lock`, no `--locked`, no `cargo deny` -> commit the lockfile, `--locked`, `cargo deny check`, `cargo audit`.
