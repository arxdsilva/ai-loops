# Java Rules

The citable Java rule book for the `java` language pack: JDK 25 LTS (JDK 27 current, JDK 21 floor for libraries), Maven 3.9/3.10 and Gradle 9 (Kotlin DSL), Spring Boot 4.1, JUnit 6. As of 2026-11. Source: `research/languages/java.md` (verified, rule IDs kept). Universal rules live in `specs/ARCHITECTURE.md`, `specs/SOLID.md`; this file only adds what is Java-specific. Project rules win: follow the project's own config over these defaults and log each override with `loops run override`. Pack data: `specs/languages/java/pack.json`.


## REPO: repository and project management

- **`JAVA-REPO-01`** (MUST) Follow the Maven standard directory layout (`src/main/java`, `src/main/resources`, `src/test/java`, `src/test/resources`) in both Maven and Gradle; never invent source roots. Every tool (IDE, JaCoCo, Surefire, Sonar) assumes it. ([Maven standard directory layout](https://maven.apache.org/guides/introduction/introduction-to-the-standard-directory-layout.html))
- **`JAVA-REPO-02`** (SHOULD) Start new services from Spring Initializr (or `quarkus create app`, Micronaut Launch) and commit the wrapper, `.gitignore`, `.editorconfig`, CI and the DB migration folder on day one. A reproducible first commit avoids "works on my JDK". ([Spring Initializr docs](https://docs.spring.io/initializr/docs/current/reference/html/))
- **`JAVA-REPO-03`** (MUST) Commit the build wrapper (`mvnw`, `mvnw.cmd`, `.mvn/wrapper/`, or `gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.{jar,properties}`) and invoke only `./mvnw` / `./gradlew` in scripts and CI. Generate with `mvn wrapper:wrapper` / `gradle wrapper --gradle-version <v>`. Pins the build-tool version for every contributor and for loops runs. ([Maven Wrapper](https://maven.apache.org/wrapper/))
- **`JAVA-REPO-04`** (MUST) Pin the JDK with a toolchain, not just the machine's `JAVA_HOME`: Gradle `java { toolchain { languageVersion = JavaLanguageVersion.of(25) } }` (resolver plugin foojay for auto-provision); Maven `maven-toolchains-plugin` + `maven-enforcer-plugin` `requireJavaVersion` and `<maven.compiler.release>25</maven.compiler.release>`. Add `.sdkmanrc` or `.tool-versions` for developers. Compiling with `--release N` fixes the API surface; toolchains decouple the build JDK from the wrapper's JVM. ([Gradle toolchains](https://docs.gradle.org/current/userguide/toolchains.html))
- **`JAVA-REPO-05`** (MUST) Manage versions centrally: import a BOM (`spring-boot-dependencies`, `quarkus-bom`, `micronaut-platform`, `junit-bom`, `testcontainers-bom`) in Maven `<dependencyManagement>` (`<scope>import</scope>`) or Gradle `platform(...)` / `gradle/libs.versions.toml` version catalog; do not repeat versions in modules. One source of truth removes diamond-version drift. ([Gradle platforms and version catalogs](https://docs.gradle.org/current/userguide/platforms.html))
- **`JAVA-REPO-06`** (SHOULD) For an application, make resolution reproducible: Gradle `dependencyLocking { lockAllConfigurations() }` with committed `gradle.lockfile` (update via `./gradlew dependencies --write-locks`); Maven pins exact versions (no ranges, no `LATEST`/`RELEASE`, no `-SNAPSHOT` in release) and enforces it with Enforcer `requireReleaseDeps` + `dependencyConvergence`. Libraries do not lock. Maven has no native lockfile; locking in Gradle gives deterministic CI. ([Gradle dependency locking](https://docs.gradle.org/current/userguide/dependency_locking.html))
- **`JAVA-REPO-07`** (SHOULD) Automate dependency updates with Renovate or Dependabot (`package-ecosystem: maven` / `gradle`), grouped per BOM, and remove unused or undeclared deps via `mvn dependency:analyze` (`failOnWarning`) or the Gradle `dependency-analysis` plugin. CVE patches arrive as PRs; unused deps enlarge the attack surface. ([Renovate docs](https://docs.renovatebot.com/))
- **`JAVA-REPO-08`** (SHOULD) Use SemVer for libraries; publish to Maven Central via the Central Portal with sources, javadoc jars, GPG signatures and a POM with licenses, scm and developers; for services tag `vX.Y.Z` and build the image from the tag. Use reproducible-build settings (`project.build.outputTimestamp`). Central rejects unsigned/incomplete artifacts; reproducible jars allow provenance checks. ([Central Portal publishing requirements](https://central.sonatype.org/publish/requirements/))
- **`JAVA-REPO-09`** (MUST) Hygiene: `.gitignore` must list `target/`, `build/`, `.gradle/`, `out/`, `*.class`, `*.log`, `.idea/`, `*.iml`, `hs_err_pid*`, `.mvn/wrapper/maven-wrapper.jar` only if the wrapper downloads it; commit `.gitattributes` (`* text=auto`, `*.jar binary`, `gradlew text eol=lf`, `mvnw text eol=lf`) and `.editorconfig`. Windows CRLF breaks `mvnw`/`gradlew`; build output in git bloats history. ([GitHub gitignore templates: Java](https://github.com/github/gitignore/blob/main/Java.gitignore))
- **`JAVA-REPO-10`** (SHOULD) CI shape: checkout, `setup-java` (Temurin, `cache: maven` or `cache: gradle`), `./mvnw -B -ntp verify` (format check, compile with Error Prone, tests, JaCoCo, ArchUnit, SpotBugs) then vuln scan, SBOM and image build. Use `--fail-at-end` in reactors and a JDK matrix (LTS 21, 25) for libraries only. One verify command is the same gate locally and in CI. ([actions/setup-java](https://github.com/actions/setup-java))
- **`JAVA-REPO-11`** (SHOULD) In a monorepo prefer one Maven reactor or Gradle multi-project build (with `includeBuild` composite builds for shared conventions plugins and a `build-logic` / `buildSrc` convention-plugin module); reach for Bazel or Pants only past ~hundreds of modules. Split repos by deployable, not by layer. Native multi-module builds share one dependency graph and build cache. ([Gradle multi-project builds](https://docs.gradle.org/current/userguide/multi_project_builds.html))
- **`JAVA-REPO-12`** (SHOULD) Use conventional commits and generate changelogs/versions with `release-please`, `semantic-release`, or `maven-release-plugin`/`axion-release`; loops' own release flow already uses conventional commits. Consistent history drives automatic bump levels. ([Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/))

## TOOL: toolchain

- **`JAVA-TOOL-01`** (MUST) Target an LTS: JDK 25 for new services, JDK 21 as the floor for libraries and Spring Boot 3 holdouts. Non-LTS (26, 27, 28) only for experiments. Cadence: a feature release every March and September, an LTS every 2 years. Manage JDKs with SDKMAN, `mise`/asdf or the Gradle foojay toolchain resolver. LTS has multi-year security updates; non-LTS drops after 6 months. ([Oracle Java SE support roadmap](https://www.oracle.com/java/technologies/java-se-support-roadmap.html))
- **`JAVA-TOOL-02`** (MUST) Format with Spotless wrapping google-java-format (`<googleJavaFormat/>`) or palantir-java-format; the check argv is `./mvnw spotless:check` / `./gradlew spotlessCheck`, the fix argv is `spotless:apply` / `spotlessApply`; use `ratchetFrom 'origin/main'` to touch only changed files in legacy repos. A single non-configurable style ends style review; ratchet adopts it gradually. ([Spotless](https://github.com/diffplug/spotless))
- **`JAVA-TOOL-03`** (SHOULD) Compile with Error Prone (`-XDcompilePolicy=simple --should-stop=ifError=FLOW -Xplugin:ErrorProne` plus the `--add-exports`/`--add-opens` flags from its install page; Gradle: `net.ltgt.errorprone` plugin) and NullAway at `ERROR` for the application package prefix. Treat warnings as errors in CI (`-Werror`, `-Xlint:all`). Catches real bugs (e.g. `EqualsHashCode`, `FutureReturnValueIgnored`, `MissingOverride`) at compile time; NullAway gives a near-Kotlin null guarantee. ([Error Prone install](https://errorprone.info/docs/installation))
- **`JAVA-TOOL-04`** (SHOULD) Run SpotBugs with the FindSecBugs plugin at effort `max`, threshold `medium`: `./mvnw spotbugs:check` / `./gradlew spotbugsMain`. Add PMD (`./mvnw pmd:check` / `pmdMain`) and Checkstyle (`checkstyle:check` / `checkstyleMain`) only with a curated ruleset; do not overlap with Spotless/Error Prone. Overlapping linters generate noise that teams then disable. ([SpotBugs](https://spotbugs.github.io/))
- **`JAVA-TOOL-05`** (SHOULD) Scan dependencies on every PR with OSV-Scanner (`osv-scanner scan source -r .`, reads `pom.xml`, `gradle.lockfile`) or OWASP dependency-check (`./mvnw org.owasp:dependency-check-maven:check -DfailBuildOnCVSS=7`; Gradle `dependencyCheckAnalyze`). dependency-check needs an NVD API key and a cached DB (slow cold); OSV is faster and needs no key. Pick one as the gate; the other nightly. NVD rate limits make cold dependency-check runs flaky. ([OSV-Scanner](https://google.github.io/osv-scanner/))
- **`JAVA-TOOL-06`** (SHOULD) Generate a CycloneDX SBOM in the build (`./mvnw org.cyclonedx:cyclonedx-maven-plugin:makeAggregateBom` writes `target/bom.json`; Gradle `cyclonedxBom`) and enforce a license allow-list (`license-maven-plugin` / `gradle-license-report`). SBOMs and license checks are procurement and incident-response inputs. ([cyclonedx-maven-plugin](https://github.com/cyclonedx/cyclonedx-maven-plugin))
- **`JAVA-TOOL-07`** (SHOULD) IDE/LSP baseline: IntelliJ IDEA or VS Code with Red Hat's `jdtls`; import the build file, never hand-edit `.idea`/`.classpath`; configure format-on-save to call the same formatter as Spotless (google-java-format plugin) to avoid fights. A second formatter in the editor creates diff churn. ([google-java-format IDE plugins](https://github.com/google/google-java-format#intellij-android-studio-and-other-jetbrains-ides))
- **`JAVA-TOOL-08`** (SHOULD) Use `maven-enforcer-plugin` (`requireMavenVersion`, `requireJavaVersion`, `banDuplicatePomDependencyVersions`, `dependencyConvergence`, `bannedDependencies` for `commons-logging`, `log4j:log4j`, `javax.*`) and Gradle `failOnVersionConflict()`. Fails fast on version skew and banned transitive legacy APIs. ([Maven Enforcer rules](https://maven.apache.org/enforcer/enforcer-rules/index.html))

## ARCH: architecture

- **`JAVA-ARCH-01`** (MUST) Map the loops layers: `domain` (pure), `application` (use cases and consumer-owned ports), `adapter.in.*` / `adapter.out.*`, `config` or `bootstrap` (composition root). Name packages by feature first, layer second. Same dependency rule as Go, expressed with packages or modules. ([Spring Modulith reference](https://docs.spring.io/spring-modulith/reference/))
- **`JAVA-ARCH-02`** (MUST) Java access: package-private by default; `public` only for the module's API; sealed interfaces to close type hierarchies; JPMS `module-info.java` is optional for services (use it for libraries). A package maps to a directory (`com.acme.orders` = `com/acme/orders/`); import forms: `import a.b.C;`, `import a.b.*;`, `import static a.b.C.m;`. Package cycles compile; forbid them with ArchUnit `slices().matching("..(*)..").should().beFreeOfCycles()`. Needed for the loops arch parser (`resolver: package-dir`). ([Java Language Specification ch. 7 Packages](https://docs.oracle.com/javase/specs/jls/se25/html/jls-7.html))
- **`JAVA-ARCH-03`** (MUST) Enforce direction with ArchUnit in the normal test run: `layeredArchitecture().consideringOnlyDependenciesInLayers()` or `onionArchitecture()` (`domainModels`, `domainServices`, `applicationServices`, `adapter(...)`), plus `noClasses().that().resideInAPackage("..domain..").should().dependOnClassesThat().resideInAnyPackage("org.springframework..","jakarta.persistence..","com.fasterxml..","java.sql..","java.net.http..")`. In Spring Modulith use `ApplicationModules.of(App.class).verify()`. A failing test is the cheapest arch gate and needs no parser in loops. ([ArchUnit](https://www.archunit.org/userguide/html/000_Index.html))
- **`JAVA-ARCH-04`** (MUST) Use constructor injection only: one constructor (no `@Autowired` needed), `final` fields, no field or setter injection, no `ApplicationContext.getBean` / static service locators. Wire adapters to ports in `@Configuration` classes in the composition root. Immutable, testable without a container, visible dependencies. ([Spring Framework: constructor-based DI](https://docs.spring.io/spring-framework/reference/core/beans/dependencies/factory-collaborators.html))
- **`JAVA-ARCH-05`** (MUST) Keep the domain pure: no `org.springframework.*`, `jakarta.persistence.*`, `jakarta.validation.*` (except in adapters), Jackson, no `System.currentTimeMillis()`, `Instant.now()`, `LocalDate.now()`, `new Random()`, `UUID.randomUUID()`, `Thread`/`ExecutorService`, `java.io`/`java.nio.file`/`java.net`/`java.sql`. Inject `java.time.Clock` and an `IdGenerator` port. Determinism and unit-test speed. ([loops consistency skill](https://github.com/arxdsilva/ai-loops/tree/main/skills/consistency))
- **`JAVA-ARCH-06`** (SHOULD) Do not annotate domain classes as `@Entity`: keep a separate JPA entity in `adapter.out.persistence` with a mapper (MapStruct or hand-written), or accept pragmatic annotated domain only when the team records an ADR. Prevents lazy-loading and proxy semantics leaking into business logic. ([Hexagonal architecture with Spring (Reflectoring)](https://reflectoring.io/spring-hexagonal/))
- **`JAVA-ARCH-07`** (SHOULD) Define ports as small interfaces in the consumer's package (`domain` or `application`); name them for the capability (`OrderRepository`, `PaymentGateway`), not `IFoo`/`FooImpl`. Use Spring Data repositories behind a port, not as the port. Consumer-owned, narrow interfaces keep dependency inversion real. ([loops HEXAGONAL consumer-owned ports](https://github.com/arxdsilva/ai-loops/blob/main/specs/HEXAGONAL_ARCHITECTURE.md))
- **`JAVA-ARCH-08`** (SHOULD) SOLID size heuristics (warnings): class ≤ 300 lines, method ≤ 30 lines, ≤ 4 constructor params (collapse into a parameter object/record or split the class), cyclomatic complexity ≤ 10 (Checkstyle `CyclomaticComplexity`, PMD `CyclomaticComplexity`), interface ≤ 5 methods. Constructor param count is the Java signal of SRP violation. ([Checkstyle metrics checks](https://checkstyle.org/checks/metrics/index.html))
- **`JAVA-ARCH-09`** (SHOULD) Prefer a modular monolith (Spring Modulith, `@ApplicationModule`, module-to-module only via published events or the module's API package, `@NamedInterface` for exposed sub-packages) before microservices. Use `@ApplicationModuleTest` for module slices and `Documenter` to generate C4/PlantUML docs. Boundaries are enforced early without distributed-system cost. ([Spring Modulith](https://docs.spring.io/spring-modulith/reference/))
- **`JAVA-ARCH-10`** (SHOULD) Cross-module/aggregate communication: publish domain events with `ApplicationEventPublisher` and `@ApplicationModuleListener` (async, transactional, persisted in the event publication registry) rather than calling another module's service. Decouples modules and gives at-least-once delivery inside the monolith. ([Spring Modulith events](https://docs.spring.io/spring-modulith/reference/events.html))

## IDIOM: what to do and what to avoid

- **`JAVA-IDIOM-01`** (SHOULD) Use unchecked (`RuntimeException` subclasses) for programming errors and for domain failures that callers cannot recover from; use checked exceptions only for recoverable conditions the caller must handle. Spring and modern libraries are unchecked; wrap checked exceptions from adapters (`IOException`, `SQLException`) in an adapter-level unchecked type at the boundary. Checked exceptions force signatures through every layer (and break lambdas). ([Effective Java Items 69-72](https://www.oreilly.com/library/view/effective-java/9780134686097/))
- **`JAVA-IDIOM-02`** (MUST) Never swallow: no empty `catch`, no `catch (Exception | Throwable)` outside a boundary, no `e.printStackTrace()`. Wrap with cause (`new DomainException("...", e)`), log once at the boundary, and restore interrupt status (`Thread.currentThread().interrupt()`) when catching `InterruptedException`. Lost causes and swallowed interrupts make shutdown and debugging impossible. ([Error Prone `CatchAndPrintStackTrace`, `InterruptedExceptionSwallowed`](https://errorprone.info/bugpatterns))
- **`JAVA-IDIOM-03`** (MUST) Use `Optional<T>` only as a method return type for "maybe no result"; never as a field, parameter, collection element or `Optional<Optional>`; never call `get()` without `isPresent` (use `orElseThrow`, `map`, `ifPresentOrElse`); never return `null` for `Optional`/collections (return `Optional.empty()` / `List.of()`). Optional is not serializable, adds allocation and does not remove null from parameters. ([Optional Javadoc (API note)](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Optional.html))
- **`JAVA-IDIOM-04`** (SHOULD) Express null contract with JSpecify (`@NullMarked` on package, `@Nullable` on exceptions) and enforce with NullAway; Spring Framework 7 and Boot 4 use JSpecify. Use `Objects.requireNonNull(x, "x")` at constructors of domain types. Gives Java real null-safety checking without Kotlin. ([JSpecify](https://jspecify.dev/))
- **`JAVA-IDIOM-05`** (SHOULD) Model value objects and DTOs as `record` (immutable, `equals`/`hashCode`/`toString` generated), with validation in the compact constructor; prefer `List.copyOf` for collection components. Records cannot extend classes and are shallowly immutable. Do not use Lombok `@Data` on domain types; `@Builder`/`@Value` acceptable at boundaries, Lombok is optional. Records are the idiomatic value type since Java 16 and a good fit for ports and DTOs. ([JEP 395 Records](https://openjdk.org/jeps/395))
- **`JAVA-IDIOM-06`** (SHOULD) Use sealed interfaces plus records for closed sum types (`sealed interface PaymentResult permits Paid, Declined, Failed`), switch pattern matching without `default` so the compiler proves exhaustiveness, and record deconstruction patterns. Pattern matching for `switch` and record patterns are final since Java 21 (JEP 441, 440); primitive patterns are still preview in JDK 25/26. Replaces visitor and `instanceof` chains, and new variants become compile errors. ([JEP 409 Sealed classes](https://openjdk.org/jeps/409))
- **`JAVA-IDIOM-07`** (MUST) Close resources with try-with-resources (`AutoCloseable`); never rely on `finalize()` (deprecated for removal) or `Cleaner` for correctness; close JDBC `Connection`/`Statement`/`ResultSet`, `InputStream`, HTTP client response bodies and `Stream` from `Files.lines`/`Files.walk`/JPA `getResultStream`. Leaked connections exhaust the pool and file handles. ([Oracle tutorial: try-with-resources](https://docs.oracle.com/javase/tutorial/essential/exceptions/tryResourceClose.html))
- **`JAVA-IDIOM-08`** (MUST) Always override `equals` and `hashCode` together (use records or `Objects.equals/hash`); compare with `equals`, never `==`, for `String` and boxed types (`==` is fine for enums); never put mutable fields in `hashCode` of objects stored in hash sets. For JPA entities see DATA-04. Violating the contract breaks `HashMap`/`HashSet`. ([Effective Java Items 10-11](https://www.oreilly.com/library/view/effective-java/9780134686097/))
- **`JAVA-IDIOM-09`** (MUST) Time: use `java.time` only (`Instant` for timestamps, `ZonedDateTime`/`OffsetDateTime` at boundaries, `LocalDate` for dates, `Duration`), inject `Clock`, store UTC, ISO-8601 on the wire; ban `java.util.Date`, `Calendar`, `SimpleDateFormat` (not thread-safe). Money: `BigDecimal` constructed from `String` (`new BigDecimal("0.1")`), compare with `compareTo`, specify `RoundingMode`; never `double`. Strings: `StringBuilder` in loops, `String.format`/text blocks, UTF-8 explicit (`StandardCharsets.UTF_8`). Classic data-corrupting traps. ([java.time Javadoc](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/time/package-summary.html))
- **`JAVA-IDIOM-10`** (SHOULD) Prefer composition over inheritance; make classes `final` unless designed for extension; use `static` factory methods and builders for classes with many parameters; prefer interfaces and `List`/`Map` types in signatures and `var` only where the type is obvious from the right-hand side. Effective Java's central design guidance. ([Effective Java Items 15-18, 24, 50](https://www.oreilly.com/library/view/effective-java/9780134686097/))
- **`JAVA-IDIOM-11`** (AVOID) Avoid reflection, `sun.misc.Unsafe`, bytecode weaving and custom annotation processors in domain/application code; they are acceptable in frameworks and adapters (Jackson, JPA, MapStruct). Prefer compile-time processing (MapStruct, Micronaut, Quarkus) when GraalVM native image is a target. Use annotations as metadata, not logic (no AOP-driven business rules). Reflection hides dependencies from ArchUnit and breaks native image without hints. ([GraalVM reachability metadata](https://www.graalvm.org/latest/reference-manual/native-image/metadata/))
- **`JAVA-IDIOM-12`** (SHOULD) Naming follows the Google Java Style Guide / Oracle conventions: `UpperCamelCase` types, `lowerCamelCase` members, `UPPER_SNAKE` constants, lowercase package names with reversed domain, no Hungarian or `I` prefixes; Javadoc on every public API (first sentence is the summary). Uniform naming across libraries and tools. ([Google Java Style Guide §5](https://google.github.io/styleguide/javaguide.html#s5-naming))
- **`JAVA-IDIOM-13`** (AVOID) Footguns to avoid: boxed `Integer` `==` outside -128..127, `Arrays.asList(int[])` giving `List<int[]>`, `list.remove(int)` vs `remove(Object)`, `Collectors.toMap` without a merge function (throws on duplicate keys), mutating a collection during iteration (`ConcurrentModificationException`), `Stream.toList()` is unmodifiable, `SimpleDateFormat`/`DecimalFormat` shared across threads, `String.split` regex semantics, `catch` of `Throwable`/`Error`. Each produces silent wrong results or runtime failures. ([Java Puzzlers](https://www.oreilly.com/library/view/java-puzzlers-traps/0321336780/))

## CONC: concurrency and the `-race` equivalent

- **`JAVA-CONC-01`** (SHOULD) Concurrency model: platform threads (`ExecutorService`), virtual threads (final in Java 21, JEP 444) for blocking IO, and reactive (Reactor/WebFlux, Mutiny, Vert.x) only where backpressure streaming is needed. Enable virtual threads in Spring Boot with `spring.threads.virtual.enabled=true`; use one task per virtual thread (`Executors.newVirtualThreadPerTaskExecutor()`), never pool them. Virtual threads give blocking-style code with high scalability. ([JEP 444 Virtual Threads](https://openjdk.org/jeps/444))
- **`JAVA-CONC-02`** (SHOULD) Avoid virtual-thread pinning and starvation: since JDK 24 (JEP 491) `synchronized` no longer pins carriers, but native frames and `Object.wait` in some cases still do; use `ReentrantLock`/`java.util.concurrent` for long critical sections, bound concurrency of downstream calls with a `Semaphore`, and avoid `ThreadLocal` caches of big objects. Diagnose with `-Djdk.tracePinnedThreads=full` (JDK 21-23) or JFR `jdk.VirtualThreadPinned`. Pinning silently removes the scalability benefit. ([JEP 491](https://openjdk.org/jeps/491))
- **`JAVA-CONC-03`** (AVOID) Structured concurrency (`StructuredTaskScope`) is a preview API: sixth preview in JDK 26 (JEP 525), seventh in JDK 27 (JEP 533), and proposed final in JDK 28 (JEP 543, integrated, due 2027-03). It is NOT final in the JDK 25 LTS. Do not use it in production code without `--enable-preview` on every JVM and compiler invocation; on JDK 25 LTS use `ExecutorService` + `CompletableFuture`/`invokeAll`. Re-evaluate when the next LTS (29) arrives. Preview APIs can change or be removed, and class files compiled with preview features only run on the same feature release. ([JEP 505 (fifth preview, JDK 25)](https://openjdk.org/jeps/505))
- **`JAVA-CONC-04`** (SHOULD) Scoped values (`ScopedValue`) are final in JDK 25 (JEP 506); use them instead of `ThreadLocal` for per-request context (user, trace id, tenant) that is inherited by child virtual threads, and avoid `ThreadLocal` with virtual threads (and `InheritableThreadLocal`). Spring `RequestContextHolder`/MDC still use ThreadLocal; propagate explicitly in async code. Immutable, bounded lifetime, cheap with millions of threads. ([JEP 506 Scoped Values](https://openjdk.org/jeps/506))
- **`JAVA-CONC-05`** (MUST) Share state by immutability first (records, `List.copyOf`), then `java.util.concurrent` (`ConcurrentHashMap` with `compute`/`merge`, `AtomicReference`, `LongAdder`, `CopyOnWriteArrayList` for rarely written lists, `BlockingQueue`); use `synchronized`/`ReentrantLock` with the lock hierarchy documented; publish with `final` fields or `volatile`; never double-checked-lock without `volatile`; never `synchronized` on a `String`, boxed value or `this` of a public class. The Java Memory Model only guarantees visibility via happens-before edges. ([Java Concurrency in Practice](https://jcip.net/))
- **`JAVA-CONC-06`** (MUST) Race detection is tooling-assisted, not a flag: stress lock-free or memory-model-sensitive code with `jcstress` (`java -jar target/jcstress.jar` from the jcstress archetype, results in `results/`), model-check concurrent data structures with Lincheck (`org.jetbrains.lincheck`, runs under JUnit, works for Java), and run the full test suite with JUnit parallel execution and random order. SpotBugs concurrency detectors (`IS2_INCONSISTENT_SYNC`, `DC_DOUBLECHECK`) and Error Prone `GuardedBy` checks catch lock discipline bugs statically. Annotate with `@GuardedBy` / `@ThreadSafe` (JCIP annotations or Error Prone `errorprone-annotations`). No detector is complete: honest policy is substitutes plus review. ([jcstress](https://github.com/openjdk/jcstress))
- **`JAVA-CONC-07`** (MUST) Async code: never block the event loop (WebFlux/Vert.x) with JDBC or `Thread.sleep`; give every remote call a timeout; propagate cancellation (`Future.cancel`, `CompletableFuture.orTimeout`, interrupt); name threads (`Thread.ofVirtual().name("req-",0)`); handle exceptions in `CompletableFuture` chains (`exceptionally`/`handle`) and set `UncaughtExceptionHandler`; use bounded queues for backpressure (`ThreadPoolExecutor` with `CallerRunsPolicy`). Unhandled async failures disappear silently. ([CompletableFuture Javadoc](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/CompletableFuture.html))
- **`JAVA-CONC-08`** (MUST) Background work: define executors as Spring beans (`ThreadPoolTaskExecutor` with `setWaitForTasksToCompleteOnShutdown(true)` and `setAwaitTerminationSeconds`), use `@Scheduled` with ShedLock or Quartz/JobRunr/db-scheduler for clustered jobs, make jobs idempotent, and call `executor.shutdown(); awaitTermination()` on stop. Never `new Thread()` or unbounded `Executors.newCachedThreadPool()`. Orphaned threads block graceful shutdown and run twice in clusters. ([Spring task execution and scheduling](https://docs.spring.io/spring-framework/reference/integration/scheduling.html))

## TEST: testing

- **`JAVA-TEST-01`** (MUST) Use JUnit Jupiter 5.x/6.x (`org.junit.jupiter:junit-jupiter`, imported via `junit-bom`; JUnit 6.1.x is current on Maven Central as of 2026-11, and JUnit 6 requires Java 17) with AssertJ for assertions, Mockito for doubles, and Testcontainers for real dependencies. No JUnit 4 or TestNG in new code; no `org.junit.Assert`/Hamcrest where AssertJ is available. One stack across the codebase. ([JUnit 5 user guide](https://docs.junit.org/current/))
- **`JAVA-TEST-02`** (MUST) Tests live in `src/test/java` mirroring the main package; unit tests end `*Test` (Surefire), integration tests end `*IT` (Failsafe in `integration-test`/`verify` phases) or live in a Gradle `jvm-test-suite` named `integrationTest`; test globs are `**/src/test/java/**/*.java`, `**/*Test.java`, `**/*Tests.java`, `**/*IT.java`, and `src/integrationTest/**`. Naming decides which plugin runs the test, and loops uses the globs to classify edits. ([Maven Surefire inclusions](https://maven.apache.org/surefire/maven-surefire-plugin/examples/inclusion-exclusion.html))
- **`JAVA-TEST-03`** (SHOULD) Style: arrange-act-assert, one behaviour per test, names as sentences with `@DisplayName` or `method_condition_result`; parametrise with `@ParameterizedTest` + `@ValueSource`/`@CsvSource`/`@MethodSource`/`@EnumSource`; group with `@Nested`; fresh instance per test (default lifecycle `PER_METHOD`). Table-driven equivalence of Go's pattern. ([JUnit parameterized tests](https://docs.junit.org/current/writing-tests/parameterized-classes-and-tests.html))
- **`JAVA-TEST-04`** (SHOULD) Test doubles: fakes and in-memory implementations of ports for application tests; Mockito (`@ExtendWith(MockitoExtension.class)`, strict stubs) only for collaborators at the boundary; never mock types you do not own (wrap them in a port), value objects or the class under test; avoid `@MockBean`/`@SpyBean` sprawl (they fragment the Spring context cache; Boot 3.4+/4 provide `@MockitoBean`). Mockito's inline mock maker is default since 5; the JDK warns about dynamic agent loading from JDK 21, so attach it with `-javaagent` for JDK 25+. Over-mocking couples tests to implementation. ([Mockito docs](https://site.mockito.org/))
- **`JAVA-TEST-05`** (MUST) Integration tests use Testcontainers (`@Testcontainers`, `@Container static PostgreSQLContainer`, or Spring Boot `@ServiceConnection`), pinned to the production DB image tag; reuse containers across a class with a `static` field and keep per-test isolation with transaction rollback, `@Sql` reset, or Flyway clean + migrate; never H2 as a stand-in for PostgreSQL/MySQL semantics. In-memory dialects hide real SQL and migration bugs. ([Testcontainers for Java](https://java.testcontainers.org/))
- **`JAVA-TEST-06`** (MUST) Measure coverage with JaCoCo in every build: Maven `jacoco:prepare-agent` + `jacoco:report` (+ `jacoco:check` rules, `COVEREDRATIO` ≥ 0.70 for LINE and BRANCH on bundle); Gradle `jacocoTestReport` and `jacocoTestCoverageVerification`. Exclude generated code via `<excludes>` (`**/generated/**`, `**/*MapperImpl*`, `**/*Application*`) or `@Generated`-annotated classes (JaCoCo ignores classes and methods annotated with an annotation whose simple name contains `Generated` and retention CLASS/RUNTIME, Lombok `lombok.addLombokGeneratedAnnotation = true`). JaCoCo works on bytecode; the XML is the portable format. ([JaCoCo Maven plugin](https://www.jacoco.org/jacoco/trunk/doc/maven.html))
- **`JAVA-TEST-07`** (MUST) Make loops compute new-code coverage from `jacoco.xml` (`<package><sourcefile name="X.java"><line nr="12" mi="0" ci="3"/>` where `ci>0` is covered, `mi>0` partially/uncovered) against `git diff -U0 <base>` for `**/src/main/java/**/*.java`, threshold ≥70% of changed executable lines; fall back to `diff-cover` (Python) for polyrepo CI. Branch coverage (`mb`/`cb` per line) is reported but not gated by default. In multi-module builds read each module's XML, or the aggregate. JaCoCo has no diff mode; the XML's line numbers make diff mapping straightforward. ([JaCoCo XML report DTD](https://www.jacoco.org/jacoco/trunk/coverage/report.dtd))
- **`JAVA-TEST-08`** (SHOULD) Property-based testing with jqwik (`@Property`, shrinking, seeds in `.jqwik-database`) for parsers, mappers, money and state machines; mutation testing with PIT (`./mvnw org.pitest:pitest-maven:mutationCoverage`, scope to changed classes with `-DtargetClasses`, `pitest-junit5-plugin`) on a nightly job. Line coverage cannot prove assertions are meaningful. ([jqwik](https://jqwik.net/))
- **`JAVA-TEST-09`** (MUST) Flakiness: no `Thread.sleep` in tests (use Awaitility), inject `Clock`/`Random` seeds, no shared static state, no test-order dependence (enforce with `MethodOrderer.Random` as in CONC), set `@Timeout`, run Spring tests with a bounded context cache (avoid unique `@MockBean` combos), and quarantine rather than retry (Surefire `rerunFailingTestsCount` only for IT with a ticket). Retries hide races; random order exposes order dependence. ([Awaitility](https://github.com/awaitility/awaitility))
- **`JAVA-TEST-10`** (SHOULD) Fast TDD loop: run one test with `./mvnw -pl <module> -Dtest=OrderServiceTest#placesOrder test -DfailIfNoTests=false` or `./gradlew :module:test --tests 'com.acme.OrderServiceTest.placesOrder'`; Gradle `--continuous` for watch mode and build cache for incremental tests; use `-Dsurefire.failIfNoSpecifiedTests=false`; reserve `verify` for the gate. Seconds-level feedback keeps TDD practical on the JVM. ([Surefire single test](https://maven.apache.org/surefire/maven-surefire-plugin/examples/single-test.html))
- **`JAVA-TEST-11`** (SHOULD) Prefer slice tests in Spring (`@WebMvcTest`, `@DataJpaTest`, `@JsonTest`, `@RestClientTest`) for adapters and plain unit tests (no Spring context) for domain and application; reserve `@SpringBootTest` for a few end-to-end tests. `@DataJpaTest` is transactional and rolls back, which can mask flush/lazy bugs (add `Propagation.NOT_SUPPORTED` or `entityManager.flush(); clear()`). Context start dominates test time. ([Spring Boot test slices](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html))
- **`JAVA-TEST-12`** (SHOULD) Contract and API tests: use REST-assured or `MockMvcTester`/`WebTestClient` for HTTP, `spring-cloud-contract` or Pact for consumer-driven contracts, and `ArchUnit` tests as ordinary JUnit tests so they run in the same gate. Contracts catch integration drift before deploy. ([REST Assured](https://rest-assured.io/))

## PERF: performance and profiling

- **`JAVA-PERF-01`** (MUST) Benchmark with JMH only (never `System.nanoTime` loops): `@Benchmark`, `@State`, `@Fork(2)`, `@Warmup`, `@Measurement`, `Blackhole.consume`; run via the `jmh-maven-plugin`/`me.champeau.jmh` Gradle plugin; compare results with `-rf json` and JMH Visualizer or `jmh-compare`; always keep results in a separate JVM. JIT, dead-code elimination and constant folding invalidate naive timing. ([OpenJDK JMH](https://github.com/openjdk/jmh))
- **`JAVA-PERF-02`** (SHOULD) Profile with JDK Flight Recorder (`-XX:StartFlightRecording=filename=rec.jfr,settings=profile`, `jfr print`, JDK Mission Control), async-profiler for CPU/alloc flame graphs, and `jcmd <pid> GC.heap_dump`/Eclipse MAT for leaks; continuous profiling with Pyroscope or Grafana. Always measure before tuning. JFR is built in and low overhead (<2%). ([JFR / JDK Flight Recorder](https://docs.oracle.com/en/java/javase/21/jfapi/))
- **`JAVA-PERF-03`** (SHOULD) Memory and GC: containers use `-XX:MaxRAMPercentage=75` (JVM is container-aware); default G1 for most services, ZGC (generational, default mode since JDK 23) for large heaps and low pause; set `-XX:+ExitOnOutOfMemoryError` and `-XX:+HeapDumpOnOutOfMemoryError`; do not set `-Xmx` below the container limit minus metaspace and thread stacks; reduce startup with AppCDS / `-XX:+AutoCreateSharedArchive` (JDK 19+), Spring AOT + CRaC, or native image. OOM-kills in containers are the #1 JVM ops failure. ([Java GC tuning guide](https://docs.oracle.com/en/java/javase/21/gctuning/))
- **`JAVA-PERF-04`** (AVOID) Hot-path mistakes: string `+` in loops (use `StringBuilder`), boxing in hot loops (`IntStream`, primitive collections), regex compiled per call (`Pattern` constants), `Stream` in tight loops over small collections, `Exception` for control flow, unbounded caches (use Caffeine with `maximumSize` and TTL), `synchronized` on hot paths (use `LongAdder`), serialising the same `ObjectMapper` creation per call (share a configured instance), and `LinkedList`. Common JVM allocation and contention traps. ([Effective Java Items 6, 61, 67](https://www.oreilly.com/library/view/effective-java/9780134686097/))
- **`JAVA-PERF-05`** (SHOULD) Database throughput matters more than micro-opts: fix N+1 (DATA-04), set `hibernate.jdbc.batch_size`, use projections/DTO queries, add indexes, and set connection pool size from DB capacity (HikariCP default 10) rather than CPU count. Most Java backend latency is IO. ([HikariCP: About pool sizing](https://github.com/brettwooldridge/HikariCP/wiki/About-Pool-Sizing))

## SEC: security

- **`JAVA-SEC-01`** (MUST) Prevent injection: parameterised `PreparedStatement`/JPA named parameters/Spring Data derived queries/jOOQ/JdbcClient `.param()`; never concatenate input into JPQL/HQL/SQL (including `ORDER BY`: whitelist columns), `Runtime.exec`/`ProcessBuilder` (pass an argv list, never a shell string), LDAP filters (escape), or templates (disable Spring SpEL on user input). Injection is the top web risk (OWASP A03). ([OWASP Injection Prevention in Java](https://cheatsheetseries.owasp.org/cheatsheets/Injection_Prevention_in_Java_Cheat_Sheet.html))
- **`JAVA-SEC-02`** (MUST) Never deserialize untrusted data with Java native serialization (`ObjectInputStream`); set a JVM-wide deserialization filter (`-Djdk.serialFilter=...`, JEP 290/415) and avoid `enableDefaultTyping`/polymorphic `@JsonTypeInfo(use = Id.CLASS)` in Jackson, and `Yaml` constructors that instantiate arbitrary types (SnakeYAML `SafeConstructor`). Disable XXE in every XML parser (`XMLConstants.FEATURE_SECURE_PROCESSING`, `disallow-doctype-decl`, `ACCESS_EXTERNAL_DTD=""`). Gadget chains give remote code execution. ([OWASP Deserialization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html))
- **`JAVA-SEC-03`** (MUST) Web risks: validate and allow-list outbound URLs (SSRF; Spring Framework 7 / Boot 4.1 add an `InetAddressFilter`-based SSRF filter), normalise and check paths (`Path.normalize().startsWith(base)`) against traversal, validate redirect targets, keep Spring Security CSRF on for browser sessions (disable only for stateless token APIs), configure CORS with explicit origins (never `*` with credentials), and set security headers. Spring Security defaults are secure only if not disabled. ([Spring Security reference](https://docs.spring.io/spring-security/reference/))
- **`JAVA-SEC-04`** (MUST) Secrets from the environment, Vault/Kubernetes secrets or Spring Cloud Config with encryption, never in `application.yaml`, source or images; passwords with `PasswordEncoder` (Argon2/bcrypt/scrypt via Spring Security `DelegatingPasswordEncoder`); use `SecureRandom` (never `Random`/`Math.random`) for tokens; crypto via JCA with AES-GCM and random IV, RSA-OAEP, `MessageDigest` SHA-256+; avoid MD5, SHA-1, DES, ECB; keep TLS defaults and do not disable hostname verification. Hard-coded secrets and weak randomness are common CWE findings. ([OWASP Java Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Java_Security_Cheat_Sheet.html))
- **`JAVA-SEC-05`** (MUST) Validate at the adapter boundary with Jakarta Bean Validation (`@Valid`, `@NotBlank`, `@Size`, `@Pattern`, custom `ConstraintValidator`) on request records, and construct domain value objects with invariant checks; do not trust `@Valid` alone for authorization. Mass assignment: bind to dedicated request records, never directly to JPA entities. Validation belongs where bytes become typed data. ([Jakarta Bean Validation](https://beanvalidation.org/))
- **`JAVA-SEC-06`** (MUST) Supply chain: depend only on Maven Central/an internal mirror (Nexus/Artifactory) with checksums verified, enable Gradle dependency verification (`gradle/verification-metadata.xml`, `./gradlew --write-verification-metadata sha256`), keep Maven checksum policy `fail`, check new coordinates against typosquats, pin plugin versions, and keep Log4Shell-class transitive libs updated via the BOM. Use `-Dmaven.wagon.http.ssl.insecure=false` (default). Maven builds execute plugin code. ([Gradle dependency verification](https://docs.gradle.org/current/userguide/dependency_verification.html))
- **`JAVA-SEC-07`** (SHOULD) SAST: SpotBugs + FindSecBugs (`SQL_INJECTION_JDBC`, `COMMAND_INJECTION`, `OBJECT_DESERIALIZATION`, `PATH_TRAVERSAL_IN`) in the build and Semgrep (`p/java`, `p/owasp-top-ten`) or CodeQL (`java-kotlin`) in CI; triage findings with a baseline file, never `@SuppressFBWarnings` without a justification comment. Build-time SAST catches taint flows reviewers miss. ([Find Security Bugs bug patterns](https://find-sec-bugs.github.io/bugs.htm))
- **`JAVA-SEC-08`** (MUST) Spring Boot actuator and defaults: expose only `health`, `info`, `prometheus` on a separate management port, secured; disable `spring.jpa.show-sql` in prod; never log request bodies with credentials; avoid `permitAll()` on `/**`, use `authorizeHttpRequests` with deny-by-default and method security (`@PreAuthorize`) for business rules. Exposed `/actuator/env`/`heapdump` leak secrets. ([Spring Boot actuator endpoints security](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html#actuator.endpoints.security))

## DATA: persistence

- **`JAVA-DATA-01`** (SHOULD) Choose access deliberately: JPA/Hibernate (Spring Data JPA) for aggregate CRUD; jOOQ, Spring `JdbcClient`, or Spring Data JDBC for reporting, bulk and complex queries; never use JPA lazy entities as the domain model across layers. Spring Data JDBC fits DDD aggregates and has no lazy loading, no dirty tracking and no sessions. The ORM is a persistence adapter, not the domain. ([Spring Data JDBC reference](https://docs.spring.io/spring-data/relational/reference/jdbc.html))
- **`JAVA-DATA-02`** (MUST) Manage schema with Flyway (`V<n>__desc.sql` in `src/main/resources/db/migration`, immutable once merged, repeatable `R__`) or Liquibase (changelog YAML/XML with `changeSet` id/author); set `spring.jpa.hibernate.ddl-auto=validate` (or `none`), never `update`/`create` outside tests. Prefer forward-only migrations with expand/contract for zero downtime (add nullable column, backfill, switch, drop later). Run migrations in a separate step/job for multi-instance deploys. Hibernate DDL generation silently diverges from migrations. ([Flyway docs](https://documentation.red-gate.com/flyway))
- **`JAVA-DATA-03`** (MUST) Put `@Transactional` on application use-case methods (the application layer), not on controllers, repositories or domain; keep transactions short, no remote calls inside; `@Transactional` is proxy-based, so self-invocation and `private`/`final` methods bypass it; only unchecked exceptions roll back by default (`rollbackFor` for checked); mark read-only queries `readOnly = true`; choose isolation explicitly (default is the DB default, READ COMMITTED on PostgreSQL), use optimistic locking (`@Version`) for concurrent updates. The hexagon's use case is the unit of work. ([Spring transaction management](https://docs.spring.io/spring-framework/reference/data-access/transaction.html))
- **`JAVA-DATA-04`** (MUST) N+1 and lazy loading: set associations `LAZY` (`@ManyToOne` default is EAGER, change it), fetch what a use case needs with `JOIN FETCH`, `@EntityGraph`, DTO projections or batch fetching (`hibernate.default_batch_fetch_size`); detect with Hibernate statistics, `datasource-proxy`/Hypersistence Utils `assertSelectCount`, and Testcontainers-backed tests. Never return entities from the application layer. N+1 is the most common JPA performance defect; `LazyInitializationException` the most common crash. ([Hibernate User Guide: fetching](https://docs.hibernate.org/orm/current/userguide/html_single/Hibernate_User_Guide.html#fetching))
- **`JAVA-DATA-05`** (MUST) Disable open-session-in-view: `spring.jpa.open-in-view=false` (Spring Boot defaults to true and logs a warning). Initialise needed data inside the transaction boundary and map to DTOs there. OSIV holds a DB connection through view rendering and hides lazy-loading queries in controllers. ([Spring Boot reference: open-in-view](https://docs.spring.io/spring-boot/reference/data/sql.html#data.sql.jpa-and-spring-data.open-entity-manager-in-view))
- **`JAVA-DATA-06`** (MUST) JPA entity `equals`/`hashCode`: use a natural/business key, or the generated id with a constant `hashCode()` (`getClass().hashCode()`) and an `equals` that treats `null` ids as unequal and uses `Hibernate.getClass`/`instanceof` for proxies; never include lazy associations or `@GeneratedValue` ids that change after `persist` in a value-based hash. Never use Lombok `@Data`/`@EqualsAndHashCode`/`@ToString` on entities. Entities need a no-arg constructor (protected), non-final class and fields. Mutable ids break `HashSet`; `@ToString` triggers lazy loads. ([Vlad Mihalcea: equals/hashCode with entity identifier](https://vladmihalcea.com/how-to-implement-equals-and-hashcode-using-the-jpa-entity-identifier/))
- **`JAVA-DATA-07`** (SHOULD) Connections: use HikariCP (Spring Boot default) with explicit `maximumPoolSize`, `connectionTimeout`, `maxLifetime` below the DB/proxy timeout, `leakDetectionThreshold` in non-prod; set JDBC and statement timeouts, avoid `spring.datasource.hikari` defaults copied between services; with virtual threads the pool (not threads) is the bottleneck, so size it for the DB. R2DBC only for fully reactive stacks. Pool exhaustion cascades into outage. ([HikariCP configuration](https://github.com/brettwooldridge/HikariCP#gear-configuration-knobs-baby))

## API: APIs and integration

- **`JAVA-API-01`** (SHOULD) HTTP stack: Spring MVC (servlet, blocking, works with virtual threads) is the default; WebFlux only for reactive backpressure; Quarkus RESTEasy Reactive/Vert.x; Micronaut HTTP. Cross-cutting behaviour goes in filters/interceptors/`@ControllerAdvice`; controllers are thin inbound adapters that translate to use-case commands. Controllers belong in the adapter layer. ([Spring Web MVC](https://docs.spring.io/spring-framework/reference/web/webmvc.html))
- **`JAVA-API-02`** (SHOULD) Contracts: OpenAPI-first (generate server interfaces/DTOs with `openapi-generator`) or code-first with `springdoc-openapi`/Quarkus OpenAPI; commit the spec and diff it in CI (`oasdiff`); version in the URL or header and never break clients; gRPC with `protoc` + `grpc-java` (Boot 4.1 has gRPC starters). Keep generated code out of coverage and out of review. Contract drift is the main cross-team failure. ([springdoc-openapi](https://springdoc.org/))
- **`JAVA-API-03`** (MUST) Return RFC 9457 problem details: Spring `ProblemDetail` with `spring.mvc.problemdetails.enabled=true` and a `@RestControllerAdvice` mapping domain exceptions (not found 404, validation 400/422, conflict 409, auth 401/403, downstream 502/503); never leak stack traces or SQL. Uniform error contract and no information leak. ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457))
- **`JAVA-API-04`** (MUST) Resilience: set timeouts on every outbound call, retry only idempotent operations with exponential backoff and jitter, circuit-break and bulkhead with Resilience4j (or Spring Framework 7 `@Retryable`/`@ConcurrencyLimit`), accept an `Idempotency-Key` header on non-idempotent POSTs, and rate-limit at the gateway or with Bucket4j. Unbounded retries cause retry storms. ([Resilience4j](https://resilience4j.readme.io/docs/getting-started))
- **`JAVA-API-05`** (MUST) Messaging: Spring Kafka/Spring Cloud Stream or Quarkus Reactive Messaging; use the transactional outbox (write the event with the state change, relay via Debezium CDC or Spring Modulith event publication registry), consumers are idempotent (dedupe by event id), dead-letter topics, `enable.idempotence=true`, commit offsets after processing. Dual writes lose or duplicate events. ([Spring for Apache Kafka](https://docs.spring.io/spring-kafka/reference/))
- **`JAVA-API-06`** (MUST) HTTP clients: use Spring `RestClient` (blocking) / `WebClient` (reactive) / declarative `@HttpExchange` clients, or `java.net.http.HttpClient` (one shared instance, HTTP/2, timeouts via `HttpRequest.timeout`), configured with connection pool, connect/read timeouts and trace propagation; never `new RestTemplate()` without timeouts (RestTemplate is in maintenance, deprecation planned in Spring Framework 7). Connection reuse and deadlines are mandatory. ([Spring RestClient](https://docs.spring.io/spring-framework/reference/integration/rest-clients.html))

## OBS: observability

- **`JAVA-OBS-01`** (MUST) Log with SLF4J API + Logback (Spring Boot default) or Log4j2; structured JSON (Boot 3.4+ `logging.structured.format.console=ecs` or `logstash`), parameterised messages (`log.info("order {}", id)`), levels used consistently, MDC for `traceId`/`requestId`, never log secrets or PII, never `System.out`. Use one `log` call per event and log an exception once at the boundary. Parameterised logging avoids string building; structured logs are queryable. ([Spring Boot logging](https://docs.spring.io/spring-boot/reference/features/logging.html))
- **`JAVA-OBS-02`** (SHOULD) Metrics with Micrometer (`MeterRegistry`, `@Timed`/`Observation`), exported to Prometheus (`/actuator/prometheus`) or OTLP; names lowercase dot-separated (`orders.placed`), low-cardinality tags only (never user id or URL path with ids). High-cardinality tags explode the TSDB. ([Micrometer docs](https://micrometer.io/docs))
- **`JAVA-OBS-03`** (SHOULD) Tracing: OpenTelemetry via the Java agent (`-javaagent:opentelemetry-javaagent.jar`, zero-code) or Spring Boot's `spring-boot-starter-opentelemetry` / Micrometer Tracing bridge; propagate W3C `traceparent` and copy `trace_id` into logs; sample in production. Cross-service correlation is the baseline of debugging distributed systems. ([OpenTelemetry Java agent](https://opentelemetry.io/docs/zero-code/java/agent/))
- **`JAVA-OBS-04`** (MUST) Health: enable `management.endpoint.health.probes.enabled=true` for `/actuator/health/liveness` and `/readiness` (Kubernetes); liveness must not depend on the database; readiness includes dependencies and goes `OUT_OF_SERVICE` on shutdown. Quarkus: SmallRye Health `/q/health/live` `/q/health/ready`. A DB blip must not restart all pods. ([Spring Boot Kubernetes probes](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html#actuator.endpoints.kubernetes-probes))
- **`JAVA-OBS-05`** (SHOULD) Add JFR and GC logging in production (`-Xlog:gc*:file=gc.log:time,uptime:filecount=5,filesize=10m`), expose thread/heap metrics through Micrometer JVM binders, and alert on error rate, latency p99, pool saturation and GC pause. JVM-internal signals explain most incidents. ([Unified JVM logging (JEP 158)](https://openjdk.org/jeps/158))

## OPS: configuration, packaging and deployment

- **`JAVA-OPS-01`** (MUST) Config: 12-factor, typed binding with `@ConfigurationProperties` records (`@Validated`, constructor binding), profiles only for environment toggles, env vars override (`SPRING_DATASOURCE_URL`), secrets from env/Vault/K8s secrets/Config Server; Quarkus `@ConfigMapping`; Micronaut `@ConfigurationProperties`. Never branch domain logic on profiles. Typed config fails at startup, not at runtime. ([Spring Boot externalized configuration](https://docs.spring.io/spring-boot/reference/features/external-config.html))
- **`JAVA-OPS-02`** (SHOULD) Package as a layered/executable jar (`spring-boot:repackage`, `bootJar`) and build the image with Cloud Native Buildpacks (`./mvnw spring-boot:build-image`, `./gradlew bootBuildImage`) or Jib (`jib:dockerBuild`, no Docker daemon) or a multi-stage Dockerfile (`eclipse-temurin:25-jre` runtime stage, non-root user, `--chown`), exploded jar via `-Djarmode=tools`. Layered images cache dependencies and shrink rebuilds. ([Spring Boot container images](https://docs.spring.io/spring-boot/reference/packaging/container-images/index.html))
- **`JAVA-OPS-03`** (SHOULD) Native image (GraalVM / Mandrel): use for CLIs, serverless and scale-to-zero (ms startup, low RSS) via `./mvnw -Pnative native:compile` or `./gradlew nativeCompile`; trade-offs are 1-10 minute builds, closed-world reflection/proxy/resource hints (`reachability-metadata.json`), no runtime agents or JFR parity, and peak throughput typically below C2 JIT. Test the native binary in CI (`nativeTest`) and keep a JVM profile. Quarkus and Micronaut are native-first; Spring uses AOT processing. Native is a deliberate deployment choice. ([GraalVM Native Image](https://www.graalvm.org/latest/reference-manual/native-image/))
- **`JAVA-OPS-04`** (MUST) Lifecycle: `server.shutdown=graceful` with `spring.lifecycle.timeout-per-shutdown-phase=30s`, handle SIGTERM (JVM runs shutdown hooks; PID 1 must be the JVM, use `exec` or `tini`), mark readiness down first, drain consumers/executors, make the K8s `terminationGracePeriodSeconds` larger than the timeout, and `preStop` sleep for load balancer deregistration. Dropped in-flight requests during deploys. ([Spring Boot graceful shutdown](https://docs.spring.io/spring-boot/reference/web/graceful-shutdown.html))
- **`JAVA-OPS-05`** (MUST) Build caches for a per-run workspace (loops OPS-05): safe to relocate per run: Maven/Gradle project outputs `target/` and `build/`, the Gradle project cache dir (`--project-cache-dir <dir>` for `.gradle/`), `java.io.tmpdir` (`-Djava.io.tmpdir=<dir>` via `JAVA_TOOL_OPTIONS` or `.mvn/jvm.config`), Testcontainers temp, and JaCoCo exec (set both `-Djacoco.destFile=<dir>/jacoco.exec` and `-Djacoco.dataFile=<dir>/jacoco.exec`; destFile alone leaves `jacoco:report` reading a stale `target/jacoco.exec`). Do NOT relocate `~/.m2/repository` (`-Dmaven.repo.local`) or `GRADLE_USER_HOME` per run unless seeded: they hold every downloaded artifact, wrapper distributions, toolchains and the daemon registry, so a cold run re-downloads the world (minutes) and may hit rate limits. Both are designed for concurrent processes (Maven resolver named locks, Gradle cross-process locks), so share them read-write across parallel runs; set `GRADLE_USER_HOME` once per machine or CI job, and use `org.gradle.daemon=false`/`--no-daemon` in runs to avoid daemons outliving the run. The shared dependency caches are safe to share and expensive to rebuild; build outputs are not safe to share across parallel agents. ([Gradle build environment (`GRADLE_USER_HOME`, project cache dir)](https://docs.gradle.org/current/userguide/build_environment.html))
- **`JAVA-OPS-06`** (SHOULD) Artifacts left in the tree that loops cleanup must remove (and `.gitignore` must list): `target/`, `build/`, `.gradle/`, `out/`, `*.class`, `hs_err_pid*.log`, `replay_pid*.log`, `*.hprof`, `*.jfr`, `jacoco.exec`, `*.exec`, `.jqwik-database`, `dependency-check-report.*`, `.pitest/` and `target/pit-reports/`, `spring.log`, `bom.json`/`bom.xml`, `.flattened-pom.xml`, `dependency-reduced-pom.xml`, `.mvn/.develocity/`. ## FW: frameworks

- **`JAVA-FW-01`** (MUST) Dominant frameworks: Spring Boot (by far the most used, 4.1.x current as of 2026-11, built on Spring Framework 7, Jakarta EE 11, Java 17 minimum and Java 25 supported; OSS support for 4.1 to about 2027-07), Quarkus (Red Hat, build-time CDI, native-first, Dev Services), Micronaut (compile-time DI, no reflection, native-first), then Jakarta EE servers (WildFly, Open Liberty, Payara) and Helidon/Vert.x. Usage: Spring leads the JVM ecosystem reports; check the current JetBrains/Snyk/New Relic JVM surveys before quoting numbers. Pack conventions must follow the framework in use. ([Spring Boot 4.1.0 announcement](https://spring.io/blog/2026/06/10/spring-boot-4/))
- **`JAVA-FW-02`** (SHOULD) Spring Boot conventions: starter parent or BOM import, `@SpringBootApplication` at the root package (component scan from there, so keep it above all modules), `application.yaml` + profiles, Actuator, `@ConfigurationProperties`, Spring Data repositories, auto-configuration with `@ConditionalOn*`. Conflicts with hexagonal: `@Service`/`@Component` in the domain, repositories as the port, `@Entity` as the domain; resolve with ArchUnit rules and the composition root in `config`. Following the framework avoids a custom-framework fork. ([Spring Boot reference](https://docs.spring.io/spring-boot/reference/))
- **`JAVA-FW-03`** (SHOULD) Quarkus: build-time DI (ArC, CDI Lite subset), `@ApplicationScoped`, constructor injection, Panache (active record) conflicts with hexagonal (prefer repository pattern `PanacheRepository` in the adapter), `@QuarkusTest`, Dev Services (auto Testcontainers), `application.properties`; `./mvnw quarkus:dev` for live reload and `-Dquarkus.test.continuous-testing=enabled`. Quarkus replaces Spring-isms. ([Quarkus CDI reference](https://quarkus.io/guides/cdi-reference))
- **`JAVA-FW-04`** (SHOULD) Micronaut: compile-time DI/AOP (annotation processors; `@Singleton`, `@Requires`), constructor injection, Micronaut Data (compile-time repositories, no runtime reflection), `@MicronautTest`, GraalVM-friendly; hexagonal maps directly because beans are plain classes. No proxies or reflection means faster start and simpler native image. ([Micronaut Guide](https://docs.micronaut.io/latest/guide/))
- **`JAVA-FW-05`** (AVOID) Spring footguns: `@Transactional` self-invocation and `private` methods (proxy bypass); `@Async` without executor config and with self-invocation; `@Autowired` field injection; `@Scheduled` on every pod; circular dependencies (disabled by default in Boot 2.6+); `@Value` strings instead of typed properties; `@ComponentScan` pulling test or sibling modules; component-scan order and `@Primary` ambiguity; `@SpringBootTest` per class with unique mocks (context cache misses); returning JPA entities from controllers (Jackson lazy-load and cycles); catching exceptions inside `@Transactional` and swallowing rollback. These repeat in nearly every Spring code review. ([Spring Framework transaction pitfalls](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html))
- **`JAVA-FW-06`** (SHOULD) Spring Modulith specifics: module = direct sub-package of the application class's package; `package-info.java` with `@ApplicationModule(displayName=..., allowedDependencies={...})`; `ApplicationModules.of(Application.class).verify()` in a test; `@ApplicationModuleTest(mode=...)` for slice; events externalised with `@Externalized` (Kafka/AMQP). Gives the arch gate for free in a Boot monolith. ([Spring Modulith fundamentals](https://docs.spring.io/spring-modulith/reference/fundamentals.html))
- **`JAVA-FW-07`** (SHOULD) Choose: Spring Boot for broad ecosystem and hiring; Quarkus for Kubernetes-native, fast restarts and native image with an opinionated CDI; Micronaut for compile-time DI and serverless/CLI workloads. The pack must follow whichever the repo already uses (`pom.xml`/`build.gradle.kts` dependency detection: `spring-boot`, `io.quarkus`, `io.micronaut`); project rules win. Framework detection drives which rule set applies. ([Quarkus vs Spring comparison (Quarkus docs)](https://quarkus.io/guides/spring-di))

## Top 10 footguns

1. Open-session-in-view and lazy loading: `spring.jpa.open-in-view=true` with controllers touching lazy collections -> set it `false`, fetch with `JOIN FETCH` or DTO projections inside the transaction.
2. N+1 queries: `orders.forEach(o -> o.getItems().size())` -> `@EntityGraph`, `JOIN FETCH` or `default_batch_fetch_size`; assert query counts in tests.
3. `@Transactional` self-invocation or on private methods: `this.save()` bypasses the proxy -> move to another bean or use `TransactionTemplate`.
4. Lombok `@Data` on entities and naive `equals`/`hashCode` -> id-based equals, constant `hashCode`, no `@ToString` over associations.
5. `Optional` as a field or parameter, or `.get()` -> overloads or a JSpecify-nullable parameter; `orElseThrow`.
6. Mutable singleton beans: a `@Service` with a `HashMap` written per request -> stateless beans, immutable state, `ConcurrentHashMap`.
7. Swallowed `InterruptedException` (`catch (InterruptedException e) {}`) -> `Thread.currentThread().interrupt()` and propagate.
8. Preview APIs (`StructuredTaskScope`, `--enable-preview`) on an LTS -> executors or `CompletableFuture` until the JEP is final in an LTS.
9. `double` for money, `new BigDecimal(0.1)`, shared `SimpleDateFormat` -> `new BigDecimal("0.10")` and `java.time`.
10. Native deserialization, XXE and SSRF defaults (`ObjectInputStream` on a request body, unconfigured `DocumentBuilderFactory`) -> JSON with a closed type set and secure-processing features.
