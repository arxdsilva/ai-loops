# Ruby rules

Language: Ruby 4.0 (3.4 acceptable; 3.3 security-only, EOL expected 2027-03-31). Rails 8.1. As of 2026-11.
Source: `research/languages/ruby.md` (verified 2026-11-10; the Verification section overrides earlier text). Pack: `specs/languages/ruby/pack.json`.

Rule format: `RUBY-<SEC>-NN` (MUST|SHOULD|AVOID). Project rules win: follow the repo's own config (`.rubocop.yml`, `.standard.yml`, `.rspec`, Rails conventions) over these defaults and log each override with `loops run override`.

## REPO: repository and project management

Layout, lockfiles, pins and CI order. Universal repo rules: see specs/REPO_PRACTICES.md (when present).

- **`RUBY-REPO-01`** (MUST) Create services with `rails new <app> --api -d postgresql` (or `--minimal`) and keep the generated layout (`app/`, `config/`, `db/`, `lib/`, `bin/`, `spec/` or `test/`); do not invent a parallel tree. The generator's layout is what Zeitwerk, the guides, generators and every Rails dev expect; deviation costs autoload bugs. ([source](https://guides.rubyonrails.org/command_line.html))
- **`RUBY-REPO-02`** (SHOULD) For non-Rails services, use the Bundler gem layout: `lib/<name>.rb` plus `lib/<name>/` for code, `spec/` or `test/` for tests, `exe/` for executables, one namespace module per gem. Rubygems and Bundler assume `lib/` is on the load path and the file path mirrors the constant name. ([source](https://guides.rubygems.org/make-your-own-gem/))
- **`RUBY-REPO-03`** (SHOULD) Prefer one application with internal boundaries (Packwerk packs, or Rails engines when a deployable-in-isolation unit is truly needed) over many repos; use a monorepo with a single root `Gemfile.lock` for related gems. A single lockfile avoids version skew between apps; Ruby has no native multi-package workspace like Cargo. ([source](https://github.com/Shopify/packwerk))
- **`RUBY-REPO-04`** (MUST) Commit `Gemfile.lock` for applications; for gems commit it only if CI uses it, and test against a lockless matrix too. The lockfile makes `bundle install` reproducible; a library must prove it works across dependency ranges. ([source](https://bundler.io/guides/gemfile.html))
- **`RUBY-REPO-05`** (MUST) In CI and in the loops gate install with `BUNDLE_FROZEN=true bundle install` (or `bundle config set frozen true`); fail if the lockfile would change. The gate itself runs the verify form `bundle check` (D11). Frozen mode errors when `Gemfile` and `Gemfile.lock` disagree, so a PR cannot silently change resolved gems. ([source](https://bundler.io/man/bundle-config.1.html))
- **`RUBY-REPO-06`** (SHOULD) Pin gems pessimistically (`gem "rails", "~> 8.1.0"`) and let Dependabot or Renovate raise bumps; never use unbounded `gem "x"` for production gems and never point at a git branch without `ref:`. The lockfile pins exact versions; the Gemfile constraint bounds what an update can pull in. ([source](https://bundler.io/man/gemfile.5.html))
- **`RUBY-REPO-07`** (SHOULD) Configure `.github/dependabot.yml` with the `bundler` and `github-actions` ecosystems (weekly, grouped). Automated, reviewable dependency PRs keep CVE exposure short. ([source](https://docs.github.com/en/code-security/dependabot/ecosystems-supported-by-dependabot/supported-ecosystems-and-repositories))
- **`RUBY-REPO-08`** (MUST) Pin Ruby in `.ruby-version` and read it from the Gemfile (`ruby file: ".ruby-version"`); use rbenv, mise or asdf, and `ruby/setup-ruby` in CI with `bundler-cache: true`. One source of truth for the interpreter version locally and in CI. ([source](https://bundler.io/man/gemfile.5.html))
- **`RUBY-REPO-09`** (SHOULD) Release gems with a `vX.Y.Z` tag and RubyGems trusted publishing (`rubygems/release-gem`, OIDC; no long-lived API key); set `rubygems_mfa_required: "true"` in the gemspec metadata. OIDC publishing removes a stealable secret; MFA enforcement protects maintainers. ([source](https://guides.rubygems.org/trusted-publishing/))
- **`RUBY-REPO-10`** (SHOULD) Follow SemVer for gems and keep a `CHANGELOG.md`; applications are versioned by tag or commit SHA, not by a `VERSION` constant. Rubygems resolution relies on SemVer; apps ship as images. ([source](https://guides.rubygems.org/specification-reference/))
- **`RUBY-REPO-11`** (MUST) `.gitignore` must cover `/log/*`, `/tmp/*`, `/coverage`, `/.bundle`, `/vendor/bundle`, `/public/assets`, `config/*.key`, `.env*` (but keep `.keep` files); let `rails new` generate it and extend it. Prevents committing logs, caches, coverage and secrets (`config/master.key`). ([source](https://github.com/rails/rails/blob/main/railties/lib/rails/generators/rails/app/templates/gitignore.tt))
- **`RUBY-REPO-12`** (SHOULD) Add `.editorconfig` (UTF-8, LF, 2-space indent); RuboCop's `Layout/*` cops enforce it. Ruby source needs no encoding comment (UTF-8 is default); keep `# frozen_string_literal: true` as the first line. Ruby's community indent is 2 spaces; frozen-literal comment prevents string mutation bugs. ([source](https://rubystyle.guide/))
- **`RUBY-REPO-13`** (SHOULD) CI order: `bundle install` (frozen, cached) -> `rubocop` -> `brakeman` -> `bundle-audit check --update` -> typecheck (if any) -> `packwerk check` -> `db:test:prepare` -> tests with SimpleCov -> upload `coverage/`. Rails 8.1 ships `config/ci.rb` and `bin/ci` so the same steps run locally. One shared definition of CI prevents "green locally, red in CI". ([source](https://rubyonrails.org/2025/10/22/rails-8-1))
- **`RUBY-REPO-14`** (SHOULD) Run the CI matrix on the newest Ruby plus the oldest supported one (for apps: the pinned version only; for gems: every maintained branch 3.3, 3.4, 4.0). Gems must not break on a maintained Ruby; apps only run what they pin. ([source](https://www.ruby-lang.org/en/downloads/branches/))

## TOOL: toolchain

Gate commands come from `specs/languages/ruby/pack.json`; run them through `loops gate`.

- **`RUBY-TOOL-01`** (MUST) Target Ruby 4.0 for new apps (3.4 acceptable); do not start anything on 3.3 (security-only, EOL expected 2027-03-31) or 3.2 (EOL). Ruby ships a new minor every 25 December. Use YJIT in production (`RUBY_YJIT_ENABLE=1`, `--yjit`, or `RubyVM::YJIT.enable`); Rails 7.2+ enables it by default. ZJIT (`--zjit`) is not production ready yet. EOL branches get no security fixes; YJIT is a large, low-risk speed-up. ([source](https://www.ruby-lang.org/en/downloads/branches/))
- **`RUBY-TOOL-02`** (MUST) Format and lint with one tool: `bundle exec rubocop` (config `.rubocop.yml`) or Standard (`bundle exec standardrb`, config `.standard.yml`, zero options by design). Never run both. RuboCop has no separate formatter; two tools fight over layout. ([source](https://docs.rubocop.org/rubocop/1.81/usage/basic_usage.html))
- **`RUBY-TOOL-03`** (MUST) Use RuboCop check-only in the gate (`bundle exec rubocop`, exit 1 on offenses, exit 2 on config error); autocorrect locally with `-a` (safe) and review `-A` (unsafe) diffs. `--parallel` is the default. `-A` can change behaviour; only safe cops are auto-applied unreviewed. ([source](https://docs.rubocop.org/rubocop/1.81/usage/basic_usage.html))
- **`RUBY-TOOL-04`** (SHOULD) Add the department gems that match the stack: `rubocop-rails`, `rubocop-rspec` or `rubocop-minitest`, `rubocop-performance`, `rubocop-sorbet` when Sorbet is used. Start Rails apps from the Omakase style or Standard rather than hand-tuning hundreds of cops. Domain cops catch Rails-specific bugs (`Rails/SkipsModelValidations`, `Rails/FindEach`). ([source](https://github.com/rubocop/rubocop-rails))
- **`RUBY-TOOL-05`** (SHOULD) Ruby is dynamically typed: choose Sorbet (`bundle exec srb tc`, inline `sig` blocks, Tapioca for RBI generation) or RBS + Steep (`bundle exec steep check`, `.rbs` files in `sig/`, `rbs collection` for gem signatures); do not mix them in one codebase. Start at `# typed: false` then ratchet files to `typed: true`. Gradual typing only pays off if the checker runs in CI and strictness only increases. ([source](https://sorbet.org/docs/overview))
- **`RUBY-TOOL-06`** (MUST) Run `bundle exec bundle-audit check --update` (gem CVEs from ruby-advisory-db) and `bundle exec brakeman -q --no-pager` (code SAST) in CI; both exit non-zero on findings. Add `bundle outdated`/Dependabot for freshness. Two different layers: vulnerable dependencies vs. vulnerable code. ([source](https://github.com/rubysec/bundler-audit))
- **`RUBY-TOOL-07`** (SHOULD) Ship Ruby LSP (`ruby-lsp`, Shopify) as the editor server and let it call RuboCop for format-on-save; turn off a second formatter (Solargraph formatting, Prettier-ruby). Two format-on-save tools produce diff churn. ([source](https://shopify.github.io/ruby-lsp/))
- **`RUBY-TOOL-08`** (MUST) Use `bundle exec` (or binstubs in `bin/`) for every tool invocation, never a globally installed gem version. Global gems can differ from the lockfile and give different lint results. ([source](https://bundler.io/guides/gemfile.html))

## ARCH: architecture

Layering and the loops hexagon: see specs/ARCHITECTURE.md and specs/SOLID.md. Ruby has no import graph (Zeitwerk constant references), so the gate delegates direction checks to Packwerk (`arch.parser = none`).

Rails + hexagon tree (each `app/*` folder is an autoload root, so the folder is not in the constant name):

```text
app/
├── domain/            # pure Ruby: entities, Data.define value objects, domain services, errors
├── application/       # use cases (one public `call`) + ports
├── adapters/
│   ├── inbound/       # controllers, jobs (thin)
│   └── outbound/      # persistence (ActiveRecord), clients (Faraday)
config/initializers/container.rb  # composition root
packs/<name>/package.yml          # Packwerk: enforce_dependencies: true
```

- **`RUBY-ARCH-01`** (SHOULD) Use the Rails way (fat-model-free MVC) for CRUD apps; adopt hexagonal only where domain logic is non-trivial, and say which in an ADR. Rails is opinionated: project rules win. Fighting the framework everywhere raises cost; hexagonal everywhere is overkill for CRUD. ([source](https://guides.rubyonrails.org/getting_started.html))
- **`RUBY-ARCH-02`** (MUST) Keep controllers thin: params parsing and authz, one call to a use case, rendering. No business rules, no queries beyond the use case, no callbacks that fan out side effects. Controller logic is untestable without HTTP and gets duplicated in jobs. ([source](https://guides.rubyonrails.org/action_controller_overview.html))
- **`RUBY-ARCH-03`** (SHOULD) Put orchestration in single-purpose use case classes exposing one public `call`; return a result (value or `Dry::Monads::Result`/own `Result` struct) instead of raising for expected failures. Gives the application layer an explicit, testable entry point. ([source](https://dry-rb.org/))
- **`RUBY-ARCH-04`** (SHOULD) Treat Active Record models as persistence adapters when the domain is rich: map rows to domain objects in a repository class. For simple domains, using models directly is acceptable if business rules stay in plain objects/services. Active Record is an active-record pattern (data + behaviour + persistence); it couples the domain to the database by design. ([source](https://guides.rubyonrails.org/active_record_basics.html))
- **`RUBY-ARCH-05`** (MUST) Ruby has no access control across files: `private` and `protected` are per-class and bypassable with `send`. Use `private_constant`, plus privacy checks from the `packwerk-extensions` gem (`enforce_privacy`, `app/public/` as the pack's public API; core Packwerk checks only dependencies) to define module surfaces. Without a tool, any constant can be referenced from anywhere (no cycle checks either). ([source](https://github.com/Shopify/packwerk))
- **`RUBY-ARCH-06`** (MUST) Constants map to files via Zeitwerk: `app/domain/billing/invoice.rb` defines `Billing::Invoice`; each `app/*` subdirectory is an autoload root and is not part of the constant name. Dependencies are constant references, not import lines; `require`/`require_relative` appear only for non-autoloaded `lib/` code and gems. The loops arch checker must scan constant references and Zeitwerk roots, not import statements. ([source](https://guides.rubyonrails.org/autoloading_and_reloading_constants.html))
- **`RUBY-ARCH-07`** (MUST) Enforce dependency direction with Packwerk: `bin/packwerk check` and `bin/packwerk validate` in CI; each `package.yml` sets `enforce_dependencies: true` (or `strict`); privacy needs the `packwerk-extensions` gem (`enforce_privacy: true`); commit `package_todo.yml` and only shrink it. Packwerk sees only Zeitwerk-resolvable constants, not method calls. It is the de-facto boundary checker for Rails (Shopify). ([source](https://github.com/Shopify/packwerk))
- **`RUBY-ARCH-08`** (SHOULD) Wire dependencies by constructor injection with keyword arguments and defaults (`def initialize(clock: Clock.new, repo: InvoiceRepo.new)`); the composition root is an initializer or a `Dry::Container`. Avoid service locators (`Rails.application.config.x` lookups inside domain code) and global singletons. Keyword defaults give cheap DI without a container; locators hide dependencies. ([source](https://dry-rb.org/))
- **`RUBY-ARCH-09`** (MUST) Keep the domain pure: no `ActiveRecord::`, `ActionController::`, `Rails.`, `ENV`, `Net::HTTP`, `File`, `Time.now`/`Date.today`/`Time.current`, `rand`/`SecureRandom`, `Thread`, `sleep`, `puts`. Inject a clock and an id generator. Determinism and fast unit tests. (see specs/ARCHITECTURE.md, [Ruby Time](https://docs.ruby-lang.org/en/master/Time.html))
- **`RUBY-ARCH-10`** (SHOULD) Define ports as small modules documenting the methods (or an RBS/Sorbet interface) in the application layer, owned by the consumer; rely on duck typing at runtime and verify with `instance_double`/contract tests. Ruby has no interface keyword; a documented contract plus a shared spec keeps adapters honest. ([source](https://github.com/ruby/rbs))
- **`RUBY-ARCH-11`** (SHOULD) SOLID limits: methods under ~10 lines (RuboCop `Metrics/MethodLength`), classes under ~100 lines, at most 4 params (use keyword args beyond that); ABC size and cyclomatic complexity caps via `Metrics/*`. Metrics cops are the native size gate. ([source](https://rubystyle.guide/))
- **`RUBY-ARCH-12`** (AVOID) Avoid callbacks (`after_save`, `after_commit`) that call other services or send email; prefer an explicit use case or a domain event published after commit. Callbacks hide control flow, run in seeds/tests/console, and break transaction boundaries. ([source](https://guides.rubyonrails.org/active_record_callbacks.html))

## IDIOM: what to do and what to avoid

- **`RUBY-IDIOM-01`** (MUST) Raise exceptions for exceptional failures, inherit from `StandardError` (never `Exception`), define an app error hierarchy (`class MyApp::Error < StandardError`), and rescue the narrowest class. Never `rescue Exception` or an empty `rescue`. Re-raise with `raise ... , cause: e` or let `cause` be implicit. `rescue Exception` swallows `SignalException`/`NoMemoryError`; bare `rescue => e` without handling hides bugs. ([source](https://rubystyle.guide/#exceptions))
- **`RUBY-IDIOM-02`** (AVOID) Do not use exceptions for control flow; return result objects or `nil`+reason for expected outcomes. Use `retry` sparingly with a cap. Raising is slow-ish and obscures flow. ([source](https://rubystyle.guide/#exceptions))
- **`RUBY-IDIOM-03`** (SHOULD) Absence is `nil`: use safe navigation `&.`, `Hash#fetch` (raises on missing key), `dig`, and `Array#first`/`find` with explicit handling. Avoid `try` chains and `nil` returns that carry meaning silently; do not return `false` for "not found". `nil` is falsy and propagates `NoMethodError` far from the cause. ([source](https://rubystyle.guide/#no-nil-compare))
- **`RUBY-IDIOM-04`** (MUST) Start every file with `# frozen_string_literal: true` and freeze constants (`.freeze` or `Ractor.make_shareable`); model value objects with `Data.define(:a, :b)` (immutable, keyword init) and `Struct` with `keyword_init: true` only when mutation is needed. Mutable shared constants and strings are a classic thread-safety and aliasing bug. ([source](https://docs.rubocop.org/rubocop/cops_style.html))
- **`RUBY-IDIOM-05`** (SHOULD) Use pattern matching (`case/in`, `in {status: "ok"}`) for destructuring result hashes; give `case/in` an `else` or accept `NoMatchingPatternError` deliberately. Pattern matching replaces nested hash/array poking; a missing branch raises. ([source](https://docs.ruby-lang.org/en/master/syntax/pattern_matching_rdoc.html))
- **`RUBY-IDIOM-06`** (MUST) Release resources with block forms (`File.open(path) { ... }`, `connection_pool.with { }`, `Tempfile.create { }`) or `ensure`; never rely on GC to close files and sockets. Block forms guarantee close on exception. ([source](https://docs.ruby-lang.org/en/master/File.html))
- **`RUBY-IDIOM-07`** (MUST) Compare with `==`/`eql?`; override `==`, `eql?` and `hash` together for value objects (or use `Data`). Build strings with `<<`/`String#+`/interpolation or `Array#join`, not `+=` in loops. Treat strings as UTF-8, use `Time.current`/`Time.zone` (Rails) or `Time.now.utc`, store UTC. `Hash` keys use `eql?`/`hash`; naive times cause DST and TZ bugs. ([source](https://docs.ruby-lang.org/en/master/Time.html))
- **`RUBY-IDIOM-08`** (SHOULD) Follow the community Ruby Style Guide: snake_case methods/vars, CamelCase classes, SCREAMING_SNAKE constants, predicate methods end in `?`, dangerous ones in `!` only when a non-bang twin exists. Document public API with YARD tags. `!` means "more dangerous than the plain version", not "mutates". ([source](https://rubystyle.guide/#naming))
- **`RUBY-IDIOM-09`** (AVOID) Avoid monkey-patching core classes and `method_missing`/`define_method` magic in application code; when needed use `Module#prepend` or refinements, always define `respond_to_missing?`, and never `eval` user input. Active Support core extensions are the one accepted exception inside Rails. Global patches break gems and make `ruby 4.0 Ruby::Box` isolation matter; `method_missing` without `respond_to_missing?` lies to callers. ([source](https://rubystyle.guide/))
- **`RUBY-IDIOM-10`** (MUST) Never mutate default args or constants (`def f(opts = {})` is fine only if not mutated; use `opts.dup`). Beware `Hash.new([])` (shared default), `Array.new(3, [])` (same object), and `a` memoised into shared state; use the block form of `Hash.new` (the block receives the hash and the key). Shared mutable default is the classic aliasing bug. ([source](https://docs.ruby-lang.org/en/master/Hash.html))
- **`RUBY-IDIOM-11`** (MUST) Use `Integer`/`BigDecimal`/`Rational` for money, never `Float`; use `Comparable`/`Enumerable` instead of hand-written loops where they fit. Float rounding errors in currency. ([source](https://github.com/ruby/bigdecimal))
- **`RUBY-IDIOM-12`** (SHOULD) Use keyword arguments for >2 params and for booleans; avoid positional boolean flags and opts-hash args. Ruby 3 separates positional and keyword args; no implicit hash-to-kwargs. Readability and Ruby 3 argument-separation correctness. ([source](https://rubystyle.guide/#no-optional-hash-params))
- **`RUBY-IDIOM-13`** (SHOULD) Prefer `each`/`map`/`select`/`sum`/`each_with_object` and enumerators; use `find_each`/`in_batches` (Active Record) for large tables and `lazy` for big streams; avoid `for` loops and building big arrays only to iterate. Memory and clarity. ([source](https://rubystyle.guide/))

## CONC: concurrency and the `-race` equivalent

**Race policy: `mode = none`.** CRuby has no data-race detector; the substitute is the `test` check (RUBY-CONC-05, WORKFLOW §6).

- **`RUBY-CONC-01`** (MUST) Know the model: CRuby runs Ruby threads concurrently only for blocking I/O; the GVL serialises Ruby code, so CPU parallelism needs multiple processes (Puma workers, Sidekiq processes) or Ractors (still experimental in 4.0). Fibers plus the fiber scheduler (`Fiber.set_scheduler`, used by the `async` gem) give cooperative I/O concurrency. Picking the wrong model wastes cores or deadlocks. ([source](https://docs.ruby-lang.org/en/master/Thread.html))
- **`RUBY-CONC-02`** (MUST) The GVL does not make compound operations atomic: `@x ||= compute`, `h[k] ||= v`, `count += 1` can interleave at method boundaries and on JRuby/TruffleRuby run truly parallel. Guard shared state with `Mutex#synchronize`, `Concurrent::Map`/`Concurrent::AtomicFixnum` (concurrent-ruby), or avoid shared state. Check-then-act races exist even under the GVL. ([source](https://docs.ruby-lang.org/en/master/Thread/Mutex.html))
- **`RUBY-CONC-03`** (MUST) Puma runs threads per process: never keep per-request state in class variables, class-level instance variables, constants or `Thread.current`-less globals; use `ActiveSupport::CurrentAttributes` or locals; make memoised class-level caches thread-safe. Check gems for thread safety before adding. Rails app code is shared by all threads of a process. ([source](https://guides.rubyonrails.org/threading_and_code_execution.html))
- **`RUBY-CONC-04`** (MUST) Size pools consistently: DB pool (`pool:` in `database.yml`) >= Puma threads per process (and Sidekiq `concurrency`); set `RAILS_MAX_THREADS` once and read it in both `puma.rb` and `database.yml`. Fewer connections than threads causes `ConnectionTimeoutError`. ([source](https://github.com/puma/puma))
- **`RUBY-CONC-05`** (MUST) Race substitute (`race.mode = none`): the gate's `test` check runs the suite in random order with a printed seed (`--order random --seed {seed}`) and repeats it (`repeat: 2`, a new seed each time). A failure that disappears on rerun is a bug, not flake. Parallel processes (`parallel_rspec`, Rails `parallelize`) and stress tests that spin N threads against shared objects are review items. No detector exists; order and parallelism randomise interleavings and expose global-state leaks. ([source](https://rspec.info/features/3-13/rspec-core/command-line/order/))
- **`RUBY-CONC-06`** (AVOID) Do not use Ractors in production services yet: they are experimental in 4.0 (new `Ractor::Port`, `Ractor.yield`/`take` removed), isolate objects (deep copy or `move: true`) and many gems are not Ractor-safe. API churn and low gem support. ([source](https://www.ruby-lang.org/en/news/2025/12/25/ruby-4-0-0-released/))
- **`RUBY-CONC-07`** (SHOULD) Async I/O: use `Async`/Falcon only if the whole stack is fiber-scheduler-aware; never call a blocking C extension or `sleep`-style code inside a scheduler fiber, and always set timeouts (`Timeout` is unsafe; use client-level timeouts or `Async::Task#with_timeout`). `Timeout.timeout` raises asynchronously and can corrupt state. ([source](https://docs.ruby-lang.org/en/master/Fiber/Scheduler.html))
- **`RUBY-CONC-08`** (MUST) Background jobs (Sidekiq, Active Job with Solid Queue/Sidekiq/GoodJob): pass simple JSON-safe ids, make `perform` idempotent (at-least-once delivery), wrap side effects in transactions or idempotency keys, cap retries, use `sidekiq_retries_exhausted`, and shut down on `TSTP` then `TERM` with `-t` timeout. Jobs re-run on retry or crash; complex args break serialization. ([source](https://github.com/sidekiq/sidekiq/wiki/Best-Practices))
- **`RUBY-CONC-09`** (MUST) Enqueue jobs after the transaction commits (`after_commit`, or Rails 7.2+ `enqueue_after_transaction_commit`), not inside it. The job can run before the row is visible and fail with `RecordNotFound`. ([source](https://guides.rubyonrails.org/active_job_basics.html))
- **`RUBY-CONC-10`** (MUST) Use `ConnectionPool`/`ActiveRecord::Base.connection_pool.with_connection` in manually created threads, and join them; never leave `Thread.new` fire-and-forget in request code. Threads that check out connections leak them. ([source](https://github.com/mperham/connection_pool))

## TEST: testing

Coverage is lcov at `coverage/lcov.info` through `simplecov-lcov` (RUBY-TEST-06); wave 0 adds the helper (D13).

- **`RUBY-TEST-01`** (MUST) Pick RSpec (`rspec-rails`) or Minitest (Rails default) per project and do not mix; run via `bundle exec rspec` or `bin/rails test`. Two frameworks split conventions and CI time. ([source](https://github.com/rspec/rspec-rails))
- **`RUBY-TEST-02`** (MUST) Test layout: RSpec `spec/**/*_spec.rb` mirroring `app/`; Minitest `test/**/*_test.rb`; helpers in `spec/spec_helper.rb`/`rails_helper.rb`/`test/test_helper.rb`. Test globs: `spec/**/*_spec.rb`, `test/**/*_test.rb`, `test/**/test_*.rb`. Lets hooks and the arch checker classify files. ([source](https://guides.rubyonrails.org/testing.html))
- **`RUBY-TEST-03`** (SHOULD) RSpec style: `describe`/`context`/`it` with behaviour-naming strings, one expectation concept per example, `let` lazily, `subject` sparingly; shared examples for port contracts. Minitest: `test "..."`, arrange-act-assert. Parametrise with loops over data, not copy-paste. Readable failure output, no cross-test state. ([source](https://rspec.info/))
- **`RUBY-TEST-04`** (SHOULD) Prefer fakes and real in-memory adapters; use `instance_double`/`verify_partial_doubles` (rspec-mocks) so doubles fail when the real method changes; stub HTTP at the boundary with WebMock/VCR; do not mock the object under test or Active Record chains. Verifying doubles stop drift; mock chains break on refactor. ([source](https://rspec.info/features/3-13/rspec-mocks/))
- **`RUBY-TEST-05`** (SHOULD) Use a real database for integration tests (Rails wraps each test in a transaction by default; `use_transactional_fixtures`); use Testcontainers-style Docker services in CI (Postgres/Redis) rather than SQLite substitutes; DatabaseCleaner only for non-transactional (JS/system) tests. SQLite-vs-Postgres behaviour differs. ([source](https://guides.rubyonrails.org/testing.html))
- **`RUBY-TEST-06`** (MUST) Measure coverage with SimpleCov, loaded **first** in the spec/test helper (before app code), with `enable_coverage :branch`, a per-criterion `minimum`, and `skip` for `/spec/`, `/test/`, `/config/`, `/db/`, `/vendor/` (SimpleCov 1.x: `cover`/`skip`/`group`; `add_filter` is deprecated). loops reads **lcov** (D6): add the `simplecov-lcov` gem with `report_with_single_file = true` and `single_report_path = "coverage/lcov.info"`; its `SF:` paths are `./`-prefixed and the parser normalises them. SimpleCov alone writes only `coverage/index.html` and `coverage/coverage.json`. The helper must start SimpleCov before code loads or results are missing; the gate parses `coverage/lcov.info`. ([source](https://github.com/simplecov-ruby/simplecov))
- **`RUBY-TEST-07`** (MUST) New-code coverage >= 70%: loops computes it from `git diff <base>` lines against the `DA:` records of `coverage/lcov.info`; `undercover --compare <base>` (reads `coverage/coverage.json`) is the project-side alternative. In parallel runs merge result sets (`SimpleCov.collate Dir["coverage/.resultset*.json"]`) first. Diff-based gate; parallel workers write separate partial results. ([source](https://github.com/grodowski/undercover))
- **`RUBY-TEST-08`** (SHOULD) Property and mutation testing: `rantly` or `propcheck` for properties (rare); use `mutant` (commercial for closed source) on hot domain code only. Use `rspec-benchmark`/`benchmark-ips` for perf assertions. Mutation testing is costly; reserve for pure domain logic. ([source](https://github.com/mbj/mutant))
- **`RUBY-TEST-09`** (MUST) Run RSpec with `config.order = :random` (`--order random`), print and reuse the seed (`--seed N`), enable `config.warnings`; Minitest randomises by default (`--seed`). Freeze time with `travel_to`/`Timecop` and inject clocks; seed `Random.srand`. Parallelise with `parallelize(workers: :number_of_processors)` (Rails) or `parallel_tests` (one DB per process via `TEST_ENV_NUMBER`). Random order and parallelism expose hidden shared state. ([source](https://rspec.info/features/3-13/rspec-core/command-line/order/))
- **`RUBY-TEST-10`** (SHOULD) Fast loop: `bundle exec rspec path/to/file_spec.rb:LINE`, `bin/rails test test/models/user_test.rb:12`, `--only-failures` (RSpec `example_status_persistence_file_path`), `--fail-fast`; use Spring-free `bin/rails` with bootsnap; `guard-rspec` for watch mode. Quick red/green cycles. ([source](https://rspec.info/features/3-13/rspec-core/command-line/))
- **`RUBY-TEST-11`** (SHOULD) Use factories (`factory_bot`) or fixtures consistently; avoid factories that create deep association graphs by default; keep factories valid and lint them (`FactoryBot.lint`) in CI. Heavy factories make suites slow and brittle. ([source](https://github.com/thoughtbot/factory_bot))
- **`RUBY-TEST-12`** (SHOULD) Exclude generated code from coverage with `skip` (db/schema, migrations, vendor) and `# :nocov:` only with a justification comment. Honest denominators. ([source](https://github.com/simplecov-ruby/simplecov))

## PERF: performance and profiling

- **`RUBY-PERF-01`** (SHOULD) Benchmark with `benchmark-ips` (iterations per second with error margin) not `Benchmark.realtime` loops; compare two implementations in one run. Statistically meaningful comparisons. ([source](https://github.com/evanphx/benchmark-ips))
- **`RUBY-PERF-02`** (SHOULD) Profile CPU with `stackprof` (sampling) and flamegraphs, allocations/memory with `memory_profiler`, Rails request profiling with `rack-mini-profiler`; prefer sampling profilers over `ruby-prof` in production. Sampling has low overhead. ([source](https://github.com/tmm1/stackprof))
- **`RUBY-PERF-03`** (SHOULD) Enable YJIT in production, use jemalloc or `MALLOC_ARENA_MAX=2` to curb memory fragmentation, tune Puma workers = cores and threads 3-5, and use `bootsnap` to cut boot time. Measure before/after. Biggest cheap wins for Rails memory and latency. ([source](https://docs.ruby-lang.org/en/master/jit/yjit_md.html))
- **`RUBY-PERF-04`** (MUST) Avoid N+1 queries (`includes`/`preload`, Bullet in dev/test), loading whole tables (`.all.each` -> `find_each`), `Array#include?` on big lists (use `Set`, core in 4.0), `+=` string building in loops, and per-request regex compilation. These dominate Rails request time. ([source](https://github.com/flyerhzm/bullet))
- **`RUBY-PERF-05`** (SHOULD) Cache deliberately: Rails low-level `Rails.cache.fetch` with an expiry and a versioned key; Solid Cache for DB-backed caching; never cache per-user data under a shared key. Stale or leaked cache data. ([source](https://guides.rubyonrails.org/caching_with_rails.html))

## SEC: security

- **`RUBY-SEC-01`** (MUST) Never interpolate input into SQL: use `where(name: x)`, `where("name = ?", x)` or named binds; `sanitize_sql_like` for LIKE; whitelist `order`/`pluck`/`group` column names. Avoid `find_by_sql`, `exists?`, `calculate` with raw strings. Command injection: use `system("cmd", arg1, arg2)` array form, never backticks/`system("..#{x}")`/`open(...)` with user data. The classic Rails SQLi/command injection vectors. ([source](https://guides.rubyonrails.org/security.html))
- **`RUBY-SEC-02`** (MUST) Never `Marshal.load`, `YAML.load`, `Psych.unsafe_load`, `Oj.load` (object mode) or `ERB.new(user)` on untrusted data; use `JSON.parse`, `YAML.safe_load(permitted_classes: [...])`, and Rails `config.active_record.use_yaml_unsafe_load = false`. Marshal can run code on load. Unsafe deserialization gives remote code execution. ([source](https://docs.ruby-lang.org/en/master/Marshal.html))
- **`RUBY-SEC-03`** (MUST) Use strong parameters (`params.require(:x).permit(:a, :b)`); never `permit!` or `update(params[:x])`; do not permit `admin`, `role`, `*_id` ownership fields; scope lookups to the current user (`current_user.orders.find`). Mass assignment and IDOR. ([source](https://guides.rubyonrails.org/action_controller_overview.html))
- **`RUBY-SEC-04`** (MUST) Keep CSRF protection (`protect_from_forgery`/default in full-stack apps), escape output (`<%= %>` escapes; avoid `raw`, `html_safe`, `sanitize` with loose allowlists), set `config.force_ssl = true`, `config.hosts`, a CSP, and SSRF-safe outbound HTTP (allowlist hosts, resolve and check IPs, no redirects to private ranges). Use `redirect_to` only with `only_path`/allowlisted URLs. Rails defaults protect only if not disabled. ([source](https://guides.rubyonrails.org/security.html))
- **`RUBY-SEC-05`** (MUST) Secrets: Rails encrypted credentials (`config/credentials/*.yml.enc`, key in `config/*.key` or `RAILS_MASTER_KEY`, never committed) or env vars/vault; never log them (`config.filter_parameters`). Use `SecureRandom`, `bcrypt`/`has_secure_password` or `argon2` for passwords, `ActiveSupport::MessageEncryptor`/Active Record Encryption for data; avoid `rand`, `Digest::MD5/SHA1` for passwords and `==` for secret comparison (use `ActiveSupport::SecurityUtils.secure_compare`). Standard secret and crypto pitfalls. ([source](https://guides.rubyonrails.org/security.html))
- **`RUBY-SEC-06`** (SHOULD) Validate at the boundary with strong params plus a schema (`dry-validation`/`dry-schema`, or Active Model validations on form objects); never trust model validations as authorization. Input shape is an adapter concern. ([source](https://github.com/dry-rb/dry-validation))
- **`RUBY-SEC-07`** (MUST) Supply chain: commit and verify `Gemfile.lock`, use `https://rubygems.org` only, avoid `git:` gems from forks, require MFA on own gems, review native-extension gems, and run `bundle-audit` and Dependabot. Gem typosquatting and compromised maintainers occur. ([source](https://guides.rubygems.org/security/))
- **`RUBY-SEC-08`** (MUST) Run Brakeman on every PR (`brakeman -q --no-pager`, formats `-f json`/`-f html`/`-o file`); keep `config/brakeman.ignore` reviewed with notes, never blanket-ignore. Catches SQLi, XSS, mass assignment, unsafe deserialization statically. ([source](https://brakemanscanner.org/docs/options/))

## DATA: persistence

- **`RUBY-DATA-01`** (SHOULD) Default to Active Record in Rails; use Sequel or ROM (Hanami) for repository-style persistence; drop to Arel or `connection.exec_query` with binds for hard queries; never build SQL by string concatenation. Active Record is the idiom; raw SQL is an escape hatch. ([source](https://guides.rubyonrails.org/active_record_basics.html))
- **`RUBY-DATA-02`** (MUST) Migrations: `bin/rails g migration`, commit `db/schema.rb` (or `structure.sql` for DB-specific features), write reversible `change` methods or explicit `up`/`down`, never edit a merged migration, and run `strong_migrations` to block unsafe ops (add index concurrently, split NOT NULL, no column renames in one deploy). Zero-downtime: expand, backfill in batches, contract. Locks and incompatible deploys cause outages. ([source](https://guides.rubyonrails.org/active_record_migrations.html))
- **`RUBY-DATA-03`** (MUST) Wrap multi-record writes in `ActiveRecord::Base.transaction` inside the use case (application layer), not in controllers/models callbacks; keep transactions short with no HTTP calls or job enqueue inside; use `with_lock`/optimistic `lock_version` for concurrent updates. Transaction boundary is a use-case decision. ([source](https://guides.rubyonrails.org/active_record_basics.html))
- **`RUBY-DATA-04`** (MUST) Prevent N+1 with `includes`/`preload`/`eager_load`, Bullet in dev/test, `strict_loading` (`has_many ..., strict_loading: true` or `config.active_record.strict_loading_by_default`); use `counter_cache`, `pluck`, `exists?`. Avoid default scopes. Mark deprecated associations with Rails 8.1 `deprecated: true`. N+1 is the most common Rails production slowdown. ([source](https://guides.rubyonrails.org/active_record_querying.html))
- **`RUBY-DATA-05`** (MUST) Set the pool (`pool: ENV.fetch("RAILS_MAX_THREADS", 3)`), `checkout_timeout`, DB statement/lock timeouts and `connect_timeout` in `database.yml`; use PgBouncer if processes x threads exceed server limits; use multi-DB config for replicas (`connects_to`, role switching). Connection exhaustion and hung queries. ([source](https://guides.rubyonrails.org/configuring.html))
- **`RUBY-DATA-06`** (MUST) Add database-level constraints (NOT NULL, unique index, foreign keys) in addition to model validations; `validates_uniqueness_of` alone races. Validations run in app memory, so races pass. ([source](https://guides.rubyonrails.org/active_record_validations.html))

## API: APIs and integration

- **`RUBY-API-01`** (SHOULD) Rails API apps: `rails new --api`, routes in `config/routes.rb`, Rack middleware stack for cross-cutting concerns; use Roda (routing tree) or Sinatra for tiny services, Hanami for explicit architecture. Match framework weight to the problem. ([source](https://guides.rubyonrails.org/api_app.html))

## FW: frameworks

Rails conventions win over loops layering when they conflict; log the override (RUBY-FW-02).

- **`RUBY-FW-01`** (MUST) Dominant: Rails 8.1 (current series; bug fixes one year, security fixes two years after first release, so 8.1 bug fixes about 2026-10 and security about 2027-10; 8.0 security about 2026-11; 7.2 is EOL, security support ended about 2026-08), then Sinatra, Roda, Hanami. Jobs: Sidekiq or Solid Queue (Rails 8 default, DB-backed). Servers: Puma (default), Falcon, Unicorn. Pick supported versions; dates derived from the maintenance policy. ([source](https://guides.rubyonrails.org/maintenance_policy.html))
- **`RUBY-FW-02`** (MUST) Rails conventions that override loops: Zeitwerk autoload roots under `app/`, models in `app/models`, tests in `spec/` or `test/`, migrations in `db/migrate`, schema file committed. Where hexagonal conflicts (Active Record as entity), follow Rails and log the override. Loops follows the framework; project rules win. ([source](https://guides.rubyonrails.org/autoloading_and_reloading_constants.html))
- **`RUBY-FW-03`** (SHOULD) Hanami: slices with containers, actions, repositories (ROM), operations, and explicit dependency injection via `Deps[]`; matches hexagonal almost 1:1. Roda/Sinatra: no structure imposed; add one yourself. Frameworks differ in how much architecture they force. ([source](https://hanamirb.org/))
- **`RUBY-FW-04`** (AVOID) Rails footguns: autoload outside `eager_load` in production (use Zeitwerk, `bin/rails zeitwerk:check`), `default_scope`, callbacks with side effects, fat controllers/models, `update_attribute`/`update_column` skipping validations (`Rails/SkipsModelValidations`), `find_by` returning `nil` unnoticed, `Time.now` instead of `Time.current`, `rescue_from` swallowing errors. Known sources of production bugs. ([source](https://guides.rubyonrails.org/autoloading_and_reloading_constants.html))
- **`RUBY-FW-05`** (SHOULD) Puma/Sidekiq config: Puma `workers` = cores, `threads 3,3` (5 is typical), `preload_app!` with `on_worker_boot` DB reconnects; Sidekiq `concurrency <= DB pool`, queues weighted, scheduled/retry jobs idempotent. Misconfigured pools are a top outage cause. ([source](https://github.com/puma/puma))

## Top 10 footguns

1. No race detector. Assuming the GVL makes code thread-safe -> no shared mutable state, `Mutex`/`Concurrent::Map`, random order plus repeat runs. ([source](https://docs.ruby-lang.org/en/master/Thread.html))
2. `Marshal.load`/`YAML.load` on untrusted data -> `JSON.parse`, `YAML.safe_load(permitted_classes: [])`. ([source](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html))
3. SQL string interpolation (`where("name = '#{x}'")`) -> `where(name: x)` or bind parameters. ([source](https://rails-sqli.org/))
4. Mass assignment (`User.create(params[:user])`, `permit!`) -> a strong-params allowlist. ([source](https://guides.rubyonrails.org/action_controller_overview.html))
5. N+1 queries (`posts.each { |p| p.author.name }`) -> `includes(:author)`, `strict_loading`. ([source](https://guides.rubyonrails.org/active_record_querying.html))
6. Shared mutable state in Puma (`@@cache`, class-level `@x ||=`, mutable constants) -> `CurrentAttributes`, frozen constants, `Concurrent::Map`. ([source](https://guides.rubyonrails.org/threading_and_code_execution.html))
7. `rescue Exception` or an empty `rescue` -> rescue `StandardError` subclasses and re-raise. ([source](https://rubystyle.guide/#exceptions))
8. Non-idempotent jobs, or enqueuing inside a transaction -> idempotency keys, enqueue after commit. ([source](https://github.com/sidekiq/sidekiq/wiki/Best-Practices))
9. Callback side effects and fat models -> explicit use cases. ([source](https://guides.rubyonrails.org/active_record_callbacks.html))
10. Shared defaults and mutated literals (`Hash.new([])`, no `frozen_string_literal`) -> block form of `Hash.new`, freeze. ([source](https://docs.ruby-lang.org/en/master/Hash.html))
